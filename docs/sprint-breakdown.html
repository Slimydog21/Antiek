Master Product Spec — Sprint Breakdown

Antiek — Road from MVP to Multi-User Network Effects

An exhaustive, page-per-sprint reading of docs/master-product-spec.md §14

This document is a single-source navigable companion to the Antiek Master Product Spec. Every sprint that the spec sequences — Sprints 11 through Sprint 30+, plus four parallel tracks — gets its own page below. Each page answers the same five questions in the same order: what is this sprint for, what is the strategic objective, which goals are achieved in progression, which deliverables ship as evidence, and what does the sprint unblock.

Sprints 11–16 are shipped and committed. Sprint 17 through Sprint 21 substrate is written and tested locally, but as of the most recent audit it remains uncommitted in the operator's working tree — no GitHub push, no Cloudflare Pages auto-deploy, no Hetzner Ansible run. Sprints 22 and beyond are future work. Parallel tracks (RLM, Loop 3 unlock, autoresearch, Prime Intellect) sit off the mainline critical path and gate on explicit ratification criteria.

How to read this Each sprint page is self-contained and prints as its own physical page. Click any sprint in the left sidebar to navigate; use Cmd+P to produce a paginated PDF with one sprint per leaf. The status dot beside each sprint name reflects the latest audit, not the spec's optimistic assertion.

§1Status legend

Scaffold landed locally — code, schema, tests in worktree; not committed; not yet visible on the website

Parallel track — off the mainline critical path, governed by its own ratification criteria

§2The mainline arc, compressed

  1. Sprints 11–16 — built the substrate, four surfaces, attribution telemetry, and interview machinery. Workstation reached "usable." Compounding thesis enters the demonstration period.
  2. Sprints 17–21 — sharpen the workstation, ship the legal gate, light up the notebook surface, turn on the pay-as-you-go pricing model, prove the visible-artifact growth motion, ratify autoresearch and dispatch posture verdicts.
  3. Sprint 22 — the multi-user pivot. Two-graph architecture, Auth, Trust Center publication, substrate Stage 0 → Stage 1 transition. Gated on six months of solo-operator compounding demonstration.
  4. Sprints 23–30+ — ad inventory matures, IP attribution payouts route real money, cross-graph network effects unlock once the creator and publisher populations are live.

§3Disciplines that govern every sprint

  • Voice and style discipline (§5) — prose flows, no LLM-slop patterns, no forced bullets inside synthesis prose. Extends to UI choices and AI-driven UI actions.
  • DuckDB single-writer invariant (§16) — never run uvicorn with --workers > 1 until the substrate explicitly transitions stage.
  • Provenance is non-negotiable — every claim cites chunks, every chunk cites documents, every document carries an ip_holder_id.
  • Substrate is the moat (§2.5) — one graph, four surfaces, no "four products" framing.
  • Legal gate is binding (§9.0) — no payouts on an ungated graph, no commingled escrow funds, no pre-onboarded escrow active against unconsenting rights holders.
Phase 0 · Shipped & pushed · Sprint 11

Sprint 11 — Research Workstation MVP

From "operator runs Python and reads markdown" to "operator uses a web app"
Shipped Surface A Substrate prep

§1Strategic objective

Sprint 11 is the moment Antiek becomes usable. Sprints 0–10 built a fully working substrate behind a Python entrypoint; Sprint 11 wraps it in the web UI that turns the operator's accumulated graph into an interactive workstation. Every later sprint assumes Sprint 11's surface as the default frame of reference.

§2Progressive phases

API surface — three REST endpoints

Wire the substrate's existing investigation lifecycle into a public HTTP contract: POST /investigations to start, GET /investigations/{id} to poll, WS /investigations/{id}/trajectory to stream phase-by-phase progress. The orchestrator and dispatch layers stay unchanged; the API is the thinnest possible adapter.

Exit: curl can start an investigation end-to-end and stream the 8-phase trajectory.

Voice and style v1 — substrate prompt engineering

Land the §5 discipline at the substrate level: synthesizer prompt addendum (~50 LOC) with forbidden constructions, evidence-retriever prompt parallel discipline (~30 LOC), and the new style_extractor role (~150 LOC) that produces a 150–300 word house-style guide injected into the synthesizer's context pack.

Exit: MASTER.md output passes the §5.4 verification checks — ≤2 em-dashes per thesis, no padding constructions, ≥40% sector-vocabulary match.

Multi-user schema prep — owner_user_id on every row

Add owner_user_id to documents, chunks, nodes, edges, investigations with a single hard-coded default. Sprint 22's multi-user pivot then requires only application-layer changes, not schema migrations. Per §13.10 substrate hygiene.

Exit: schema migration applied to the production DuckDB; all writers populate the column; reads ignore it.

Mode A — the Research Workstation UI

Vite + React 18 + TypeScript strict + Tailwind, served from Cloudflare Pages at antiek.ai (then-canonical app.antiek.ai). Chat input, live trajectory view (WebSocket-driven), MASTER.md viewer with hover-citation, chunk modal, highlight-to-chase, past-investigations sidebar with parent-child tree.

Exit: operator can run a real research session entirely from the browser; chase-from-highlight produces a child investigation that completes.

Cross-mode bridge — A ⇄ B

From Mode A's chunk modal, "Open in document viewer" jumps to /wrestle/<document_id>?page=N. The existing WrestleApp's PdfViewer.tsx learns an initialPage prop. From Mode B, an emergent cross-doc question can spawn a Mode A investigation. Same substrate; fluid handoff.

Exit: a Mode A session can land the operator inside the actual source PDF on the right page in under two clicks.

Sprint 12 — Multimodal Acquisition & Continuous Mode

YouTube + podcasts on the input side; autonomous chase on the orchestration side; Hermes-primary on dispatch
Shipped Dispatch flip Acquisition

§1Strategic objective

Sprint 11 made the substrate usable; Sprint 12 makes it fed. Until this sprint, Antiek could only ingest text it could already find as a document. Sprint 12 opens YouTube and podcast adapters and turns on the continuous-mode orchestrator so the substrate keeps working between operator sessions. Simultaneously, this sprint flips dispatch from OpenRouter-first to Hermes-primary, locking in a posture that all later sprints assume.

§2Progressive phases

YouTube adapter — captions in, transcript out

New acquisition/youtube/ module that fetches captions via the official API, falls back to whisper transcription when captions are absent, and emits documents with section_path = "timestamp_seconds" per §6.3. Source-tier policy: tier-3 by default (operator can promote per-document).

Exit: YouTube URL pasted into the workstation produces a document with chunk-level timestamps and full searchability.

Podcast adapter — RSS feeds and audio transcription

acquisition/podcasts/ resolves RSS feeds, pulls audio, transcribes via whisper, emits document_kind = "podcast" with timestamp-keyed chunks. Lands a podcast-ingest endpoint and the Sources UI tab in apps/reading/ for at-a-glance feed management.

Exit: an RSS feed URL produces transcripts of all recent episodes, ingested into the graph with hand-off into Mode A search.

Continuous-mode orchestrator — autonomous chase

The substrate gains a chase_mode schema field. When an investigation completes, open-questions whose chase budget is approved fire follow-up investigations autonomously. A daemon loop enforces a $5/day default cap (§16) and emits typed events into the existing trajectory log.

Exit: overnight chase produces ≥3 child investigations on a seed without operator interaction; cost stays under the cap.

Hermes-primary dispatch flip

Per antiek-hermes-bridge, route all four tiers (flash, pro, synthesis, verify) primary to hermes/grok-4.3 via the Hermes Agent OAuth bridge, with OpenRouter (DeepSeek-Flash / DeepSeek-Pro / Claude Opus 4.7) as fallback. Provider routing config moves to substrate/dispatch/config.yaml; every call still emits dispatch.call events.

Exit: live production traffic routes through Hermes; fallback path tested manually.

Sprint 13 — Voice Notes & Creation Surface v0

First step into the creation side; voice as the simplest acquisition mode
Shipped Surface C v0 Voice acquisition

§1Strategic objective

Sprints 11–12 built consumption: a research workstation fed by a growing multimodal corpus. Sprint 13 is the first step toward creation — the surface where the operator's accumulated graph becomes a draft document. It also lands the lowest-friction acquisition channel that exists, voice notes, which double as a substrate primitive for the brainstorming workstation that arrives in Sprint 17.

§2Progressive phases

Voice acquisition pipeline

acquisition/voice/ records audio in the browser via MediaRecorder, uploads to the substrate, dispatches the new transcription tier to whisper. The resulting transcript becomes a document with document_kind = "voice_note".

Exit: a 2–20 minute voice note turns into a fully-chunked document with insights and open-questions extracted by the existing note-taker pipeline.

creative_writer role

New role at roles/creative_writer/. Inputs: section title, ordered list of attached blocks (insights, open-questions, operator notes), full deliverable title + kind, and the cached style-guide from style_extractor. Output: prose, a prose_provenance map (which blocks contributed to which paragraphs), and preserved claim citations.

Exit: given a section + attached blocks, creative_writer produces prose that passes the §5.4 voice-and-style verification.

Deliverable data model

Three new substrate tables — deliverables, deliverable_sections, section_blocks — landed per §10.2. Stable IDs, lifecycle status (draft / in_review / final), block-to-section assignment indexed by ordered position.

Exit: schema migration applied; CRUD endpoints reachable from the API.

Mode C v0 — Creation Workstation

The first version of /write. No drag-drop yet; blocks are added to a section via search-and-select. The operator can: create a deliverable, add sections, attach blocks, click "Generate prose" to fire creative_writer for that section, edit the result inline.

Exit: a complete one-section deliverable can be created end-to-end and exported as plain markdown.

voice_note_followup role

Per §12.2 — after a voice-note is processed, the substrate identifies gaps with the new voice_note_followup role (~80 LOC) and surfaces a "Follow-up?" card with prompts. Operator clicks → records another voice note in response. Conversational chain captured natively without an interview-UX dependency.

Exit: the substrate proposes follow-up prompts that are recognisably specific to the operator's prior notes, not generic.

Sprint 14 — Drag-Drop Outlines & X Ingestion

Multi-section coherence in the creation surface; the X browser extension as the practical path to social ingestion
Shipped Surface C v1 Browser extension

§1Strategic objective

Sprint 13 produced single-section drafts. Sprint 14 makes the creation surface a real writing tool by adding drag-drop outlining and multi-section coherence to creative_writer. In parallel it answers §15.2 — the X-ingestion question — with a Chrome-only sideloaded browser extension that captures threads and tweets on the operator's click. The extension is the workable substitute for API access that the platform has consistently refused.

§2Progressive phases

Drag-drop outline UI

The three-pane Mode C layout from §10.5 lands at full fidelity. Left panel: searchable, filterable insight index. Centre: outline tree with drag-drop. Right: editor on the current section. Blocks are draggable from left to right; sections are reorderable; titles inline-editable.

Exit: a multi-section deliverable can be assembled visually in under five minutes from an existing investigation.

Multi-section coherence in creative_writer

The role learns to read adjacent sections' prose when generating its own, so consecutive sections do not repeat the same evidence or introduction. Coherence is implemented as a context-pack layer — adjacent prose injected as previous_section_summary and next_section_outline.

Exit: three consecutive sections read as a single coherent draft; the §5.4 verification still passes per section.

X browser extension — Chrome sideload

A minimal Chrome extension that captures the active thread or tweet on operator click and posts it to POST /sources. Per §15.2, distribution is sideloaded (operator + small group only). Manifest v3, single content-script + popup, no auto-collect.

Exit: the extension can capture a 50-tweet thread including embedded media URLs and create one document in the substrate.

X-source-tier policy

Default source tier for X documents is tier-4. The substrate's existing source-tier middleware governs synthesis-time treatment. Operator can promote individual documents manually.

Exit: X-sourced claims show up in syntheses with the correct tier badging.

Sprint 15 — Edit-Back-Into-Graph & Deliverable Export

Closing the loop between the creation surface and the substrate; first publishable artifact path
Shipped Recursive value loop Export pipeline

§1Strategic objective

The creation surface that emerged in Sprints 13 + 14 produces drafts in a one-way flow: graph → outline → prose → file. Sprint 15 closes the loop. When the operator edits generated prose, those edits can be promoted back into the graph as CLAIM_ASSERTED_BY_OPERATOR rows that future investigations can cite. This is the recursive-value mechanism that makes the creation surface a substrate contributor, not just a consumer. Sprint 15 also ships the export pipeline so deliverables become real published artifacts.

§2Progressive phases

CLAIM_ASSERTED_BY_OPERATOR event type

A new typed event captures (a) the original generated text, (b) the operator's edited text, (c) the deliverable/section context. The substrate inserts a claim with policy_id = "operator/<deliverable_id>" and source_tier = 5 unless the operator manually attaches chunk citations.

Exit: an edit in Mode C produces a queryable claim that the next investigation can retrieve.

Diff-aware edit detection

Per §10.4 Option B — only "significant" edits become new claims; trivial whitespace / capitalisation / punctuation changes do not. Diff classification runs at save time; the operator sees what will be promoted before confirming.

Exit: the operator can edit prose freely without polluting the graph with cosmetic changes.

Grounder-on-operator-claims

The grounder role can still run on operator-asserted claims even though they lack primary-source citation. The verdict shows up as a small badge on the prose paragraph; the operator can manually attach chunk citations to upgrade tier.

Exit: grounder verdicts populate next to operator-asserted prose without breaking on the missing-citation case.

Export pipeline — PDF, EPUB, Substack draft

Three export targets land. PDF via a serif-typography template that matches the reading surface. EPUB for book-length deliverables. Substack draft format (markdown + frontmatter) for the operator's writing workflow. Each format preserves claim spans as inline tooltips or footnotes.

Exit: a complete multi-section deliverable can be exported to any of the three formats; PDF passes a print-quality eye-test.

Sprint 16 — IP Attribution Telemetry & Interview Machinery

The substrate-side foundation for Phase 1 monetisation and Surface D's multi-party interview product
Shipped Attribution v1 Loop 4 Hermes chaos test

§1Strategic objective

Sprint 16 lands two big foundational pieces that don't quite light up user-visibly. First, the IP-attribution telemetry path: every synthesis page emits page_attribution_computed events carrying all three §9.3 algorithms. No money flows yet — but the operator can read attribution reports, qualitatively assess if they "feel right," and decide which algorithm survives into Sprint 18's payout activation. Closing the sprint is the cd602c9 chaos test that locks in the Hermes-primary posture with a tested fallback path.

§2Progressive phases

Three attribution algorithms

Per §9.3 — Option A (equal split per chunk citation), Option B (weighted by claim confidence × source tier), Option C (weighted by load-bearing-ness via secondary LLM pass). All three compute on every synthesis page; the substrate stores per-document attribution weights as a row in a new page_attribution table.

Exit: attribution reports surface in the operator dashboard; all three algorithms produce values for the same page.

page_attribution_computed telemetry events

Each synthesis emits a typed event recording the algorithm version, the per-document weights, and the chunk-set that produced each weight. These events become the Phase-1 dataset that proves the algorithm "feels right" before Stripe Connect activates anything in Sprint 18.

Exit: ≥10 synthesis pages have telemetry rows the operator can review.

Loop 4 — interview state machine

A fourth orchestration loop joins Loops 1 (research), 2 (wrestling) and the chase. Loop 4 manages multi-turn conversation state, has memory across the conversation, dispatches each turn through the interviewer role to the pro tier, and ends when must-cover questions are answered or the informant exits.

Exit: a fully scripted interview runs end-to-end against a test informant flow.

interviewer role + informant UI

Per §11.3, a new role at roles/interviewer/. The informant lands on interview.antiek.ai/<link> with consent checkbox, voice-or-text toggle, chat-style conversation, and a permanent "End interview" button. Voice mode is deferred to Sprint 17; text mode ships here.

Exit: an external informant can complete a text interview from a unique link; transcript lands in the substrate.

Hermes verify-tier fallback chaos test (cd602c9)

Property-based test at tests/test_dispatch_fallback_chain.py. The verify tier — the safety net in front of the synthesizer — is dropped to simulate a Hermes outage; the dispatch layer must fail over cleanly to OpenRouter. The test runs under --workers 1 per the single-writer invariant. This commit lands the architectural invariant the rest of the platform depends on.

Exit: chaos test passes in CI; commit hash recorded as the canonical reference.

Sprint 18 — Publisher Dashboard, Retrieval-Time Gating, Notebook Surface

The legal gate becomes binding; the linchpin notebook surface lights up; pre-onboarded escrow architecture lands
Substrate landed Legal gate binding PostHog Wedge 2 — linchpin Stripe Connect scaffold

§1Strategic objective

Sprint 18 is the single most carefully gated sprint in the entire spec. Three precedents — Bartz, Hachette, Authors Guild MDL — make procurement, not use, the dispositive variable for IP liability.
