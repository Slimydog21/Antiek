Sprint 22 — Multi-User Pivot & Two-Graph Architecture

Theme. Sprint 22 is the architectural inflection from single-operator Antiek to personal-graph-as-memory plus collective public graph. It is explicitly gated on six months of solo-operator compounding evidence.

Current reconciliation. Local multi-user, graph routing, auth-decision, federation-probe, and DP preference substrate tests passed. The sprint is not shipped and should not be activated until the compounding gate and real second-user evidence exist.

1. Binding gate #

Six-month compounding gate

Sprint 22 ships only after six months of operator-graph accumulation demonstrates the compounding curve. Premature multi-user risks graph contamination before the moat has been proven. Sprint 20's visible-artifact growth motion is the demonstration input.

2. Progressive phases #

2.1 Auth integration — Clerk or Supabase

Sign-up, sign-in, session management, and OAuth scope mapping for Antiek Memory MCP per-user resources. The Clerk versus Supabase choice remains an operator-decided spike.

Exit: a second user can register and sign in independently of the operator.

2.2 Per-user personal graph at storage level

Per-user DuckDB files with per-partition encryption keys. Private-facing notes cannot write into the collective graph by schema design. This is a physical separation claim, not a tagging convention.

Exit: a synthetic cross-user-read attempt fails at the database boundary.

2.3 Collective graph aggregation

Public-facing notes flow into the collective graph through quality gates covering verification, voice-style scoring, and source-tier validation. Pre-onboarded IP-holder content sits alongside operator-curated corpus material.

Exit: a second user's published note appears in collective graph search, attributable and ad-eligible.

2.4 DuckLake catalog separation activated

The catalog Postgres becomes operational for per-user file routing. Stage 1 opens the Stage 2 path if per-user file count later approaches operating-system handle limits.

Exit: catalog-routed queries reach the right per-user DuckDB and backups stay within the backup window.

2.5 Cross-graph writes flow through shared substrate

Skill patches discovered in a user's private-facing notes propagate as discovered rules through the shared-substrate writer queue, never as the original private content. Differential-privacy guarantees must hold at this boundary.

Exit: a skill patch derived from User B's private graph reaches shared substrate without exfiltrating original private content.

2.6 Privacy dashboard and Trust Center

The privacy dashboard gives a real-time view of telemetry collected from the user's private graph, category toggles, and deletion control. The public Trust Center documents privacy architecture, DP parameters, retention, deletion SLA, incident response, and dashboard behavior.

Exit: a user can inspect, disable, and delete telemetry; a prospective user can read the public Trust Center without an account.

2.7 Differential privacy enforcement live

The DP shuffler enforces per-surface epsilon budgets in production. Any DP claim above the binding cap is rejected.

Exit: production telemetry routes through the shuffler at the documented epsilon for each surface.

  • substrate/ducklake/ — catalog Postgres and per-user routing.
  • apps/reading/src/modes/PrivacyDashboard/ — telemetry controls and delete-all flow.
  • apps/reading/src/modes/TrustCenter/ — public-facing trust documentation.

4. Status reconciliation #

Strategic-gated, not shipped

Substrate slices exist and scoped tests are green. The sprint remains gated because the six-month solo-operator compounding proof, second-user activation, public Trust Center publication, and production privacy guarantees are not established by local tests.

5. Acceptance & exit criteria #

  • Two real users are live on independent personal graphs.
  • The architectural-incapability claim holds under a cross-graph leak attempt.
  • Trust Center is publicly published and accurately describes the architecture.
  • Substrate is in Stage 1 of the transition matrix.
  • SOC 2 Type II is explicitly deferred; substrate-controls work is the foundation either way.
