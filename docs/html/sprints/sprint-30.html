1. Thread triggers #

Trigger discipline

Federation requires a partner Antiek instance willing to negotiate a slice exchange. Long-tail creator economics require more than 200 active monthly-earning creators. Programmatic requires advertiser demand exceeding manual-curation capacity. Vision extraction requires at least 30% non-text citable material. Autoresearch Wedge 3 requires at least 500 graded outcomes. Threads without cleared triggers stay explicitly deferred.

2. Threads #

2.1 Federation layer

Antiek instances can opt in to expose collective-graph slices under negotiated terms. The protocol is signed-resource-pull, not push. The receiving instance validates signatures and ingests under its own quality gate; no cross-instance write path exists.

Exit: two Antiek instances federate one slice successfully and the protocol passes adversarial review.

2.2 Long-tail user-as-IP-holder economics

The user-as-IP-holder path matures into hundreds or thousands of users earning meaningful rev-share. Anti-gaming hardens around creator clusters, payout-graph forensics, and non-trivial tax reporting volume.

Exit: long-tail creator economics run without per-case operator intervention and a sampled 1099 batch passes accountant review.

2.3 Programmatic auction

Programmatic display remains rejected unless scale warrants it. If triggered, integrate one SSP and run a brand-safety classifier in front of served ads. If not triggered, renew the rejection with current-quarter numbers.

Exit: programmatic is live or the rejection is renewed with cited numbers.

2.4 Vision-capable role

Frame-level analysis extracts claims from images and video. The visual verification rubric must include frame timestamp, visual-element bounding box, and surrounding-text grounding.

Exit: the substrate extracts claims from video frames and passes a 50-frame audit.

2.5 Autoresearch Wedge 3 config sweeps

Nightly sweeps over context-pack composition and dispatch-tier routing produce operator-reviewed config deltas. No automatic promotion occurs.

Exit: one proposed config delta survives operator review and improves held-out outcomes.

2.6 Stage 2 storage transition

If per-user DuckDB file count or catalog contention warrants it, user partitions move to a sharded model mediated by DuckLake catalog routing. Otherwise Stage 1 continues.

Exit: if triggered, Stage 2 is live without user-facing latency regression; otherwise Stage 1 remains adequate.
