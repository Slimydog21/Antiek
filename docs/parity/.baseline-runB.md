## Per-dimension findings

### Visual crispness — 2/3
The token discipline is real and in places beats PostHog, but the level-3 bar fails on two countable criteria: the centralized focus system has zero in-scope consumers, and disabled is not a single sourced token.

- **Token source-of-truth (all surfaces): strong.** Radius is a named 3-level scale (`apps/reading/src/design/tokens.css:148-150` `--radius-sm:4px/--radius:6px/--radius-lg:10px`) mirrored in Tailwind (`apps/reading/tailwind.config.js:114-117` `borderRadius hog:6px/hog-lg:10px`); shadow is a 4-level scale (`tokens.css:142-145` `--shadow-z1..z3/--shadow-lift`); a full `--ice-*/--glacial-*/--ink/--sun*` color ramp is the color source of truth (`tokens.css:62-94`). Borders/shadows reference color tokens, not literals: `index.css` has 0 raw hex (grep `#[0-9a-f]{3,6}` over `apps/reading/src/index.css` = 0) and 4 `var(--)` consumers.
- **Designed focus ring exists, keyed on `:focus-visible`, from a token — but DELEGATED, and the centralized bundle is unconsumed in scope.** A `.feel-focusable` / `.feel-focusable-ring` bundle is defined at `apps/reading/src/design/feel-focus.css:9-12,18-19` (`:focus-visible { outline:2px solid var(--sun) }`, paired with `:focus { outline:none }`). **Coverage caveat (binding):** `grep -rl feel-focusable apps/reading/src` returns exactly 2 files — `feel-focus.css` (the definition) and `feel-focus.test.ts` (its test). **0 scene controls and 0 shell controls consume it** (`grep -rn feel-focusable apps/reading/src/scene apps/reading/src/shell` = 0). The shell instead inlines its own focus ring per-control via Tailwind: `apps/reading/src/shell/NavRail.tsx:318` (`focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ink`) and `apps/reading/src/shell/ProductsLauncher.tsx:226` (`outline-none focus:border-sun` — note `:focus`, not `:focus-visible`). So a designed, token-keyed `:focus-visible` ring DOES exist and is per-control (clears the L1 "global-only / bare `:focus`" failure for NavRail), keeping the surface at 2 — but the rubric's level-3 refinement (the shared bundle adopted by the scene/shell controls) is unmet; the bundle is built and unused in scope.
- **Disabled is ad-hoc, not a single sourced opacity token.** There is no `--opacity-disabled` analogue in `tokens.css`. Disabled renders as three different inline values: `disabled:opacity-50` (`apps/reading/src/components/lemon/LemonButton.tsx:36`, `LemonDropdown.tsx:111`), `disabled:opacity-60` (`apps/reading/src/shell/SceneChrome.tsx:198`), and `opacity-40` (`LemonSelect.tsx:168`). Level-3 criterion (d) is unmet on every in-scope surface.
- **Scene crispness: 2.** Scene paints from token vars only — `apps/reading/src/scene/scene.css:14` declares "Colours are token vars only; this file declares motion, not palette, so it adds no hex" (verified: 0 hex in the file). No designed focus indicator on scene controls (the scene has no focusable controls of its own; the journey/penguin layers are decorative).
- **Fallback crispness: 2 — holds when the scene is off.** The opaque fallback `--glass-bg-solid` is defined day+night (`tokens.css:111,248`) and consumed by GlassSurface (`apps/reading/src/shell/GlassSurface.tsx:32-38`), `SceneChrome.tsx`, and `WorkspaceWindow.tsx`; GlassSurface's scrim contract proves WCAG-AA body text over the solid fallback (`GlassSurface.tsx:27-69`, `SCRIM_MIN_OPACITY=0.2` at `:73`). Crispness does not collapse with the scene off, so the fallback earns the same grade as the on-state (it is not the on-3 broken-off-0 case the spec forbids).
- **Werner crispness: 2.** Werner fills are all token-sourced (`tokens.css:118-133` `--werner-coat/belly/bill/foot/eye/rod/fish`, each leaning on the brand `--sun`/`--aurora` family, not new literals). Graded for token discipline only, never hedgehog-resemblance (firewall row 3).

### Motion & life — 2/3
A genuinely strong, mostly-tokenized motion system with a SYSTEMIC reduced-motion guard (a place Antiek beats PostHog) and 0 layout-thrash transitions, held below 3 overall by partial token adoption on the shell/scene primitives and the not-yet-wired panel `enter` primitive. Werner and the fallback individually reach 3.

- **Universal reduced-motion guard (systemic, beats PostHog): present.** `apps/reading/src/design/motion.css:23-32` collapses ALL `transition-duration`/`animation-duration` to `0.01ms` globally under `prefers-reduced-motion: reduce` with `!important` — one universal guard, stronger than PostHog's per-component handling. 31 files carry `prefers-reduced-motion` (`grep -rl prefers-reduced-motion apps/reading/src` = 31).
- **Named motion tokens with a single source of truth.** Durations/easings are tokens, not magic numbers: `tokens.css:157-161` (`--motion-fast:80ms/--motion-base:150ms/--motion-slow:800ms` + `--ease-standard/--ease-enter`), mirrored in `tailwind.config.js:121-` (`transitionDuration fast/base/slow`) and `apps/reading/src/design/motion.ts`. Consumed in 15 places (`grep -rn 'var(--motion|duration-fast|duration-base|duration-slow' apps/reading/src` = 15).
- **GPU-cheap discipline holds.** 0 transitions on layout properties: `grep -rnE 'transition:[^;]*(width|height|top|left|margin)' apps/reading/src` = 0.
- **Scene motion (the ambient living background): 2 — exercised under the logged exception.** The scene keyframes are transform/opacity only (`apps/reading/src/scene/scene.css:21-30` `akb-penguin-journey`/`akb-penguin-bob`) and freeze under reduced-motion both structurally (JS `useSceneClock`) and in CSS (`scene.css:32-38`). Per the rubric's logged living-scene DECISION, the always-on ambient motion is a named justified exception and is NOT scored as a level-0 decorative violation. It stays at 2 (not 3) because it is one ambient surface, not the full hand-authored enter/exit + directional system the L3 cell counts.
- **Shell motion: 2.** Transient overlay surfaces DO choreograph enter AND exit before unmount: `WorkspaceWindow` uses Framer Motion `animate`/`exit`/`transition` (`apps/reading/src/components/windows/WorkspaceWindow.tsx:259-261`, reduced-motion-aware: `exit={reduceMotion ? undefined : {scale:0.97,opacity:0}}`), wired through `AnimatePresence` (`apps/reading/src/components/windows/WindowsLayer.tsx:1,34,62`) which is what makes exit-before-unmount real. Held at 2: the shared `enter` panel primitive is authored but NOT yet adopted — `apps/reading/src/design/motion.ts:59-65` self-documents "Provided for panel/modal adoption; not yet wired to a consumer in this run."
- **Werner motion: 3.** ~25 Werner `@keyframes` (of 35 total in `apps/reading/src`; `grep -rn @keyframes apps/reading/src` = 35, Werner-heavy across `src/brand/werner/animated/animations.css`, `src/werner/waddle.css`, `src/werner/ice-fishing.css`) are each a purposeful pose/feedback state (waddle, sleep-breath, thinking-dot, fish-flipper, toboggan) with directional `transform-origin` per pose (`src/brand/werner/animated/animations.css:48,62,90,123,137` — 22 `transform-origin` uses in src). Werner poses carry their own static-but-recognizable reduced-motion fallback (`motion.css:13-15` notes this). This is a hand-authored, GPU-cheap, reduced-motion-respecting pose system = 3.
- **Fallback motion: 3 — degrades gracefully, does not vanish.** Under `prefers-reduced-motion` the scene FREEZES to one static legible frame rather than blanking, proven as a first-class authored e2e state: `apps/reading/e2e/glass-reduced-motion.spec.ts:1-40` ("the frozen scene is still painted (not a flat colour)" + body text still clears WCAG-AA over the opaque fallback). This is exactly the "degrade gracefully, not vanish" the spec demands = 3.
