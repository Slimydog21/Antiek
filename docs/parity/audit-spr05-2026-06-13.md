## Per-dimension findings (Scene surface)

### Visual crispness — Scene 3/3 (maintained)
The baseline graded Scene 3/3 because `scene.css` carried zero hex. SPR-05 adds a
much larger colour surface (a 28-token per-dayPart atmosphere ramp + a star field
+ depth planes) and the token discipline HOLDS — this is the substantive test of
the 3, not a freebie.
- **Zero raw colour literals in any scene layer.** `grep -rcE '#[0-9a-fA-F]{3,8}|rgb\(' src/scene/layers/*.tsx` = **0** across all 7 layer files (Clouds, Peaks, Snow, ProceduralSky, KreaArtLayer, PenguinJourney, **Mountainscape**). The new atmosphere is composed of `var(--scene-*)` strings only (`src/scene/palette.ts:90-97`).
- **All new colour is token-SOURCED with origin comments.** 29 `--scene-*` tokens defined in `src/design/tokens.css:208-259` (+ the dark-block `--scene-star-base` re-assertion at `:315`), each named + origin-commented (the decision, not just the hex) — e.g. `--scene-glow-dawn: var(--sun-light); /* the warm twilight glow band (shared with dusk) */` (`tokens.css:212`). The scene layers consume them through `atmosphereFor(dayPart)` (`palette.ts:88-99`), a pure unit-tested resolver (`palette.test.ts`, 10 tests green incl. the star-visibility gate). One source of truth; no parallel palette.
- **No NEW raw hex anywhere (token-lint forward gate).** `npx tsx scripts/lint_tokens.ts` = OK; the grandfathered baseline SHRANK 120 → 80 (SPR-05 removed a pre-existing dead literal-fallback in `SceneStatusBadge.tsx`; it added zero). Token-lint allows hex only in the two source files (`tokens.ts`/`tokens.css`) — the new `--space-*`/`--charcoal-*` CSS-var promotion lives there, byte-equal to `tailwind.config.js`.
- **Geometry/radius token-sourced.** `var(--radius-sm)` on the scene status chip (`SceneStatusBadge.tsx:82`); the scene paints full-bleed (`absolute inset-0`), so radius is N/A on the sky/peak layers by design (a sky has no corner radius).
- **WCAG-AA token backstop green — with the precise scope.** `tokens.contrast.test.ts` = 12/12, but its COVERAGE is UNCHANGED by SPR-05: it asserts the AMS highlighter-veil + accent-edge pairs (`sun.*`/`barAccent`/`sunLight`), NOT the atmosphere tokens. That is CORRECT, not a gap: the `--scene-*` sky/glow/haze tokens are decorative `aria-hidden="true"` background fills (`ProceduralSky.tsx:121`) with **no text or meaningful-edge AA pair** to assert, so they are legitimately absent from the contrast test. The ONE atmosphere token that DOES carry a real graphical-object contrast obligation — the night/dusk **star** colour over the deep sky — is gated by a dedicated, dark-cascade-resolved test (see the star-visibility gate below); the rest are additive references to the already-AA-cleared ramp, and no glass/ink/sun/bar token was altered (blast-radius verified).
- **NEW star-visibility gate (sharpen R2 — Defect 1) — this is the actual gate for the star feature.** `src/scene/palette.test.ts` now RESOLVES `--scene-star-night` / `--scene-star-dusk` through the dark cascade (parsing `tokens.css`, dark block wins) and asserts WCAG ≥3:1 (1.4.11 graphical-object floor) over every deep-sky stop. The R1 star tests asserted PRESENCE + determinism only — never contrast — which is exactly why the invisible-star bug (star resolved to `var(--ice-2)` → #0D1019 under dark, ~1.04:1 over the night sky) slipped. The fix pins the star to a fixed bright `--scene-star-base` (#F4F7FA, ~15–18:1); the gate FAILS on the old `var(--ice-2)` value (revert-to-confirm: 1.04:1 < 3) and PASSES on the fix. 4 net-new tests (10/10 in `palette.test.ts`).
