Werner activity system · SPR-21 · Wave 21

Let the mountain scene change without lying about the sun

One OS-theme-subordinate civil-time authority activates existing dawn and dusk scene keys and seeded compositions, repairs non-reactive theme reading, and schedules no polling loop. Distinct transitional colour ramps remain future art direction.

Implemented 5 milestones

Parent context and goal

The Mountain Shell already models and renders dawn, day, dusk, and night, but production calls prefersDark() only during render and emits binary day/night. The verification report therefore marks dawn/dusk partial, while its stronger claim that OS theme changes immediately update the scene is not mechanically true.

Implement one bounded branded-ambience clock subordinate to the existing OS color-scheme authority. It is not sunrise data: light mode may select dawn only inside a named morning interval; dark mode may select dusk only inside a named evening interval. Manually pinned OS theme wins even when it disagrees with wall time.

Technical milestones and acceptance

  1. Pure bounded mapping. A pure function accepts dark and local civil minutes. Dawn is [05:30,08:00), dusk is [17:00,20:00); light outside dawn is day, dark outside dusk is night. Weather remains snow. The values describe Antiek art direction, not astronomy.
  2. Single semantic authority. A derived-mood hook owns exactly one color-scheme listener and at most one timeout for the next boundary capable of changing the current OS band. No interval, rAF, polling, geolocation, or useSceneClock coupling.
  3. Civil-time recovery. Every media, visibility, and timeout signal recomputes from a fresh injected Date. Hidden tabs cancel the timeout; visibility return recomputes immediately. Early, late, sleep/wake, timezone, DST, and manual-clock discontinuities are re-derived when the next browser signal arrives rather than applying a stale intended mood.
  4. Override dormancy and cost honesty. A mount-time explicit Scene mood renders through a component split with no derived listener/timer. Runtime authority switching is unsupported because it remounts the scene. Within one mounted authority, a derived mood-key change causes one production Krea effect; React development StrictMode may probe that existing effect twice. Endpoints, retries, caps, kill switch, and budget policy do not change.
  5. Proof. Unit tests cover every interval edge, midnight/02:00, listener/timer cardinality, hidden recovery, discontinuous clocks, StrictMode/unmount teardown, and mount-time override dormancy. Reduced motion is structurally absent from semantic authority rather than represented as a hook input. Deterministic procedural plates show all four seeded compositions at 768/1024/1280; dawn/day and dusk/night currently share colour ramps.

Five-values rigor

Intellectual honestyName these fixed intervals “branded ambience windows,” never sunrise/sunset. Document that automatic key transitions can add bounded Krea requests and that pinned OS theme can intentionally show night at noon.
FairnessReduced-motion users still receive semantic color changes without movement; hidden users receive no timer churn. An explicit test or Storybook mood stays fully deterministic and dormant rather than paying for an unused production subscription.
RigorProve exact inclusive/exclusive boundaries and the hostile case that 02:00 under dark mode is night, not dusk. Inject time, scheduler, media query, and visibility; do not make the test suite depend on Riyadh wall time.
DiligenceRepair the existing false reactivity claim at the same seam. Keep animation time in useSceneClock, semantic time in the new authority, and retain one timeout after every rearm and zero after hide/unmount.
DefensibilityRecord why fixed windows beat location/geolocation complexity, why OS theme remains sovereign, and what evidence would justify astronomical solar data later. Every named minute value carries its art-direction rationale.

Rejected alternatives

Single “before evening” thresholdRejected: labels 02:00 dusk. Transitional moods require lower and upper bounds.
Wall clock owns light/darkRejected: creates a second theme authority and can put bright sky behind dark chrome.
Geolocation sunrise/sunsetRejected: permission, privacy, timezone, network, polar-day, and test complexity are unjustified for branded ambience.
Animation clock reuseRejected: reduced motion must not freeze semantic time and per-frame evaluation would be wasteful.
Always run hook under explicit overrideRejected: unused listeners and timers violate the override’s deterministic contract.

Out of scope, open questions, and verification

No AppShell edit, theme store, Tailwind strategy change, weather source, astronomical claim, Werner behavior, Krea policy change, backend, network API, merge, or deploy.

Open question: the 05:30–08:00 and 17:00–20:00 windows are an explicit product judgment chosen to make dawn/dusk visible during plausible research sessions while bounding Krea transitions to at most two semantic edges per current OS band per day. Operator evidence can revise them later; implementation must keep them named.
