Werner activity system · SPR-34

Let Werner examine completed model evidence

After the current explicit model comparison resolves, play the existing curious evidence-card reaction in the sole mascot.

Implemented

Parent context

Antiek Settings owns a server-issued advisory comparison over registered providers, known budget state, and measured Antiek-bench evidence. The extracted ModelEvidenceInstrument is presentation-only; Settings owns request freshness and commits the response.

The reaction bus already translates a closed product-experience vocabulary into the sole WernerStage. This sprint extends that vocabulary without a second mascot, pose, event framework, or model recommendation claim.

Authority path

operator explicitly compares models
→ fetchModelDecision resolves
→ request version is still current and Settings is mounted
→ runtime authority is advisory and response task matches the request
→ response commits to the visible evidence rail
→ model_evidence_compared
→ existing curious evidence-card composition
→ sole WernerStage

The episode means “Werner examined the returned evidence.” It does not mean a route was recommended, measured, verified, affordable, selected, or dispatched.

Technical milestones

  1. Extend the closed experience map with exactly model_evidence_compared → curious and expose one domain signal helper.
  2. Emit beside the current-response state commit, after freshness, advisory-authority, and task-match checks; invalidate comparison authority from both Settings input surfaces and on unmount.
  3. Prove success once, failure/malformed/stale silence, post-unmount silence, closed-map alignment, and sole-stage translation.

Five-values rigor

Intellectual honestyUse curious, never happy: a valid response can contain insufficient evidence or no measured pick. The beat acknowledges examination, not recommendation or verification.
FairnessMeasured and unmeasured responses receive the same bounded acknowledgment; users without a qualifying cohort are not rendered as failures. Reduced motion retains the existing meaningful still.
RigorExercise task changes, the shared Overview inputs, rejection, and unmount while a request is in flight. A visible result without exactly one event or any silent-path event fails the sprint.
DiligenceInstrument the existing requestVersion owner and reuse WernerCurious; keep ModelEvidenceInstrument, backend schemas, and Storybook fixtures event-free.
DefensibilityThe event name records a completed comparison, while the authored evidence card says only “examines the evidence.” Reconsider only if Antiek later distinguishes evidence-received and recommendation-accepted as separate authoritative actions.

Acceptance and verification

  1. The runtime allowlist and exhaustive map contain one new experience mapped to curious.
  2. A current successful advisory response emits once even when it has no measured pick.
  3. Click/loading, rejected requests, unexpected authority, mismatched task, stale task/input responses, rerenders, and post-unmount responses emit nothing.
  4. Both Overview and Decision-tree input controls invalidate an in-flight comparison.
  5. The sole mascot stage translates the new event; no new raster or SVG asset is added.
  6. Focused Vitest, TypeScript, production build, diff hygiene, HardenX, and adversarial review pass before publication.

Strict non-goals

No happy/verified response, model auto-selection, dispatch, budget mutation, benchmark generation, response payload on the global event, click reaction, error reaction, cooldown, queue, replay, analytics, generic event abstraction, new pose, second Werner, ChatGPT Image asset, backend change, merge, or deployment.

Execution harness

A critic must try to prove optimistic celebration, a stale event through either input surface, post-unmount emission, duplicate emission, presentational coupling, payload creep, or a second mascot authority.
