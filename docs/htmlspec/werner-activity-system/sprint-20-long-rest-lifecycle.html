Werner activity system · SPR-20 · Wave 20

Let Werner sleep only after the station truly rests

One shell authority separates short activity idle from a persistent sleep→wake episode and adopts the authored waking pose without inventing a second penguin.

Executing 5 milestones

Parent context and goal

SPR-18 removed pointer idle → sleeping because two-second pointer idle already belongs to the selected station activity. SPR-17 preserved a ChatGPT Image waking asset but correctly withheld runtime adoption because no live waking lifecycle existed. The only production owner is AppShell → PenguinMascot.

Implement one monotonic, epoch-safe long-rest lifecycle at that owner: active → sleeping → waking → active, with suspended as the hidden/reduced-motion/arcade/foreground floor. The interaction that wakes Werner must still execute normally.

Technical milestones and acceptance

  1. Shared lifecycle authority. A pure controller owns one rest deadline and one wake deadline. Eligibility loss invalidates stale callbacks; visibility return never fabricates waking.
  2. Sanctioned authored pose. Add waking to the private authored-pose map and render it through a dedicated decorative wrapper; no direct PNG import in the mascot and no fifth public mood.
  3. Live shell integration. Pointer-down, keyboard, wheel, and input reset the single clock. Persistent sleeping begins only after 120,000 ms of eligible station rest; waking lasts 900 ms and occurs once per sleep episode. These named product values are injectable in controller tests.
  4. Single visual owner. Fishing, sleep, wake, product emote, drag, directed travel, return home, hidden tab, reduced motion, and arcade play never stack. Arcade uses the existing suspension lease.
  5. Proof. Pure and live-mascot tests cover timing, stale epochs, preemption, teardown, input pass-through, accessibility, and exact authored sources; deterministic Storybook plates cover sleep, wake, and reduced motion.

Five-values rigor

Intellectual honestyDo not call pointer inactivity “whole-station rest.” The accepted activity event set and the deliberate 120-second value must be named; missing keyboard/arcade/visibility coverage is a blocking gap.
FairnessReduced-motion users keep the neutral static project control rather than receiving a frozen involuntary episode. The underlying click, keyboard, drag, and project navigation remain higher authority than mascot theater.
RigorFake clocks prove the exact boundary, wake cardinality, stale-token rejection, and fresh epoch after every suspension. A 2.6-second regression test must still show fishing and no sleeping.
DiligenceReuse stationAmbientClass, stationInstrumentSuspension, WernerSleeping, and the private pose map. Do not add a second stage, activity registry, or direct raster owner.
DefensibilityThe decision record explains why long rest is separate from activity idle, why 120/0.9 seconds are named product values, and what evidence would justify changing them.
