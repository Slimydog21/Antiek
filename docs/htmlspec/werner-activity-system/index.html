Master spec · WERNER-ACT

Werner Station Activity System

Make Werner a fixed, living character whose current activity turns the cursor into an instrument—without giving any activity permission to move him.

  • No child specs yet; dirty campaign work already owns the first arcade, hotspot, reaction-bus, and session-image implementations.

Goal

Replace the one-off ice-fishing coupling with a typed activity boundary. An activity may declare ambient classes, a cursor instrument, and an unlock rule. The contract grants no Werner-position authority, and a focused source-boundary test rejects direct movement, navigation, and network dependencies. Ice fishing remains behavior-identical as the default.

Success criteria

  • StationActivity contains no position, movement, mascot ref, or stage-controller capability.
  • The production shell mounts the default activity's instrument; the mascot reads its idle class; current fishing tests remain green.
  • Future page activities and games register through one boundary instead of editing PenguinMascot.tsx.

Failure mode to avoid

A superficially extensible registry that quietly lets an activity chase the cursor, forks a second Werner, or changes reduced-motion behavior.

Distinctive design direction

Antiek is a researcher's illustrated alpine observatory, not a mascot-skinned SaaS dashboard.

Invariants

  • Exactly one interactive Werner exists at shell level.
  • Reduced motion disables involuntary activity motion and custom cursor layers.
  • The activity contract grants no product authority, spend, network, navigation, or mascot-position capability; the source gate catches direct violations but is not presented as a JavaScript sandbox.
  • Every generated image is presentation evidence, never interaction or research evidence.
