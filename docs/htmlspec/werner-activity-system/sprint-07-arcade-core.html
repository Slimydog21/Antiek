Deterministic arcade core

Recover two playful game rulesets on one narrow engine boundary before any product surface is allowed to host them.

Implemented on stacked branch4 milestones

Cold context and goal

The shared checkout contains a mixed, uncommitted arcade prototype alongside cabinet, wait-host, route, scene, reaction, and generated-image work. Copying that directory wholesale would conceal authority and quality gaps.

Reconstruct only the engine, factory, Ice Fishing cartridge, and Paperclip Zombies cartridge from exact parent c2b4b24e3, then harden input cardinality, focus, scaling, reduced motion, determinism, terminal persistence, design tokens, and teardown. This sprint creates playable substrate, not a shipped cabinet or easter egg.

Technical milestones

1
Make fixed-step input truthful

Do not sample an edge until a simulation step can consume it. Deliver each press to only the first catch-up substep, pause hidden time, and cancel one scheduled frame exactly.

Acceptance: zero-step, one-step, multi-step, hidden, start/stop, and reduced-motion tests pin update cardinality.
engine/loop.ts · loop.test.ts
2
Bound browser input authority

Keyboard control belongs to the focused canvas, not the window. Pointer positions map from responsive CSS pixels into logical canvas pixels, and active captures/listeners are released on exit.

Acceptance: focusable described canvas; game keys prevent page scrolling only in focus; scaled pointer and teardown tests pass; reduced motion accepts discrete input without a continuous clock.
engine/ArcadeMount.tsx · ArcadeMount.test.tsx
3
Harden both cartridges

Preserve configured lives across restart, pin identical seed plus trace to identical final state, exercise catch/hazard and hit/breach/wave/exit lifecycles, and report best score once per terminal transition.

Acceptance: both rulesets cover ready, playing, terminal, restart, reduced-motion, and deterministic behavior; factory helpers always teardown.
games/ice-fishing · games/zombies · cartridgeFactory
4
Keep the core brand-native and powerless

Canvas colors resolve from the canonical Antiek token module. The arcade core has no route, shell, mascot, product event, storage, telemetry, content, network, or spend imports.

Acceptance: token and type lints, production build, scope boundary, Hardenx, independent review, and remote checks pass.

Five values

Intellectual honesty

Colored primitive rendering is a mechanics prototype, not yet the promised Club Penguin or Black Ops level of visual craft.

Fairness

Reduced-motion users receive deliberate discrete play rather than exclusion or hidden continuous simulation.

Rigor

Tests pin event cardinality and complete final state, not only counts or lack of exceptions.

Diligence

Focus, coordinate systems, hidden time, capture release, restart configuration, and terminal write cardinality each have a named proof.

Defensibility

The 20-file source-and-test boundary makes later cabinet and wait-host review separable.

Out of scope

  • ArcadeCabinet, arcade/host, barrel exposure, routes, App/AppShell/Deep Research integration, feature flags, discovery sequence, or automatic launch.
  • Generated/session artwork, SceneHotspots, reaction events, station activity, mascot changes, persistence, telemetry, network, content, spend, merge, or deploy.
