Parent context

Parent PR #2838 adds an exact, stable, rights-aware BookReader window from grounded Deep Research Canvas blocks. It preserves Canvas continuity, byte-exact identity, bounded fan-out, and focus. The current window uses a generic cascade and the reader’s loading state is text-only. Goal

When geometry permits, a new reader appears fully beside the clicked source control; otherwise it falls back honestly. Werner’s existing curious beat fires once only after current readable content commits.

Rigor — operating manual

1 · Intellectual honesty

Do not narrate impossible geometry

If no full-fit rectangle exists, return undefined and test the cascade fallback. Never clamp an overlapping rectangle and call it adjacent; report which viewport/anchor cases remain inherently impossible.

2 · Fairness

Protect keyboard and narrow-screen operators

The spatial flourish cannot cost focus, reachability, or source access. Stable reopen retains the operator’s moved rectangle, while narrow viewports keep the parent’s bounded cascade rather than being forced into a desktop composition.

3 · Rigor

Separate click, fetch, and commit

Tests must prove click intent and loading do not emit evidence_source_opened; only a current readable gate response does. Include stale/unmounted completion and route-hosted reading, not only the successful window case.

4 · Diligence

Reuse four existing owners

Read and reuse BlockCard’s exact provenance seam, windowsStore’s stable-ID/cap behavior, BookReader’s servability response, and Werner’s existing signal/spinner. A fifth parallel owner is a defect unless the handoff proves none can carry the responsibility.

5 · Defensibility

Justify every constant and ordering

Reader dimensions must match windowsStore defaults or be exported from one owner; gutter and side precedence need comments plus tests. Record why no new reaction or bitmap was created.
