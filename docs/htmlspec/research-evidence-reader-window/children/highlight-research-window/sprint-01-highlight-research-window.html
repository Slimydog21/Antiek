Move Read highlight research into canonical workspace windows

Fresh concurrent chases, exact host closure, full-screen affordance, one existing launch authority.

Parent context

Read currently mounts the shared FloatMenu over gate-served HTML and routes Deep-research through outboundText, but then opens ChaseThread in the older WorkspaceStore panel layer. Grounded evidence now uses windowsStore, whose chrome supports drag, focus, bounded fan-out, expand/restore, and exact close.

This sprint changes only the Read host. ChaseThread continues to call the same startInvestigation, carry the same parent and spawn context, record the same relationship, and render the same ThinkingStream.

Goal

Every authorized Read highlight activation opens a fresh adjacent research window that can expand to full and closes exactly itself after main-view handoff.

Technical milestones

1

Generalize adjacent placement

Rename the evidence-specific pure helper to workspace-neutral vocabulary and add a pure viewport-to-layer translation seam consumed by both result evidence and reading selection.

Acceptance:
  • Existing right/left/below/above/fallback semantics remain byte-equivalent.
  • Tests cover a non-zero layer origin and no mutation.

Canvas/adjacentWindowPlacement.ts and tests/callers.

2

Expose exact host identity

Add a read-only window-instance context supplied by WorkspaceWindow. It must coexist with the existing boolean useInWindow API.

Acceptance:
  • Hosted content reads its exact window id.
  • Route and legacy-panel content read null; existing adaptation tests stay green.
3

Register a fresh-instance chase

Add window-native research-chase using the existing ChaseThread renderer and an openNewWindow API that deliberately bypasses kind-level singleton identity while preserving the cap.

Acceptance:
  • Two activations create two descriptors with exact independent payloads.
  • At cap, an exact chase replaces the oldest eligible window rather than focusing unrelated content, but never evicts the reader initiating the chase.
  • No raw passage appears in window id or title.
4

Migrate Read and close the exact host

Read computes adjacent geometry from the FloatMenu selection and opens the new window. Window and legacy panel renderers each provide exact host-instance context, so ChaseThread’s main-view handoff closes only its own host.

Acceptance:
  • The selected passage and reading parent id reach the existing ChaseThread unchanged.
  • Expand/restore is inherited from WorkspaceWindow.
  • Main-view handoff closes only the initiating chase window or legacy panel under simultaneous instances, including an OS-popout panel handing navigation back to its main tab.
  • Withheld selection opens no window; malformed payload authority never reaches ChaseThread or launches research.

Rigor — operating manual

1 · Intellectual honesty

Do not call a focused old window a new chase

Assert descriptor count and payload identity after two activations. A cap fallback that focuses unrelated content is a failure, even if open() returns an id.

2 · Fairness

Preserve the panel stakeholder

ResearchWorkstation still owns legacy panels. Prove a panel-hosted ChaseThread retains its existing handoff instead of optimizing Read by silently breaking Research.

3 · Rigor

Separate presentation id from research id

Tests must show the random window id never enters startInvestigation; only the backend response becomes child investigation identity.

4 · Diligence

Reuse four owners

Reuse FloatMenu’s outbound guard, ChaseThread’s launch path, WorkspaceWindow’s chrome, and the adjacent placement helper. A second guard, launcher, titlebar, or placement order is a defect.

5 · Defensibility

Freshness is explicit API policy

Name the fresh-instance API separately from stable openWindow; do not hide concurrency behind a magic id convention. Document why the eight-window replacement policy applies to exact chases.
