Research composition review

Collect completed research branches into one ordered, conflict-visible HTML index without pretending that collection is synthesis.

One serial sprint

Spec lineage

Parent: Highlight research window. This child turns concurrent chase results into a truthful operator-review surface.

    Goal and proof boundary

    The operator selects two through eight completed investigations in canonical lineage order, opens one stable workspace review window, and sees the backend-authored member order, questions, content hashes, outline blocks, and hash conflicts. The server delegates to existing compose_artifacts; the client never joins HTML or calls a model.

    Truth boundary: the result is a collection/index, not a merged draft, synthesized answer, graph merge, or cohesive prompt context.

    completed rows → ephemeral ordered selection → POST /research/artifacts/compose → existing ResearchArtifact exports + compose index → stable composition-review workspace window → later, separately authorized versioned synthesis

    Invariants

    • Only two through eight unique completed investigations compose; the request fails as a unit.
    • Caller order is preserved; duplicate content is disclosed by hash conflict and never silently removed.
    • Raw artifact HTML and host filesystem paths do not enter persisted window payloads.
    • Selection creates no investigation, graph edge, model call, cost, or merge.
    • The stable review window represents one evolving operator basket; highlight chase windows remain fresh concurrent instances.
