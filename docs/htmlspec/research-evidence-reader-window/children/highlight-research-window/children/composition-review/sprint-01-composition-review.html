← Composition review · SPR-01

Expose the existing compose authority as an honest workspace review

Ordered completed selection, conflict-visible server index, zero synthesis claims.

Parent context

Read highlights now create independent ChaseThread windows and completed investigations already export canonical ResearchArtifact HTML. compose_artifacts creates an operator index with per-member hashes and collision reporting, but only through the CLI.

This sprint exposes that existing review authority in My Research. It does not create semantic synthesis, edit source investigations, or authorize a model prompt.

Goal

Select two through eight completed researches and inspect one ordered, conflict-visible collection in canonical workspace chrome.

Technical milestones

1

Add strict compose transport

Add POST /research/artifacts/compose. Validate unique trimmed IDs, current completed terminal events, and the 2–8 bound before any export. Delegate to compose_artifacts and list_outline_blocks.

Acceptance:
  • All-or-nothing rejection for missing, running, failed, stopped, duplicate, whitespace, too-few, and too-many members.
  • Response order equals request order and exposes hashes/conflicts; no HTML bodies.
2

Add completed-row selection

Extend the canonical lineage board with optional controlled selection. Completed rows gain accessible checkboxes; every other status stays visibly ineligible. Preserve title and replay navigation.

Acceptance:
  • Click order becomes composition order; deselect/reselect moves the member to the end.
  • The ninth member cannot be selected and selection reconciles when list state changes.
3

Open one stable review window

A calm composition tray opens research-composition-review with only ordered IDs in persisted payload. The renderer revalidates payload, fetches server authority, and shows member questions, hash prefixes, blocks, and collisions.

Acceptance:
  • Copy reads “Collected research — not yet synthesized.”
  • No filesystem path, artifact HTML, or model prompt enters window state.
  • Reopening updates the stable review window instead of stacking duplicates.
4

Preserve extension seams

Document the later versioned draft endpoint, explicit approve/merge, cohesive prompt, provenance binding, and cost consent as separate transitions. Add no placeholder button that implies those transitions exist.

Acceptance:
  • No new dispatch/startInvestigation/graph write call exists.
  • The review response can later seed a versioned composition identity without changing selection semantics.

Rigor — operating manual

1 · Intellectual honesty

Ban the word synthesis from the result noun

Tests pin kind="artifact_index" and the “not yet synthesized” notice. A filesystem index path or pretty window is not evidence of merged prose.

2 · Fairness

Keep unfinished branches visible but ineligible

Running, failed, and stopped research remains readable/navigable in My Research; only its composition checkbox is absent. Do not hide inconvenient outcomes to simplify selection.

3 · Rigor

Prove authority before export side effects

Route tests must show every member is terminal-completed before compose_artifacts runs, then assert order and exact collision pairs.

4 · Diligence

Reuse three existing owners

Reuse MyResearch lineage identity/status, ResearchArtifact export/compose, and stable openWindow. A new research list, HTML joiner, or window manager is a defect.

5 · Defensibility

Make collection→synthesis a visible state boundary

The handoff names the future versioned draft and approval contracts. Do not bury an irreversible merge behind today’s review button.
