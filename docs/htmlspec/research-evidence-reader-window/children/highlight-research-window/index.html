Highlight research window

A selected passage opens a fresh, expandable ChaseThread workspace window without changing research authority or collapsing the book.

One serial sprint

Spec lineage

Parent: Research evidence reader window. This child closes the split between evidence windows and highlight research panels.

    Goal and falsifiable boundary

    Read-mode Deep-research opens one new research-chase workspace window per activation, positioned beside the live selection when possible. The window can expand/restore through existing chrome. The existing ChaseThread remains the sole owner of question editing, voice input, budget-capped launch, relationship recording, and live stream.

    Failure boundary: a kind-level singleton, a second investigation launcher, unsafe passage leakage, closing an arbitrary legacy panel, or claiming workspace placement when no full-fit rectangle exists.

    gate-served selection → existing outboundText guard → fresh research-chase workspace window → existing ChaseThread form / startInvestigation → exact window closes only after “open in main” handoff

    Invariants

    • Every activation may coexist with earlier chases; the eight-window cap remains the explicit performance bound.
    • Window identity is presentation-only and never becomes investigation identity.
    • Selection text crosses only the existing servability chokepoint.
    • Legacy ResearchWorkstation panel callers remain supported; only Read-mode hosting migrates.
    • Selection anchoring generalizes the existing pure adjacent-window geometry rather than creating a second placement policy.
