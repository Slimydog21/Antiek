Grounded reader window

Make evidence a live, exact, rights-aware HTML surface without sacrificing the selected research organism.

Wave 14 milestonesOwner: isolated builder

Parent context

PR #2829 makes Werner’s research-arrival broadcast resolve the exact completed investigation into its Canvas. Each Canvas block already carries optional source_document_id, and BlockCard already has an unused onCiteSource seam. The result surface therefore tells the operator that a source exists but cannot open it.

Antiek already has one canonical BookReader. It fetches BookDetail and FullTextResponse, renders only gate-served content, and supports the same FloatMenu/deep-research substrate. The shell already mounts WindowsLayer. This sprint composes those organisms; it does not invent a renderer or trust caller HTML.

Goal

A grounded Canvas block opens its exact source in a stable per-document BookReader window while Canvas stays mounted.

Route use remains unchanged. Window use injects documentId as a prop and changes only the root height/background contract needed to fit the existing window host.

Rigor — sprint-specific operating manual

1 · Intellectual honesty

Do not call identity content

A source_document_id proves only which document grounds the block. It does not prove a chunk, title, servability, or body. Pass only identity into BookReader and let its live API responses determine every visible content claim.

2 · Fairness

Preserve route readers

Window-first evidence must not make the canonical full-page reader a second-class path. Prove both hosts use the same component and that route height/navigation behavior remains unchanged.

3 · Rigor

Test the composition boundary

A BlockCard callback unit test is insufficient. Prove Monitor creates the exact stable window descriptor and a window-hosted BookReader fetches the prop document, while the existing exact-result tests still pass.

4 · Diligence

Reuse the live rights gate

Read BookReader, WindowsLayer, openWindow, Canvas, and the deleted HostedHtmlDocumentHost history before editing. Any attempt to render payload HTML or reproduce servability branches is a scope failure.

5 · Defensibility

Explain why the old host stays dead

Record that the historical host’s dangerouslySetInnerHTML and caller-supplied body bypassed the canonical reader boundary. Reconsider only if Antiek defines a separately sanitized, signed HTML artifact contract.

Dependencies

  • Exact parent head 34bf6571b and PR #2829 result continuity.
  • Existing WindowsLayer, windowsStore, BookReader APIs, and source_document_id on DistilledNode.
  • No provider credentials or backend mutation.

Out of scope

  • Session twin generation, multi-twin selection, or porting the divergent twin branch.
  • Chunk preview: Canvas lacks a verified chunk id.
  • Marketplace purchase/hosting, arbitrary HTML payload rendering, PDF support, reader redesign, new mascot art, merge, or deployment.

If reader adaptation reveals it owns a nested dock or cannot fit without a third layout, stop and record a BLOCK; do not force a broken window contract.
