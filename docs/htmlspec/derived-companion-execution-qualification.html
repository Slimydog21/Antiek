Derived Companion Execution Qualification

Status: executable Cycle 61 spec. Parent: Cycle 60 verified citation handoff.

Outcome

Replace the companion's hardcoded paid-route placeholder with a deterministic, server-derived qualification projection over the checked provider evidence registry. The projection may describe why routes are refused, but it cannot quote, reserve, approve, dispatch, retry, reconcile, or claim an answer while every route remains unqualified.

Authority boundaries

AuthorityRule
RevisionThe existing owner-scoped derived-asset read verifies the exact current or pinned revision before qualification is returned.
Provider evidenceprovider_qualification.json is the only source for the five checked capability dimensions. Malformed or missing evidence fails closed.
PriceA documented pricing page is not an executable numeric quote. Without a positive server-owned cost catalog entry bound to a bounded workload, pricing_status=unavailable, ceiling is null, and approval is disabled.
SpendNo research-spend run or hold is created by this projection. Future execution must reuse ResearchProviderGateway and ResearchSpendLedger.
TransportA route is not executable unless all five evidence dimensions pass and a production adapter supplies durable idempotency, disabled hidden retries, and authoritative reconciliation.

Projection contract

The response is closed and deterministic: schema version; exact derived asset/revision/hash/generation; available, reservable, and dispatch_authorized; stable reason; pricing status; nullable recommended ceiling; and a sorted route list. Each route contains provider, model, operation, checked date, verdict, and the exact failed/unproven dimension names. It omits source findings, owner identity, credentials, internal paths, raw registry JSON, and speculative prices.

API and companion

  • Evidence preparation and conversation reads return the current qualification projection under execution; it is not copied into immutable evidence packs or stored turn rows.
  • Current and pinned revision calls preserve their existing owner privacy and no-store behavior.
  • The reader shows the stable refusal reason and candidate route count. It renders no approval or answer control while unavailable.
  • Evidence retrieval and Follow-this research remain functional and provider-free.

Refusals

  • Malformed qualification registry: value-free qualification_registry_invalid, zero candidates, no exception detail.
  • No fully passing provider: no_provider_route_qualified.
  • A future fully passing evidence row without a numeric catalog/adapter still remains unavailable; evidence alone never grants dispatch authority.
  • Unknown, zero, stale, non-USD, or unbounded pricing never becomes free.

Acceptance evidence

  • Domain tests prove deterministic ordering, exact blocker names, malformed-registry fail closure, and no numeric quote.
  • API tests prove current and historical scope, replay refresh, owner privacy, and zero research-spend mutations.
  • Frontend tests prove the concrete unavailable reason is rendered and no approval/answer control appears.
  • Existing derived companion, citation handoff, generated-type, typecheck, and production-build gates remain green.

Non-goals and next seam

No provider call, model answer, catalog price authoring, operator approval, reservation, settlement, retry, reconciliation, BYOK change, merge, or deploy. The next executable paid seam begins only when one route has independently verified five-dimension evidence, a positive expiring numeric catalog entry, bounded token/tool workload, and a real recovery adapter.

Harness hint

Use one reviewer to attack accidental authority promotion and another to attack owner leakage, stale policy persistence, and UI overclaiming.
