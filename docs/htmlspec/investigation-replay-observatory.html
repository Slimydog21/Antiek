Investigation Replay Observatory

An evidence-honest authored surface for re-reading one typed investigation trajectory without creating a second replay authority.

SPR-01adversarial verificationstacked on PR #2736

Spec lineage

Root bounded execution spec. Parent authority: the operator’s persistent Antiek goal. Immediate code parent: cycle 571, commit 473e06a88, PR #2736. No child specs: route, shared projection, player shell, stories, and tests are one tightly coupled lane.

    Problem and goal

    Canonical /replay/:investigationId underpins operator-graded outcomes but has no route-level tests or deterministic whole-surface stories, renders raw thrown failures, and has no authored environment. More seriously, the main view uses an initial fetch plus WebSocket while ReplayStepList independently polls the same endpoint every five seconds. The displays can disagree.

    Build one calm observatory over one route-owned event collection. Preserve the endpoint, socket construction, ping and malformed-frame rejection, event-id deduplication, cleanup, typed Event records, and existing cross-panel goto event.

    Egghead verdict

    Strongest counterargument: an attractive observatory can become a persuasive second replay engine by independently filtering, sorting, classifying, or summarizing evidence. That is worse than the plain UI.

    Surviving concept: the route is the sole transport adapter; a read-only context shares its exact event collection with both main view and step rail. HTML may improve hierarchy and access but cannot infer outcomes, rewrite chronology, hide unknown events, or add grading.

    Authority topology

    GET /trajectory + existing WebSocket (Replay route only)
  -> ReplayContext: readonly Event[] + transport state
     -> Replay observatory / TrajectoryReplay
     -> ReplayStepList
  existing antiek:replay:goto remains navigation seam
    • ReplayStepList owns no fetch and no timer.
    • Stories inject complete view state with execution hard-disabled; no fetch, WebSocket, interval, or global transport mock.
    • Event records remain generated Event; no parallel evidence schema.
    • Transport status, investigation terminal events, and operator replay position remain separate.

    Truth-copy constraints

    • Say “Re-read the recorded trajectory”; never imply DOM or video reconstruction.
    • “Live tail connected” describes transport only, not investigation health or completion.
    • “Offline” means no live tail; fetched evidence remains inspectable.
    • A typed investigation.failed event is evidence, not a transport failure.
    • Errors never reveal raw exceptions, response bodies, URLs, tokens, payloads, or stacks.
    • No grade, approve, reject, score, or inferred-outcome control appears.

    Five-values rigor

    Intellectual honestyConnection health is never conflated with outcome. Unknown event kinds remain visible.
    FairnessVisual emphasis follows operator position, not model-assigned importance; terminal states get no persuasive editorial weight.
    RigorTests prove one transport authority, overlap dedupe, malformed rejection, cleanup, safe failures, and story inertness.
    DiligenceLoading, empty, offline, live, long, failed-event, transport-failure, night, reduced-motion, and narrow are distinct.
    DefensibilityThe endpoint, generated Event type, and goto event remain traceable; every projection retains its source record.

    Rejected alternatives

    • Second endpoint or reducer: forks evidence authority.
    • Keep step polling: permits contradictory views.
    • Mutable events in frozen starter props: not a live contract.
    • Sort by phase, importance, or event ID: invents chronology.
    • Replace payloads with summaries: loses grading evidence.
    • Storybook transport mocks: risk connections and test mocks rather than states.
    • rrweb/video reconstruction: Antiek records typed events, not DOM playback.
    • Semantic timeline in raster: inaccessible and unverifiable.

    Out of scope

    Trajectory/event API or schema, WebSocket URL/protocol, server ordering semantics, outcome grading, automated judgment, backend, global shell, Werner/cursor/arcade, merge, deployment, providers, and spend.

    Acceptance and gates

    1. One production trajectory fetch and one WebSocket construction remain.
    2. Step rail has zero network operations and timers.
    3. Socket URL, ping filtering, malformed dropping, ID dedupe, and cleanup are tested.
    4. Stories use fixed data, paused playback, and hard-disabled execution.
    5. Safe errors redact arbitrary hostile strings.
    6. Labels, live status, keyboard, reduced motion, narrow wrapping, axe, and overflow pass.
    7. Focused tests, TypeScript, token/type/parity gates, Storybook, and production build pass.
    8. Different-lineage hostile review and hardenx leave no REAL finding.
