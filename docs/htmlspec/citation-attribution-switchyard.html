Citation Attribution Switchyard

A bounded redesign of /cross-graph/citations as an honest operator surface for recording references.

Goal and context

Turn a raw identifier form into an accessible, authored Antiek environment without expanding backend authority. The existing endpoint records a cross-graph citation and may emit an event. It does not itself verify federation trust or consent, accept an inbound reference, or execute a payout.

Egghead verdict

Strongest counterargument: a beautiful “switchyard” can make one POST appear to own three deliberately separate authorities: citation recording, federation policy, and money movement.

Surviving concept: one active “Record reference” lane plus a read-only authority boundary. The interface must be more explicit about what did not happen than the legacy screen.

Architecture and seams

  1. Accessible form produces a typed citation draft.
  2. An injected recordCitation(draft) seam makes stories and tests deterministic.
  3. The production default performs exactly POST /cross-graph/citations with the existing JSON body.
  4. Successful responses append to React session state only; no durable-history claim.
  5. The generated image is aria-hidden decorative atmosphere. HTML owns direction, state, copy, controls, and receipts.

Truth constraints

  • Say: “Records a citation reference.”
  • Say: “This screen does not verify partner trust or consent and does not execute a payout.”
  • Say: “Attribution and any revenue handling happen downstream under separate policy.”
  • Say: “Receipts shown here last for this session only.”
  • A federated substrate ID is metadata, not evidence of federation success.
  • Never render raw response bodies or thrown error text.
  • Primary action is “Record reference”, never “federate”, “verify”, or “route payout”.

Deterministic stories

  • ready — same-substrate draft ready to record.
  • federation — partner substrate metadata with explicit warning.
  • submitting — stable busy controls.
  • safe-failure — generic, redacted failure.
  • recorded — session-local receipt.
  • night — dark authored environment.
  • narrow — responsive operator surface.

All stories hard-lock execution off and perform no network mutation.

Five values

  • Truth: separate recording from federation and payout authority.
  • Agency: preserve exact identifiers and make federation metadata opt-in and reversible before submit.
  • Calm: one primary action, progressive disclosure, session receipts below the work.
  • Legibility: real labels, described warnings, live status, keyboard focus, non-color status cues.
  • Craft: polar archival worldbuilding supports the task without encoding product meaning in pixels.

Acceptance criteria

  • Exact endpoint and trimmed request body are covered for same-substrate and federated drafts.
  • Failures redact arbitrary server/exception secrets.
  • Labels use htmlFor/id; status is announced politely; busy/disabled states are semantic.
  • Long IDs wrap or remain accessible; narrow layouts do not overflow; reduced motion is honored.
  • Seven stories pass axe and horizontal-overflow checks.
  • Production build and focused unit tests pass.

Rejected alternatives

  • One-click “federate and attribute”: real outbound gates are a separate security flow.
  • Payout language: the POST records an event/reference, not a transfer.
  • Persisted history: no listing/audit endpoint backs it.
  • Raw backend error detail: unsafe and unnecessary.
  • Semantic graph or arrows baked into the raster: inaccessible and dishonest.

Out of scope

Backend/schema changes, federation execution, partner trust, consent verification, inbound acceptance, payout/Stripe, durable history, authentication, policy changes, merge, deployment, and spend.
