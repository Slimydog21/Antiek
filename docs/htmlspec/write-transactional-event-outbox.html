Cycle 44: Write transactional event outbox

Status: executable master sprint spec. Base: Cycle 43 reviewed commit 31ebfa833.

Problem

Write mutations commit to DuckDB and then call emit_typed. The event emitter deliberately suppresses filesystem failures and still returns the allocated ID. A crash or append failure can therefore leave authoritative prose, provenance, graph promotion, or outline state without the recursive trajectory event that downstream note-taking and learning depend on.

Authority boundary

DuckDB is authoritative for mutation plus delivery intent. JSONL remains authoritative for live trajectory consumption. This sprint does not move trajectory history into the graph database. It adds a durable bridge: an exact typed envelope is inserted into a V18 outbox in the same transaction as its Write mutation, then dispatched after commit.

Stored intent

Each row binds a unique event ID, investigation ID, aggregate kind and ID, monotonically allocated outbox sequence, canonical event JSON, SHA-256, state, attempt count, creation time, and optional delivered time. Rows are append-only except the closed delivery transition from pending to delivered. Reusing an event ID or operation identity with different bytes fails.

Delivery protocol

  1. Build and validate the complete typed Event envelope before the mutation transaction. Disabled telemetry does not disable authoritative Write outbox intent.
  2. Commit domain mutation and exact outbox row together. A transaction failure leaves neither.
  3. After commit, acquire a new investigation-scoped event-file lock shared by dispatch and sealing. Reconcile the event ID against the live JSONL before append.
  4. If absent, append the exact canonical line, flush, and fsync. If present with identical canonical bytes, treat it as recovered delivery. If present with different bytes, fail closed.
  5. Mark delivered in a new short DuckDB transaction only after durable append or exact reconciliation. A crash after append but before receipt creates no duplicate on retry.

Ordering and sealing

Dispatch pending rows in outbox sequence order per investigation. A later row cannot pass an earlier pending or failed row. Sealing must refuse while pending rows exist and must share the database-then-investigation lock order with eventful writes and dispatch. Antiek's established reopen contract permits a durable JSONL tail after a Parquet snapshot; resealing merges and deduplicates the snapshot and tail by immutable event ID.

Crash matrix

BoundaryRequired result
Before domain commitNo domain mutation, no outbox row, no JSONL event.
After commit before appendPending intent survives restart and dispatches once.
During append or fsyncRetry reconciles complete identical lines; malformed or partial tails fail closed and never mark delivered.
After fsync before delivery receiptRetry finds exact event ID and bytes, writes only the receipt, and does not append again.
After receiptReplay is an exact no-op.

Acceptance

  1. Schema fast-path detects and repairs a missing or partial V18 outbox.
  2. Tests inject every crash boundary and prove exact domain, outbox, JSONL, and receipt state after restart.
  3. Concurrent dispatchers produce one canonical line per event and preserve per-investigation sequence.
  4. Changed bytes under a reused operation or event identity fail closed.
  5. Filesystem permission, symlink, hard-link, malformed-tail, replacement, and lock-timeout failures retain pending intent and expose an actionable error.
  6. Existing event readers consume the emitted line unchanged. No consumer-specific dual-write is introduced.
  7. Focused Write, event-log, schema, and API suites, process-crash tests, Ruff, compileall, HardenX, and independent review pass.
