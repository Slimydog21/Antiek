Review generated documentary visuals in Antiek

Child of the generated visual candidate resolver. This sprint connects the mounted multimedia storyboard to the complete owner-authenticated visual lifecycle without exposing provider or cryptographic authority.

Workflow

  1. A ready balanced or highest-quality asset presents its spoken chapters in plan order.
  2. For one chapter, the operator enters a maximum USD ceiling and explicitly approves it before the server derives visual authority.
  3. The operator submits exactly once, checks generation explicitly, then materializes successful candidates into private quarantine.
  4. The client fetches exact image bytes through authenticated preview routes, owns bounded blob URLs, and revokes them on error, revision change, or unmount.
  5. A generated-provenance acknowledgement gates attestation and selection. Selection cannot imply archival provenance.
  6. Every spoken chapter must have one attested candidate before the ordered reviewed set can be locked.

Client authority

Every response is cross-bound to the requested asset, revision, chapter, authorization, execution, candidate, receipt, or ordered set as applicable. Changed identity fails closed. Candidate paths, content digests, provider locators, account identity, signatures, keys, and raw authorization details are not rendered.

Interaction model

The workspace uses a chapter rail and stable two-column contact sheet inside the existing multimedia production surface. Paid commands are unavailable before plan approval and absent on the cheapest route. Explicit polling avoids hidden loops or duplicate provider calls. Asset or revision changes invalidate pending responses.

Responsive and accessible behavior

The rail collapses to two columns before the contact sheet stacks on narrow screens. Image frames use a fixed 16:9 ratio. Controls retain visible labels, keyboard focus through existing Lemon primitives, disabled states, and live error roles. No text overlaps or resizes the image grid.

Non-goals

No automatic spend, background polling, browser-authored prompt/path/digest, automatic provenance attestation, sourced or archival rights review, renderer changes, publication, merge, or deployment.

Done bar

API and component tests prove the complete command sequence, spend and provenance gates, response identity checks, complete chapter coverage, authority redaction, stale-revision handling, and blob URL cleanup. Typecheck, production build, broad frontend tests, HTML parsing, security review, and independent review pass. Desktop and mobile screenshots are required when the in-app browser is available.
