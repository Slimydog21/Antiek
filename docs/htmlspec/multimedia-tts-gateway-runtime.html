Install paid narration through one idempotent HTTPS authority

Stacked on PR #1304. This sprint replaces the worker’s deployment-time callback gap with a fixed server-configured gateway and composes the full production runtime. It does not alter authorization, budget, reconciliation, or media state machines.

Gateway request

TTSSynthesisGateway accepts only a canonical PreparedChapterTTSRequest. It sends one POST to a configured absolute HTTPS URL with redirects disabled, bounded connect/read timeout, Authorization: Bearer secret, Content-Type: application/json, and Idempotency-Key: antiek-tts-{request.body_digest}. The JSON envelope contains schema version, request body digest, account identity digest, provider, model, endpoint capability, and the exact parsed canonical request body. It sends no signing key, authorization receipt, approved ceiling, recovery key, local path, or unrelated plan content.

Gateway response

A successful bounded JSON response contains schema version, status completed, provider request ID, request body digest, provider, model, MIME type, and base64 audio. The adapter rejects redirects, non-2xx, non-JSON, duplicate/extra/missing fields, non-completed status, invalid IDs/digests, provider/model drift, digest drift, unsupported MIME, invalid base64, empty audio, and audio above the chapter byte ceiling. Only then does it return ChapterTTSSynthesisResult.

Unknown submission

The adapter performs exactly one transport attempt and no internal retry. DNS/TLS/connect/write/read timeout, connection reset, truncated response, malformed response, or 5xx after send raises. produce_chapter_narration has already durably marked send-started before invoking the callback, so the existing provider-execution state machine records submission unknown and charges the reserved ceiling conservatively. Recovery must use the configured recovery authority and the same request-body/account identity digest; a user retry cannot call synthesis again until reconciliation resolves the attempt.

Transport injection

The default transport uses a no-redirect HTTPS opener and bounded response reader. Tests inject a GatewayPoster so CI never reaches the network. The injectable seam receives URL, headers, canonical body bytes, timeout, and response byte ceiling and must return status, headers, and body; production configuration never accepts a transport from HTTP.

Runtime composition

multimedia_production_worker_runtime_from_environment is all-or-nothing and disabled when no related variable is present. When enabled it validates: production DuckDB path; six independent 32-byte keys; private narration/visual/render/receipt directories; reviewed-visual registry DB/key; playback receipt root consistency; visual-evidence DB, Ed25519 verify key, evidence key, and bounded reviewer allowlist; fixed HTTPS TTS gateway URL/token/account digest/timeout; FFmpeg and FFprobe absolute executable paths; bounded dimensions/FPS/timeout. It builds one ReviewedVisualRegistry, VerifiedPlaybackRuntime, VisualEvidenceAuthority, TTSSynthesisGateway, and AuthorizedProductionRuntime over the same keys and roots.

Startup and secrecy

register_multimedia_routes installs the runtime dependency only after complete validation. Partial or malformed configuration aborts startup rather than leaving a deceptively available route. HTTP request and response schemas remain unchanged and expose no environment values, bearer token, key, executable path, database path, media root, account digest, or reviewer identity.

Non-goals

No provider gateway server implementation, secret storage UI, authorization issuance, recovery adapter changes, automatic unknown retry, image generation, publication, merge, or deploy.

Acceptance

  • Exact request produces one canonical POST and a cross-bound synthesis result.
  • Every malformed/oversized/drifted/redirected response fails without returning audio.
  • Ambiguous transport performs no retry and integrates with submission-unknown behavior in a worker test.
  • Empty configuration disables the runtime; partial or malformed configuration raises at startup; complete configuration installs exactly once.
  • Runtime components share exact keys, roots, DB, evidence authority, and playback authority required by receipt registration.
  • Focused and broad tests, typecheck/build where affected, Ruff, HTML parse, HardenX zero real findings, and heterogeneous review pass.
