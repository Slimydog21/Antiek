Antiek Auth Diagnostic Precision

Make login failures mechanically diagnosable — Layer A (transport) vs Layer B (policy/delivery) — with zero conflation and operator-grade verification gates.

Goal

What success looks like and how we measure it.

Operators and agents must never again treat “Failed to fetch” (browser TypeError, no Response) as synonymous with “email not allowlisted” (HTTP 200 {"sent": true}, no mail). This program ships a closed failure-mode matrix, normative error codes, callback surfaces on the email-click path, a composed auth probe, Playwright login e2e, and multi-email allowlist/middleware consistency — each with mechanical gates.

Success criteria

  • Every login symptom maps to exactly one row in the failure-mode matrix with a discriminant command and expected output.
  • Login UI never shows raw Failed to fetch without Layer A context; Layer B success UI never implies mail was sent when allowlist blocked delivery.
  • Expired/invalid magic links clicked from email show operator-grade copy (API HTML or frontend ?error=), not anonymous JSON on api.antiek.ai.
  • tools/auth_probe.py (composed with prod_parity) exits 0/1/2 with staged checks documented in handoff.
  • Playwright tier-B spec: mock provider link → callback → cookie → /auth/me 200; one expired-token path.
  • ANTIEK_OPERATOR_EMAIL comma-list works identically in auth.py allowlist and app.py session middleware; the@faisalnazer.com onboarded on production with pasted probe output.

Failure mode to avoid

UI-only renames (“say Offline instead of Failed to fetch”) while API and middleware still conflate layers — craftsmanship that is easy to vary and fails under hostile re-read.

Context & motivation

Why this, why now.

A prior diagnosis session conflated Layer A transport (fetch() threw → requestMagicLink catch → message Failed to fetch) with Layer B policy (non-allowlisted email → silent sent: true → “Check your email”). Code proof: apps/reading/src/lib/auth.tsx L101–129 vs interfaces/research/api/auth.py L236–261.

Magic-link auth (H6) is shipped and covered by tests/test_magic_link_auth.py, but AMS Playwright mocks auth at the network layer; callback failures return JSON on the API host; middleware compares session email to the entire ANTIEK_OPERATOR_EMAIL string when comma-separated — a latent multi-email bug at app.py L1190, L1247–1248 vs auth.py L97–107 split.

Architecture overview

Load-bearing shape for executors.

Browser (antiek.ai/login) │ POST /auth/request ──cross-origin──► api.antiek.ai (FastAPI) │ ├─ allowlist? send email : silent sent:true │ Email link ──GET──► api.antiek.ai/auth/callback?token= │ ├─ 302 + Set-Cookie (Domain=.antiek.ai) │ └─ 400/403 JSON (today — SPR-03 fixes surface) │ └─ VITE_API_BASE_URL=https://api.antiek.ai (Pages build) Dev: API_BASE="" + Vite proxy /auth → localhost:8000 Layer A: fetch throws (no Response) — wrong host, backend down, CORS, TLS, offline Layer B: HTTP completes — sent:true w/o mail, 503 email_delivery_failed, callback codes

Key invariants

  • Enumeration guard: non-allowlisted addresses always get {"sent": true}; no not_allowlisted code (security).
  • Magic-link click lands on API origin first; frontend redirect uses ANTIEK_FRONTEND_BASE_URL / ANTIEK_PUBLIC_BASE_URL.
  • credentials: "include" on all apiFetch calls — required for cross-origin cookies.
