Make the notebook index feel like a living knowledge conservatory

Stacked on PR #2595. Transform the canonical /notebooks entry from generic administrative chrome into an authored place for working books without inventing notebook, twin, publication, or graph authority.

Five values

  1. Intellectual honesty: copy describes claims, questions, source traces, and working prose already supported by notebooks; it does not claim automatic twin generation.
  2. Fairness: private working books and public contributions remain visibly distinct without ranking either as inherently better.
  3. Rigor: GET /notebooks, POST /notebooks, trimmed title/investigation payloads, exact content-class filtering, and encoded navigation remain unchanged.
  4. Diligence: loading, empty, populated, filtered, creating, and private-safe failure states receive deterministic proof.
  5. Defensibility: generated art is decorative only; PanelLayout retains the route-level main landmark and every semantic element is live HTML.

Surface contract

The masthead names the notebook conservatory and reports one lifecycle phase. A living inventory counts total, private, and public rows from the authoritative list. The creation form keeps explicit labels and optional investigation binding. The catalogue keeps LemonTable row authority, exact content classes, and encoded notebook navigation.

Failure boundary

GET and POST failures render fixed recovery copy. Raw HTTP status, exception strings, paths, credentials, and response bodies never enter visible HTML.

Visual contract

A ChatGPT Image-authored polar glasshouse plate supplies atmosphere around a broad quiet center. It contains no controls, readable writing, state, notebook data, or mascot. HTML remains responsible for layout and interaction at every breakpoint.

Acceptance

  • Exact list, create payload, filter, and navigation behaviors are tested.
  • One route-level main landmark remains.
  • Six deterministic lifecycle stories plus one production-raster proof exist.
  • Fixture baselines cover 768, 1024, and 1280 pixels.
  • Axe, TypeScript, token/type, Storybook, production build, security, and heterogeneous hostile review are green.

Non-goals

No API/schema changes, content-class mutation, promotion gate, notebook editor/detail redesign, automatic twin generation, graph writes, backend, shell, Werner, cursor, merge, or deploy.
