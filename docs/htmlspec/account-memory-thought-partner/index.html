Account memory in Thought Partner

Make owner-private long-term memory reach a real production model prompt, with exact owner isolation and no-memory byte equivalence.

Status: executableOwner: Codex primary1 sprint · 1 wave2026-08-12

Spec lineage

Root spec. The operator brief is the interview record; no unresolved user choice changes this bounded implementation.

Parent: BYOT request authority is adjacent security context, not a dependency.

Child specs

None. This is one tightly coupled prompt-boundary sprint; splitting retrieval from dispatch proof would recreate the current false-positive architecture.

Goal

An authenticated owner’s current account-memory facts are recalled under the canonical database lock, rendered by the existing provenance-preserving JSON renderer, and inserted into the exact Thought Partner prompt sent to dispatch. A different owner sees none of them; an empty or unavailable memory store produces the exact pre-feature prompt.

Success criteria

  • A distinctive owner-A marker appears in the first captured provider prompt for owner A.
  • The same marker is absent for owner B, unauthenticated-local requests, responses, logs, and errors.
  • Empty memory produces byte-for-byte identical prompt input.
  • Memory text stays JSON-escaped data and cannot select tools, models, routes, budgets, or system instructions.
Failure mode: emitting a “memory recalled” event or constructing a context object that is never consumed. Provider-call capture is the only completion proof.

Architecture

authenticated request.state.user_id → short connect_write(default_db_path(), purpose="thought-partner:account-memory-recall") → recall_memory(owner, query=user prompt, limit=8) → format_memory_for_prompt(items) → release database lock → append guarded owner-private JSON layer only when non-empty → existing role prompt → dispatch(captured full prompt)

Invariants

  • Identity comes only from authenticated middleware state. unauthenticated_local and shared __operator__ identities do not receive private memory.
  • Recall failure degrades to the exact no-memory prompt and a value-free operational warning; cross-owner leakage is never a recoverable relevance miss.
  • No raw memory or owner identifier is added to the HTTP response or event payload.
  • The database lock closes before provider dispatch.
