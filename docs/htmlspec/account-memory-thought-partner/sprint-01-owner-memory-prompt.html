Owner memory prompt boundary

Recall, compose, dispatch, and prove owner-private memory at the real provider call.

Wave 1Status: executable5 milestonesOwner: Codex primary

Parent context

Antiek already stores versioned owner-scoped memory and renders recalled items as canonical provenance-tagged JSON. No production API or runner consumes that output. A nearby ResearchRunner function constructs and discards a context pack, demonstrating why retrieval events cannot prove model use.

This sprint owns one narrow production path: POST /thought-partner. It must preserve the current prompt exactly when memory is absent while inserting private context only for a distinct authenticated owner.

Position: first real account-memory consumer; future Research/Write integrations should reuse its retrieval helper and tests, not copy endpoint-local SQL.

Goal

An owner-A memory marker must appear in the exact prompt argument captured by the first provider call, and nowhere for owner B.

The implementation must use middleware identity, a short canonical database lock, the existing recall/ranking and JSON renderer, and a platform-authored boundary that says memory is private factual data rather than instructions.

Technical milestones

1

Build the retrieval boundary

Add a small module that validates a distinct authenticated owner from request state, opens connect_write briefly, calls recall_memory(..., limit=8), renders via format_memory_for_prompt, and closes before returning.

  • No body-supplied owner; shared __operator__ and unauthenticated_local receive no memory.
  • Empty recall returns exactly "".
  • Expected availability failures return "" with value-free logging; validation/integrity tests stay loud.
interfaces/research/api/account_memory_context.pytests/test_thought_partner_account_memory.py
2

Compose one guarded prompt layer

Insert the rendered memory between the platform system prompt and the existing role prompt only when non-empty. Use a fixed platform header; do not reuse caller system_context.

  • Memory JSON cannot escape its layer or become a system/developer directive.
  • No memory produces the pre-feature prompt byte-for-byte.
  • Existing client system context remains semantically and byte-order compatible.
interfaces/research/api/app.py
3

Prove provider receipt and isolation

Seed owner-A and owner-B memory through the canonical store, authenticate real sessions, capture the mock provider’s first prompt, and assert exact inclusion/exclusion.

  • A marker is in owner A’s provider.calls[0]["prompt"].
  • A marker is absent for B, unauthenticated local, and forged owner body/header attempts.
  • HTTP response, logs, and exception details contain no raw memory.
tests/test_thought_partner_account_memory.py
4

Exercise injection and failure cases

Store memory containing instruction-like text, delimiters, URLs, and newlines. Prove it remains JSON data and cannot alter dispatch role, model, tools, budget, or provider.

  • Recall timeout/unavailable store preserves exact no-memory prompt.
  • Eight large items are bounded deterministically without losing the user/role prompt.
  • The database lock is closed before the provider mock runs.
tests/test_thought_partner_account_memory.py
5

Run reachability and regression gates

Ensure the new helper has a production caller and the existing Thought Partner behavior remains green. Do not baseline new type or reachability findings.

  • Focused tests, strict declared bar, Ruff, reachability, and diff checks pass.
  • An independent reviewer tries to refute identity, prompt equivalence, and secret-leak claims.

Rigor — operating manual

1 · Intellectual honesty

Provider capture or it did not happen

Do not count a recall return, event, or assembled string as success. The marker must be asserted in the exact mock provider prompt; if the endpoint path does not dispatch, report the test as inconclusive.

2 · Fairness

Protect the absent owner

Steelman availability-first fallback: silently dropping memory keeps Thought Partner usable. Retain it only for value-free operational failures; never reinterpret cross-owner rows as a harmless miss.

3 · Rigor

Compare exact bytes

Record the baseline prompt before wiring memory and assert equality for empty, disabled, unauthenticated, and recall-failure cases. Substring-only checks are insufficient for the no-memory contract.

4 · Diligence

Reuse memory and auth authorities

Read substrate/memory/recall.py, store.py, auth middleware, and existing Thought Partner provider-capture tests before editing. Do not introduce parallel ranking, rendering, or owner-resolution logic.

5 · Defensibility

Leave the trust boundary reconstructable

Document why connect_write is required for recall, why the lock closes before dispatch, and why shared operator auth is excluded. A future ResearchRunner integrator must be able to reuse the boundary without reading this chat.

Dependencies

  • PRs #2989 and #2990 are already on main: account-memory store and recall renderer.
  • A configured signed session is required to exercise private memory; unauthenticated local remains exact baseline.
  • No dependency on BYOT dispatch PRs #3010–#3013.

Out of scope

  • Memory CRUD Settings UI or automatic memory extraction from every conversation.
  • ResearchRunner/cascade propagation until that path owns a real provider prompt.
  • New context-pack event schema, provider/model selection, tools, or payer authority.
  • Changing memory ranking, graph schema, or provenance format.
Stop if tempted: this sprint proves consumption, not the full lifecycle.
