Produce one verified playable documentary from exact authorities

Stacked on PR #1284. This sprint composes the existing durable narration, visual, render, receipt, registration, and playback authorities. It introduces no alternate provider or media pipeline.

Input authority

The authenticated operator submits only the expected current parent revision and one complete signed V2 narration authorization per spoken chapter. Authorizations are untrusted transport objects: the server re-prepares every request body from the persisted plan and verifies signatures, owner, asset, deterministic child revision, provider/model, capability, catalog, quote, recovery authority, body digest, ceiling, and expiry before provider admission. The reviewed visual set is loaded only from the owner/revision registry; no visual path, digest, label, grounding, or evidence identity crosses HTTP.

Stage order

  1. Load owner/current ready video asset and exact reviewed visual set before spend.
  2. Derive spoken chapter order and prepare the canonical narration run from signed authority routes.
  3. Authorize the exact set and call produce_narration_run, which atomically admits all ceilings before any callback and replays sealed children/aggregate.
  4. Reopen sealed narration and derive chapter timing from its real source durations and persisted chapter bindings.
  5. Build server-derived scenes and timeline; adopt the reviewed disclosure label for each canonical scene while preserving plan grounding and real narration boundaries.
  6. Call produce_educational_video, which reopens narration, copies and evidence-verifies reviewed stills, renders FFmpeg output, and cross-binds all artifacts.
  7. Issue the canonical private EducationalVideoReceipt.
  8. Recheck owner/current revision and register receipt metadata into the asset through register_multimedia_production. Success means the current asset is durably linked and verified playback can reopen it.

Replay and crash recovery

The request has no separate mutable job identity: its identity is owner, asset, parent revision, narration authorization-set digest, and reviewed visual set ID. Narration child calls, aggregate narration, visual packet, render bundle, educational receipt, and production link each use existing deterministic identities and exact-replay checks. A retry after any committed stage reopens that stage and continues. A changed authorization set, candidate set, plan, media bytes, or output conflicts instead of overwriting authority.

A revision change before provider admission fails without spend. A revision change after provider admission can leave sealed orphan media for audit/reconciliation, but the post-narration, post-render, pre-receipt-registration, and registration CAS checks prevent stale artifacts becoming current playback. The API reports a conflict, not success.

Trusted runtime

The runtime owns signing/integrity keys, DuckDB path, private output roots, FFmpeg/FFprobe paths, synthesis callback, evidence verifier, reviewed visual registry, verified playback runtime, and asset store. HTTP cannot select a callback, executable, directory, signing key, evidence authority, provider route, or model.

HTTP and product

POST /multimedia/assets/{asset_id}/production is authenticated and accepts expected revision plus signed chapter authorizations. It returns the current MultimediaAssetRecord only after production_link is attached. The workstation enables production only when the current revision has a reviewed visual set and a complete chapter authorization set. In-flight completion is asset/revision bound. The UI distinguishes authorizing, producing, produced, conflict, and runtime-unavailable states; it never presents authorization as spend or production as publication.

Non-goals

No authorization issuance, quote generation, image generation, candidate catalog authoring, arbitrary upload/path, fake production mode, publication, merge, or deploy.

Acceptance

  • One valid multi-chapter command makes exactly one provider submission per chapter, creates real WAV/MP4 artifacts, issues a receipt, attaches the current production link, and becomes verified playback.
  • Exact retry after success performs zero new provider callbacks and returns the same production link.
  • Injected crashes after narration, render, and receipt resume without duplicate provider submission or authority reinterpretation.
  • Foreign/stale/unready/audio/cheapest/incomplete/duplicate/tampered/expired/wrong-owner/wrong-body/wrong-visual requests fail closed at the earliest authority boundary.
  • A revision race cannot attach stale playback.
  • Focused and broad tests, real FFmpeg fixture, typecheck/build, Ruff, HTML parse, HardenX zero real findings, and heterogeneous review pass.
