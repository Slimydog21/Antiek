Multimedia Graph Evidence Attachment

Status: Cycle 17 implementation contract.

Outcome

An honestly unsourced multimedia plan can discover canonical chunks from the operator's knowledge graph, let the operator review exact candidates, and create a separate grounded draft without changing the original.

Authority boundary

  • The server derives the search query from the persisted topic, research scope, and must-cover constraints.
  • Search is restricted to documents whose canonical owner matches the authenticated operator, and takedown overrides remain excluded.
  • The browser receives bounded excerpts and identities, never authority to submit replacement text or document metadata.
  • Apply submits only selected chunk IDs and reviewed text digests. The server reopens full canonical text and rejects owner, identity, deletion, or digest drift.

Lifecycle

  1. Search the current exact parent revision.
  2. Review and select candidates.
  3. Reopen selected chunks under owner scope and verify reviewed digests.
  4. Build a new planned asset linked by parent_asset_id; preserve the source asset byte-for-byte.
  5. Recompute suggestions, chapters, citations, scenes, and the unsourced ledger from canonical evidence.

Refusals

Foreign chunks, duplicates, stale asset revisions, changed text, missing graph runtime, empty selections, oversized corpora, and malformed identities fail before derivative persistence. No provider call, render, spend, authorization, publication, or graph write occurs.
