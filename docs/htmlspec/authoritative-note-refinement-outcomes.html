Authoritative note refinement outcomes

Make a living-note decision durable in the same transaction as its graph state, then let later wrestling prompts consume only those authoritative outcomes.

Five values

  • Truth: no event may claim a refinement applied unless the graph mutation committed with its delivery intent.
  • Causality: later prompts fold only decisions physically before their request cutoff.
  • Determinism: sequence ordering decides graph state independent of arrival order.
  • Recovery: exact retries replay one immutable decision and drain pending delivery without mutating twice.
  • Compatibility: legacy audit-only note.refined events remain readable but never become prompt truth.

Outcome contract

FieldMeaning
note_idThe promoted graph insight node targeted by the attempt.
origin_note_idThe originating note.emerged identity when graph metadata can prove it; nullable for graph-only notes.
sequenceThe attempted monotonic sequence.
previous_sequenceThe highest sequence applied before this decision, or -1 for none.
outcomeapplied iff sequence is greater than previous sequence; otherwise superseded.
text fieldsprevious_text is authoritative graph text immediately before the decision. new_text is the attempted replacement.

All new authority fields are optional at schema level so historical audit events deserialize. Authority is all-or-nothing: a partially populated outcome is corruption.

Atomic write

  1. Derive a content-addressed operation identity from investigation, graph note, proposed text, reason, sequence, and document.
  2. Under the existing single DuckDB writer and one eventful_transaction, read current note state, decide applied versus superseded, mutate only for applied, build the typed outcome, and enqueue it.
  3. Commit graph state and outbox intent together.
  4. After commit, deliver this note aggregate's pending event. A delivery failure is surfaced; retry finds the exact stored event, performs no second mutation, and retries delivery.
  5. Reusing an operation identity with different bytes fails closed. Distinct content at the same sequence remains a distinct attempt and is decided against current graph state.

Working-memory fold

  • Legacy outcome-absent refinement events are ignored.
  • Complete applied outcomes replace the corresponding emerged snapshot with new_text.
  • Complete superseded outcomes set the corresponding memory to authoritative previous_text, never attempted new_text.
  • The first complete outcome may rebase an older emerged snapshot across legacy audit history; later complete outcomes must form a coherent sequence chain.
  • An outcome with no provable emerged identity is excluded rather than attached by text similarity.
  • Partial outcomes, impossible sequence/outcome combinations, identity changes, and broken authoritative chains fail closed before provider dispatch.

Authority boundary

No cross-investigation lookup, embedding, graph retrieval, provider call, spend, schema migration, or merge/deploy authority. This cycle records and consumes a decision already made by the existing deterministic living-note rule.

Acceptance

  • Applied graph text and its outbox event commit together; injected failures prove rollback before commit and replay after commit.
  • Exact retry emits one physical event and increments refinement count once.
  • Higher sequence wins regardless of arrival; a later lower sequence is durably superseded and never enters prompt text.
  • Legacy events deserialize and remain ignored until a complete outcome rebases memory.
  • A later live wrestling prompt contains the authoritative applied text, excludes emerged/stale/losing text, and makes no additional provider call.
  • Ruff, generated contracts, focused and coupled tests, frontend typecheck/build, independent review, HardenX, and diff checks pass.

Harness hint

Attack pre-commit rollback, post-commit/pre-delivery failure, exact replay, same-sequence different-content collision, malformed partial authority, false applied/superseded sequence relations, origin substitution, legacy rebasing, future-event leakage, and losing text injection.
