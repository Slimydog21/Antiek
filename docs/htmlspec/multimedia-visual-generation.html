Submit and observe an authorized Krea visual

Child of multimedia-visual-authorization.html. This sprint makes the exact stored authority executable without making generation synchronous or retryable.

Submit

POST /multimedia/assets/{asset_id}/visual-generations accepts only authority request ID and expected current revision. The server reopens the owner-scoped MAC row, rechecks current asset/revision, rederives the exact Imagen request, verifies quote/V2 signatures, reserves the existing budget hold, durably marks sending, and performs at most one Krea POST through the fixed client. Exact replay returns durable execution state and never posts twice. Ambiguous transport fully charges and remains unknown.

Observe

POST /multimedia/assets/{asset_id}/visual-generations/{execution_id}/poll accepts expected revision only. The server loads the signed execution, verifies owner/asset/current revision, derives the bound provider job, performs one authenticated fixed-origin GET, and applies account-bound reconciliation. It does not loop or trust webhooks.

Safe projection

Responses contain execution ID, authorization request ID, provider job ID when bound, status, and integrity-verified candidate count. They omit prompts, request bytes/digests, result URLs, Krea token/account digest, quote/signatures, budget internals, recovery authority, and paths.

Non-goals

No automatic poll or retry, no stale-send retry, no artifact download/quarantine, attestation, aesthetic review, reviewed-set registration, rendering, publication, merge, or deploy.

Done bar

Tests prove owner/current authority reopening, one POST across replay/concurrency, ambiguity quarantine, no browser job/body terms, one poll per command, account-bound candidate creation, candidate-MAC count verification, safe responses, and all-or-nothing startup. Broad tests, lint, HardenX, and independent review pass.
