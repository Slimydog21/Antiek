Durable, owner-bound marketplace library

Make purchased and hosted books survive application restarts without weakening account isolation or HTML-native viewing.

1 sprintNo payment rails

Evidence-backed gap

The original marketplace sprints are implemented and 40 focused tests pass, but API routes resolve a module-global InMemoryHostStore. Production app creation cannot inject a durable store, and shared hosted-document routes reach the same global through a no-argument accessor. A restart can erase documents, memberships, and receipts.

today: create_app → global InMemoryHostStore → restart loses library
next: create_app(explicit store) → app.state owner-bound store → restart reopens SQLite

Invariants

  • Middleware identity remains the only owner authority; storage keys never come from an unverified account claim.
  • Marketplace and generic hosted-document routes use exactly the same app-scoped store.
  • Documents, memberships, and opaque receipt records persist across new app/store instances.
  • No card data, checkout, network call, model routing, or PDF viewing is added.
  • The default remains offline and non-spending; production durability requires explicit composition.
