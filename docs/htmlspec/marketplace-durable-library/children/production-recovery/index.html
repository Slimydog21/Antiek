Marketplace production activation and recovery

Turn the durable store from an injectable capability into a production and disaster-recovery guarantee.

Status: executing1 sprint · 1 waveOwner: primary orchestrator

Goal

Production uvicorn starts with a validated SQLite store at one explicit state path; nightly archives carry an online-consistent snapshot; disaster recovery restores and validates it before the service starts.

Success criteria

  • Systemd and application composition share ANTIEK_MARKETPLACE_HOST_DB_PATH.
  • An explicit invalid path fails startup without an in-memory fallback.
  • Backup round-trips documents, memberships, and receipts with mode 0600.
  • The recovery runbook stops the service, restores backward-compatibly, and verifies schema plus quick_check.

Failure mode to avoid

Reporting marketplace durability because SQLite exists in code while production writes to memory or R2 archives omit the database.

Context and architecture

MDL-SPR-01 added SQLiteHostStore and an explicit create_app(marketplace_host_store=...) seam. The deployed unit still imports interfaces.research.api.app:app, whose module-level app selected the in-memory default. The nightly backup exported DuckDB and copied append-only directories but did not include marketplace state.

systemd env
  -> module-level runtime composer
  -> create_app(explicit SQLiteHostStore)
  -> /home/antiek/.antiek/marketplace-host.sqlite3

nightly backup
  -> sqlite online backup API
  -> schema validation + PRAGMA quick_check
  -> marketplace-host.sqlite3 in R2 archive
  -> stopped-service restore + repeat validation

Key invariants

  • The factory itself never guesses environment or filesystem state.
  • Absence means local in-memory development; malformed presence means startup failure.
  • The live SQLite file is never copied byte-for-byte while writers may be active.
  • Restore overwrites state only after systemctl stop antiek.
