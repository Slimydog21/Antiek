Runtime activation, backup, and restore proof

Make the marketplace SQLite store an explicit production dependency and a verified recoverable asset.

Wave 1Status: executing5 milestonesOwner: primary orchestrator

Parent context

Antiek's marketplace can ingest licensed source bytes, project them to HTML, bind hosted documents to middleware-authenticated owners, and persist documents, memberships, and opaque receipts in SQLiteHostStore. Application tests prove those records survive fresh store and app instances.

That capability is not yet an operational guarantee. Production imports the module-level FastAPI app without passing the store, systemd does not name a marketplace path, and the R2 backup archive omits the SQLite database. This sprint closes all three seams without deploying, enabling payment rails, or changing owner authorization.

Position: Child of ANT-MDL after durable composition. It is the activation and recoverability closure, not a new marketplace feature.

Goal

One path contract controls production startup, online snapshotting, and stopped-service recovery.

Local development remains offline and in-memory when the variable is absent. Once production explicitly supplies it, initialization and validation are fail-closed. Every uploaded backup either contains a validated marketplace snapshot or clearly records that no database existed yet.

Technical milestones

1

Compose runtime store from explicit environment

Add a small runtime adapter that returns no store when the variable is absent or empty, constructs SQLiteHostStore for an absolute explicit path, and turns malformed configuration or database errors into startup failures.

Acceptance criteria
  • Factory injection remains explicit and environment-free.
  • Unset preserves the in-memory route default.
  • Relative or whitespace-padded explicit values fail.
  • Reopening the configured path recovers prior records.

interfaces/research/api/marketplace_host_runtime.py · interfaces/research/api/app.py

2

Declare the production path

Render ANTIEK_MARKETPLACE_HOST_DB_PATH={{ antiek_state_dir }}/marketplace-host.sqlite3 into the systemd unit beside the other state paths.

Acceptance criteria
  • The path is inside ReadWritePaths.
  • The existing one-worker topology is unchanged.
  • No secrets or feature gates are introduced.

infrastructure/ansible/templates/antiek.service.j2

3

Create a verified online snapshot primitive

Use sqlite3.Connection.backup from a read-only source connection into an exclusive mode-0600 destination. Reopen through SQLiteHostStore, run PRAGMA quick_check, and delete partial output on failure.

Acceptance criteria
  • Documents, memberships, and receipts round-trip.
  • Existing destinations are never overwritten.
  • A missing source cannot create an empty success artifact.
  • The CLI delegates to the same tested primitive.

substrate/marketplace_host/library.py · substrate/marketplace_host/__init__.py · tools/backup_marketplace_sqlite.py

4

Include marketplace state in nightly R2 archives

Invoke the snapshot CLI as the Antiek user after DuckDB export. Skip only when the source database does not yet exist; any snapshot or validation failure aborts the backup before upload.

Acceptance criteria
  • The destination is inside the timestamped staging directory.
  • Shell quoting preserves state and install paths.
  • set -euo pipefail makes validation failure fatal.

infrastructure/ansible/templates/backup.sh.j2

5

Document a backward-compatible stopped restore

Stop the service before replacement, restore the file with owner/group and mode 0600 when present, support historical archives without it, and validate schema plus integrity before restart.

Acceptance criteria
  • The runbook names marketplace state as recoverable.
  • Old archives are explicitly supported.
  • No live database is overwritten.
  • Verification commands are copy-pasteable and precede systemctl start.

infrastructure/runbooks/disaster-recovery.md · docs/decisions/marketplace-production-durability.md

Rigor: operating manual

1 · Intellectual honestyDo not equate a green SQLite unit test with production durability. Prove the module-level app consumes the environment adapter and the rendered backup template calls the verified snapshot CLI. If the Ansible template is not executed against a live VM, report that as unverified deployment, not as completion.
2 · FairnessSteelman raw file copy: it is simpler and is valid when the service is fully stopped. Reject it here only because the nightly job intentionally runs online; preserve file-copy restore because the archived snapshot is already consistent.
3 · RigorExercise missing source, existing destination, permissions, schema validation, quick-check, restart persistence, and malformed environment paths. A test that only asserts the file exists does not cover recoverability.
4 · DiligenceRead the systemd sandbox, backup privilege boundary, current DuckDB normalization, and full disaster-recovery order before editing. Preserve workers=1 and the existing R2 retention flow.
5 · DefensibilityRecord why absence is a development default while malformed presence is fatal, why online backup replaces live copy, and what would trigger migration into DuckDB or Postgres. Keep those reasons in the decision record, not only chat.
