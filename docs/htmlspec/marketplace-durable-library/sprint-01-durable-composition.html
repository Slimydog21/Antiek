Marketplace durable library · MDL-SPR-01

Durable store and explicit API composition

Status: implemented offline · owner: primary Codex orchestrator

Milestones

1. Closed durable schema.

Add a SQLite-backed HostStore for JSON documents, owner memberships, and manual receipt records.

Schema initialization is idempotent; writes are transactional; rows round-trip as defensive copies; duplicate membership is idempotent.
2. App-scoped dependency.

Allow route registration and create_app to receive one explicit HostStore; place it on app state and resolve it from the authenticated request.

Marketplace and hosted-document routes share the injected object. No request can select or replace the store.
3. Restart proof.

Host a public-domain and a purchased HTML book through one app, construct a fresh store and app against the same database, then read the owner library and HTML.

Document IDs, membership, receipt authorization, and projection receipts survive. A second owner cannot list or open them.
4. Failure and default proof.

Reject malformed persisted JSON as storage failure and retain the in-memory default for networkless local/test composition.

No silent fallback from an explicitly supplied durable store. No payment/provider call exists in the diff.

Rigor

Intellectual honesty: this makes account libraries durable; it does not add checkout, DRM access, or vendor download automation.

Fairness: a file-per-record store is simpler, but SQLite gives transactional concurrency and closed schema checks without a new dependency.

Rigor: tests must construct fresh app and store objects, not merely re-read through one in-memory instance.

Diligence: preserve existing ingest crash recovery, canonical document IDs, owner authorization ordering, and HTML projection acknowledgement.

Defensibility: storage composition is explicit and inspectable; production never guesses a path or silently downgrades to memory.
