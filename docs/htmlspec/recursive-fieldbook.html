Recursive Fieldbook

An authored notebook detail surface where operator prose and substrate references remain distinguishable, mutations remain exact, and no visual treatment implies automatic twin or graph intelligence.

Status: executableOwner: Codex Infinite1 inline sprint · 7 milestonesBase: PR #2749 @ 4c6338ba4

Spec lineage

Root cycle spec derived from the full Antiek reading/research/writing and branding/UI mandate plus a live audit of canonical /notebook/:notebookId. No child specs: route state, mutation serialization, canvas semantics, keyboard controls, stories, CSS, tests, and decorative asset share one authority seam.

    Egghead verdict

    Proceed, with high confidence, only as an honest fieldbook—not as a fake recursive-note engine. The strongest counterargument is that styling a notebook can conceal the missing automation the north star actually demands. The surviving intervention improves the existing literate-analysis instrument: it clarifies which blocks are prose, live references, cached excerpts, tombstones, or unknown; it does not claim to generate twins, resolve deleted references, or edit the knowledge graph.

    What would reverse this decision: a canonical notebook API that already exposes twin-generation status and resolved graph entities. It does not on this head.

    Goal and catastrophic failure mode

    Let the operator read, append, edit, reorder, delete, and export an ordered notebook without raw errors, stale route data, overlapping mutations, pointer-only controls, or ambiguous provenance.

    Failure mode: an attractive page that loses a successful mutation to a stale response, labels cached reference text as live truth, makes destructive controls unreachable by keyboard, or implies an LLM twin was generated when only caller-supplied blocks exist.

    Authority topology

    route notebook id ─ GET /notebooks/:id ─ required notebook projection │ operator append ─ POST /blocks ───────────────┤ operator edit ─ PATCH /blocks/:block ─────────┤── serialized mutation lane ─ latest server notebook operator delete ─ DELETE /blocks/:block ──────┤ operator move ─ POST /blocks/reorder ─────────┘ ArtifactExport ─ existing export authority (unchanged) analytics ─ existing append/delete event names (unchanged) raster ─ decorative environment only; zero notebook semantics
    • A route sequence suppresses late GET results after navigation or unmount.
    • One mutation queue/single-flight contract prevents overlapping snapshots from overwriting newer notebook state.
    • Every mutation failure uses fixed safe copy; the last confirmed notebook remains rendered.
    • References are visibly identified by type and reference ID; cached text is never called resolved/live.
    • Stories inject a notebook and executionEnabled=false; no transport is possible.

    Technical milestones

    1 · Freeze the projection seam

    Add typed fixture props for notebook, loading, safe failure, and execution lock. Validate the required response shape before rendering it.

    2 · Suppress stale route loads

    Sequence required GETs across notebook ID changes and unmount. A late prior route may not replace the current notebook.

    3 · Serialize mutations

    Give append/edit/delete/reorder one explicit mutation lane. Disable affected controls while the server snapshot is pending; preserve exact API helpers and analytics names.

    4 · Author semantic block grammar

    Make prose, claims, notes, questions, regions, cross-document links, chats, equations, images, tombstones, and unknown types visually distinct without claiming reference resolution.

    5 · Complete keyboard authority

    Replace hover-only discovery with focus-within visibility and explicit accessible labels. Editing, moving, deleting, cancelling, and adding blocks remain reachable by keyboard.

    6 · Author fieldbook atmosphere

    Use the ChatGPT Image environment as pointer-inert, empty atmosphere. All content, labels, statuses, controls, and provenance remain HTML/CSS.

    7 · Prove the state matrix

    Add deterministic missing-ID, loading, safe-failure, empty, populated, mutating, night, and 375px narrow stories plus route/mutation/a11y tests.

    Rigor — sprint-specific operating manual

    1 · HonestyCached text is not resolved truth.

    Claim, note, region, and question blocks must label their reference ID and cached/display text without saying the entity is current. A null reference renders a tombstone; it never disappears and never becomes an empty prose block.

    2 · FairnessDo not privilege generated-looking blocks over operator prose.

    Prose, questions, and references receive equal readable hierarchy; color distinguishes type rather than epistemic quality. Steelman leaving the plain canvas: reject it for raw errors and inaccessible controls, not because ornament is inherently better.

    3 · RigorAttack response ordering.

    Tests must settle GETs and mutations out of order, double-activate controls, reject each action, and prove exact helper arguments. A happy-path block render count is insufficient evidence.

    4 · DiligenceRead both notebook paths before changing one.

    Inspect Notebook/Editor.tsx, API helper payloads, backend response models, ArtifactExport, and index-conservatory decisions. Do not replace the editor or create a second notebook client.

    5 · DefensibilityKeep every authority reconstructable.

    The spec, tests, safe copy, provenance README, and block labels must explain why this fieldbook mutates ordered notebook blocks but does not generate twins, resolve the graph, or change export authority.
