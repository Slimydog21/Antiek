Bind reviewed visuals without trusting browser-supplied media authority

Stacked on PR #1265. This sprint supplies the missing owner/revision-bound visual input authority required by the educational-video production worker. It does not generate imagery or render video.

Problem

produce_educational_video correctly requires ReviewedVisualSelection rows containing local paths, expected digests, disclosure labels, source grounding, and generated-artifact or rights evidence. None of those fields may cross the browser trust boundary, and the current asset lifecycle has no durable reviewed set for a production worker to resolve.

Authority split

The operator controls an idempotency request ID, expected current revision, and exactly one opaque candidate ID for each spoken chapter. The server controls owner identity, canonical chapter and scene order, candidate existence, local path, expected digest, disclosure label, source chunk grounding, generation receipts or rights decision, and registry integrity key.

Substrate contract

A trusted VisualCandidateResolver maps (asset record, chapter ID, candidate ID) to a complete ReviewedVisualSelection. The service requires a ready non-audio non-cheapest current asset, derives scene-{chapter_id} in spoken chapter order, requires exact chapter coverage and unique candidate IDs, and rejects any resolver row whose scene ID or source chunks conflict with the persisted plan. It snapshots each regular non-symlink file digest and requires it to equal the resolver digest before writing.

ReviewedVisualRegistry persists one canonical JSON payload and HMAC per owner identity digest, asset, revision, and request ID under a cross-process DuckDB write lock. Exact request replay returns the same receipt. Reusing the request ID with changed candidate bindings conflicts. A second request producing the identical set may return the existing set; a different set for the same asset revision conflicts rather than silently replacing reviewed authority.

Read contract

The production worker resolves a set with owner identity digest, asset ID, and revision ID and receives the exact ReviewedVisualSelection tuple. Registry reopening revalidates HMAC, canonical ordering, payload shape, and current file digests. This is not final evidence approval: compile_visual_selection_packet must still copy bytes and call the trusted evidence authority immediately before rendering.

HTTP contract

POST /multimedia/assets/{asset_id}/reviewed-visuals accepts request ID, expected revision, and chapter/candidate bindings only. The response returns set ID, asset/revision, ordered chapter/scene IDs, candidate IDs, selection digest, and creation time. It never returns local paths, file digests, execution/artifact receipt IDs, source locator digests, rights decision IDs, evidence MACs, keys, or candidate resolver internals. GET returns the same safe projection or an opaque 404.

Races and recovery

Owner-scoped asset state is checked before resolution and rechecked immediately before registry persistence. Steering during candidate resolution causes a stale-revision conflict. Registry insertion and idempotency receipt are one transaction. A crash before commit writes nothing; a retry after commit exactly replays. File drift after review makes read/reopen fail closed and cannot reach the renderer.

Product contract

The plan review reads the owner/current-revision reviewed-set status and displays only reviewed-set identity and scene count, never candidate IDs, local paths, evidence internals, or the claims “generated,” “rendered,” “produced,” or “playable.” Candidate choice remains an upstream server-catalog workflow until a safe candidate-list contract is specified; this sprint does not invent a browser filesystem picker or require operators to understand opaque IDs.

Non-goals

No Krea/provider call, upload endpoint, arbitrary local path, narration execution, budget claim, visual packet compile, FFmpeg render, educational-video receipt, production registration, playback mutation, publication, merge, or deploy.

Acceptance

  • HTTP cannot express a path, digest, label, grounding, or evidence receipt.
  • Foreign, stale, unready, audio-only, cheapest, incomplete, duplicate, unknown, scene-drifted, grounding-drifted, symlinked, oversized, or digest-drifted candidates fail before persistence.
  • Exact replay is stable and changed idempotency terms conflict.
  • A revision race between resolution and persistence fails closed.
  • Safe response projection contains no local or evidence authority details.
  • Stored selection reopening detects database and file tampering.
  • Focused and broad tests, typecheck/build, HTML parse, Ruff, HardenX zero real findings, and independent review evidence complete the sprint.
