Cycle 36 / Cycle 37

Bedrock live guard journal

Persist immutable acquisition intent and completion facts with exact recovery inspection and no authority replay.

Status: executableSQLite authorityProduction refused

Spec lineage

Cycle 36 defines an injected append-only journal protocol. Cycle 37 implements that protocol as a private SQLite authority and adds bounded inspection. It does not add AWS credentials, live adapters, scheduling, or production eligibility.

  • A future child may bind deployed workload identity and attestor endpoints only after this journal and the Cycle 36 coordinator pass process-kill and independent-account exercises.

Verdict

Incomplete is evidence, not authority. A command and attempt may exist without a completion after a crash. Inspection reports that state as in_progress; it neither deletes the attempt nor promotes it. Recovery must call Cycle 36 again, which reacquires all external evidence.

Storage model

TableImmutable facts
commandsOne command ID binds exact canonical command JSON and recomputed digest. Same ID or digest with different bytes fails.
attemptsOne attempt ID binds its command ID/digest, exact canonical attempt JSON, attempt digest, nonce, and trusted start. It has a foreign key to the exact command.
completionsOne attempt ID binds exact canonical acquisition receipt JSON and receipt digest. It is inserted only; attempts are never updated to look complete.

Every table has database triggers rejecting update and delete. Foreign keys are enabled on every connection. Schema shape, indexes, triggers, and SQLite integrity are verified before authority reads.

Filesystem

  • The configured root must be an absolute, owner-controlled, mode-0700 regular directory without symlink traversal.
  • The database is created with exclusive mode 0600, opened without following symlinks, and must remain one owner-controlled regular link with the same device/inode across descriptor and SQLite open.
  • SQLite uses rollback-journal mode, synchronous=FULL, foreign keys, disabled trusted schema, and a bounded busy timeout. Lock failures are controlled storage errors, never partial success.
  • No caller-controlled path, SQL, pragma, migration, or cleanup operation exists.

Protocol

  1. record_intent strictly parses command and attempt JSON, recomputes IDs/digests, checks their cross-binding, then atomically inserts or exactly reopens both under BEGIN IMMEDIATE.
  2. commit_attempt strictly parses the receipt, reopens and validates the exact command/attempt chain, then inserts or exactly reopens one completion in a separate transaction.
  3. read_attempt returns null only when the exact attempt exists without a completion. Missing, malformed, conflicting, or corrupt authority fails.
  4. inspect_attempt and bounded list_attempts return canonical derived status with exact IDs/digests and all production capability booleans false.
  5. verify_all runs SQLite integrity and foreign-key checks, verifies schema/triggers/indexes, then decodes and recomputes every command, attempt, completion, scalar, relationship, and count.
  6. Injected failure checkpoints prove rollback after each insert and before commit. A post-commit error intentionally leaves durable exact bytes for Cycle 36 readback reconciliation.

Acceptance

  1. Exact intent and completion are idempotent across process reopen; changed bytes under any reused identity fail.
  2. Command plus attempt insert atomically. Failure after either insert or before commit leaves neither new row.
  3. Completion failure before commit leaves an inspectable in-progress attempt. Failure after commit leaves one exact completed receipt recoverable by readback.
  4. Missing command, mismatched command/attempt/receipt digests, malformed JSON, scalar drift, foreign-key break, trigger/schema/index removal, SQLite corruption, unsafe root/file mode, symlink, hard link, replacement race, and lock timeout fail closed.
  5. Update and delete fail at the database layer for all three tables. There is no abandon, cleanup, overwrite, migration, or stale-authority replay API.
  6. Inspection is bounded, deterministic, ordered, and distinguishes in-progress from completed without claiming whether an in-progress process is alive.
  7. No SDK, credentials, external call, signer, policy mutation, scheduler, worker, route, provider dispatch, spend, settlement, release, event, graph write, UI, or production authority is added.

Five Values

  • Truth: completion is a separate immutable fact; absence stays absence.
  • Care: operators can inspect crash residue without deleting forensic history.
  • Agency: storage root, timeout, and failure hook are explicit injection points.
  • Craft: canonical bytes, scalar redundancy, triggers, exact schema, full traversal, and rollback injection make persistence hard to vary.
  • Restraint: the journal cannot reacquire evidence or grant production authority.

Out of scope

No migration from an earlier journal because none exists; no retention/GC, process liveness lease, distributed database, remote backup, encryption key management, IAM/STS, Organizations adapter, attestor deployment, daemon, production route, billing settlement, or UI.
