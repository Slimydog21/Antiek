Grounded Companion Answer Contract

Status: executable Cycle 62 spec. Parent: Cycle 61 execution qualification.

Outcome

Define the only artifact Antiek may display as a companion answer and persist it idempotently behind a default-deny internal receipt-verification port. No public answer-write endpoint and no provider dispatch are added. A future qualified executor must target this contract rather than inventing provider-shaped answer storage.

Answer shape

An answer is a deterministic ordered list of at most 64 claims. Each claim has a deterministic claim ID, bounded plain text, and zero or more citation IDs from the exact immutable evidence pack. Server code renders escaped semantic HTML from the claims; provider HTML is never accepted. Claims with no citation are retained only as explicitly disclosed unsupported claims. Unknown, duplicate, or cross-pack citations are rejected.

BindingRequired authority
TurnExact owner-scoped stored turn ID and evidence-pack hash.
ExecutionVerified receipt ID/digest, settled status, provider, model, evidence-pack hash, and answer-output digest.
ArtifactSchema version, answer ID, canonical claims JSON/hash, rendered HTML/hash, cited IDs, unsupported count, provider/model, receipt identity, and admitted timestamp.

Default deny

  • The repository constructor has no verifier by default. Calling answer admission without one raises before any write.
  • The verifier receives the exact expected turn/evidence/output bindings and must return a frozen verified receipt with matching values and settled status.
  • A verifier exception, mismatch, unknown receipt, unsettled receipt, malformed candidate, or evidence-integrity conflict writes nothing.
  • This cycle adds no HTTP POST for answers, no environment-selected verifier, no spend-ledger mutation, and no model call.

Durable lifecycle

  • First valid admission inserts one immutable answer row and marks only its cited turn-citation rows used_in_answer=true in the same transaction.
  • Exact command replay returns the stored artifact with replayed=true. Reusing an admission key or receipt identity with changed intent is a conflict.
  • Conversation and evidence replay return the admitted answer when present. Qualification remains a separate current-time projection.
  • Answer rows cannot update or delete through repository code. Historical revision answers remain bound to their original revision.

Read projection

The public answer projection contains server-rendered inert HTML, claim records, cited IDs, unsupported claim count, provider/model, and answer digest. It omits owner ID, admission key, raw receipt, internal request digest, filesystem paths, credentials, prices, and provider evidence. The reader renders admitted structured claims as React text instead of injecting stored HTML, links exact citations, and labels unsupported claims; absence remains honest evidence-only mode.

Acceptance evidence

  • Validator tests cover empty/oversized claims, unknown/duplicate citations, escaped HTML, deterministic IDs/hashes, receipt-binding conflicts, and explicit unsupported claims.
  • Repository tests cover default deny, verified admission, exact replay after verifier removal, changed replay, wrong owner, atomic citation flags, and durable reopen through the API repository.
  • API/read tests prove no answer-write route exists, admitted answers hydrate in evidence replay and current conversation, no internal receipt fields leak, and evidence-only behavior is unchanged.
  • Frontend tests prove structured claims render without injecting stored HTML, unsupported count is visible, exact citation controls remain available, and no answer-generation control appears.

Non-goals and next seam

No provider adapter, qualification promotion, numeric quote, budget approval, reservation, settlement, retry, reconciliation, model call, public write route, merge, or deployment. Cycle 63 may implement a receipt verifier only by consuming an existing settled ResearchSpendLedger hold and exact provider gateway evidence.

Harness hint

Use one refuter for forged receipts/idempotency races and one for XSS, cross-revision citations, partial writes, and read-side leakage.
