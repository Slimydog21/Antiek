Bind verified production to the owner asset lifecycle

Stacked on PR #1239. Production primitives can issue a composite educational-video receipt, but the account-scoped asset store does not record that production and playback previously discovered orphan receipt files by deterministic name. This sprint creates the durable handoff without introducing an API spend path.

Five values

  1. Owner is one fact: authenticated account, account envelope, asset owner digest, and production link owner digest agree.
  2. Receipt is authority: every link field is derived from a complete composite/nested-authority reopen; callers provide only asset and expected revision.
  3. Current revision only: stale or steered revisions cannot register or play.
  4. Replay repairs: a receipt may exist before the asset link after a crash; exact registration replay attaches or returns the same link without regenerating media or spending.
  5. Orphans do not play: deterministic receipt existence alone is insufficient after this sprint.

Production link

MultimediaProductionLink stores schema version, owner digest, asset/revision, canonical receipt JSON SHA-256, video and narration SHA-256, duration, dimensions, and ordered chapter IDs. It stores no filesystem path, key, provider credential, or caller assertion.

Registration flow

  1. Authenticate owner and load the owner-scoped current ready video asset.
  2. Require an exact expected revision.
  3. Resolve the canonical receipt path under the configured private root and reopen receipt, narration, visual, render, and media authorities.
  4. Derive the production link from verified metadata.
  5. Atomically compare-and-set the link in the account asset envelope. Exact replay returns existing state; conflict never overwrites.

Playback binding

Metadata and media routes first require a production link for the authenticated current revision. Every reopened receipt response is compared with the link's receipt/media digests and media facts before bytes are returned. Stream handles close before any conflict response. Steering clears the previous production link.

Failure model

Foreign owner, stale revision, unready or audio-only asset, missing/tampered receipt, wrong nested key, link identity mismatch, receipt/media digest drift, duration/dimension/chapter drift, conflicting replay, or late frontend response fails closed. Registration errors expose no receipt path or key.

Non-goals

No provider call, authorization issuance or consumption, TTS, visual generation, FFmpeg execution, receipt issuance, automatic worker, publication, merge, or deploy. The next worker-orchestration sprint must consume existing signed provider authorities and call this registration boundary only after successful receipt issuance.

Acceptance

  • Exact verified link attaches and replays.
  • Crash-created orphan receipt can be linked but cannot play before linking.
  • Foreign/stale/unready/audio/conflicting cases fail without mutation.
  • Playback rejects absent or drifted links.
  • Frontend explicitly checks for an existing produced receipt and rejects stale responses.
  • Focused/broad tests, typecheck/build, Ruff, HTML parse, HardenX zero real findings, and independent acceptance pass.
