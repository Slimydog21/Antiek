Werner thought-partner reply beat

Cold-executable contract for the workstation's shared AI sidecar.

Product truth

  • Emit exactly one thought_partner_reply_received only after a 2xx response is decoded and parsed into the visible reply.
  • Map the event to Werner's existing authored happy pose. The pending state already owns thinking.
  • HTTP errors, JSON failure, request failure, stale ownership, and unmount emit nothing. A local CHALLENGE error reply is not an assistant reply.
  • Emit before structured action dispatch. A later action-triggered experience may legitimately supersede happy, and action failure cannot erase a visible reply's earned beat.
  • The assistant cannot close the canonical AI sidecar from its own reply. Other actions are isolated so one dispatch failure cannot erase the reply or suppress later valid actions.
  • Snapshot prompt and composed context before dispatch so action audit attribution cannot drift while the response is pending.

Collision policy

This interaction is independent of deep_research_complete. Both may map to happy; latest-wins yields one visible acknowledgment. SpokenReply is downstream and currently owns no Werner playback signal.
