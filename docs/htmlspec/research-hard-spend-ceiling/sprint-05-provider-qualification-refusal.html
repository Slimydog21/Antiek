ANT-RHC / sprint 05

Provider qualification refusal gate

Convert current primary-source provider evidence into a machine-checkable refusal and prevent a future boolean flip from overstating hard-ceiling eligibility.

Owner: provider-contract agentWave 45 milestonesStatus: executableDepends: SPR-03

Parent context

SPR-01 through SPR-04 shipped a fail-closed projector, durable spend ledger, one-send provider gateway, and operator evidence surface. Production hard mode currently performs only manually planned, zero-cost contract gather; Exa, automatic decomposition, and paid synthesis are refused.

This sprint does not force a provider through the gateway. It qualifies Exa Agent, Tavily Research, Perplexity Agent, and OpenAI Responses against the exact crash-recovery contract. Current documentation gives each route useful pricing or cost evidence, but no route closes the lost-create-response identity gap.

Decisive trace: provider accepts and bills POST, response with provider ID is lost, recovery has only Antiek's key, provider retrieval requires its own unknown ID. Retrying may double-charge and releasing may hide spend.

Goal

Ship an auditable provider qualification registry and make checked-in paid eligibility structurally depend on an exact fully passing record.

The deliverable is successful when all evaluated routes remain refused for named evidence gaps, the cost catalog cannot claim all three runtime capabilities without five passing evidence dimensions, and a future agent has a precise reversal procedure.

Technical milestones

  1. Record the five-dimensional primary-source matrix. Add exact provider/model/operation keys, check date, verdict, source URL, status, and finding for pricing, idempotency, retry control, reconciliation, and stable evidence. Acceptance: no blog, search-result page, or model memory is an authority. Files: runtime/research_runner/provider_qualification.json.
  2. Parse a closed schema. Implement typed enums and immutable records; reject missing/extra dimensions, duplicate routes, malformed evidence, non-HTTPS sources, and a qualified verdict containing any non-pass. Files: runtime/research_runner/provider_qualification.py.
  3. Gate paid catalog capability claims. At server catalog construction, reject any paid route with all three runtime capability booleans true unless the exact provider/model/operation has a fully passing qualification. Keep custom unit-test projectors independent. Acceptance: startup fails before a route can project as hold-eligible from an unsupported claim. Files: runtime/research_runner/cost_projection.py.
  4. Prove refusal and reversal. Test the checked-in four-provider refusal, exact route matching, refused/unproven rejection, valid all-pass acceptance, and malformed registry failures. Files: tests/test_research_provider_qualification.py.
  5. Preserve the decision. Write an ADR with the exact failure trace, strongest callback/metadata counterargument, primary contracts, and reversal conditions. Update this master spec and handoff with commands and evidence. Files: docs/decisions/research-hard-ceiling-provider-qualification.md, this spec tree.

Five-values rigor

Intellectual honesty

unproven means the official contract did not establish the guarantee; it does not claim the provider can never offer it. Record partial strengths such as exact returned cost without rounding them up to end-to-end reconciliation.

Fairness

Steelman background callbacks, caller metadata, per-operation API keys, and aggregate usage deltas. Reject them only at the precise crash window they leave open, and keep every candidate available in stop-limit mode.

Rigor

Mutation-test the meaningful boundary: a catalog entry with all three capability booleans must fail without an exact all-pass registry route, and pass only with one. A JSON file that tests only its own current contents is insufficient.

Diligence

Read the create, retrieve, pricing, usage, and retry contracts separately. Provider-generated IDs returned after POST are not caller-supplied idempotency keys; support tracing is not deduplication; aggregate billing is not per-operation not-found proof.

Defensibility

The ADR and registry must let a future maintainer reproduce every verdict from a direct primary URL, identify exactly what would reverse it, and update one closed schema without reconstructing this session.

Dependencies

  • origin/main includes ANT-RHC SPR-01 through SPR-04 and ResearchProviderGateway.
  • Primary provider contracts are current as of 2026-07-13; browsing is mandatory on future refreshes.
  • No provider credential or live billable call is required; this sprint evaluates contracts and fail-closed code.

Out of scope

  • No paid provider adapter, live smoke spend, provider-account mutation, or hard-mode eligibility flip.
  • No weakening of durable idempotency, authoritative not-found, one-send transport, or full-hold unknown semantics.
  • No claim that stop limits are unsafe or unusable; they remain the correct contract for these routes.
  • No multimedia provider routing changes, automatic decomposition, paid synthesis, or model-router work.

Execution hint

One owner edits the registry, parser, gate, tests, and ADR. An independent critic tries to qualify a route through callbacks, metadata, aggregate billing, or per-key isolation. Merge only if the critic either supplies a complete provider contract or upholds refusal.
