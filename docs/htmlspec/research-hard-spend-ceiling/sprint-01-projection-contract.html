ANT-RHC / sprint 01

Conservative projection contract

Owner: pricing/projection agentWave 15 milestonesStatus: proposed

Parent context

Research currently records provider-reported cost after a step. That supports honest accounting and stop-limit behavior, but cannot enforce a hard ceiling. This sprint supplies the conservative maximum that a later atomic hold reserves before dispatch.

The contract is eligibility-sensitive: if the selected provider/model or reachable tool path cannot be bounded, it must return an explicit ineligible result. It must never manufacture a price merely to keep the hard-ceiling option available.

Goal

Implement one server-owned projection interface that returns an integer-cent conservative maximum plus complete assumptions and provenance for every billable cascade dispatch, or fails closed with a typed reason.

Technical milestones

  1. Inventory dispatches. Trace every cascade path that can incur provider cost from runtime/research_runner into dispatch/provider adapters. Acceptance: a checked-in exhaustive table/test maps every paid seam to an adapter or typed ineligibility. Files: runtime/research_runner/cost_projection.py, tests/test_research_cost_projection.py.
  2. Define immutable types. Add request/result types carrying provider, model, operation, bounded units, rate snapshot/version, USD currency, rounded reservation cents, and ineligibility reason. Acceptance: invalid/missing fields cannot construct an eligible result. Files: runtime/research_runner/protocol.py, runtime/research_runner/cost_projection.py.
  3. Resolve pricing and capabilities server-side. Pin exact provider/model fallback before projection; require durable provider idempotency/reconciliation and disabled SDK retries for hard mode. Acceptance: client rates and providers lacking either capability are rejected. Files: runtime/research_runner/cost_projection.py, interfaces/research/api/settings_budget.py.
  4. Compute conservatively. Use decimal arithmetic, explicit upper bounds, overflow checks, and upward cent rounding. Zero-cost/local models return a zero-cost receipt classification, not a ledger hold. Acceptance: paid missing/zero pricing, unbounded output, NaN, negative, stale catalog, or non-USD billing is ineligible. Files: runtime/research_runner/cost_projection.py, tests/test_research_cost_projection.py.
  5. Prove monotonicity and coverage. Acceptance: property tests show larger bounded usage never lowers reservation; unknown variants fail closed; fallback or currency changes invalidate the projection. Files: tests/test_research_cost_projection.py.

Five-values rigor

Intellectual honesty

Return “hard ceiling unavailable” when a provider's maximum cannot be defended. A high percentile, average, or observed historical maximum is not a contractual bound.

Fairness

Steelman provider-specific projection inside each adapter before forcing one token formula across image, search, or language calls. Shared types must not erase materially different billing units.

Rigor

Use exact decimal fixtures from real configured rate shapes and assert upward rounding at sub-cent boundaries. Require an exhaustive dispatcher inventory test so new paid seams cannot silently bypass projection.

Diligence

Trace fallback routing, retries, tools, cached/free calls, and zero-priced local paths. Record every assumption in the projection receipt so downstream disputes are diagnosable.

Defensibility

The handoff must show why each value is a maximum, cite the owning config field or provider contract, and list any providers deliberately excluded from hard mode.

Dependencies

No code dependency on another sprint. Read the current model decision advisory and Midnight Oil ledger projection call sites. No provider secret or live billable call is required.

Out of scope

No ledger mutation, provider dispatch, UI, plan approval, benchmarking, dynamic learned routing, multimedia projection rewrite, or claim that estimation itself enforces the ceiling.
