ANT-RHC / sprint 03

Provider-bound dispatch and recovery

Owner: runner integration agentWave 26 milestonesStatus: proposedDepends: SPR-01, SPR-02

Parent context

SPR-01 supplies conservative provider/model-specific maxima; SPR-02 supplies durable atomic holds. This sprint joins them at the only boundary that matters: immediately before a billable provider request can leave Antiek.

The integration must distinguish failures before send from ambiguous failures after send. A timeout after request bytes may have left Antiek cannot safely be retried or released without provider reconciliation.

Goal

Make every cascade provider dispatch execute as project -> reserve -> mark sending -> send at most once -> settle/release/unknown, with deterministic recovery after process failure or lost responses.

Technical milestones

  1. Bind run authority. Create/reopen a USD-only run bound to owner, deterministic session/root, exact plan digest, mode, and ceiling. Acceptance: plan/model/currency edits revoke approval and cannot reuse the run. Files: interfaces/research/api/cascade_routes.py, runtime/research_runner/protocol.py, tests/test_cascade_api.py.
  2. Centralize dispatch. Route every inventoried call through one gateway: paid calls project/reserve before network work, while eligible free/local calls prepare and complete/fail the ledger's zero-cost attempt receipt. Acceptance: no direct paid client or unreceipted zero-cost call is reachable in hard mode; replay resumes a prepared local attempt without false completion. Files: runtime/research_runner/provider_gateway.py, adapters listed in runtime/research_runner/dispatch_inventory.json, tests/test_research_provider_gateway.py.
  3. Require safe provider capability. Hard mode requires durable provider idempotency plus status/billing reconciliation; adapter and SDK retries are disabled. Acceptance: unsupported providers are ineligible and one hold can cause at most one billable provider operation. Files: runtime/research_runner/provider_gateway.py, adapters in dispatch_inventory.json, tests/test_research_cost_projection.py.
  4. Persist send intent. Before I/O, bind hold, provider idempotency identity, operation digest, and sending. Acceptance: timeout never becomes “not sent,” and replay never issues a blind second operation. Files: runtime/research_runner/provider_gateway.py, tests/test_research_provider_gateway.py.
  5. Reconcile outcomes. Success settles verified actual; definite pre-send failure releases; ambiguity keeps full hold. Per-operation actual above projected hold records observed excess while authorized accounting remains bounded, freezes the run as ceiling_breached, and alerts. Acceptance: authorization and observed billing remain separately complete. Files: runtime/research_runner/provider_gateway.py, substrate/research_spend/ledger.py, tests/test_research_provider_gateway.py.
  6. Recover and close execution deterministically. Restart releases/resumes only a provably unsent reserved hold; sending/unknown queries provider by durable identity. Cancellation forbids new dispatch. closed_unresolved permits evidence-only reconciliation and advances to closed_reconciled after all holds resolve. Preserve stop-limit mode for unsupported providers. Acceptance: every durable state has one documented action and both modes remain distinct. Files: runtime/research_runner/host_local.py, interfaces/research/api/cascade_routes.py, tests/test_research_provider_gateway.py.

Five-values rigor

Intellectual honesty

Classify network exceptions by evidence, not convenience. If the system cannot prove bytes were not accepted, retain the hold and surface outcome unknown.

Fairness

Support provider idempotency/reconciliation capabilities through adapters; do not impose retry behavior that is safe for one provider onto another that lacks equivalent authority.

Rigor

Inject process termination at every boundary around reserve, send marker, provider return, and settlement. Assert call count, durable state, and ledger invariant after restart.

Diligence

Audit every route to provider work, including fallback, tool loops, retries, and queued semaphore workers. No reachable billable path may call a client directly in hard mode.

Defensibility

Produce a sequence diagram and failure matrix mapping each interruption point to allowed replay behavior. Include provider evidence required to resolve an unknown hold.

Dependencies

SPR-01 projection contract and SPR-02 ledger adapter must be merged and independently reviewed. Provider test doubles must expose call counts, idempotency identity, injected ambiguous errors, and reconciliation.

Out of scope

No broad provider-router rewrite, learned routing, multimedia migration, automatic forgiveness of unknown spend, UI redesign, or promise that upstream provider billing errors are impossible.
