ANT-RHC / sprint 04

Operator approval and execution evidence

Owner: API/UI evidence agentWave 36 milestonesStatus: proposedDepends: SPR-03

Parent context

The backend can now enforce a hard ceiling on provider spend Antiek authorizes when every paid dispatch is projectable, idempotent, and reconcilable. Operators still need to understand what they are approving, why hard mode may be unavailable, how much is authorized, observed, or held, and what to do when a provider outcome is unknown.

The current cascade surface already has explicit stop-limit input and approval. This sprint evolves it without rewriting the workstation or weakening the truthful stop-limit path.

Goal

Expose server-owned hard-ceiling eligibility, explicit mode approval, live integer-cent balances, and stage-aware recovery, then prove end to end that concurrent provider work never exceeds approved spend plus holds.

Technical milestones

  1. Extend safe API projections. Expose eligibility, assumptions, USD currency, authorized/observed/held/available balances, run state, and opaque unknown count. Acceptance: provider secrets and client-authored rates never cross the API. Files: interfaces/research/api/cascade_routes.py, apps/reading/src/api/research.ts, tests/test_cascade_api.py.
  2. Require explicit mode approval. Use a segmented control for hard authorized-spend ceiling versus stop limit. Acceptance: hard mode is disabled for any unbounded, non-idempotent, non-reconcilable, or non-USD path; consent binds exact plan/model/mode/amount. Files: apps/reading/src/modes/ResearchWorkstation/CascadeProposal.tsx, apps/reading/src/api/research.ts, apps/reading/src/modes/ResearchWorkstation/CascadeProposal.test.tsx.
  3. Invalidate stale consent. Any plan/model/fallback/provider/currency/ceiling mutation revokes approval synchronously. Acceptance: stale launch conflicts and reloads authoritative state. Files: apps/reading/src/modes/ResearchWorkstation/CascadeProposal.tsx, interfaces/research/api/cascade_routes.py, CascadeProposal.test.tsx, tests/test_cascade_api.py.
  4. Show execution balances. Display approved, authorized spent, observed provider spend, held, and available from server state. Acceptance: no optimistic arithmetic; breach and unresolved holds remain visible and stable. Files: apps/reading/src/modes/ResearchWorkstation/CascadeProposal.tsx, apps/reading/src/modes/ResearchWorkstation/CascadeProposal.test.tsx.
  5. Build stage-aware recovery. Lost edit/launch responses use existing authoritative recovery; unknown provider outcomes offer status reconciliation, not retry. closed_unresolved remains execution-closed but evidence-reconcilable until closed_reconciled. Acceptance: abandonment cannot release unresolved headroom; only provider evidence settles/releases. Files: apps/reading/src/api/research.ts, CascadeProposal.tsx, interfaces/research/api/cascade_routes.py, their focused tests.
  6. Prove the product. Launch concurrent exact-headroom leaves and inject ambiguous sends/restarts. Acceptance: provider operation counts match sent holds; authorized invariant holds; above-hold provider billing enters visible breach; desktop/mobile states render. Files: tests/test_cascade_api.py, tests/test_research_provider_gateway.py, apps/reading/src/modes/ResearchWorkstation/CascadeProposal.test.tsx, apps/reading/e2e/research-hard-ceiling.spec.ts.

Five-values rigor

Intellectual honesty

Describe hard mode as enforcement of what Antiek authorizes, backed by reservations. Explicitly exclude taxes, currency conversion, external account fees, and provider misbilling from the guarantee while showing observed breaches.

Fairness

Keep stop-limit mode usable for valuable providers with unknown maxima and explain its weaker semantics plainly. Do not hide capability gaps by silently changing providers or models.

Rigor

Assert approval invalidation synchronously in component tests and authority binding server-side. Browser screenshots alone are insufficient; provider call count and durable ledger state are the end-to-end truth.

Diligence

Test keyboard use, narrow screens, long provider/reason text, stale responses, double clicks, reconnects, unknown outcomes, exhausted balances, exact-cent boundaries, and changed fallback plans.

Defensibility

The handoff includes screenshots, accessibility results, exact API examples, and an invariant trace from operator approval through hold, send, and settlement.

Dependencies

SPR-03 must be merged with its provider gateway and recovery states. Use Lucide icons and existing Research Workstation patterns. A local test provider must support known, definite-failure, and ambiguous outcomes.

Out of scope

No marketing page, budget-setting redesign, automatic model router, Antiek-bench scoring, multimedia UI changes, refunds, provider billing dispute workflow, or voice approval.
