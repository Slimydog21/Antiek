MCP server scaffold + personal resource

FastMCP server with antiek://private/notes/{user_id}/{note_id} resource. Reads from DuckDB substrate. OAuth-scope enforcement.

Wave 1 ~3 days

Parent context

Standalone briefing — do not require master spec open.

Antiek Memory is the developer-facing exposure of a user's personal graph to external LLMs via MCP. This sprint builds the server scaffold and the first resource: private notes. Single-operator until Sprint 22 — no OAuth complexity yet, just the shape.

Position: MCP-SPR-01 of ANT-MCP — Antiek Memory MCP server programme.

Goal

FastMCP server running, serving antiek://private/notes/{user_id}/{note_id} from DuckDB substrate, with typed errors for missing notes.

Technical milestones

1
FastMCP server scaffold

services/mcp_server/__init__.py — FastMCP app with stdio transport. Entry point at services/mcp_server/__main__.py.

Acceptance criteria
  • python -m services.mcp_server starts without error
  • Server exposes list_resources() returning typed resources
services/mcp_server/__init__.pyservices/mcp_server/__main__.pyservices/mcp_server/server.py
2
Private notes resource

antiek://private/notes/{user_id}/{note_id} — reads from DuckDB documents table. Returns note content + metadata. Typed error for missing notes.

Acceptance criteria
  • Existing note returns content + metadata JSON
  • Missing note returns typed NoteNotFoundError
  • Content is read-only (no write through resource)
services/mcp_server/resources.pyservices/mcp_server/errors.py
3
DuckDB reader integration

Use existing substrate/graph/search.py patterns for DuckDB reads. Respect single-writer invariant — read-only connection.

Acceptance criteria
  • MCP server uses read-only DuckDB connection
  • No writes to substrate from MCP server
  • runtime/db_lock.py pattern respected
services/mcp_server/reader.pytests/test_mcp_server.py
