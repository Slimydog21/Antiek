Security hardening + manifest

Prompt-injection defense. Rug-pull defense. Tool description hashes. E2E integration tests. Programme closure.

Wave 3 ~3 days Security-critical

Goal

Every public-notes return wraps content in <antiek:content trusted="false">. Tool description hashes published in .well-known/mcp-tools.json. E2E tests prove the full MCP lifecycle.

Technical milestones

1
Prompt-injection defense

Every public-notes return wraps content in <antiek:content trusted="false">...</antiek:content>. System prompt instructs agent to treat envelope content as data, not instructions. OWASP LLM01 mitigation adapted to MCP.

Acceptance criteria
  • Public notes return wrapped in trusted="false" envelope
  • Red test: injection attempt in note content → still wrapped
  • Private notes NOT wrapped (trusted owner content)
services/mcp_server/defenses.pytests/test_mcp_defenses.py
2
Rug-pull defense

Tool description hashes published in .well-known/mcp-tools.json manifest. Clients verify on every refresh. Drift treated as fatal session-termination event.

Acceptance criteria
  • Manifest generated with SHA-256 hashes of all tool descriptions
  • Drift detection: changed description → verification fails
  • Manifest is static file, not generated at runtime
services/mcp_server/manifest.pyservices/mcp_server/.well-known/mcp-tools.json
3
E2E integration tests

Full MCP lifecycle test: start server → list resources → read resource → call tool → verify output. Hermetic (no network, no external deps).

Acceptance criteria
  • E2E test covers all 3 resources + 4 tools
  • Test is hermetic (DuckDB in-memory or temp file)
  • Test runs in CI without external deps
tests/test_mcp_e2e.py
