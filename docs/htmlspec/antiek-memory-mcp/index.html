Antiek Memory MCP Server

Connect your LLM to your user's memory of everything they've read, thought about, asked, and written.

4 sprints No substrate impact MCP-first developer surface

Goal

Ship the Antiek Memory MCP server as the primary developer surface. Three URI-addressable resources, four tools, prompt-injection defense, rug-pull defense. This is what makes Antiek a true knowledge platform — external LLMs can connect to a user's personal graph.

Position: Sprint 19 engineering per master spec §13.8. NOT gated on legal (G2/G3). The personal-notes API is free for the user's own account.

Rigor (programme-level)

1 · Intellectual honesty

Evidence-calibrated

Every resource return is verified against the substrate — no fabricated content. If a note doesn't exist, return a typed error, not a guess.

2 · Fairness

Steelman rejected

Steelman: REST API as primary surface. Rejected: MCP is the defensible primary surface per §13.8 (97M monthly SDK downloads, 92% agent framework adoption).

3 · Rigor

Mechanical gates

Every tool has pytest coverage. Every resource has round-trip test. Prompt-injection defense has red tests (injection attempt → wrapped output).

4 · Diligence

Read first

Read substrate/graph/search.py before building search tools. Read runtime/db_lock.py before touching DuckDB. Match existing patterns.

5 · Defensibility

Survives turnover

Handoff lists files touched. Every design decision has a rationale in the code. Tool description hashes are verifiable.

Dependencies

  • Substrate DuckDB schema (existing)
  • substrate/graph/search.py BM25 (existing)
  • FastMCP library (pip install fastmcp)
  • runtime/db_lock.py single-writer (existing)

Out of scope

  • Multi-user OAuth (Sprint 22)
  • Stripe Connect pricing integration
  • Publisher dashboard
  • Book API (gated on publisher onboarding)
Temptation: add pricing middleware or multi-user auth. Stop, note in handoff, stay in scope. Single-operator until Sprint 22.
