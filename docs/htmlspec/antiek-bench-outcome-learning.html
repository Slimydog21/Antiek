Outcome-grounded recursive Antiek-bench

Learn next-week benchmark emphasis from attributable, operator-graded production outcomes without accepting caller-injected success labels or silently changing dispatch authority.

Spec lineage

Root gap spec discovered while auditing PR #804. Parent product evidence: the validated weekly report exposed by corrected #799 and the existing event-log/outcomes substrates on main.

  • No child specs yet. Hatch one only if provider receipt normalization or operator grading exceeds one sprint.

Problem and non-negotiable outcome

Antiek currently has benchmark measurements and generic research outcomes, but no authoritative join across task → chosen model/route → immutable execution → cost/receipt → operator grade. The superseded prototype audited before this spec accepted arbitrary posted booleans and therefore permitted benchmark poisoning, duplicate votes, unauthenticated attribution, and circular self-evaluation.

Do not implement weight learning until the attribution join exists. Empty evidence must yield “insufficient evidence,” never Laplace-smoothed confidence that looks measured.

Success criteria

  • Every eligible learning row is derived from strict server-owned evidence and names an immutable execution, decision receipt, model route, task taxonomy version, owner-scoped grader, and grade sequence.
  • Operator grades are idempotent, auditable, revisable by supersession rather than mutation, and excluded when provenance is incomplete.
  • Weekly proposals are advisory artifacts with cohort counts, uncertainty, exclusion reasons, drift bounds, and explicit operator approval before benchmark configuration changes.
  • Replay from the same sealed evidence-ledger cutoff produces byte-identical canonical proposal JSON.

  • No public API accepts a model score, success boolean, benchmark weight, or arbitrary prior weight.
  • Only operator-authenticated grading may affect learning; automated quality signals are separate evidence, never silently promoted to user success.
  • One effective grade per run and rubric version; later grades supersede earlier IDs while retaining history.
  • A proposal cannot mutate dispatch config or benchmark definitions. Approval and application are distinct events.
  • Minimum cohorts and confidence rules are versioned configuration, not magic constants hidden in UI code.

SPR-00A contract — authoritative evidence ledger and cutoff

Goal: create the durable authority that deterministic replay requires; the investigation-partitioned JSONL event log is an input, not this authority.

  1. Create a single-writer DuckDB projection bench_evidence_events with coordinator-assigned monotonic evidence_seq, globally unique event_id, owner ID, event kind/version, canonical payload bytes, previous-row digest, row digest, and committed timestamp. DuckDB 1.5.4 has no triggers: append-only enforcement is therefore a capability boundary, not fictional DDL. Only the dedicated ledger module may open the file read-write; it exposes insert and sealed-read operations but no update/delete/raw connection, runs under the sole filesystem writer identity in production, and CI fails on any other read-write open site. Unique constraints plus the chain verifier reject duplicates or mutation; backup/restore and operator repair create a new generation rather than editing rows.
  2. Write through a strict coordinator transaction using BEGIN TRANSACTION and a lock row: read the current tail, assign tail+1, persist row and hash-chain link, commit, then return the receipt. Concurrent writers retry the entire transaction after conflict. A failed or uncommitted write returns no receipt and is ineligible. Legacy non-fatal JSONL emission cannot establish eligibility.
  3. A cutoff is the pair {ledger_generation, max_evidence_seq, chain_digest} captured in one read transaction. Replay reads that generation through evidence_seq <= max, verifies every digest/link and the terminal digest, and fails closed on gaps, corruption, duplicates, or generation/store mismatch.
  4. Late events receive later sequences and belong to a later cutoff. Equal wall-clock timestamps never determine ordering. Backfill imports preserve source digest and require the signed envelope below; unsigned or unverifiable imports are excluded.

Signature profile V1: RFC 8032 Ed25519 over RFC 8785 UTF-8 bytes of {profile:"antiek.provenance.ed25519.v1",kind,key_id,created_at,payload_digest}; the detached signature is base64url without padding. payload_digest is lowercase SHA-256 of canonical payload bytes. A versioned operator-owned trusted-key registry records public key bytes, activation instant, and optional revocation instant/reason; verification uses event time, rejects unknown/not-yet-active/revoked keys and non-canonical envelopes, then verifies digest and signature. A weekly anchor is immutable artifact antiek.bench.cutoff-anchor.v1 containing the complete cutoff tuple, definition version, created time, and prior-anchor digest, signed by the same profile and attached to a SHA-addressed GitHub Release. Replay fetches the release asset by recorded repository/release/asset identity, checks asset SHA-256, envelope signature, prior link, and cutoff digest before accepting the seal.

Threat model: defend against caller forgery, duplicate/reordered rows, local file rewriting, partial writes, stale approvals, cross-owner access, and accidental mutation. Host compromise and key exfiltration are detectable only to the last externally anchored digest; document that limit.

Acceptance fixtures: exact golden rows/digests for empty ledger, two committed events, duplicate ID, rolled-back write, concurrent writers, forbidden raw writer, missing sequence, altered payload, broken link, wrong generation, unsigned import, unknown/revoked key, altered envelope, broken anchor link, and late event. Run replay twice and compare bytes and SHA-256.

SPR-00B contract — shared execution identity and coverage

Goal: make attribution possible across ordinary, local, remote, BYOK, cascade, fallback, and composite executions before emitting learning rows.

  1. Define server-owned execution_id for each provider attempt, decision_id for each routing decision, artifact_id for each gradeable output, and composition_id for a user-visible output assembled from multiple attempts. Spend-ledger run/hold IDs are references, never substitutes for the shared identity.
  2. Inventory every text-model call boundary in a checked-in generated matrix with owner module, route type, retry/fallback behavior, receipt capability, terminal close hook, artifact link, and eligibility. CI fails when a new provider call site lacks a matrix row.
  3. One attributed row represents one execution attempt. A composite artifact records ordered contributing execution IDs and roles; operator grades attach once to the artifact. V1 credit policy is exclusion: any artifact with more than one terminal contributing execution, or one whose final content cannot be attributed to exactly one execution, is retained for audit with exclusion code composite_credit_unsupported_v1 but contributes to no cohort, route exposure, task pressure, or proposal. No role weights are accepted in V1. A later policy requires a new version and fixtures; it never reinterprets V1 cutoffs. Retries and fallbacks are separate attempts; only the single execution that produced a non-composite final artifact may inherit its grade.
  4. attributed_run_v1 must include owner, all four identities, decision policy/version, task taxonomy/version, provider/model/tier, BYOK/local flags, readiness and budget eligibility observed at decision time, prompt digest, terminal state, provider receipt when available, spend reference when available, artifact visibility, and started/closed timestamps.

Coverage acceptance: the committed matrix is exhaustive under an AST/runtime boundary scanner; tests exercise one success, failure, cancellation, retry, fallback, composite exclusion, local, BYOK, and cascade fixture. Production reachability proves the real app registration and at least one strict receipt from each qualified boundary class.

Normative learner and canonicalization contract

antiek.bench.definition.v1 is the executable weight source: {definition_id,definition_version,taxonomy_version,algorithm_version,tasks:[{task_id,weight_millionths}],created_at,content_digest}. Task IDs are unique and ascending, weights are nonnegative integers summing to 1,000,000, and content_digest covers every preceding field as RFC 8785 UTF-8. A report references this immutable definition ID/digest; measurements never imply weights. All learner arithmetic uses integers or exact rationals; binary floats are forbidden. Canonical JSON is RFC 8785 UTF-8. Arrays declare sort keys; maps use canonical key order.

  1. Eligibility: select the greatest evidence_seq non-superseded grade per {artifact_id,rubric_version} at the sealed cutoff; require intact provenance, visible artifact, qualified boundary, exactly one producing execution, terminal provider attempt, and complete task/model/version fields. Record every exclusion code and count. Composite V1 artifacts are excluded as specified in SPR-00B.
  2. Grade: rubric V1 is {useful,grounded,task_complete}, each pass|fail|not_enough_evidence. A grade is observed only when all three are pass/fail. Failure count f increments when any fails; sample count n increments once per independently graded artifact.
  3. Cohort: key by {task_taxonomy_version,task_id,model_route_id,decision_policy_version}. Exposure is the number of eligible non-composite artifacts in that key; never pool across task IDs or policy versions.
  4. Withhold: a route is eligible only when n >= 20 and exact coverage fraction n/exposure >= 2/5, compared by cross multiplication. Otherwise emit insufficient_evidence. A task is eligible only when at least two routes in the same task/policy stratum are eligible. Never treat ungraded rows as outcomes.
  5. Wilson reference: V1 uses z=49/25. For each (f,n), evaluate the standard Wilson upper-bound expression with Python decimal.Decimal context Context(prec=80, rounding=ROUND_HALF_EVEN), constructing Decimals only from integers and Decimal(49)/Decimal(25); use that context's sqrt(). Quantize the final bound upward to integer millionths with to_integral_value(rounding=ROUND_CEILING) after multiplying by 1,000,000. The checked-in reference function is the authority and its source SHA-256 is algorithm_version; alternate implementations must match all exhaustive 0<=f<=n<=10000 vectors byte-for-byte.
  6. Pressure: within each eligible task/policy stratum, sort route bounds ascending. The median is the middle value for odd count and integer floor of the sum of the two middle values divided by two for even count. Task pressure is max_bound-median. If multiple policy strata exist, use their maximum pressure; record the selected stratum. This changes task emphasis only, never route rank.
  7. Proposal: withheld tasks retain current weight. Let P be eligible tasks with positive pressure. If P is empty, return the current vector. Otherwise allocate the total current weight of eligible tasks proportionally to pressure using exact fractions and largest remainder (remainder descending, then task ID ascending); zero-pressure eligible tasks target zero. Clamp each target to current±25,000. Rebalance the resulting sum to 1,000,000 one millionth at a time in deterministic rounds over tasks with remaining room: for additions, pressure descending then task ID; for removals, pressure ascending then task ID. If no task has room before balance is restored, fail closed with movement_cap_unsatisfiable. This order is the only residual redistribution rule.
  8. Sub-benchmarks: suggest a task only when pressure is positive for two consecutive valid sealed cutoffs using the same taxonomy and algorithm versions; sort pressure descending then task ID. Version changes reset the streak.

The canonical artifact includes the complete cutoff tuple, definition ID/digest, algorithm/rubric/taxonomy versions, source-function digest, exposure and grade counts, exact coverage numerator/denominator, exclusions, current/target/clamped/proposed vectors, movement, Wilson inputs/output, withheld reasons, selected strata, residual trace, and suggestion derivation. Golden fixtures fix exact bytes and digests for sparse, even/odd median, all-zero pressure, capped/withheld residual, imbalanced, tied, late, superseded, composite-excluded, and corrupted inputs.

Authorization, lifecycle, and recovery contract

Grade mutation: accept only authenticated owner session, Cloudflare Access identity, service token, or operator bearer token already recognized by global middleware; explicitly reject unauthenticated_local. The authenticated owner must equal the attributed artifact owner. Cookie-authenticated POST requires same-origin Origin/Referer validation plus a session-bound CSRF token. Bearer/service-token calls require an idempotency key. Cross-owner is 404 to avoid existence disclosure; missing auth is 401; authenticated but disallowed authority is 403.

Proposal state: generated → pending_review → approved|rejected; only approved → published. These immutable proposal states never become applied or superseded. Publish creates one immutable benchmark definition with provenance back to the approved proposal.

Definition activation: definitions are immutable and have no mutable lifecycle status. A separate append-only active_definition_events stream records {activation_seq,from_definition_id,to_definition_id,reason:apply|rollback,proposal_id|null,expected_active_definition_id,actor,idempotency_key}. Compare-and-swap requires the expected active ID and a published target; any previously published definition, including one formerly active, is a legal rollback target. The current active definition is the target of the greatest valid activation sequence. “Superseded” is a derived UI label for a definition that was active but is not current, never a transition barrier. Approval never publishes or activates; publish never activates. Invalid/stale operations return 409.

Every proposal transition, publication, and activation is a strict append-only event referencing its prior stream event, relevant digest/version, actor, idempotency key, and timestamp. A transactional outbox commits domain event and delivery record atomically; recovery retries by event ID, consumers deduplicate by event ID, and an interrupted operation is absent or delivered at least once with exactly-once materialized effect.

Retention: free-text grade reasons are optional, owner-private, separately encrypted, excluded from learner payloads, and deletable without altering rubric facts. Prompt digests are owner-scoped HMACs with key version, not raw hashes. Provider receipts retain only the minimum stable identifier and cost fields allowed by provider policy.

Negative matrix: unauthenticated local, forged owner, cross-owner, missing/invalid CSRF, cross-origin cookie request, replayed idempotency key with different body, stale proposal digest, stale active definition, double approval, publish-before-approval, activate-unpublished, concurrent activation, rollback-to-unpublished, crash before/after outbox commit, rejected proposal transition, inaccessible artifact, and deleted reason text.

SPR-01 operating manual — attribution receipt

Goal: close the identity seam before collecting opinions.

  1. Define antiek.bench.attributed_run.v1 with the SPR-00B identities and decision, task, route, owner, eligibility, receipt, artifact, terminal, and timing fields.
  2. Emit only from the strict server execution close coordinator; reject client-authored model identity and duplicate execution IDs.
  3. Build replay projection with versioned exclusion codes: missing decision, missing terminal receipt, unknown task version, unqualified provider, cancelled-before-call, invisible artifact, broken evidence chain, and unsupported boundary.
  4. Add migration/replay and reachability proof from production app wiring.

Files to inspect first: substrate/schemas/events.py, substrate/research_spend/ledger.py, interfaces/research/api/settings_budget.py, provider gateways and the generated SPR-00B close-path matrix.

Verification: adversarial tests for duplicate close, mismatched route, forged client fields, restart replay, composite/fallback attribution, and identical digest output.

Honesty: terminal execution is not success; record status and attribution only. Fairness: preserve local/BYOK providers when they can produce equivalent receipts. Rigor: prove the event is emitted from every matrix-qualified text-model close path. Diligence: link the existing spend identity where available without treating it as the cross-platform run key. Defensibility: version every taxonomy, boundary matrix, and exclusion code.

Out of scope: scoring models, changing benchmark weights, UI.

SPR-02 operating manual — operator grade

Goal: capture what worked without conflating clicks, latency, or automated judges with user value.

  1. Define a compact rubric: useful, grounded, task-complete, and optional free-text reason; allow “not enough evidence.”
  2. Require operator authentication and an eligible attributed run. Create new grade IDs; corrections supersede prior grade IDs.
  3. Bind grade to rubric version and artifact/run visibility so deleted or quarantined outputs cannot remain silently eligible.
  4. Add a low-friction grade affordance at completed research/reading/writing outputs; disclose how it influences weekly evaluation.

Verification: unauthenticated 401, cross-run grade rejection, duplicate idempotency, supersession replay, not-enough-evidence exclusion, accessibility keyboard path.

Honesty: absence of a grade is missing data, not failure. Fairness: do not punish models used on harder tasks without task-stratified cohorts. Rigor: keep automated quality signals in separate fields. Diligence: reuse operator middleware and append-only event patterns. Defensibility: make rubric copy/version visible in the grade event and Settings.

Out of scope: inferred sentiment, passive engagement scoring, reward-model training.

SPR-03 operating manual — deterministic weekly learner

Goal: propose, never self-authorize, next-week benchmark emphasis.

  1. Select a sealed evidence-ledger cutoff and materialize eligible attributed-run/grade joins with counts and exclusion reasons.
  2. Apply the fixed V1 thresholds: at least 20 observed grades, at least 2/5 exact grading coverage per route, and at least two eligible routes per task/policy stratum.
  3. Compute the specified Wilson bound, pressure, target, cap, and residual trace exactly. Do not normalize tiny cohorts into 100% mass.
  4. Emit canonical antiek.bench.proposal.v1 JSON containing the complete cutoff, definition and algorithm identities, current/target/proposed weights, confidence inputs, exclusions, and suggested sub-benchmarks.
  5. Prove byte-identical replay and property-test nonnegative weights, exact sum, bounded drift, and monotonic response to added failures within the same cohort.

Verification command target: uv run pytest tests/test_antiek_bench_outcome_learning.py -q plus a replay fixture run twice with identical SHA-256.

Honesty: “insufficient evidence” is a first-class output. Fairness: stratify by task and compare like-for-like routes before up-weighting. Rigor: property tests must attack cohort imbalance and superseded grades. Diligence: source current weights from the validated benchmark definition, never request JSON. Defensibility: publish the full derivation ledger alongside each proposal.

Out of scope: online reinforcement learning, automatic provider routing, mutation of dispatch config.

SPR-04 operating manual — review and approval

Goal: make recursive learning inspectable and reversible.

  1. Add a Settings evidence view showing cohort sizes, excluded rows by reason, uncertainty, old/new weights, movement caps, and suggested sub-benchmarks.
  2. Require operator confirmation that creates antiek.bench.proposal.approved.v1; approval references exact proposal digest.
  3. Publish a new versioned benchmark definition artifact; never edit the prior definition in place.
  4. Show applied/not-applied state and rollback-by-selecting-prior-version. Keep dispatch use advisory until separately authorized.

Verification: stale-digest approval conflict, double approval idempotency, inaccessible proposal refusal, visual/a11y states for insufficient evidence, pending, approved, rejected, superseded.

Honesty: display uncertainty and exclusions beside recommendations. Fairness: the operator can inspect which providers/tasks lose weight. Rigor: approval must bind the exact digest tested in UI. Diligence: integrate the corrected #799 panel instead of adding a second Settings surface. Defensibility: retain proposal, decision, approver, and rollback target as immutable artifacts.

Out of scope: automatic approval, provider billing changes, NotDiamond production routing.
