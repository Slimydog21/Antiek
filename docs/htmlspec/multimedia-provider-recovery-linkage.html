Multimedia Provider Recovery and Asset Linkage

Status: executable TQ sub-spec, stacked on PR #921. Outcome: an operator opens one multimedia asset and can inspect or recover its signed provider executions without copying authority identifiers.

Five Values

  1. Information density: recovery exists to preserve an already-paid educational narration, never to trigger a second call.
  2. Operator authority: only the authenticated owner may see or mutate an execution; IDs are results of verification, not user input.
  3. Evidence before state: provider-account bytes are normalized, cross-bound, hashed, and signed before the existing recovery transition can consume them.
  4. One source of truth: execution and run linkage is projected from signed DuckDB receipts; the JSON asset store does not become a second authority.
  5. Honest absence: missing gateway configuration, no match, multiple matches, or unverifiable evidence returns a safe unavailable state and performs no mutation.

Architecture

selected asset → authenticated reconciliation-links projection → signed execution/run verification → operator action → provider-account gateway lookup → normalized Antiek evidence signature → existing recovery state machine

BoundaryContract
Gateway lookupFixed HTTPS host, bearer secret held server-side, no redirects, bounded response. Request binds execution, authorization, SHA-256 operator identity, asset, revision, provider, and request-body digest; the raw operator identifier never leaves Antiek.
Gateway responseVersioned exact-key JSON with exactly one match, configured account digest, provider request ID, source, timestamp, audio bytes, and audio SHA-256.
Evidence authorityAntiek validates account and every lookup field, timestamp chronology, Base64 and SHA-256, then signs the existing external-evidence tuple. The gateway never receives Antiek's evidence key.
Asset projectionCurrent revision comes from the mounted asset store. Execution rows and narration receipts are reopened under the signing key and filtered to the authenticated operator and current parent/child revisions.
UIThe selected asset drives loading. Linked chapter/run buttons replace free-form execution and run ID inputs. Request generations invalidate stale loads and actions.

Configuration

The reconciliation runtime remains disabled unless its database, output directory, signing key, recovery key, and evidence key are complete. Provider recovery is independently all-or-none:

  • ANTIEK_MULTIMEDIA_RECOVERY_ENDPOINT
  • ANTIEK_MULTIMEDIA_RECOVERY_TOKEN
  • ANTIEK_MULTIMEDIA_RECOVERY_OPERATOR_SHA256 (the normalized Antiek owner identity digest)
  • ANTIEK_MULTIMEDIA_RECOVERY_ACCOUNT_SHA256
  • ANTIEK_MULTIMEDIA_RECOVERY_ALLOWED_HOST

Partial or invalid configuration is a startup error. Missing provider configuration preserves read/quarantine/seal-release behavior but makes provider recovery return safe HTTP 409.

Acceptance Gates

  1. Focused adapter and route tests prove exact binding, ambiguity denial, account isolation, chronology, size/schema checks, and no-secret errors.
  2. Stacked multimedia suite passes with no regression to signed execution, budget, reconciliation, or seal-lease authority.
  3. Frontend tests prove selected-asset linkage, no editable authority IDs, linked parent inspection, action fencing, empty and unavailable states; production build passes.
  4. Ruff, strict scoped mypy, HTML parse, diff check, hardenx zero real findings, and a different-lineage critic pass.
  5. Live provider recovery is labeled NOT RUN until an operator configures a real account gateway and authorizes a non-paid reconciliation canary.

Non-Goals and Handoff

No new provider generation call, retry, refund, router authority, billing mutation, graph mutation, campaign push, merge, or deployment. This sprint does not claim a particular TTS vendor API supports idempotency lookup; the gateway is the provider-specific translation boundary. A future adapter may implement that translation only after live API evidence proves the lookup shape and account identity.
