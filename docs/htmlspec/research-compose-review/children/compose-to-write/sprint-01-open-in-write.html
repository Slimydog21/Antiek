Open the reviewed folio in Write

Build one zero-spend analysis desk from the immutable compose, preserving exact source identity and honest gaps.

Wave 1Ready5 milestones

Parent context

The parent shipped completed-only selection, exact-hash preview, and an immutable directory-level compose with a manifest and static member HTML snapshots. Those snapshots contain the canonical #antiek-artifact-v1 machine body.

Write already supports graph-backed outline blocks and one-investigation promotion, but its singular root link and live synthesis query cannot truthfully represent a reviewed multi-source compose. This sprint adds the missing bridge; it does not generate prose.

Goal

An explicit “Start writing from these sources” action creates or reuses one Write workspace whose blocks are selected from the frozen compose and whose source history remains reconstructable.

Technical milestones

1Validate the immutable input.

Load the manifest and every indexed member, parse the embedded body, require matching investigation ID and canonical content hash, and collect ordered insight/question occurrences.

Accept: corrupt, swapped, missing, or hash-divergent members fail before any DB write.

2Create a durable multi-root promotion primitive.

Add a unique compose→deliverable mapping. Under one write lock and explicit transaction, dedupe first-seen node IDs, lookup live types/liveness, create a NULL-root deliverable and section, place graph-provenance blocks, and commit the mapping.

Accept: sequential and concurrent retries return the same IDs; dangling nodes are retained; duplicate/conflict counts are deterministic.

3Expose the zero-spend API.

Add POST /research/artifact-composes/{compose_id}/write-workspace with validated optional title/kind and an honest receipt including write_url, counts, and reused.

Accept: first creation is 201, reuse is 200, missing is 404, integrity failure is 409, and no dispatch/cost path is imported or called.

4Design the binding-desk receipt.

After compose creation, keep the HTML-draft link and add one secondary action. On success show a compact stitched-spine receipt—member count feeding unique source blocks, duplicates folded, unavailable sources flagged—and an explicit “Open in Write” link.

Accept: keyboard accessible, pending-safe, error preserves the draft, no surprise navigation, no new palette or raster art.

5Prove and harden.

Exercise backend integrity, idempotency, rollback, dedupe, dangling provenance, API statuses, frontend pending/retry/success, type/lint/build, visual/accessibility, and independent adversarial review.

Rigor — operating manual

1 · Intellectual honesty

Do not call a live rebuilt body “the reviewed compose.” Report snapshot occurrence count, unique block count, kind conflicts, and dangling count separately; an empty workspace is not “analysis generated.”

2 · Fairness

Steelman live graph reconstruction: it is fresher and simpler, but it invalidates the exact-hash review. Preserve freshness only for type/liveness and document that boundary.

3 · Rigor

Inject corruption before writes and failure during the DB transaction; verify no partial mapping/deliverable/section/block survives. Exercise simultaneous identical requests, not only serial retries.

4 · Diligence

Reuse parse_body_from_html, place_block semantics, existing write routing, Lemon components, and the ComposeTray state machine. Do not invent parallel provenance or button systems.

5 · Defensibility

Persist source compose ID and selection fingerprint in a normalized mapping plus deliverable metadata. Record why investigation_root_id is NULL and why node ordering is manifest/member/first-occurrence order.

Dependencies

  • Parent compose draft exists and passed exact-hash creation.
  • Graph schema supports deliverables, sections, and soft graph-node outline blocks.
  • No model credential, budget approval, or provider is required.

Out of scope

  • Generated synthesis, model selection, budget projection, collective prompting, and automatic prose.
  • Editing the immutable compose, merging member HTML bodies, or deleting it after promotion.
  • Making Write’s canvas understand multiple live investigation roots; this workspace is compose-backed.
