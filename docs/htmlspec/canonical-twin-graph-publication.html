Cycle 110: Canonical Twin Graph Publication

Parent: Cycle 109 canonical paid aggregate projection. Outcome: one ready canonical advisory twin becomes an HTML document and deterministic retrieval chunk in the existing DuckDB substrate.

1. Product Contract

The twin is a first-class information asset users can read and retrieve. It remains advisory: generated insights, questions and synthesis live only in document HTML and chunk text. They do not become graph nodes, edges, grounded findings or gaps until a later evidence-backed promotion action.

2. Authorities

AuthorityResponsibility
TwinRecursionLedgerExact ready source, binding, twin identity, canonical body, aggregate provenance and non-recursive derivation.
LockedConnectionSingle DuckDB writer and transaction owner.
insert_documentCanonical document row, owner/content gate and twin source envelope in the same row.
insert_chunkDeterministic unembedded retrieval text tied to the document.

3. Canonical Snapshot

The lifecycle exposes a context-managed CanonicalTwinPublication. It opens one SQLite read transaction, verifies schema and complete ledger integrity, requires a ready twinnable parent binding, reconstructs exact source and twin commitments, and keeps that snapshot open through DuckDB commit.

Callers cannot submit body, HTML, title, owner, document ID, binding ID claims other than the exact lookup ID, content class, chunk text or publication metadata.

4. One Transaction

  1. Require an exact LockedConnection and exact canonical ledger.
  2. Acquire the canonical publication snapshot before opening the DuckDB transaction.
  3. Begin one DuckDB transaction.
  4. Insert document ID equal to the canonical twin ID, source URI identifying the immutable binding, rendered HTML as raw_text, owner from the canonical account, canonical_twin document type and owner-only personal_reading content class.
  5. Insert one deterministic chunk containing the canonical advisory notes. Embedding remains NULL; this sprint never calls an embedding provider.
  6. Commit both rows together. Any error rolls back both.

5. Replay and Conflict

  • Exact replay verifies every persisted document/chunk field and returns the same publication.
  • An existing document or chunk with any different field conflicts; on_conflict=ignore is insufficient authority.
  • Concurrent calls serialize through the existing write lock and converge on one document and one chunk.
  • Crash before commit leaves neither row.
  • Lifecycle corruption, missing binding, failed/pending state, derived-child lookup or authority change refuses before graph mutation.

6. Recursion and Retrieval

canonical_twin documents receive a requires_binding envelope whose reason is canonical_twin_is_derived; source projection never creates a new generation obligation. The personal_reading chunk is owner-retrievable under the private_research policy tag and excluded from public/attribution paths. Without an embedding it is honestly absent from vector ranking; a later authorized embedding job may index it without changing publication identity.

7. Acceptance

  1. One ready paid aggregate binding publishes one HTML document and one advisory chunk.
  2. Document metadata binds owner, canonical source, canonical binding, body hash and authority.
  3. No nodes, edges, findings or gaps are added.
  4. Exact replay is stable; substituted rows fail closed.
  5. Injected failure after document insertion rolls back document and chunk.
  6. Derived publication cannot create a recursive twin obligation.
  7. Owner retrieval gate includes it; public/attribution retrieval excludes it.
  8. Coupled tests, strict typing, Ruff, HTML parse, HardenX and hostile review pass.

8. Non-Goals

No embedding call, graph node/edge promotion, grounding, API/UI, provider call, spend, production corpus mutation, merge, deployment or live spend.

9. Next

Add authenticated reader navigation to the published HTML twin and an explicit evidence-backed promotion workflow for selected advisory insights/questions. Then mount canonical short-form twins through the same publication authority.
