Cycle 88: Live Canonical Note Convergence

Status: executable specification.

Problem

Repeated observations are distinct provenance records but resolve to one global knowledge node. After a refinement targets one observation, other live rows can continue showing stale wording even though completed DistillView and the graph expose one canonical truth. Live NotesPanel also offers only a one-step local change disclosure while completed research exposes the integrity-checked global history.

Decision

  • Every known live alias of one graph node renders the latest authoritative canonical text.
  • Each alias retains its immutable emerged wording as observation provenance.
  • Applied and superseded outcomes advance one node-global sequence projection; broken, stale, partial, or substituted outcomes remain ignored.
  • Applied outcomes update canonical text, prior text, refinement count, and sequence across all known aliases.
  • Superseded outcomes may rebase canonical text/sequence but never expose losing attempted text or increment refinement count.
  • A shared lazy history disclosure component reads the backend's committed authoritative aggregate in both live and completed surfaces.

Presentation

  • Canonical text remains the primary row text.
  • When source-local wording differs, an inline disclosure shows “observed as” wording without presenting it as current truth.
  • History labels accepted changes and rejected attempts identically in NotesPanel and DistillView.
  • Integrity/transport failure remains explicit and retryable; no history is reconstructed client-side.

Acceptance Criteria

  1. A refinement targeting observation A updates visible canonical text for known aliases A and B of the same node.
  2. A subsequent refinement targeting B updates both aliases while each preserves its original observation wording.
  3. Aliases of another node are unchanged.
  4. Superseded and malformed outcomes cannot expose losing or untrusted text.
  5. Live history loads lazily, caches while unchanged, invalidates when node count changes, and retries failures.
  6. Completed DistillView retains equivalent history behavior through the shared component.
  7. Focused frontend tests, typecheck, production build, and diff checks pass.
