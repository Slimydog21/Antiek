Never repay one distillation request by accident

Close the pre-existing crash window between provider acceptance and durable distillation delivery without pretending retrospective events are idempotency authority.

Problem

The wrestling handler can receive one distillation.requested event more than once. The current dispatcher calls a provider before recording a dispatch event. A crash after provider acceptance but before durable result/delivery can therefore cause an automatic replay and a second charge.

Durable authority

  1. Create a DuckDB dispatch command keyed by request event ID and bound to the canonical request, prompt, role, route, and projection digests.
  2. Persist reserved before transport. Concurrent exact callers observe one command; changed bytes under the same identity fail closed.
  3. Carry a digest-derived provider idempotency key only when current provider qualification proves durable idempotency or authoritative lookup.
  4. Persist the normalized provider result as completed before emitting delivery. Replay from completed emits only the missing exact delivery.
  5. If transport may have reached a provider and no authoritative result can be recovered, transition to ambiguous. Automatic retry is forbidden; operator reconciliation is required.
  6. Mark delivered only after the exact event is durably present or reconciled byte-for-byte.

Crash matrix

BoundaryRequired behavior
Before reservation commitNo provider call and no command.
After reservation, before sendRecoverable no-send state may dispatch once.
During/after send without authoritative resultAmbiguous; retain conservative exposure and never auto-retry.
After completed result, before deliveryReplay emits delivery without provider transport.
After delivery append, before receiptExact event reconciliation records receipt without duplication.

Provider qualification

A provider lacking proven idempotency or request-status lookup cannot support transparent crash replay. The product must expose reconciliation or require a fresh operator decision; it may not infer “not charged” from a timeout.

Acceptance

  • Concurrent duplicate handlers create one command, one provider call, and one delivery.
  • Crash injection covers every boundary and process restart.
  • Changed prompt/request/route bytes under one request event fail closed.
  • Completed replay performs zero provider calls; ambiguous replay performs zero provider calls.
  • Spend reservation and settlement remain conservative and auditable across success, provider failure, timeout, and reconciliation.
  • Two-account fixtures are deferred until a durable investigation-owner authority exists; the current implementation must state its authenticated single-operator scope.

Non-goals

No in-memory dedupe, trajectory-only scan, silent retry, fabricated provider capability, or weakening of spend approval.
