Never repay one distillation request by accident

Close the crash window between provider acceptance and durable delivery without pretending that provider idempotency, spend approval, or retrospective trajectory scans exist.

Current boundary

The authenticated single-operator wrestling handler receives replayable distillation.requested events. Its legacy synchronous router can reach providers, but provider adapters expose neither authoritative idempotency nor result lookup. This sprint adds a safety floor around that one call site. It does not make the legacy route an approved paid execution caller.

Durable authority

  1. Bind the request event envelope, complete prompt digest, synthesizer role, route-policy digest, and explicit unavailable spend projection into canonical JSON and SHA-256.
  2. Persist one DuckDB command keyed by request event ID as reserved. DuckDB has no SQLite STRICT suffix; explicit column types, closed state checks, payload checks, digests, primary keys, and unique delivery identity are the enforced contract.
  3. Hold one private per-command kernel flock across reserve, transport, normalized completion, and delivery. Concurrent processes wait; process death releases the lock without rewriting command state.
  4. Move reserved → sending before transport. A later lock owner that finds sending moves it to ambiguous, emits one deterministic uncertainty notice, and performs zero provider calls.
  5. After success, parse and persist the exact typed DistillationDeliveredPayload, its digest, policy, scope, and deterministic event ID as completed before event publication.
  6. Publish with strict_write, explicit event ID, and idempotent append. Reconcile the physical trajectory before append so a sealed or live event is not duplicated. Mark delivered only after durable presence.

Acceptance evidence

  • Concurrent exact callers produce one simulated provider call.
  • Reopen tests cover reserved, sending, completed, delivered, and ambiguous states.
  • Changed request or prompt bytes under one event ID fail with a binding conflict.
  • Stored payload corruption fails closed before publication.
  • Completed replay and append-before-receipt replay make zero additional provider calls and preserve one event ID.
  • A crash after transport leaves sending; restart records ambiguity, emits a value-free notice, and does not redispatch.

Explicit gaps and next sprint

The legacy wrestling call still has no operator-approved hard ceiling, spend hold, settlement, or fallback-chain authorization. Cycle 91 must not be described as budget-safe paid execution. The next money-path sprint must connect distillation to the existing approved research provider gateway or refuse paid transport; that integration requires an exact owner/run/operation binding and must preserve this command identity. Permanently ambiguous commands also need an authenticated operator reconciliation or abandonment surface before any fresh command can be authorized.

Non-goals

No in-memory dedupe, age lease, trajectory-only authority, silent retry, provider capability fabrication, general router mutation, approval bypass, operator reconciliation, live provider call, merge, or deployment.
