Canonical Twin Owner Reader

Expose a canonical advisory twin only to its authenticated owner, navigated by the exact source asset and revision hash.

Authority

The output is advisory AI-generated notes, is not shareable, and creates no grounded graph claim.

Contract

  1. The HTTP adapter derives owner identity from an authenticated server dependency; request data cannot select an owner.
  2. The read projection filters by owner before inspecting metadata, requires one exact source match, and revalidates the binding against the canonical lifecycle snapshot.
  3. The document, metadata, and exactly one deterministic advisory chunk must match publication commitments.
  4. Publication v2 sanitizes on write; exact legacy v1 rows migrate atomically on authorized replay while substitutions remain conflicts.
  5. HTML passes through the parser-based allowlist sanitizer before release. Responses are private and non-cacheable.
  6. Absence, wrong owner, malformed metadata, duplicate rows, substitution, and lifecycle corruption collapse to the same external 404.

Non-goals

No public or link sharing, embedding call, evidence promotion, graph node or edge, provider action, spend, merge, or deployment.

Acceptance

Tests prove owner success, source navigation, explicit advisory labeling, XSS inertness, anonymous rejection, cross-owner non-disclosure, and forged/duplicate/chunk-substituted fail-closed behavior. Strict typing, Ruff, HTML parsing, coupled tests, hostile review, and HardenX must pass.
