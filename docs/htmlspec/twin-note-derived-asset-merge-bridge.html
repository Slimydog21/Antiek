CYCLE 51

Twin-note derived-asset merge bridge

Turn exact verified recursive notes into reviewable merge members without rewriting acquired source truth or creating a second derived-asset authority.

Spec lineage

Parent: Cycle 50 owner-scoped discovery. Exact twin authority remains Cycle 48 V21/V22 serving. Merge authority is the active safe-derived-asset sequence, currently PR #2374; this spec composes with it and must not fork its canonicalizer, draft/review tables, or parent-CAS model.

Outcome

An authenticated owner selects one exact source HTML projection and one or more exact V21 twin-note revisions or one V22 composition, previews a deterministic provenance-labelled appendix merge, creates one immutable derived-asset draft through the shared canonical merge substrate, reviews its exact stored bytes, and later applies it through that substrate's explicit revision authority. Source and twin rows remain byte-identical.

Non-negotiable truth

  • documents has no revision history and therefore cannot be an in-place merge target. Acquired or registered raw_text, chunks, rights metadata, hashes, and knowledge links remain untouched.
  • A twin note is advisory machine-authored evidence. It may appear only in a visibly labelled derived appendix with exact revision, source, and note provenance; it never masquerades as source authorship.
  • Write remains an optional editable workspace, not canonical merge authority. Mutable Write saves require a later immutable projection and review before publication.
  • Cycle 51 adds an adapter and operator workflow. It does not copy or weaken the generic canonical HTML parser, projection storage, merge draft/review schema, derived revision lineage, or restore semantics from PR #2374 and its descendants.

Prerequisite gate

Execution begins only when one pinned integration commit descends from reviewed PR #2374 and passes a contract probe proving: owner-scoped immutable HtmlProjectionContract rows; one descriptor-safe atomic hosted-object writer; closed canonicalization of ordered projection members; immutable draft and exact review rows; inert stored-byte preview; reviewed-draft apply into parent-bound derived revisions; active-head compare-and-swap; and append-only restore authority. The probe records the exact prerequisite SHA in the Cycle 51 test artifact. If any seam is absent, agents update this spec or the prerequisite rather than implementing a parallel canonicalizer, generic projection table, merge draft/review table, revision table, or head pointer.

Bridge contract

POST /research/twin-notes/merge-projections
{
  source_projection_id,
  source: {kind: "revision"|"composition", id},
  selected_notes: [{revision_id, note_ordinal}],
  idempotency_key
}
-> {
  projection_id,
  source_projection_id,
  twin_source: {kind, id},
  member_count,
  hosted_html_sha256,
  merge_draft_input: {projection_ids: [source_projection_id, projection_id]}
}
  • Owner derives only from authenticated request state. No owner, path, raw HTML, note text, digest, count, parent, or projection bytes are caller authority.
  • The source projection is reopened through the prerequisite verifier. The exact revision/composition is reopened through Cycle 48's whole-chain owner verifier.
  • For a revision source, every selected revision_id must equal that source. For a composition source, every selected revision must be an exact composition member and selection order is independent explicit operator order. Duplicate, absent, foreign, non-member, or out-of-range note identities are one value-free unavailable response.
  • The generated member is deterministic, script-free HTML containing only a heading, provenance statement, ordered selected note text, stable per-selection ordinal, and source-attribution count. Investigation IDs, window IDs, source-event IDs, raw digests, provider/model metadata, timestamps, and hidden totals are omitted.
  • The bridge uses the prerequisite's descriptor-safe object writer to atomically publish exact bounded appendix bytes, then stores a ready projection row pointing to that verified object. Publication is an external effect with a durable pending/published receipt and recovery; it is not authorization.
  • The projection uses a dedicated synthetic source_document_id naming the immutable bridge record, source_asset_id equal to the exact target source projection's asset, source_sha256 equal to the bridge manifest digest, and pinned bridge converter/sanitizer policy versions. The returned projection can enter only the existing ordered merge-draft path. This route cannot create a draft, review, revision, active head, graph node, or Write mutation.

Bridge persistence

twin_note_merge_bridges(
 bridge_id PRIMARY KEY, owner_user_id, idempotency_key,
 request_json, request_sha256, source_projection_id,
 twin_source_kind, twin_source_id, manifest_json, manifest_sha256,
 appendix_html_sha256, projection_id UNIQUE, object_locator,
 object_state CHECK pending|published,
 UNIQUE(owner_user_id,idempotency_key), UNIQUE(owner_user_id,request_sha256)
)
twin_note_merge_bridge_members(
 bridge_id, member_ordinal, revision_id, note_ordinal,
 revision_body_sha256, revision_html_sha256, canonical_note_sha256,
 PRIMARY KEY(bridge_id,member_ordinal), UNIQUE(bridge_id,revision_id,note_ordinal)
)
  • These tables are bridge receipts only. They may reference but never replace the prerequisite's generic projection, draft, review, revision, or head tables.
  • The canonical manifest contains bridge policy/version, source projection identity and hosted hash, exact twin source identity, ordered member rows, generated-byte hash, projection identity, and object locator. Reopen verifies every row, exact V21/V22 authority, object bytes, and generic projection bytes.
  • DDL has strict columns, defaults, checks, indexes, and foreign keys. Empty malformed partial state may repair at startup; populated incompatibility fails without mutation. Request handling never initializes schema.

Identity and replay

bridge identity = SHA256(canonical JSON of
  owner identity digest,
  bridge policy/version,
  exact source projection identity + hosted hash,
  exact twin kind/id and verified body/html/member hashes,
  ordered selected revision/note ordinals,
  exact generated appendix bytes)
  • Same owner/key/request reopens and verifies the complete bridge, members, object, projection, and bytes. Changed request conflicts. Same semantic request under a different key converges on the content identity and records no second bridge.
  • The transaction stores pending bridge/object authority and the generic projection identity; descriptor-safe publication occurs after commit; recovery verifies or publishes the exact stored bytes and marks the receipt published. Only published bridges return a ready projection.
  • No model, provider, network, graph promotion, chunking, embedding, event dispatch, or budget operation occurs.

Workstation

  • Extend the existing Twin Notes panel with “Merge into derived asset” only after an exact source projection is selected from owner-scoped asset context.
  • A comparison view renders the source projection and exact twin HTML in separate empty-sandbox frames. A note checklist shows exact derived note text and source counts; selections preserve click order.
  • Creating the bridge projection freezes discovery, history, open, compose, preview/apply, import, merge, and review controls. Late source, twin, or bridge responses carry generation identity and cannot overwrite a newer selection.
  • After bridge creation, hand off the exact two-member order to the prerequisite merge-draft UI. Draft preview and review remain visibly separate; review does not silently apply; apply does not rewrite source.
  • Changing source projection, twin source, selected notes, or order invalidates every downstream preview and rotates command identity.

Rejected alternatives

  • Update documents.raw_text: destroys source identity and invalidates chunks, rights, hashes, and finalization receipts.
  • Cherry-pick or recreate PR #2374 tables on the twin-note stack: creates two merge authorities and incompatible schema lineages.
  • Store only a DOM diff: makes replay depend on parser and canonicalization versions; the shared substrate stores complete canonical bytes.
  • Use twin HTML as source projection: confuses advisory notes with acquired source authorship.
  • Apply from comparison: collapses evaluation, review, and authority transfer.
  • Generic document support in the first bridge: expands rights, revision, and projection authority before the dependency has landed.

Harness hint
