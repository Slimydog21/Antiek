Master spec · ANT-BYOT-AUTH

Request-scoped BYOT/BYOK authority

Bind every paid model dispatch to the immutable authenticated owner, that owner's credential route, and an explicit payer decision before reservation or provider I/O.

Outcome and boundary

The first production consumer is the authenticated Write action POST /write/sections/{section_id}/generate. It must capture owner identity once at the HTTP boundary and pass an immutable DispatchAuthority through creative-writer dispatch, route resolution, gateway reservation, provider send, and settlement. The existing account model dropdown may propose a model; it cannot mint authority, select another account's credential, choose the payer, bypass qualification, or widen fallback.

Failure to avoid: a valid account selection or process-global adapter silently causes an operator environment key/house account to pay, or a request authenticated as user A decrypts or settles against user B's key.

Normative request contract

DispatchAuthority {
  authority_version: 1
  request_id: UUID                         // server minted
  authenticated_owner_id: UserId          // captured once; immutable
  action: "write.section.generate"
  resource: {deliverable_id, section_id}   // owner authorization already proved
  selection: {source, provider_id, model_id, tier?}
  credential:
    | {kind: "byot", cred_ref, request_owner_id, artifact_fingerprint, binding_version: 3}
    | {kind: "house", house_route_binding_digest, platform_credential_surrogate}
  payer: {kind: "byot" | "house", approval_id?: UUID}
  route_authority_digest: sha256
  fallback_manifest_digest: sha256 | null
}

Invariant for BYOT: owner(request) = owner(resource) = owner(model record) = owner(credential)
Invariant for house: owner(request) = owner(resource) = owner(approval); the platform-owned
  house route/credential is authorized by that approval and is never attributed to the user
Invariant: payer=house only with a live, action-scoped, owner-scoped approval
Invariant: credential plaintext is absent from this object, logs, events, holds, receipts, and responses

Construct this object server-side after authentication and resource authorization. Freeze it before dispatch. Re-resolve non-secret credential metadata and route authority immediately before reservation; decrypt only inside the selected adapter immediately before the one authorized send. Never accept owner_id, cred_ref, payer, endpoint, route digest, fallback manifest, or approval ID as authoritative client claims.

Global acceptance

  • Both account-facing Write creation routes persist the authenticated owner through the canonical promotion functions; no new friend deliverable silently inherits __operator__.
  • Every paid Write provider call has exactly one immutable authenticated owner, one credential binding, one payer, one route digest, one logical operation, and one durable receipt.
  • No owner key failure can select environment/operator/house payment without a valid explicit approval; BYOT_ONLY makes house approval ineligible.
  • Reservation, send, unknown-outcome recovery, release, settlement, usage rollup, and balance response all converge on the same binding after restart.
  • Responses and receipts are non-secret and name requested versus actual provider/model/payer without returning owner IDs or credential refs.
  • Account model choice UX remains useful, but tests prove it has no independent execution authority.

Resolved owner seam and remaining open questions

Current schema authority: deliverables.owner_user_id TEXT NOT NULL DEFAULT '__operator__'. A section action authorizes by joining section → deliverable and comparing that column to the authenticated owner. New authenticated creation must write the authenticated owner explicitly. Existing __operator__ rows remain a legacy operator namespace accessible only to the configured operator; never backfill or claim them for a friend from request text, creator metadata, or first access.
