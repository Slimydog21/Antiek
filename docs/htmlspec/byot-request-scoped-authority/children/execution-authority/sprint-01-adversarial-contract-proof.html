Adversarial authority proof

Owner: independent security verifier · Budget: 5 attack families

Parent context

The implementation claims that a paid Write call is bound to one authenticated owner, that owner's credential, and exactly one payer before reservation. This sprint tries to refute that claim across HTTP, storage tampering, concurrency, fallback, and restart. It authors tests/findings only; it does not redesign product UX.

Goal and milestones

Fail the release if any path can change owner, credential, payer, route, or fallback authority after authentication.

  1. Attack cross-owner IDs across resource, model, credential, approval, hold, receipt, and usage routes.
  2. Tamper registry fingerprint, binding version, ciphertext identity, duplicate metadata, and cached adapter state.
  3. Race replacement/revocation against resolution, reservation, decrypt, send, and settlement using barriers.
  4. Force not-sent, unknown, malformed success, timeout, and reconciliation conflict; assert fallback rules.
  5. Capture serialized events/logs/errors/receipts and scan for submitted secret, credential ref, owner ID, endpoint userinfo/query, and raw evidence.

Five-values rigor

Honesty

A green happy path is no evidence here; report untestable race windows explicitly.

Fairness

Distinguish an unavailable feature from an exploitable path; do not inflate severity.

Rigor

Each finding includes deterministic setup, observed call counters, persisted rows, and expected refusal.

Diligence

Exercise both BYOT_ONLY states, house approval expiry/replay, every gateway terminal state, and legacy holds.

Defensibility

Map every test to a threat-table row and retain minimal red proof before a fix.

Dependencies / out of scope

Run after SPR-01–03 implementation. No live keys, paid calls, production mutation, provider pentest, host-compromise simulation, or UI aesthetic review.
