Execution authority

Domain and gateway mechanics for owner, credential, payer, reservation, fallback, and settlement.

Spec lineage

Parent: Request-scoped BYOT/BYOK authority

Child sprint: Adversarial contract proof

Owned boundary

This subtree owns the security property, not general dispatch UX. The authoritative chain is authenticated owner → resource authorization → tagged credential authority → payer policy → exact route/fallback manifest → payer-specific durable pre-reservation binding → call-time decrypt → send once → settlement/reconciliation receipt.

InvariantEnforcement point
Conditional owner equalityBYOT requires request/resource/model/credential owner equality. House requires request/resource/approval owner equality while its platform credential surrogate remains platform-owned.
One payer and ledgerFrozen payer binding; BYOT never debits house, house never receives BYOT attribution, and BYOT_ONLY rejects house even if approval exists.
No implicit fallbackPersisted manifest; every rung independently credential/payer qualified.
Recovery continuityHold persists authority digest, payer-specific ledger account, and non-secret credential surrogate.
Secret containmentDecrypt only at send; receipts/logs use allowlist.

Acceptance boundary

  • User A cannot reserve, decrypt, send, recover, settle, or view key-specific usage for user B.
  • Missing/ambiguous/changed owner key yields zero decrypt, zero reservation, zero provider I/O.
  • Unknown provider outcome blocks all fallback until same hold reconciles.
  • Restart cannot change credential, payer, approval, route, fallback index, or operation identity.

Rejected alternatives

  • Process-global adapter as account authority: cannot bind a request owner.
  • Post-reservation register_hold_key: too late and not restart-safe.
  • Client-signed dropdown state: selection freshness is not resource, credential, or payer authorization.
  • Fallback to env on decryption failure: converts a user-key fault into silent house spend.

Harness hint

Run implementation sprints from the parent; use the child sprint as a default-to-refuted security gate.
