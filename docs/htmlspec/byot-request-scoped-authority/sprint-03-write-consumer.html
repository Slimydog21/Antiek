Authenticated Write vertical slice

Owner: Write/API worker · Budget: 7 milestones · Depends on SPR-01 (and gateway API from SPR-02 for final green)

Parent context

Today generate_section_draft reads deliverable/section context then calls default_dispatch_fn(investigation_id=deliverable_id); edit_selection calls central dispatch directly. Neither passes authenticated owner or a payer binding. Provider exceptions are interpolated into 503 responses, which risks leaking details.

This sprint makes section generation the first consumer. Selection editing follows only after the same resource-owner relation can be proved; it must not be smuggled into this sprint if ownership is ambiguous.

Goal

Execute one real Write generation action only through the request-scoped authority and return an honest non-secret execution receipt.

Technical milestones

  1. Require the repository's canonical authenticated identity dependency on section generation. Ignore/reject body/query owner claims.
  2. Make creation usable. Require authenticated identity on POST /write/context/promote and POST /write/deliverables/from-investigation. Thread it through promote_to_outline and promote_investigation_to_deliverable to insert_deliverable(owner_user_id=authenticated_owner); remove reliance on its __operator__ default for account-facing creation. Tests prove user A-created rows carry A, user B cannot use them, unauthenticated creation refuses, and the configured operator retains explicit legacy behavior.
  3. Authorize section → deliverable → deliverables.owner_user_id before reading prompt material. Legacy __operator__ rows are accessible only to the configured operator until an explicit audited claim; friends receive 403, and no backfill infers ownership.
  4. Accept optional account model choice as advisory {provider_id,model_id}. Resolve it server-side into SPR-01 authority; absent choice uses server routing policy but still requires owner credential or house approval.
  5. Pass the frozen authority through creative-writer generation to the SPR-02 gateway. Preserve no-blocks→gap as a zero-dispatch path.
  6. Map typed failures to stable HTTP envelopes: 401 unauthenticated, 403 resource/owner mismatch, 409 stale/unavailable selection or approval, 402/409 budget policy as established by billing conventions, 503 provider unavailable. Never interpolate provider/credential exception text.
  7. Return execution_receipt only on an attempted gateway action; include requested versus actual route and payer kind. Add end-to-end tests for authenticated creation, owner A/B, legacy operator rows, BYOT_ONLY, explicit house approval, missing key, stale choice, no blocks, fallback, and secret-negative logs/responses.

Likely files: interfaces/research/api/write_routes.py, substrate/write/promote_context.py, substrate/graph/ops.py, substrate/write/draft_generation.py, API/frontend types and focused tests. Keep edit-selection explicitly deferred unless the same owner proof is available.

Authoritative execution sequence

HTTP auth → resource owner check → advisory selection parse
→ owner-bound route + payer resolve (no decrypt) → freeze authority
→ prompt build → projection → persist authority with reservation
→ dispatch guard → revalidate metadata/approval → decrypt selected key
→ send once → settle/reconcile same hold → non-secret receipt

Any failure before reserve: zero provider I/O, zero secret load.
Unknown after send: no fallback; return recoverable operation state.

Rigor — five values

1 · Intellectual honesty

If deliverables are not owner-bound, report that architectural blocker. “Authenticated” alone does not prove authorization to a section.

2 · Fairness

Preserve config-selected creative-writer behavior for legacy operator actions only through the declared migration lane; do not break single-user use without a visible rollout state.

3 · Rigor

An integration test must instrument resolver, decrypt, reserve, send, settle and assert their order plus identical authority digest.

4 · Diligence

Exercise both normal generation and no-block gap; ensure the safe zero-model path never needlessly demands a credential or approval.

5 · Defensibility

Record why Write generation was chosen first and enumerate untouched Write AI actions so later work cannot imply complete coverage.

Dependencies and out of scope

SPR-01 contract required; SPR-02 gateway contract may be developed in parallel but final verification waits. Out of scope: Research roles, Read sidecar, Speak, multimedia, OAuth, provider account balance adapters, and UI redesign.
