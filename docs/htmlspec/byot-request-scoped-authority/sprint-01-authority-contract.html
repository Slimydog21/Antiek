Authority contract and payer policy

Owner: auth/dispatch worker · Budget: 6 milestones · Status: proposed

Parent context

Antiek already has owner-bound v3 BYOK metadata and a user-model resolver, while open PRs introduce operator-global certified credential bootstrap. Neither is a complete multi-user execution authority. This sprint defines the frozen request object and the only legal transitions that later sprints consume.

The account dropdown supplies a requested model choice only. Server authentication, resource authorization, credential ownership, route qualification, payer approval, and fallback authority are recomputed independently.

Goal

Introduce one immutable, plaintext-free authority contract and fail-closed resolver for a paid action. It must represent authenticated owner, authorized resource/action, exact route, tagged credential authority, payer, and fallback manifest without decrypting a secret. A BYOT binding carries an owner-bound v3 credential whose owner equals the request owner; a house binding carries only a platform route/credential surrogate authorized by the request owner's explicit approval and must never be misattributed to that user.

Technical milestones

  1. Map seams. Pin authenticated identity and the existing section → deliverable → deliverables.owner_user_id join. New rows write the authenticated owner; legacy __operator__ rows remain configured-operator-only until explicit audited claim. Confirm UserModelChoice, ResolvedUserModelRoute, certified operator route, dispatch precedence, and gateway intent types.
  2. Define tagged types. Add frozen DispatchAuthority, BYOT-versus-house CredentialBinding, PayerBinding, typed refusal codes, canonical serialization/digest. Acceptance: BYOT enforces request-owner equality; house uses a platform surrogate plus owner approval; plaintext/key-bearing types cannot inhabit fields.
  3. Resolve owner route. Join authenticated owner, deliverable owner, model record owner, and v3 credential metadata for BYOT without decrypting. House instead validates owner/resource/approval equality and exact platform route binding. Acceptance: every mismatch, duplicate, stale fingerprint, disabled record, v2 record, missing record, or false user attribution refuses.
  4. Implement payer policy. BYOT_ONLY permits only owner BYOT. House payer requires durable approval bound to owner/action/resource/route-or-manifest/ceiling/expiry/logical operation. Acceptance: table-driven truth table.
  5. Freeze fallback. Convert routing proposal to an ordered approved manifest with payer per rung; explicit call-site model remains selection input and research tier remains policy input. Acceptance: router config cannot append a rung after freeze.
  6. Threat tests. Add property/table tests for user A attacking user B, legacy operator rows, stale UI input, replayed approvals, expiry, ambient env key, and house credential misattribution. Acceptance: stable refusal, zero secret loads, zero reservations.

Likely files: new authority module under substrate/dispatch/, auth/resource adapters under interfaces/research/api/, focused tests. Do not modify gateway or Write route in this sprint.

Rigor — five values

1 · Intellectual honesty

If Write lacks an authoritative resource-owner column/relation, mark the sprint blocked; do not substitute the currently authenticated user or legacy operator owner.

2 · Fairness

Steelman process-global bootstrap: it is adequate for one configured operator. Preserve it as a separate lane while refusing to call it request-scoped multi-user authority.

3 · Rigor

Every resolution branch must assert whether secret loading and ledger reservation occurred; failures require both counts to remain zero.

4 · Diligence

Trace PR #2999 override precedence and PRs #3000/#3001 owner filtering before defining the resolver; avoid a second incompatible route selector.

5 · Defensibility

Record why payer is a first-class binding and why BYOT_ONLY dominates approvals and fallback config.

Dependencies

Upstream: none. Inputs: origin/main, PR diffs #2999–#3001, existing authenticated identity helper, credential metadata store. No real credentials or provider calls.

Out of scope

  • Provider send/reservation/settlement changes.
  • Frontend dropdown, balances, certified credential deletion, OAuth, custom endpoint qualification.
  • Broad Research/Read/Speak migration.
