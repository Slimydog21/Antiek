Operator-visible hard-ceiling fallback plan

Parent: Cycle 76 hard-ceiling fallback orchestration.

Outcome

The Settings decision tree shows the ordered server-configured fallback chain for the currently projected prompt, the independent maximum reservation for every route, the largest possible chain exposure, and the exact reason execution remains unavailable. The projection is read-only and cannot reserve, approve, dispatch, reconcile, settle, release, or imply that a configured route is qualified.

Authority boundaries

  • The request supplies a task, exact bounded usage, and optionally one route selected from the server-ranked candidates. It supplies no fallback routes, prices, capabilities, execution status, or budget facts.
  • The ordered chain comes from the selected candidate's server-owned tier in substrate/dispatch/config.yaml. Without an explicit choice, the server previews the recommended tier or, when no route is recommendable, the top server-ranked tier without relabeling it as recommended.
  • Every route is independently projected through the same project_cascade_cost authority and exact bounded workload as the chosen prompt projection. A missing or refused projection remains visibly ineligible.
  • Configured dispatch identity is not exact paid execution authority. Until a route is joined to Cycle 75's endpoint, provider kind, qualification, price, live adapter, and credential authority, its execution status is blocked_selection_authority.
  • The response authority is always advisory_fallback_plan. It is never an approval token or dispatch input.

Exposure invariant

Cycle 76 releases a proven-not-sent attempt before reserving the next route, settles and stops on success, and halts while any outcome is ambiguous. Therefore at most one route can remain charge-bearing. maximum_chain_exposure_cents is the maximum independently eligible route reservation, never the sum. It is null unless every route is hold-eligible and execution-authorized. Unknown is never rendered as zero.

Paid-chain boundary

This projection mirrors dispatch_paid_fallbacks. A zero_cost_receipt is not hold-eligible and therefore blocks this paid-chain preview; zero-cost work uses the gateway's distinct prepare_zero_cost path and cannot be presented as a paid fallback attempt.

Projection contract

{
  authority: "advisory_fallback_plan",
  tier: string,
  status: "executable" | "blocked",
  maximum_chain_exposure_cents: integer | null,
  would_exceed_budget: boolean | null,
  routes: [{
    fallback_index: integer,
    provider: string,
    model: string,
    registered: boolean,
    projection: {
      maximum_cost_usd: decimal-string,
      reservation_cents: integer,
      disposition: "hold_eligible" | "zero_cost_receipt" | "ineligible",
      ineligibility: string | null,
      rate_snapshot: string
    },
    hard_ceiling_eligible: boolean,
    execution_status: string
  }]
}

The route list is unique, ordered, bounded to 16, and shares the request seam, operation, and bounded usage. Malformed, cyclic, truncated, duplicate, missing-identity, or non-object tier state fails the complete preview closed.

Settings interaction

  • The existing Decision tree tab requests the model comparison and exact composer projection together. It displays the existing model selector, budget bar, chosen-route maximum, and the ordered fallback preview.
  • Selecting another eligible ranked model recomputes the server projection with the same task and usage. It does not launch work.
  • Changing task or usage invalidates comparison, selection, fallback preview, and errors. Starting or failing a refresh clears prior authority immediately. Monotonic request generations prevent late compare or selection responses from replacing newer state.
  • Blocked routes remain visible with their reason. There is no approval, run, retry, or provider command on this surface.

Acceptance

  • Backend tests prove server-owned order, duplicate/cycle/depth/malformed refusal, exact workload equality, route-by-route projection, max-not-sum exposure, all-or-nothing executability, unknown budget, and zero side effects.
  • HTTP tests prove no client route injection, no leaked rates or credentials, exact Decimal-string serialization, recommended and explicit-tier selection, current production blocked posture, and visible failure when the fallback projector is unavailable.
  • Frontend client validation rejects malformed route indexes, identities, costs, exposure, status contradictions, and unsafe integers.
  • Component and Settings tests prove ordered rendering, blocked reasons, no fabricated zero, explicit recomputation, stale-response refusal, input invalidation, and no launch call.
  • Run focused Python and Vitest suites, TypeScript typecheck, production build, Ruff, diff-check, hostile review, and HardenX strict.

Out of scope

No provider qualification flip, credential lookup, paid adapter, hold, execution, receipt persistence, launch payload change, learned routing, benchmark rewrite, merge, or deploy.
