Reading as a global feature

The reading experience stops being a place you navigate to and becomes a feature of every mothership: the same BookReader opens from Research and Write surfaces, one reading position follows the owner across standalone route, embedded window, workstation tab, and device — and every mount keeps the reader’s own gated fetch authority, its anchors, and its islands, unchanged.

Spec lineage

Root spec of the global-reading pillar, SIBLING to and consuming all three prior units: Anchor-first highlights (PR #3425 — anchors flow with the document), Research-thread island (PR #3428 — islands ride every reader mount), Workstation tabs (PR #3431 — the reader tab is its canonical window-kind tab; this unit wires the state bus and the affordances, it does not re-specify the container). It also stands on the SHIPPED Research evidence reader window, which proved one BookReader serves both the standalone route and an embedded window.

    Goal and proof boundary

    Success is: an operator reading a book in the standalone route hops to a Research workstation, opens the same document from a grounded source there, and the SAME reader window focuses on the SAME page — with its highlights, drifted anchors, and a live island exactly as the standalone view has them. Closing the laptop and opening another device lands on the same page. Asking about the document never requires leaving it, and no surface other than the reader ever fetches book body text.

    any mothership surface (Research source · Write cited block · workstation tab) → openWindow("reader", { documentId, origin }) — callers extended, registry untouched → stable per-document id → open = focus (one reader per document, windowsStore) → BookReader fetches via its own gated path (serve_full_text_guarded) — unchanged → reading-state bus: GET/PUT /books/{id}/reading-state (position + prefs, refs/numbers only) standalone route ⇄ embedded window ⇄ workstation tab: one position per owner+document → anchors (unit 1) + islands (unit 2) ride along from their OWN lawful stores — never duplicated

    The gap, with evidence

    One BookReader already serves both mounts: the standalone route (apps/reading/src/App.tsx:209) and the embedded reader window (openWindow.ts:106-108, stable per-document ids, anchor-aware placement from DeepResearchWorkspace evidence, modes/DeepResearchWorkspace/index.tsx:431-443) — the pattern spec’d and shipped in docs/htmlspec/research-evidence-reader-window/. But the embedding has exactly one caller: the only openWindow("reader", …) call site outside tests and the launcher is DRW evidence (DeepResearchWorkspace/index.tsx:433). ResearchWorkstation’s grounded-source rendering is an inert sentence — DistillView.tsx:296-302 shows “grounded in a source” for a node carrying source_document_id (lib/api.ts:1231) with no way to open it. Write’s block repository already searches by source document (writeApi.ts:62-78, source_document_id query param) but offers no path from a cited block to its source in the reader.

    There is no shared reading state: position is sessionStorage per documentId (modes/Reading/usePosition.ts:14-24 read, :47-61 write) — per-browser-tab, per-device, invisible to every other mount and machine. Research handoff from reading is navigate-away (ResearchThis.tsx:65-67 → /inv/:id); unit 2’s island fixes this for highlight→deep-research, and this unit’s origin-context path covers the rest. And ResearchWorkstation/Write are policy-barred from windows (openWindow.ts:42-50,78-81) — so “reading inside the workstations” composes through unit 3’s container (a reader window tab beside a route-kind surface), never through window-adapting those surfaces. Finally, a telling detail: the DRW reader payload already carries an origin marker (evidenceSourceContext: true, DeepResearchWorkspace/index.tsx:434) that nothing reads — origin context exists as a write-only precedent waiting for its first consumer.

    Key invariants

    • One BookReader: no second reader component, no reader fork, no mount-specific behavior branches inside the reader beyond what the window-mode prop already provides. Embedding questions are answered by composing the one component.
    • One position per owner+document: standalone route, embedded window(s), workstation tab, and other devices converge to a single server-held position. Two mounts of the same document on one screen show the same page because they read the same store, not because they synchronize with each other.
    • Refs and numbers, never content: the bus carries a page index, an optional anchor reference, and allowlisted pref keys. No book text, no selection text, no annotation content — those already have their lawful stores (units 1-2) or are unlawful to store (withheld text).
    • Fetch authority unchanged: embedding adds zero fetch routes to book bodies; serve_full_text_guarded remains the sole serving boundary (serve_guard.py:233). What is unservable standalone is unservable embedded, identically.
    • Origin is metadata: an origin context may prefill an affordance (dig-deeper question seed); it never creates a spawn path, never alters the spawned thread’s context beyond what the existing paths already accept, and survives being ignored.
    • Calm composition: new affordances are design-system only (DESIGN_LANGUAGE.md, FEEL_CONTRACT.md) — the grounding line gains a quiet action, the reader gains nothing visible.

    The reading-state bus (shape)

    GET /books/{document_id}/reading-state → { page_index, anchor_ref?, prefs, revision, updated_at } PUT /books/{document_id}/reading-state ← { page_index, anchor_ref?, prefs, revision } 409 on stale revision (never silent clobber) · 422 on non-allowlisted content owner-scoped (books.py conventions) · write-through, debounced client-side authority: server row (per owner+document) fallback: sessionStorage (usePosition.ts) when the server is unreachable — substrate-wins merge, same rule as useInvestigationTree.ts:40-46 sync: same-page mounts share the client store (one app, one zustand slice); cross-device converges on load + refetch on window focus

    prefs is a server-validated allowlist that is empty in v1 — the reader exposes no display prefs today (verified: no font/layout pref in modes/Reading/), so any non-empty prefs map is a 422 until a pref genuinely ships and joins the allowlist. The field exists so adding a pref later is data, not schema. anchor_ref is an optional unit-1 anchor id recording the passage the operator last engaged — a ref, never the passage.

    Sprint roster

    SPR-01 · The reading-state bus

    Contract. Server: substrate/books/reading_state.py (schema + store) following the unit-1/unit-3 conventions — additive idempotent DDL under the write lock, one table reading_state (owner_user_id · document_id · page_index INTEGER CHECK ≥ 0 · anchor_ref nullable · prefs_json CHECKed against the empty v1 allowlist · revision · updated_at, PK on (owner_user_id, document_id)). Router interfaces/research/api/reading_state_routes.py: GET/PUT as above, owner-scoped per the books.py:140 convention, 409 on stale revision. Client: api/readingState.ts on apiFetch + hooks/useReadingState.ts — a small zustand slice keyed by documentId, load-on-mount, debounced write-through on page turn, refetch on window focus, and the substrate-wins fallback to usePosition’s sessionStorage when the server is unreachable (honest degradation: reading never blocks on the bus). BookReader’s wiring change is exactly one hook substitution: position source becomes the bus with usePosition as its fallback layer; clamp-on-shrink (usePosition.ts:39-45) is preserved.

    Proof (real calls):
    • FastAPI TestClient against a real DuckDB fixture: PUT → GET round-trip per owner; a second owner’s GET is 404/empty; stale-revision PUT → 409 with the row unchanged; non-empty prefs_json → 422 (v1 allowlist enforced at the API AND as a CHECK at the DB layer).
    • Vitest with the real hook against a mocked transport: standalone route and a window-mounted reader (the renderWindowReader harness, Reading.test.tsx:262) share one position through the client store — turn the page in one mount, the other shows it; no mount-to-mount signaling exists to test because none is needed.
    • Degradation: transport failing → position still works from sessionStorage, and on recovery the server value wins (the merge rule exercised, not assumed).
    • Clamp: a stored position past a shortened book snaps to the last page on load (existing clamp, now against server-held values).

    Non-goals: new affordances, workstation integration, scroll-offset or per-paragraph position, prefs beyond the empty v1 allowlist, real-time cross-device push (converge-on-load/focus is the contract).

    SPR-02 · The affordances — reader from Research and Write

    Contract. Three callers join DRW evidence, all using openWindow("reader", …) verbatim with the stable per-document id (win:reader:{documentId}, DeepResearchWorkspace/index.tsx:436) so the one-reader-per-document invariant holds by construction. (a) ResearchWorkstation: the grounded-source line in DistillView (DistillView.tsx:296-302) becomes a quiet “Open in reader” action when source_document_id is present, carrying origin { from: "research", investigationId }. (b) Write: repository hits / outline blocks with source identity (the source_document_id seam, writeApi.ts:62-78) gain the same action, origin { from: "write", deliverableId }. (c) Origin context: the payload field becomes { from, id } metadata — the first CONSUMER of the write-only evidenceSourceContext precedent — used solely to prefill the reader’s dig-deeper/chase affordance with the calling context (e.g. chase parent = the investigation the operator came from). Ignoring the context is lawful and changes nothing. The policy bar stands: ResearchWorkstation and Write surfaces themselves are NOT window-adapted; only the reader floats.

    Proof (real calls):
    • Vitest over DistillView: a node with source_document_id renders the affordance, activation calls openWindow with the exact id + origin payload; a node without one renders the same inert “no source on record” as today (no dead affordance).
    • Vitest over the Write repository surface: a hit with source identity offers the action; activating it opens (or focuses) the reader window with { from: "write", … }.
    • Focus invariant end-to-end: open the same document from Research, then from Write, then from DRW evidence — exactly one reader window exists and each activation focused it (asserted on windowsStore state, three caller paths).
    • Origin consumption: a reader window opened with { from: "research", investigationId } prefills its dig-deeper affordance with that investigation as chase parent; a window opened WITHOUT origin renders the default affordance — and the spawn itself still goes through the existing paths (no new spawn call exists to test, asserted by network mock surface).

    Non-goals: the bus (SPR-01), workstation tabs (SPR-03), changing what the reader renders, window-adapting any barred surface, backfilling the unread evidenceSourceContext flag beyond unifying it into the origin shape.

    SPR-03 · Workstation citizen — continuity across hops and mounts

    Contract. The reader tab (unit 3: { surface: "reader", payload: { documentId } }) participates in the bus like every mount: hop away mid-book and back (⌥1-9, unit 3), the page is where the bus says it is; the standalone /read/:id view of the same document agrees because there is one position, not two synced copies. Workstation switch (unit 3’s reset + replay-open) reopens a reader tab at its bus position with default window geometry — position survives, geometry does not (both rules intact). This sprint also lands the assert-not-rebuild proof for decision 4: the FloatMenu’s Dialogue and Search actions work identically in every mount because the mounts share one BookReader and one host wiring (Reading/index.tsx:233-259) — the proof is a test matrix over mounts, and any mount-specific divergence it finds is a bug to remove, not a feature to keep. The lighter “ask about this document” path (Dialogue one-shot, Search corpus) is thereby global without a single new code path; deep-research stays with unit 2’s island.

    Proof (real calls — both mounts AND a workstation tab):
    • Hop continuity: in a workstation with a reader tab, turn to page N, ⌥-hop to another tab, hop back — page N (from the client store); reload — page N (from the server row); the standalone route of the same document shows page N (same row, one position).
    • Workstation switch: reader tab closes with its workstation; switching back replay-opens it at the bus position with default rect (window geometry session-scoped — asserted absent from every restored descriptor).
    • Mount matrix: standalone route, reader window, reader tab — FloatMenu Dialogue and Search render and fire identically in all three (same components, same payloads; §9.0 withheld-selection refusal behaves identically in all three).
    • Position conflict honesty: two “devices” (two client instances against the test server) — last writer wins via revision, the loser converges on next focus/refetch; no merge fiction, no error theater.

    Non-goals: changes to unit 3’s container, unit 2’s island, or BookReader rendering; live collaborative position (multi-owner); scroll-level continuity; making position real-time across devices (focus-convergence stands).
