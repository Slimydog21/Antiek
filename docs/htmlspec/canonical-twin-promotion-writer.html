Canonical twin promotion writer

Materialize one currently accepted evidence-bound twin proposal as one owner-private insight or question node without inventing truth, citation, or public authority.

Transaction

The writer requires a coordinator-issued graph connection and owns one DuckDB transaction. It revalidates the exact Cycle 114 candidate, signed owner review, complete promotion history, canonical twin, ordered excerpts, rights, and takedown state before insertion and immediately before commit. Any contradiction rolls back the graph write.

Node

Identity is deterministic from owner, closed kind, and canonical text through the existing sanctioned insight/question writer. The node is private, unembedded, and carries versioned hash-only metadata binding candidate, review, source revision, canonical publication, and every ordered evidence range. The metadata states that authority was current at materialization and must be revalidated before reuse. Exact replay is a no-op; an existing conflicting node fails closed.

Provenance honesty

The graph edge table links nodes to nodes. Canonical twins are documents and evidence is chunk-scoped, so this sprint creates no false self-edge, phantom claim node, or document-as-node. Complete ordered provenance remains on the node. A normalized node-to-chunk citation table is a future schema authority.

Non-goals

No post-materialization revocation worker or reuse reader, model, embedding, provider, generic claim, finding, gap, citation edge, synthesis promotion, HTTP route, UI, public sharing, production mutation, merge, deployment, or spend. A later takedown blocks replay but does not erase the historical private node.
