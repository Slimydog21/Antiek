Multimedia Knowledge Finalization

TV executable sub-spec. Join the authenticated multimedia asset store to the canonical HTML, graph, and recursive-twin lifecycle delivered by PR #1031.

Operator Contract

  1. The request is authenticated by the mounted multimedia owner boundary.
  2. The operator supplies the exact current revision and explicitly acknowledges note-model use.
  3. An unavailable, foreign, planned, stale, or unacknowledged asset fails before distiller construction.
  4. Runtime activation requires both an explicit enable flag and a graph database path.

Authority Order

StepAuthority and invariant

2. ProjectThe ready record becomes deterministic inert multimedia HTML with exact citations.
3. RegisterCanonical graph/twin registration checkpoints the first distillation, commits private nodes, and reconciles events.
4. LinkThe asset store compare-and-sets an immutable MultimediaKnowledgeLink for the same asset and revision.

Recovery

A durable in-progress claim commits before model dispatch. Concurrent requests fail closed. If the model outcome becomes uncertain before checkpoint publication, replay refuses another model call and reports that operator recovery is required. Once the checkpoint exists, graph registration precedes the JSON asset link; a link-publication failure replays without another model request and retries the owner-bound compare-and-set. A conflicting existing link fails closed.

Revision Semantics

Finalization first reserves the exact current revision in the owner-bound asset store. Steering is rejected while that reservation exists. A successful link clears the reservation; later steering creates a child revision and clears the previous revision link. Historical graph documents remain private and immutable, and the new revision requires independent finalization.

Acceptance

Tests must prove successful durable linking, list/get visibility, replay without another distiller call, graph-complete/link-missing repair, one model call under concurrency, uncertain-outcome retry denial, revision reservation, owner opacity, stale and unready rejection, acknowledgement ordering, link conflict rejection, steering invalidation, unavailable runtime behavior, and zero paid-media provider calls.

Non-Goals

No media provider execution, publication, cross-store atomicity claim, frontend redesign, merge, or deploy.
