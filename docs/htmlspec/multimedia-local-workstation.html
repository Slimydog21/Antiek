Expose cheapest-local production as an authenticated workstation

Executable child spec of the cheapest-local master and the durable coordinator. The workstation makes zero-provider production usable without routing cheapest through paid narration, Krea, paid authorization, or the paid production worker. It must describe cheapest as fully local and $0; there is no automatic paid fallback.

Product contract

  • Preflight: report one opaque capability state for local speech, ffmpeg/ffprobe, private storage, graph evidence, source-card font, operator signing authority, and verified playback. Do not return executable paths, hashes, keys, local filenames, or environment values.
  • Prepare: derive the exact current owner revision's spoken chapters and deterministic source-card requests server-side. The browser cannot author text digests, paths, graph snapshots, evidence digests, or run IDs.
  • Review: show each rendered source-card preview with its chapter, sources, and visible diagrammatic/non-archival disclosure. Attestation is an explicit owner action per card; it is never automatic or bundled into production.
  • Produce locally - $0: begin only after all spoken chapters have successful local WAV authority and all scenes have explicit diagram evidence. The command carries only asset ID, expected revision, and opaque prepared-set ID.
  • Recover: a producing/rendering/receipting unknown outcome presents one explicit recovery command. Generic retry is disabled. Recovery adopts only exact verified output.
  • Playback: after registration, use existing authenticated metadata and byte-range endpoints for video/audio. The workstation does not expose receipt internals.

Dedicated runtime

Create a separate all-or-nothing local runtime and router. Environment composition must require independent keys, private directories, graph DB, source-card font, operator signing/verify keys, /usr/bin/say, ffmpeg, and ffprobe. Partial configuration fails startup. The local runtime imports no gateway poster, provider credentials, paid authorization, Krea submitter, reviewed-visual registry, or paid worker.

Authenticated API

  1. GET /multimedia/local/capability: opaque availability and reason code.
  2. POST /multimedia/assets/{asset_id}/local/prepare: exact revision precondition; create/reopen chapter WAVs and source cards; return an owner-bound opaque prepared-set read model.
  3. GET /multimedia/assets/{asset_id}/local/{revision_id}: phase status, chapter/card review rows, recoverability, zero cost, and playback readiness.
  4. POST .../cards/{card_id}/attest: explicit owner attestation using server-held signing authority; return refreshed read model.
  5. POST .../produce: consume only the prepared-set ID and expected revision; run through receipt and registration.
  6. POST .../recover: recover the exact current run; never starts a different run.

Every command depends on the existing authenticated operator. Foreign, stale, non-ready, non-video, non-cheapest, changed-plan, incomplete-evidence, and conflicting-run requests return opaque 404/409 responses. Runtime absence is 503. Secrets, signatures, paths, provider identities, and stack traces never cross the API.

Durable prepared set

A MAC-protected set binds owner digest, asset, revision, canonical plan digest, ordered chapter request IDs, ordered source-card IDs, explicit attestation IDs, coordinator input/config digests, and status. It is immutable. Steering creates a new revision and makes the old set non-current; old receipts remain reopenable but cannot register onto the new revision.

Workstation behavior

  • Cheapest tier copy reads Fully local narration and source-card documentary. No Krea or paid-provider fallback.
  • A capability row appears only for cheapest video/hybrid assets. Audio-only local production is deferred and not mislabeled as video.
  • Chapter rows show narration ready, source card ready, attestation required/complete, and source count. Controls are icons with tooltips where conventional.
  • The primary command is disabled until preflight and evidence are complete. During execution, phase progress is stable and does not optimistically jump.
  • Unknown outcomes replace the primary command with Recover local production. The UI never says “try again.”
  • Successful registration switches directly to the existing verified player and displays $0.00 · Local.

Acceptance

  • Route tests prove owner/revision/prepared-set binding, opaque errors, explicit attestation, exact replay, and recovery-only unknown outcomes.
  • Runtime tests prove all-or-nothing configuration, independent keys, private paths, pinned executables/font, and total absence of provider/gateway/Krea seams.
  • A real API fixture prepares, reviews, attests, produces, recovers injected crashes, registers, and streams byte ranges with exactly zero cost.
  • Frontend tests prove corrected cheapest copy, preflight gating, card review, explicit attestation, phase progress, recovery replacement, stale-response invalidation, and verified playback.
  • In-app browser QA at desktop and mobile proves no overlap, clipped labels, blank media, or incoherent controls. Full backend/frontend suites, build/typecheck, HardenX, independent review, and rendered screenshots are required.
