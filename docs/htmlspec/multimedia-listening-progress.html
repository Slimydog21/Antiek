Antiek Multimedia / Cycle 22

Resume an audible lesson exactly where listening stopped

Make 15–45 minute lessons usable across interrupted walks, runs, workouts, and devices without weakening receipt-verified playback.

Product Contract

Listening progress is private user preference state, not media authority. It may select a position only after the current local or paid playback chain has independently reopened and verified the exact asset, revision, audio digest, duration, and chapter timeline.

  • Opening verified audio restores the latest non-complete position for the authenticated owner and exact registered audio revision.
  • The player displays a concise resumed state and offers Start over, which seeks to zero and durably replaces the saved position.
  • A lesson within five seconds of its verified end is recorded as complete. Reopening a complete lesson starts at zero and names it as previously completed; replay checkpoints clear completion.
  • Local-zero and authorized paid audio use the same progress contract and UI.

Durable Authority

  • Add a bounded MultimediaListeningProgress envelope stored beneath the existing private account-digest directory, in a dedicated listening-progress/ subdirectory so it cannot be enumerated as an asset.
  • Identity is owner_identity_digest + asset_id + revision_id + audio_sha256. Persist integer position_milliseconds, verified duration_milliseconds, completed, monotonic per-player session_id + sequence, and server updated_at.
  • Every read and write first loads the owner asset and requires the requested revision to be current, the asset to be audio mode, and its registered audio link to carry the same revision, digest, and duration. The browser cannot supply audio identity or duration.
  • Use the store's cross-process lock, private regular-file checks, bounded reads, no-follow creation, atomic replace, directory fsync, and raw-owner-ID exclusion. A malformed or unsafe sidecar is an integrity conflict, never absence.
  • A write accepts finite milliseconds in [0, verified_duration], a bounded random session ID, and a non-negative safe integer sequence. Within one session, a sequence at or below the stored sequence is an idempotent stale write and cannot replace newer progress. A different session may replace progress by server arrival order.
  • Historical-revision progress may remain on disk but is never returned for a new revision. No migration guesses an equivalent position.

HTTP Contract

OperationResult
GET /multimedia/assets/{asset_id}/listening-progress?revision_id=…Authenticated current-owner projection. Returns resume_available=false for no row; opaque 404 for foreign/missing asset; 409 for stale revision or integrity conflict.
PUT /multimedia/assets/{asset_id}/listening-progressAuthenticated explicit checkpoint with expected revision, position milliseconds, session ID, and sequence. Returns the stored projection, including whether the write was applied.

Responses are private, no-store. They expose no owner digest, filesystem path, receipt, MAC, signing material, or historical revision row.

Browser State Machine

  • Mint one cryptographically random session ID per mounted playback identity. Sequence numbers increase for every queued checkpoint.
  • Load progress once per asset/revision/audio URL. Apply it only on loadedmetadata, only if the response still matches the mounted identity, and never autoplay.
  • Do not checkpoint while applying resume or resetting identity. Thereafter serialize writes through one promise chain: at most one periodic checkpoint per 15 seconds of playback, plus exact checkpoint on pause, ended, Start over, and page hide where supported.
  • Seeking backward is valid. Serialization and sequence rejection prevent an older in-flight position from overwriting a later pause or Start over.
  • Progress service failure never blocks verified playback. Show a restrained status near the player; retain the local position and allow retry on the next checkpoint.
  • Unmount and identity change invalidate pending loads and UI updates. A stale response cannot seek, label, or mutate the next asset.

Refusals And Attacks

  • No progress for video, unregistered audio, foreign owner, missing link, stale revision, mismatched duration, non-finite/out-of-range position, malformed session/sequence, unsafe path, duplicate sidecar identity, or corrupt JSON.
  • No client-derived duration, chapter ID, digest, completion flag, timestamp, or owner identity.
  • No autoplay, background media fetch, provider call, synthesis, steering mutation, research launch, graph write, spend, analytics-as-authority, or claim that a checkpoint proves the user learned or heard the interval.
  • Do not modify the sealed multimedia asset envelope merely to save volatile playback preference.

Acceptance Evidence

  • Store tests cover exact owner/revision/audio identity, absent read without mutation, private atomic persistence, stale sequence idempotence, cross-session arrival, completion threshold, backward seek, corruption, symlink, permissions, and revision drift.
  • Route tests cover authentication, local and paid registered links, absent projection, save/read round trip, foreign opacity, stale revision, malformed body, no-store headers, and safe errors.
  • Browser tests cover metadata-gated restore, no autoplay/no write on load, periodic throttle, serialized pause/Start-over writes, complete replay, stale response rejection, API failure, identity reset, and both player hosts.
  • Focused and broad multimedia tests, TypeScript, production build, Ruff, HTML parse, diff hygiene, heterogeneous adversarial review, and HardenX strict pass on the exact final tree.
