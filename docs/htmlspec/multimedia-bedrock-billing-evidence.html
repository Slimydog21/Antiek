Cycle 31: Bedrock billing evidence qualification

Status: executable refusal-and-evidence specification. Parent: Cycle 30 Bedrock identity recovery. Base: 5affe95cab341ff904e8ddc5c7f449118db5773c.

Spec lineage

Cycle 30 owns provider identity and lifecycle recovery. This child owns immutable classification of billing evidence and the mechanical proof that presently available AWS evidence cannot settle one job.

  • A future child may add settlement only after official provider evidence satisfies every exact-attribution criterion below.

Verdict

Do not qualify or production-enable Bedrock. The job output manifest authoritatively reports job token totals, but token totals multiplied by public rates are derived list price. CUR/Data Exports can report account billing line items, but AWS documents lineItem/ResourceId as optional and blank for usage not associated with an instantiated resource; Bedrock does not document a guaranteed job ARN or client token join on every charge, discount, credit, refund, or tax line. Cost-allocation tags are delayed and their propagation to every batch charge is unproven. No current evidence class is exact final per-job USD.

Five load-bearing values

  1. Classification before authority: evidence states what it proves and never gains settlement power by being persisted.
  2. Metering is not billing: provider token totals and rate multiplication remain separate from account charges.
  3. Aggregate truth is not job truth: a valid CUR row can be authoritative for an account period while remaining unattributable to one job.
  4. Finality is multidimensional: report period closure does not allocate later credits, refunds, discounts, or taxes to a job.
  5. Unknown retains authority: every non-exact class leaves the full hold and billing_pending unchanged.

Evidence contract

Job metering

Bind job ARN, account digest, region, model, terminal provider observation, output-manifest object identity/version/digest, exact integer record and token counts, and retrieval timestamp. Never persist prompt or output bytes.

Derived list price

Bind metering digest plus immutable provider/model/region/tier/rate snapshot and exact decimal calculation. Label it derived_list_price; it is projection evidence, not settlement.

CUR observation

Bind report/export identity, billing period, account, region, product, operation, usage type, resource ID, line-item type, exact decimal usage/rate/cost fields, tags, ingestion time, raw digest, and report status. Store no credentials or raw report rows.

Qualification

Derive a fixed classification and ordered reason codes from canonical evidence. Caller-supplied labels, totals, finality, or attribution claims have no authority.

Schema v5

Add an append-only research_provider_billing_assessments table in the shared spend ledger. Each deterministic assessment binds one Cycle 30 submission and hold, owner/run/provider/job identity, evidence kind, canonical redacted evidence, raw digest, classification, ordered reason codes, literal settlement_authorized=0, and timestamp. Immutable database triggers reject update/delete. Command receipts make exact replay byte-stable and changed evidence conflict.

Allowed classifications are provider_metering_only, derived_list_price, cur_aggregate_observed, invoice_period_finalized_unattributable, and exact_job_final_cost_unavailable. Schema v5 contains no exact/settled classification because no supported evidence contract earns it.

Future settlement bar

A future adapter may add an exact class only when primary provider contracts prove all of: immutable account identity; exact job identity on every relevant usage line; complete line-item set; exact USD decimal amount; explicit treatment of discounts, credits, refunds, and taxes; report finality and correction semantics; unique non-overlapping attribution; authoritative lookup after response loss; and replay-safe settlement. Every dimension must be mechanically tested. A unique tag or matching token count is insufficient.

Acceptance

  • Schema v4 migrates transactionally to v5; injected failure at every statement rolls back without changing v4 bytes.
  • Only a billing_pending Bedrock submission with a bound ARN and unknown full hold accepts an assessment.
  • Assessment ID and command replay are deterministic; changed evidence under either identity conflicts.
  • Canonical/scalar/cross-table tampering, owner substitution, malformed decimals, floats, negative counts, wrong account/region/model/job, duplicate rows, and unsupported evidence kinds fail closed.
  • Every accepted assessment leaves submission state, hold state/amount, run balance, launch operation, and qualification registry byte-equivalent.
  • Provider metering, derived price, open CUR, finalized-unattributable CUR, tags without guaranteed propagation, credits/refunds/taxes, and ambiguous concurrent jobs have explicit regression tests.
  • No AWS client factory, credentials, S3 read, CUR query, provider call, production route, qualification flip, settlement, release, event, graph write, task, or scheduler is added.

Primary-source basis

  • Bedrock batch results: output manifest exposes record and token counts.
  • CUR line-item columns: ResourceId is optional; discounts, credits, refunds, and taxes are distinct line types.
  • Cost-allocation tag activation: tags require activation and can take up to 24 hours at each stage.
  • Bedrock pricing: batch rates support list-price derivation, not invoice attribution.

Out of scope

No production AWS integration, report downloader, S3 result ingestion, automatic polling, exact invoice claim, settlement/release, provider qualification, result artifact, event/graph projection, background scheduling, or UI.

Harness hint

One builder owns schema and classifier. A separate critic tries to turn token totals, matching aggregate cost, unique tags, period closure, zero-cost rows, and caller labels into settlement authority. Require proof that every attack leaves the full hold unchanged.
