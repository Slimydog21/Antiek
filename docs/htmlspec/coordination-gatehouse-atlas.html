Coordination Gatehouse Atlas

Execution source of truth for a branded, fail-closed view of canonical operator gates and the dependency-derived cross-product roadmap.

Binding truth contract

  • The surface displays canonical state; it never changes a gate, sprint, roster, payout, or training configuration.
  • Gate and sprint counts are payload-derived. No prose may hardcode eight, thirteen, or forty-five as current truth.
  • status_raw preserves nuance; the coarse status controls presentation only.
  • Empty impacts mean “no reviewed per-product mapping,” never “no product block.”
  • Unblocked means dependency-unblocked, not done, approved, funded, or ready to ship.
  • G8 is displayed as data-bound. This work must not build or activate Loop 3 training.
  • No raw network, HTTP, parser, or validation error reaches the DOM.
  • No freshness or completeness timestamp may be invented; neither endpoint supplies one.

Prerequisite — canonical register repair

The canonical quick table contains G1–G13 while the inherited parser and its supposedly independent verifier recognize only G1–G8. Generalize both extraction paths, add the missing G13 detail section without changing its documented closed status, ground new impact mappings in repository specs, and prove quick-table/detail equality for the complete register.

Experience architecture

  1. Glass hero: “Coordination Gatehouse Atlas,” one Werner, and an Antarctic gatehouse environment.
  2. Truth boundary: read-on-request, canonical sources, no mutation authority, no freshness metadata.
  3. Blocking frontier: payload-derived status tally and open/waiting gates foregrounded without inventing priority.
  4. Gate Wall: open/waiting gates first, then closed; raw status, owner, blocks, closure evidence, and reviewed workflow impacts.
  5. Route Atlas: API reconciliation, ordered critical path, rosters, dependency waits, unblocked-now, and substrate bedrock.
  6. Cost & Consent doorway: navigation only; no money claims on this surface.

Controller contract

  • Pure exported CoordinationView plus a fetching controller.
  • Gates and roadmap have independent loading, ready, and error states.
  • A scoped retry fetches only its failed endpoint.
  • Every response is runtime-validated before render.
  • Request tokens discard stale responses after every await and on unmount.
  • Gate IDs, statuses, workflow impacts, safe integers, roster counts, unique node IDs, critical-path membership, and dependency references are validated without assuming a fixed gate/sprint count.

Visual and responsive contract

Use the project-bound, text-free ChatGPT Image environment. HTML panels remain the sole semantic and interactive layer. Use canonical Antiek tokens, static motion-safe scenery, visible focus, textual status labels, narrow stacked roster rows, and a forced-night Storybook fixture. Werner is thinking while either request loads, empty only when both fail, and otherwise calmly keeps the gatehouse.

Required stories
