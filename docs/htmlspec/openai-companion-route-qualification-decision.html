OpenAI Companion Route Qualification Decision

Decision date: 2026-07-15. Verdict: refused.

This decision evaluates the strongest current candidate for derived companion answers: OpenAI Responses deep research. It grants no adapter, registration, spend, network, or dispatch authority.

Five-dimension audit

DimensionStatusCurrent evidence
Pinned pricingUnprovenOfficial pricing publishes model and tool rates, but responses-deep-research is a route family rather than one concrete model with a bounded tool workload.
Durable idempotencyUnprovenThe API overview documents request tracing but does not document a provider-enforced idempotency key for Responses creation.
Hidden retries disabledPassThe official Python SDK documents max_retries=0.
Authoritative reconciliationUnprovenSigned webhooks can deliver terminal response events and a response ID after the create caller disconnects. The documented mechanism does not yet prove exact Antiek-key correlation, complete terminal-event coverage, authoritative absence, or final billable reconciliation.
Stable provider evidencePassStored background responses expose provider status and usage when the response ID is already known.

Polling and webhooks

Polling proves what happened after Antiek durably receives a provider response ID. Signed webhooks are the strongest documented recovery path when the create caller loses that ID, and OpenAI documents retried delivery for a bounded period. This improves recovery but does not establish provider-enforced create deduplication, an authoritative not-found answer keyed by Antiek identity, complete correlation when the response ID was never observed, or a final billing record. Retrying the create remains capable of duplicate paid work until those semantics are documented and proved.

Promotion requirements

  1. Primary documentation for provider-enforced deduplication of Responses creation using a caller-supplied stable key, including retention and conflict semantics.
  2. A provider-authoritative query that resolves completed, failed, absent, and still-running work from that same key and returns stable billable usage.
  3. One concrete model and bounded tool workload with a pinned pricing snapshot compatible with Antiek's reservation model.
  4. A concrete adapter implementing Cycle 65's pure normalization contract, registered only after the evidence registry is fully qualified.
  5. Crash-window integration tests proving no duplicate send and exact settlement/release/unknown transitions.

Acceptance

  • The machine-readable OpenAI route remains refused.
  • Its exact blockers remain pinned pricing, durable idempotency, and authoritative reconciliation.
  • The empty production adapter registry and public execution projection remain dispatch-denied.
  • A future date change alone cannot promote the route; all five evidence dimensions and explicit adapter registration must pass.
