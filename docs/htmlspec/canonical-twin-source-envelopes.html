Canonical twin source envelopes

Status: executable Cycle 105, stacked on the Cycle 104 durable twin lifecycle. This closes initial graph-document declaration and backfill. It does not execute model work or claim platform-wide twin completion.

User outcome

Every information-bearing document entering Antiek's canonical graph declares, durably and exactly, which account, source bytes, title, class, and provenance event must seed its recursive notes twin. The declaration cannot be lost after the document commits because both occupy one row mutation.

Canonical chokepoint

substrate.graph.ops.insert_document is the existing writer used by research paste/file ingest, book publication, wrestling document loads, multimedia source HTML and twin publication, and direct graph admission. Cycle 105 adds documents.twin_source_envelope and supplies it in the same INSERT INTO documents statement. It does not add a second asset registry or a cross-database transactional claim.

Any direct SQL document insert that omits the envelope remains detectable and cannot pass completeness verification.

Identity

The canonical envelope is compact sorted UTF-8 JSON. Its account is documents.owner_user_id; its asset identifier is document_id; its title is the stored title or identifier fallback; its class is document_type; and its body identity is the SHA-256 of exact raw_text. Body bytes remain only in documents.raw_text; the envelope never duplicates copyrighted or private content. A deterministic event-shaped declaration identifier binds schema, account, identifier, title, class, and body hash. It identifies this durable declaration and does not claim an external provenance event. The Cycle 104 source hash then binds the complete asset reconstructed under the graph write lock.

Migration and replay

  1. V20 adds the nullable column without inventing declarations for existing rows.
  2. The locked backfill reads canonical stored fields, derives each envelope, and commits every update in one transaction. Any invalid legacy row rolls the complete batch back.
  3. An idempotent insert_document(..., on_conflict="ignore") fills a legacy NULL from stored bytes, never replay caller bytes.
  4. The verifier re-derives every selected row and exact-compares canonical bytes. Body/title/type/owner drift, malformed JSON, substitution, or missing declarations fail closed.
  5. Legal takedown clears raw_text and replaces the envelope in the same guarded document update, leaving no hidden body copy.

Projection and tenancy

The projector first verifies only the requested account's graph rows, then registers every eligible source in the Cycle 104 SQLite authority. A crash can leave a prefix registered, but replay converges because both source identity and registration are deterministic. Foreign-account corruption cannot block an owner's projection; the global verifier still detects it. No account can supply another account's envelope or ledger key.

The lifecycle ledger stores the same hash-only source commitment, never a second copy of raw_text. Signed completion receives current source bytes from the verified graph projection boundary; the ledger exact-compares their commitment before materialization.

Coverage semantics

unknown means no eligible or unresolved information asset exists. partial means an eligible source is pending/failed or a real body still requires binding, enrichment, or segmentation. universal requires every exact eligible declaration selected for the account to have a ready Cycle 104 binding and no unresolved real-body state. Metadata-only rows are reported separately and do not manufacture either success or failure.

Acceptance evidence

  • Fresh insert and envelope are one SQL row mutation and roll back together.
  • Legacy NULLs backfill atomically and idempotently from stored bytes.
  • Direct SQL bypass, drift, and canonical-looking substitutions fail verification.
  • Short and oversized real bodies remain explicit unresolved work.
  • Projection is account-scoped, restart-safe, and creates no paid work.
  • Existing graph, research ingest, book import, multimedia registration, and twin lifecycle behavior stays green.
