Prompt-driven reformatting + bite-level provenance

Any information asset — a document, a book, a derived asset — can be reformatted by prompt: compressed to a time window, expanded around chosen insights/themes/questions, supplemented with deep research. Every bite of the derived asset carries a defensible provenance row — author-verbatim byte-PROVEN, LLM-compressed, LLM-expanded, or research-supplemented with its investigation — so the line between what the author wrote and what the model did never blurs, and every probe on a derived bite resolves to the core, unscrambled artifact.

Goal and proof boundary

The operator's words, the contract's source: "I can reformat a document/book or any other information asset based on a prompt to be read in a certain time window or to narrowly discuss the insights, themes, or questions I want to discuss. The subagent on the right where I prompted stays as an agent engagement, then it asks me to open the document in the project where it then opens it on the left pane. I can then decide to merge it later or officially fork it. …I hate static human ingestion… But one thing I do not want to lose in the reformulation is a blurred line between what the author wrote versus what was compressed or expanded with an LLM; or even what was supplemented with additional deep research… I want to build an information provenance technology that defensibly traces and sincerely understands the contribution of every information bite… Snippets from the core document digging deeper into a certain highlighted insight or question can be pulled when prompted, and the answer of a probing query of a condensed or expanded information asset always leads to a core unscrambled core artifact. It is fine if the deep research is a reasoning trace weaving various core truth artifacts as long as it is cited or at least noted in the agent-facing metadata so that the Ad system can pick up on it (not presenting the root and core evidence is the choice of the AI system being prompted — sometimes quote-bomb style hinders lucid and smooth information delivery)."

Success is: the operator prompts the right-pane agent on an open book — "the 20-minute version, focused on the pricing chapters" — and a derived document is generated with a full generation record; the agent asks to open it, the operator confirms, and the derived document opens BESIDE the source in the project; every bite of the derived document is classed (author-verbatim bites byte-PROVEN against the source spans), and one click on any compressed bite lands on the author's actual passage in the core document; a probing deep-research over the derived asset cites the core spans in its agent-facing metadata. The operator then merges later (the unit-5 shape) or officially forks (the unit-5 primitive). Throughout, the original is byte-identical, and a withheld source's derived asset inherits the gates — never a laundering path.

Key invariants

  • Originals are immutable. No reformat, review, merge-later, or fork operation ever writes the source document. Asserted by before/after body hash in every sprint's proofs, never by review.
  • The author/model line never blurs. Every derived bite carries its contribution class; author-verbatim bites are byte-verified against the source span (hash match in the unit-1 normalized scalar space). A bite whose class can't be proven reads "no direct source" honestly — and the capped/audited novelty ceiling keeps an asset from quietly becoming mostly-generated.
  • Every probe leads to the core. A probe on a derived bite resolves the anchor chain to the core document's passage, or says "no direct source" honestly. There is no path from a derived bite to "we don't know where this came from" — the attribution README's contract extended to spans.
  • Provenance is captured at WRITE, never reconstructed. The reformat pipeline records every bite's class + source spans as it generates; post-hoc reconstruction is a rejected alternative (it would guess at spans it never saw).
  • Rights inherit, never launder. The derived document registers through the rights chokepoint (register.py:201) with the source's rights posture, deny-by-default; the pipeline reads the source through serve_full_text_guarded (serve_guard.py:233) only. A derived asset of a withheld source stays owner-only under the same gates — verified against the derived document's own id.
  • Calm by default, complete on demand. The human surface never quote-bombs; the full trace lives in the agent-facing metadata. A presentation that disturbs reading flow fails the SPR-00 gate regardless of its provenance completeness.

SPR-01 · The generation record + the bite-provenance store

Contract. Server: substrate/provenance/{schema,store}.py (additive idempotent DDL under the write lock, the unit-1/unit-6 conventions): generation_records (derived_document_id PK · owner_user_id · source_document_id · prompt · model · params_json · created_at) and bite_provenance (bite_id PK — content-derived, unit 6's stable-id discipline (evidence_index.py:93): sha over the derived bite's normalized text + class + source refs · derived_document_id · bite_index ≥ 0 · contribution_class CHECK ∈ author_verbatim | llm_compressed | llm_expanded | research_supplemented · source_refs_json — unit-1 anchor payloads into the CORE document, NULLable with the honest "no direct source" · investigation_id nullable (research_supplemented only, CHECK-enforced) · verbatim_sha256 NULLable — set and VERIFIED for author_verbatim bites · created_at). The reformat pipeline (substrate/reformat/pipeline.py) is the ONLY writer: it reads the source through the gated serve path, generates per-bite through the one dispatch entry (substrate/dispatch), and records every bite's class + source spans AT WRITE TIME in the same bounded write scope as the bite — never reconstructed after. An author_verbatim bite is written ONLY when its hash matches the source span's (byte-PROVEN at write; a mismatch is an honest pipeline error, never a mislabeled bite). The novelty ceiling is enforced at write: beyond the cap, further null-source bites refuse honestly (the asset completes with sourced bites or the pipeline reports the ceiling hit). Registration: the derived document registers through register_source_document (register.py:201) with the source's rights posture inherited deny-by-default, carrying derived_from_document_id + the generation record.

Proof (real calls):
  • FastAPI-level fixtures over a real DuckDB + the hash embedding provider: reformat a fixture document with a prompt ("the 20-minute version, focused on the pricing chapters") — every bite classed, every class lawful, every research_supplemented bite carries a real investigation id.
  • Author-verbatim bites byte-PROVEN: recompute the hash from the source span — match (asserted, not reviewed); a doctored verbatim claim fails loudly.
  • The original fixture document is byte-identical before and after (hash asserted).
  • A withheld-source fixture: the pipeline reads nothing but the gate-served portion, and the derived document is owner-only under the same gates (exercised against its own id).
  • The novelty ceiling: a pipeline run forced past the cap refuses the next null-source bite honestly; the cap value is config, not hardcoded taste.
  • Idempotent capture: re-running the same generation (same prompt + params + source state) yields identical bite_ids (the stable-id contract holds at the bite level).

Non-goals: the reformat UX (SPR-02), probing (SPR-03), audio/video sources (the same contract covers them later), any edit path into the source, provenance reconstruction after the fact.
