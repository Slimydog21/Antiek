Measure NotDiamond before granting route influence

Status: executable Cycle 14 correction to ANT-ND SPR-03. Parent: /Users/slimydog/specs/antiek-notdiamond/index.html.

Decision

The old sprint simultaneously required NotDiamond to beat Antiek's baseline before promotion and made it default-on as the first live attempt. That is contradictory. This slice permits only disabled and shadow; disabled is the default. Shadow asks NotDiamond for one recommendation, records attributable evidence on the existing dispatch event, and leaves provider order, fallback, authorization, and spend authority unchanged.

Scope

  • Only explicit Deep Research roles are eligible.
  • Candidate identities come from the server-owned authoritative tier chain, including an exact per-call override.
  • The full assembled prompt is disclosed only when the operator explicitly sets both ANTIEK_NOTDIAMOND_MODE=shadow and ANTIEK_NOTDIAMOND_ALLOW_PROMPT_DISCLOSURE=true; mode alone is insufficient consent.
  • Unknown modes fail closed and remain observable as invalid_mode.
  • One daemonized selector slot and an outer deadline ensure a stuck SDK cannot delay authoritative dispatch beyond the configured budget or accumulate unbounded workers.
  • Timeout, unavailable SDK/key, malformed response, adapter errors, and off-set recommendations are bounded reason codes, never route failures.

Attribution

The existing single dispatch emitter remains the only event writer. Shadow evidence is installed with restorable ContextVar tokens immediately before authoritative dispatch and reset in finally, including exceptions before event emission and nested dispatch. The scoped evidence repeats on every attempt in the fallback chain so the eventual outcome remains joinable. Every staged record has nd_bypassed=true; shadow means the recommendation was observed but deliberately not applied.

Acceptance

  • Default configuration performs no NotDiamond network call.
  • Non-DRW calls perform no NotDiamond work and receive no synthetic attribution.
  • Shadow recommendation cannot reorder or replace any tier.
  • Exact recommendation, candidate membership, latency, tradeoff, and bounded bypass reason are recorded.
  • Provider exceptions cannot leak attribution into a later dispatch.
  • Existing fallback behavior and dispatch tests remain green.

Non-goals

No enabled mode, route mutation, promotion verdict, custom-router training, cross-workflow routing, UI control, second event writer, or claim that NotDiamond improves quality or cost.

Test the pure classifier first, then event integration and exception cleanup, then run the existing dispatch suite and inspect that provider order is byte-for-byte unchanged.
