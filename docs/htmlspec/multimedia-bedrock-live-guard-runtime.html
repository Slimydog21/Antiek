Cycle 37 / Cycle 38

Bedrock live guard runtime

Compose live acquisition only after explicit workload identity, declared narrow client capability, private journal, and recovery authority agree.

Status: simulation-onlyNarrow interfaceProduction refused

Spec lineage

Cycles 36 and 37 define acquisition and durable state but own no deployed identity. This simulation-only child defines the process boundary that may compose them. It does not satisfy Cycle 37's process-kill or independent-account prerequisites, qualify IAM, implement an SDK provider, deploy infrastructure, or grant production eligibility.

  • A future child may add a concrete SDK adapter only after process-kill exercises, independent-account execution, independently observable session identity, and deployment manifests prove the role, source, endpoint, and action constraints expressed here.

Verdict

A credential is not authority merely because a process can find it. Startup challenges and independently verifies one named workload identity, rejects enumerated environment-based ambient channels, and validates a manifest-declared two-method client surface. It does not prove which credentials the injected client uses. Recovery reopens immutable intent and runs Cycle 36 with the stored nonce and start while freshness uses current time; an old completion is historical, not current truth.

Threat model

  • Reject substituted account, role, session issuer, deployment, credential source, challenge, identity verifier, trust root, endpoint, region, action, journal, command, attempt, nonce, startup receipt, or execution receipt.
  • Reject enumerated static key, session-token, profile, shared-file, credential-process, and custom-endpoint environment channels. Mounted files, descriptors, factory closures, and provider internals remain unproved until a concrete adapter is independently exercised.
  • The exact client manifest and two-method interface constrain runtime composition but do not prove effective IAM or credential provenance.
  • Recovery may fail and leave an attempt in progress. It never deletes, abandons, overwrites, or marks failed forensic history.

Protocol

  1. Validate config and copy/check the environment before injected calls.
  2. Run complete Cycle 37 integrity traversal. Failure causes zero identity, verifier, or factory calls.
  3. Generate the challenge, observe and independently verify identity, cross-bind every scalar and challenge, and check current validity.
  4. Build and validate the manifest-declared Organizations surface without claiming credential provenance.
  5. Emit the startup receipt. Startup performs no Organizations evidence, attestation, or revocation call.
  6. Before recovery, recheck identity, reopen exact intent, and require exact Cycle 34/predecessor digests. A completed attempt fails as historical.
  7. For an incomplete attempt, call Cycle 36 with stored nonce/start for identity reconstruction while current time drives all evidence and freshness. Reopen exact receipt and reject a distinct attempt.
  8. Recheck identity and return the runtime execution receipt. Failures leave immutable history unchanged.

Acceptance

  1. Exact fakes produce deterministic fixed-schema startup and execution receipts containing no supplied secret sentinel.
  2. Every enumerated forbidden channel, missing/extra source marker, wrong metadata-disable value, non-string mapping entry, and post-construction source mutation fails at the declared boundary.
  3. Wrong challenge, repeated startup on one runtime, account, role, source, session issuer, deployment, malformed identity, verifier/trust-root mismatch, not-yet-valid/expired identity, or regressed/invalid clock fails. Cross-process challenge replay is not claimed.
  4. Wrong endpoint, region, account, identity, action manifest, extra/reordered/duplicated action, or factory exception fails. A compliant manifest remains explicitly insufficient to prove credential provenance.
  5. Missing, corrupt, locked, or replaced journal fails before identity, verifier, factory, Organizations evidence, attestation, or revocation calls. Successful startup performs no evidence acquisition.
  6. Exact in-progress intent reopens command, nonce, and start. Authority substitution fails. Recovery reacquires all Cycle 36 evidence at current time and completes the original attempt without freezing freshness.
  7. Identity expiry before or during recovery fails before the next external boundary. Completed attempts remain historical and are never fresh recovery authority.
  8. Process-kill checkpoints and independent-account execution remain mandatory unfulfilled gates for a future deployed adapter; this simulation makes no deployed-runtime claim.
  9. No SDK, credential bytes, IAM qualification, infrastructure deploy, daemon, route, scheduler, production eligibility, settlement, release, event, graph write, or UI is added.

Five Values

  • Truth: identity, manifest, credential provenance, IAM, and current evidence remain separate claims.
  • Care: secrets stay outside artifacts and crash history remains inspectable.
  • Agency: identity, trust roots, endpoint, source, and challenge are explicit boundaries.
  • Craft: canonical cross-binding, exact surfaces, environment exclusion, and current-time recovery make composition hard to vary.
  • Restraint: this cycle proves simulation behavior, not cloud deployment or production safety.

Out of scope

No boto/botocore, STS call, credential-provider implementation, secret storage, attestor/revocation transport, IAM inspection, process-kill certification, independent-account canary, infrastructure, daemon, health route, production registry, Bedrock dispatch, billing closure, settlement, release, event, graph mutation, or UI.
