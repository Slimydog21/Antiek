SPR-04 Antiek-bench Weekly Scorecards

Back to master spec

Goal

Create Antiek-bench as the model-quality feedback loop for research, reading, synthesis, verification, voice, and multimedia tasks.

Reuse

  • compounding/benchmark/ already owns a question-set/result harness.
  • benchmarks/ and tools/benchmarks/ own performance harnesses; do not mix latency microbenchmarks with model-quality scorecards.
  • Route receipts provide production examples to propose new fixtures.

Scorecard Dimensions

  • Quality: groundedness, citation precision, insight density, synthesis coherence, verifier disagreement.
  • Cost: estimated and actual cost per acceptable answer.
  • Latency: time to first useful token and total completion time.
  • Reliability: provider errors, fallback rate, retry rate, malformed outputs.
  • Task class: research question, reading highlight, merge synthesis, midnight-oil plan, multimedia script, verification.

Acceptance Tests

  • Mock run writes a schema-valid scorecard with at least two task classes.
  • Scorecard never includes raw API keys or full private prompts.
  • Weekly proposal file lists added/retired fixtures with evidence from route receipts.
  • Settings can read the latest scorecard and show best model by task class.
