SPR-01 Route Receipt Contract

Back to master spec

Goal

Every model-routed answer carries a compact route receipt: what was requested, what candidates were considered, what was selected, why, and what it cost.

Owners

  • substrate/dispatch/router.py remains the execution owner.
  • substrate/schemas/ or a dispatch-owned model module owns the receipt schema.
  • Research/Reading UI only renders receipts; it does not infer route state.

Required Fields

  • route_receipt_id, dispatch_event_id, role, task_kind.
  • objective: quality, cost, latency, balanced, or operator-selected.
  • candidate_models: provider/model/tier plus estimated cost range.
  • selected: provider/model/tier and reason code.
  • budget: cap, remaining before, projected spend, actual spend after.
  • cache_state: cache family, warm/cold/unknown, and cache-aware adjustment reason.
  • override: manual override, policy override, fallback override, or none.

Acceptance Tests

  • Dispatch success emits a receipt with selected provider/model matching the dispatch result.
  • Fallback success records primary failure and final selected fallback without exposing prompts or keys.
  • Unknown pricing produces pricing_known=false and never fabricates cost.
  • A redaction test proves provider API keys and raw prompts are absent from receipt JSON.

Non-Goals

No model choice UI and no NotDiamond call in this sprint.
