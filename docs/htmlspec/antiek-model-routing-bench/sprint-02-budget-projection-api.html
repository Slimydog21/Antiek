SPR-02 Budget Projection API

Back to master spec

Goal

Extend the existing Settings cost-estimate path so every prompt composer can ask: what will this likely cost, which model would auto-routing choose, and will it exceed my budget?

Existing Reuse

  • Frontend already has apps/reading/src/api/settings.ts with estimatePromptCost().
  • Backend already exposes settings model/budget concepts; extend, do not fork.
  • substrate/dispatch/config.yaml remains the pricing source of truth until provider pricing sync exists.

API Shape

{
  "task_kind": "research_question|reading_highlight|midnight_oil|synthesis|verification",
  "role": "synthesizer",
  "prompt_chars": 12000,
  "expected_output_tokens": 1800,
  "route_mode": "manual|auto_quality|auto_balanced|auto_cost|auto_latency",
  "manual_provider": null,
  "manual_model": null,
  "session_cache_key": "optional"
}

Acceptance Tests

  • Known pricing returns low/high estimate, selected candidate, and cap impact.
  • Unknown pricing returns honest unknown fields and no false pass.
  • Manual model selection bypasses advisor choice but still computes cap impact.
  • Cache-warm candidate can beat cheaper cold candidate when total projected cost is lower.
