Antiek Model Routing, Budget Projection, and Antiek-bench

This spec turns the operator's expanded goal into an implementation path: Antiek should let a researcher choose or delegate model selection for any prompt, see budget impact before running, learn from weekly task outcomes, and route midnight-oil/research/reading agents without losing the canonical substrate dispatch ledger.

Decision

Implement NotDiamond-style routing as an optional advisory layer feeding Antiek's existing substrate/dispatch/router.py. Do not replace the dispatch router, provider registry, event log, or cost accounting. The canonical router remains the single execution chokepoint; external routers may recommend candidates, but Antiek records and enforces the final route.

Current NotDiamond docs describe routing as choosing the best LLM per query to improve accuracy, reduce cost, and optimize latency, with pre-trained and custom routers plus quality/cost/latency tradeoff modes. Their 2026 model-routing guide separates gateways from routers and explicitly calls out cache-aware routing as decisive for agent workloads. That maps well to Antiek only if route receipts, cache state, budget ceilings, and benchmark feedback are first-class.

Why This Matters

  • The research workstation and reading mode both spawn recursive research work; fixed model choices will overpay on easy work and underpower hard synthesis.
  • Midnight oil needs an approved price ceiling before autonomous work starts; model routing must prove how it will stay inside that ceiling.
  • Settings already exposes models, budget, and prompt cost estimation; this spec turns that into a decision tree with receipts and benchmark feedback.
  • Antiek-bench should learn from real usage outcomes, not just synthetic prompts, so weekly recommendations improve with the product.

Architecture

Decision Tree UI

Settings and prompt composers expose manual model choice, auto-router choice, budget remaining, and projected prompt impact.

Route Planner

A new pure planner evaluates task kind, role, prompt size, expected output, cache state, user objective, and budget ceiling.

Router Adapters

Local deterministic policy first; optional NotDiamond advisor later. Both return recommendations, never execute provider calls.

Canonical Dispatch

dispatch() executes the selected tier/model and records actual usage/cost as it does today.

Route Receipt

Per answer: candidates, selected provider/model/tier, objective, estimated cost, actual cost, fallback chain, override reason.

Antiek-bench

Weekly task-suite runner over research, reading, synthesis, extraction, verification, voice, and multimedia prompt classes.

Acceptance Bar

  • Every new API has unit tests for known pricing, unknown pricing, cap exceeded, and no-cap cases.
  • Every route recommendation is deterministic in tests and stores an auditable reason.
  • NotDiamond is never a hard dependency for core Antiek dispatch; if unavailable, local routing continues.
  • Route receipts are visible from research workstation, reading spawned research, and midnight-oil runs.
  • Antiek-bench outputs both a human settings summary and a machine-readable scorecard for future routing policy.
