SPR-05 NotDiamond Advisor Spike

Back to master spec

Verdict

Useful to evaluate, not safe to hardwire. NotDiamond should be an optional advisor adapter that recommends a route; Antiek still executes through the canonical dispatch router.

Why

  • Current NotDiamond docs fit the objective: per-query model selection for quality, cost, and latency.
  • Their 2026 guide explicitly distinguishes routers from gateways, matching Antiek's need to keep dispatch execution separate.
  • The same guide warns that cache-aware routing is decisive for agentic workloads; Antiek must verify that before trusting recommendations.

Spike Contract

  • Feature flag: ANTIEK_ROUTER_ADVISOR=notdiamond.
  • Input: redacted prompt features, role, task kind, candidate model set, objective, budget ceiling, cache state.
  • Output: recommended provider/model plus confidence/reason if exposed by the API; otherwise record opaque advisor metadata.
  • Execution: map recommendation to an existing dispatch tier or reject with advisor_candidate_unavailable.
  • Fallback: if NotDiamond times out/errors, local policy chooses and receipt records advisor_unavailable.

Acceptance Tests

  • Mock advisor recommendation maps to a configured tier and dispatch still records a normal DispatchCall.
  • Unconfigured recommended model is rejected, not called directly.
  • Advisor timeout falls back to local policy with a route receipt.
  • Cache-aware test rejects a cheaper recommendation when cache loss makes it more expensive.

Production Gate

Promote only if Antiek-bench shows better cost-per-acceptable-answer than the local policy on research and reading tasks for two consecutive weekly runs.
