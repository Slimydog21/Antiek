Antiek / Infinite / Cycle 80

Recursive investigation working memory

Make prior notes and open questions from the current investigation inform the next wrestling prompt through a bounded, causal, auditable context layer.

Problem

The live wrestling and note-taking handlers emit auditable context packs and durable note.emerged events, but every later wrestling call rebuilds context from only the current highlight and question. Valuable prior thinking is visible in the event rail yet absent from the model's next prompt. The broader knowledge-reuse substrate is exercised by a CLI, not this live product path.

Decision

  1. Read only the triggering investigation's trajectory and cut it at the exact current distillation.requested event. Events appended after that causal boundary are invisible.
  2. Fold immutable note.emerged snapshots. Fold question.identified and remove questions resolved before the cutoff.
  3. Do not fold note.refined: the current event is an audit attempt, uses a different graph-node identity, and does not record whether the refinement won concurrency. Authoritative refined-note memory is deferred until that outcome is represented durably.
  4. Select a fixed recent suffix, render it in chronological order, cap every item and aggregate bytes, and derive the layer source digest from the exact rendered bytes.
  5. Insert one session-class working-memory layer immediately before the current-highlight session layer. It is labeled untrusted hypothesis memory, never source evidence or instruction authority.
  6. If no usable memory exists, preserve the existing three-layer prompt byte-for-byte.

Authority boundaries

ConcernRequired rule
Ownership and scopeNo caller supplies an investigation or owner to memory assembly. The handler uses the already validated triggering event's investigation and reads only that trajectory.
CausalityThe cutoff event must exist exactly once in the physical durable trajectory. Later notes, concurrent requests, and later refinements cannot enter this prompt.
IntegrityMalformed completed event records, conflicting duplicate event IDs, changed duplicate note identities, resolution of an unknown question, malformed relevant payloads, or cross-investigation rows fail memory assembly closed before provider dispatch.
Prompt safetyMemory is explicitly model/user-authored and untrusted. The model may use it to orient or challenge itself, but must not treat it as source evidence, system instruction, or support for a factual claim.
SpendNo additional dispatch, provider, embedding, graph query, reservation, or model call is introduced. Existing explicit dispatch remains the only paid boundary.
AuditThe context-pack event records a source containing a lowercase SHA-256 digest and item count. The digest covers the exact rendered memory content the model saw.

Bounds and ordering

  • At most 12 combined notes and open questions survive, selected from the newest identities after folding and rendered oldest-to-newest.
  • Each text is deterministically capped at 1,200 characters with an explicit truncation marker; total rendered memory is capped before context-pack token budgeting.
  • A fixed safe-alphabet identity digest and confidence are included for notes; an identity digest is included for questions. Raw identities, owner, document path, provider, model, source-event list, and unrelated event payloads are omitted.
  • Stable unchanged trajectories yield byte-identical memory and source digest.

Acceptance

  • A second wrestling prompt contains an earlier note and open question from the same investigation before the current highlight and question.
  • Another investigation's identical-looking memory never appears.
  • A note appended after the triggering request never appears, even when the handler runs later.
  • Refinement audit attempts never overwrite emerged-note memory, including superseded attempts.
  • Resolved questions are absent; unknown resolution fails closed.
  • Exact and over-bound fixtures prove deterministic suffix selection, per-item truncation, total bounds, chronological render order, stable digest, and no unbounded payload copying.
  • No-memory behavior preserves existing wrestling tests and prompt composition.
  • Context-pack, wrestling, note-taking, event-schema, Ruff, compilation, security, and heterogeneous hostile-review gates pass.

Non-goals

No cross-investigation reuse, owner-wide memory, embedding retrieval, graph promotion, automatic note acceptance, prompt editing UI, model routing, provider qualification, paid fallback, or new spend approval. Cross-investigation compounding requires owner-bearing graph authority or an owner-scoped verified twin-note source; this cycle does not manufacture that guarantee.

Harness hint

Attack future-event leakage, cross-investigation substitution, duplicate identities, superseded refinement attempts, unknown resolutions, oversized text, prompt-instruction confusion, ordering drift, and a second hidden dispatch.
