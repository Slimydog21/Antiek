Authorize exact chapter narration without executing it

Stacked on PR #1251. This sprint exposes the existing durable V2 asynchronous authority through an authenticated, server-derived chapter boundary. It is the authorization prerequisite for the owner-bound educational-video production command.

Authority split

The operator controls request id, current parent revision, chapter, voice/speed/media shape, TTL, an explicit maximum microdollar ceiling, and spend acknowledgement. The server controls asset plan, chapter text and grounding, deterministic child revision, provider/model, endpoint capability, catalog version/digest, quote identity/lifetime, recovery authority, and canonical request-body digest.

Flow

  1. Authenticate and load the owner-scoped asset.
  2. Require current ready non-cheapest revision and explicit spend acknowledgement.
  3. Resolve trusted narration terms from server runtime configuration.
  4. Derive spoken chapter sequence and the exact child revision shared with NarrationRun.
  5. Rebuild PreparedChapterTTSRequest from the stored plan; never accept text or body digest from HTTP.
  6. Require approved ceiling not exceed the trusted quote maximum.
  7. Call ExecutionAuthorizationIssuer.issue_async. Same owner/request id and same terms exactly replay; changed terms conflict.

HTTP contract

POST /multimedia/assets/{asset_id}/narration-authorizations returns chapter ID, child revision, body digest, and a fully typed signed V2 authority. It returns no narration text, body JSON, local path, signing key, credential, raw quote evidence, or recovery key.

Product contract

The plan review shows a numeric USD ceiling, explicit checkbox acknowledgement, and chapter-scoped authorization command. Success displays authorization ID, provider/model, body digest, and expiry. Authorization is not presented as provider execution, narration completion, or spend.

Failure model

Foreign/missing asset is opaque. Stale/unready/cheapest revision, missing chapter, missing acknowledgement, invalid shape, ceiling above trusted maximum, malformed runtime, expired quote relationship, or changed idempotency terms fail before any provider callback, authorization claim, or budget reservation.

Replay and races

The durable issuer is authoritative for exact replay. UI completion is revision/chapter request-token bound. Steering or chapter selection invalidates an in-flight response. Reusing a request id with a different ceiling, speed, voice, body, trusted terms, or TTL is a conflict rather than reinterpretation.

Non-goals

No TTS/provider call, authorization claim, budget hold, narration-run execution, reconciliation, visual generation, rendering, receipt issuance, publication, merge, or deploy. Static environment terms are an initial trusted adapter; a future quote service may replace it behind the same resolver contract.

Acceptance

  • Server-derived request digest and deterministic child revision match narration-run execution.
  • Operator cannot submit provider/catalog/quote/recovery/body fields.
  • Exact replay is byte-identical; changed terms conflict.
  • Foreign/stale/unready/cheapest/unacknowledged/over-ceiling/missing chapter cases issue nothing.
  • UI requires acknowledgement and displays signed authority facts without execution claims.
  • Broad tests, typecheck/build, Ruff, HTML parse, and HardenX report zero real findings.
  • Independent review findings are resolved; unavailable or malformed judge output is recorded as an engine gap rather than represented as acceptance.
