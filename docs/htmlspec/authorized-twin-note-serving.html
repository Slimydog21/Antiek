CYCLE 48

Authorized twin-note serving and composition

Let an authenticated operator discover, open, and combine exact immutable twin-note revisions without converting paths, caller claims, or stale files into authority.

Spec lineage

Parent: Cycle 47 durable twin-note compression. Cycle 40 investigation composition remains separate because its historical event members do not carry owner identity.

  • No child specs. Read verification, owner-bound composition, HTTP behavior, and workstation selection form one user-visible boundary.

Outcome

An authenticated account can list only its twin-note assets and immutable revision history, open current or exact revision HTML, select two through twenty exact revisions in explicit order, create or replay one owner-bound immutable HTML composition, and open it from the research workstation. Every response is derived from verified V21/V22 database bytes. No model, provider, dispatcher, budget authority, filesystem path, or signed generation receipt participates.

Five values

Precision

Account, ordered revision IDs, asset IDs, body hashes, HTML hashes, renderer version, and composition version enter identity.

Exhaustiveness

Foreign, missing, stale, malformed, rehashed, reordered, orphaned, cross-account, duplicate, and concurrently replayed inputs have explicit tests.

Craftsmanship

One verifier feeds list metadata, exact reads, current reads, composition admission, replay, and serving so no weaker read seam exists.

Honesty

The composition is an ordered review index over machine notes, not synthesis, graph truth, or ownership inferred from an asset label.

Information

History, supersession, counts, exact member order, source events, and links to immutable member revisions remain inspectable.

Authority and verifier

  • Derive account_id only from authenticated request.state.user_id. No route accepts owner/account identity in body, path, query, or header.
  • A shared read verifier loads one V21 revision by (account_id, revision_id), checks every identifier and ceiling, canonical body_json, body_sha256, typed ResearchArtifactBody, investigation identity, note/source counts, exact deterministic V21 HTML reconstruction, html_sha256, path derivation, ordered member ledger, publication effect identity/path/hash/state, and a single valid successor relation.
  • The database BLOB is serving authority. The published filesystem copy is an external effect audited by Cycle 47 recovery, never a read authorization source.
  • Current is derived as one owner/asset leaf. Zero means unavailable; more than one is integrity conflict. History is a bounded predecessor chain from that leaf, not an untrusted timestamp sort.
  • Foreign and missing assets, revisions, and compositions return the same 404 twin-note resource is unavailable. Integrity failures return a value-free 409 twin-note integrity conflict. Responses never reveal paths, account digests, membership hashes, raw window IDs, or existence across accounts.

Schema V22

twin_note_compositions(
 composition_id PRIMARY KEY, account_id, composition_version CHECK = 1,
 ordered_members_sha256, html_bytes BLOB, html_sha256,
 member_count CHECK BETWEEN 2 AND 20, created_at,
 UNIQUE(account_id, ordered_members_sha256)
)
twin_note_composition_members(
 composition_id, member_ordinal CHECK 0..19, revision_id,
 asset_id, body_sha256, html_sha256,
 PRIMARY KEY(composition_id, member_ordinal),
 UNIQUE(composition_id, revision_id),
 FOREIGN KEY(composition_id) REFERENCES twin_note_compositions
)

Strict column, default, constraint, and index fingerprints are mandatory. Empty malformed V22 tables may repair; populated incompatibility fails without mutation. Composition rows and members are immutable through this service.

Composition identity and HTML

member = [ordinal, revision_id, asset_id, body_sha256, html_sha256]
ordered_members_sha256 = sha256(canonical ordered members)
composition_id = "tnc-" + sha256(account_id, version, ordered_members_sha256)[:32]
  • Admission accepts a JSON list of two through twenty unique canonical revision IDs. Order is semantic and preserved.
  • All revisions must belong to the authenticated account. Historical superseded revisions are eligible because selection is exact; callers cannot submit asset IDs as substitutes.
  • Static HTML contains an ordered section per member with asset label, immutable revision identity, note/source counts, exact agent-note text escaped from verified body bytes, and an authenticated relative link to that exact revision.
  • The page embeds canonical composition metadata with member hashes and no active JavaScript, mutable controls, random values, timestamps, account identity, or filesystem paths.
  • Exact retry byte-compares the full composition row and member ledger. Same members in another order produce another identity. A duplicate revision is invalid rather than silently deduplicated.

HTTP contract

MethodRouteContract
GET/research/twin-notesBounded owner-only assets, each with exact current revision metadata and revision count.
GET/research/twin-notes/assets/{asset_id}/revisionsVerified current-to-root predecessor history for one exact owner asset.
GET/research/twin-notes/revisions/{revision_id}Serve exact verified V21 HTML.
POST/research/twin-notes/compositionsCreate/replay exact owner-bound ordered composition; return ID, member metadata, and relative URL only.
GET/research/twin-notes/compositions/{composition_id}Reverify V22 row, ordered members, all current immutable V21 member bytes, and deterministic HTML before serving.

All success and error responses use Cache-Control: private, no-store; HTML adds X-Content-Type-Options: nosniff and a restrictive CSP. Authentication failure is 401, malformed input 422, unavailable 404, integrity conflict 409. GET performs no repair or write.

Workstation

  • Add a dedicated Twin notes section inside the research sidebar. It loads owner-scoped current revisions, shows asset label, note count, source count, and history count, and exposes an exact-history disclosure.
  • Open current/history uses a pre-opened popup and the backend relative URL. The page never opens a filesystem URL.
  • Selection uses checkboxes, preserves click order, caps at twenty, freezes during submission, and displays a numbered ordered tray with remove and up/down controls. Compose remains disabled below two.
  • On success replace the pre-opened popup with the immutable composition URL. On failure close it, retain exact ordered selection, and show one actionable value-free error. Retrying submits the same revision order.
  • This workflow does not overload investigation composition, create a Write draft, promote graph nodes, or call a model. A later cycle may import verified twin compositions into Write.

Acceptance

  • Two accounts using equal asset labels see only their own current/history/compositions; foreign and missing probes are indistinguishable.
  • Current and history reject forks, cycles, broken predecessors, wrong-account predecessors, malformed bodies, changed body/HTML bytes or hashes, count drift, member-ledger drift, publication-effect drift, and non-published effects.
  • Exact GET returns byte-identical V21 HTML and performs zero writes, filesystem reads, recovery, provider calls, or events.
  • A,B versus B,A revisions create distinct deterministic V22 IDs and preserve rendered order; exact retry creates one row/member set and identical bytes under concurrent calls.
  • Composition serve rejects row/member/hash/count/order/account drift and any subsequently corrupted V21 member authority.
  • V22 valid populated schema reopens, auxiliary same-name schemas do not interfere, empty malformed repairs, and populated malformed fails unchanged.
  • HTTP tests cover authentication, no-store/nosniff/CSP, 401/404/409/422 mapping, no leaked paths/owners/hashes, and GET no-write behavior.
  • Frontend tests cover load, history, exact open, order, cap, pending freeze, popup safety, retained retry, error, and no investigation-composer regression.
  • Cycle 47 compression, V20 replay, shared graph schema, artifact routes, and existing investigation composition suites remain green.

Rejected alternatives

  • Reuse Cycle 40 composition: its historical event members lack owner identity and would weaken V21 account authority.
  • Serve the published pathname: turns a derived external effect into authorization and reintroduces replacement races.
  • List rows then verify only on open: leaks corrupted or foreign metadata and creates two trust levels.
  • Compose current asset IDs: retries can silently select newer revisions; exact revision IDs are mandatory.
  • Inline member HTML or iframes: nests documents and active policy surfaces; render escaped verified note text and exact links.
  • Create a Write draft now: would require a separate provenance profile and import receipt; do not counterfeit Cycle 41 investigation-member authority.

Out of scope

Model-authored synthesis, graph promotion, Write import, deletion, sharing, public links, remote object storage, semantic clustering, editing, filesystem repair during GET, and current-only alias files.

Harness hint

Implement one owner-bound verifier and V22 service; route every read and composition through it. Use separate backend-integrity, HTTP-oracle, and frontend-interaction critics.
