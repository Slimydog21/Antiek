Revision boundary

Asset or revision changes clear status, errors, and every acknowledgement before inspecting the new revision. Steering that could create another revision is disabled for the full finalization or recovery transaction. A late response is identity-checked and cannot replace a newer asset selection.

Error boundary

Unavailable runtime, opaque missing asset, state conflict, and unknown failures use safe operator copy. Recovery tokens, claim identifiers, database paths, credentials, and raw server details never enter the client contract.

Acceptance

  • No finalize call before model acknowledgement.
  • No recovery call before both acknowledgements.
  • Fresh in-progress work cannot be recovered.
  • Completed twin evidence is visible and revision-bound.
  • Revision changes reset consent and status.
  • Loading, refresh, conflict, unavailable, and successful states are tested accessibly.
  • No paid media provider call, publication, merge, or deploy.
