Midnight Oil graph-admission retry

Let the operator safely retry stranded graph effects without rerunning research or spending money.

Status: executingOwner: Codex orchestrator1 sprint · 1 waveGenerated 2026-07-13

Goal

Close the gap between Midnight Oil's truthful pending admission presentation and the existing backend resume_terminal_projection() primitive. A signed-in owner may retry only a terminal job with a closed retryable reason; success returns the same canonical job/deposit navigation contract used elsewhere.

Success criteria

  • Retry performs graph projection only: zero provider dispatch, retrieval, budget hold, or research mutation.
  • Wrong owner, nonterminal job, refused reason, already-admitted job, and contradictory state fail before graph writes.
  • The UI offers one retry control only when the closed presentation contract says retry is safe, and refreshes the canonical state after the response.

Failure mode to avoid

A helpful-looking retry button silently reruns paid research, bypasses owner authority, or lets a deterministic refusal be retried into inconsistent graph state.

Context & motivation

ANT-MOCA SPR-04 made graph admission fail closed; SPR-05 made its outcome visible. Three conditions are intentionally transient: a cited local chunk is temporarily missing, the operational artifact is pending, or the graph lock is unavailable.

The code already has an idempotent projection-only recovery primitive. What is absent is a product boundary: authenticated route, closed response/errors, API client, and operator action. This sprint exposes that primitive without expanding its authority.

Architecture overview

operator click → POST /midnight-oil/jobs/{job_id}/graph-admission/retry → authenticated owner lookup + closed state/reason gate → resume_terminal_projection(existing durable evidence) → graph receipt or typed retryable/refused outcome → canonical job JSON → UI refresh NEVER → provider dispatch · retrieval · budget hold · worker lease

Key invariants

  • The route authorizes the exact job owner before calling the projection primitive.
  • Only pending plus a member of RETRYABLE_GRAPH_ADMISSION_REASONS is actionable; absence of a reason is not permission.
  • Retry does not convert refused policy/evidence failures into pending work and does not invent automatic polling.
