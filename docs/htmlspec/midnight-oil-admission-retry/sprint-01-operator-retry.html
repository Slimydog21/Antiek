Operator-controlled admission retry

Expose the existing projection-only recovery primitive through owner-safe API and UI boundaries.

Wave 1Status: executingBudget: 5 milestonesOwner: Codex orchestrator

Parent context

Antiek is a Python/FastAPI backend plus a React/TypeScript reading workstation. Midnight Oil terminal jobs deposit HTML and twin notes, then attempt graph admission. ANT-MOCA made the graph result a closed pending|complete|refused contract and exposes three transient pending reasons.

substrate/midnight_oil/live.py::resume_terminal_projection already retries graph effects from durable evidence and does not dispatch a provider. The missing boundary is an authenticated FastAPI route in interfaces/research/api/midnight_oil_routes.py, its TypeScript client in apps/reading/src/api/midnightOil.ts, and a guarded control in apps/reading/src/modes/MidnightOil/index.tsx.

Where this sprint sits: direct successor to ANT-MOCA SPR-05. Work from branch caffen/mo-admission-retry, stacked on caffen/mo-authorization-live-convergence. Use .venv/bin/python; do not run Ruff formatter on existing Python.

Goal

Let the authenticated owner retry only safe, transient graph admission while proving zero research redispatch and zero spend.

The response must use canonical job serialization. The control disappears or disables after success and never appears for deterministic refusal, reconciliation-required, unknown, nonterminal, or reasonless-pending states.

Technical milestones

1
Freeze the route contract

Add a POST route whose body is empty and whose response is canonical job JSON. Authenticate first, resolve exact owner authority, then validate terminal status and pending + retryable reason.

  • Foreign and missing jobs reveal no private state and never call projection.
  • Complete, refused, reasonless pending, nonterminal, and contradictory jobs fail before graph writes.
  • No policy override, model, budget, or source inputs are accepted from the client.

Call only the graph recovery seam

Invoke resume_terminal_projection with the authenticated owner, durable owner/job stores, engagement store, graph path, and event directory already owned by app composition.

  • Spy tests prove zero provider dispatch, retrieval, worker lease, and budget hold.
  • Retryable failure remains typed pending; success becomes complete with canonical graph navigation.
  • Replaying after success is idempotent and returns an honest non-actionable response.

Rigor: operating manual for this sprint

1 · Intellectual honesty

A successful HTTP request is not proof of graph admission: assert the returned graph_projection_state, receipt-backed navigation, and zero dispatch spies. If the graph lock remains unavailable, keep the UI pending.

2 · Fairness

Steelman automatic retry: it reduces operator friction. Reject it here because no durable attempt/backoff policy exists and repeated lock/source failure deserves visible operator control.

3 · Rigor

Enumerate every state/reason pair. Tests must attack wrong-owner, missing, nonterminal, reasonless pending, all refused reasons, double click, retryable repeat, and already-complete replay.

4 · Diligence

Reuse resume_terminal_projection, the existing route serializer, and describeMidnightOilAdmission. Do not create a second projection implementation or a looser frontend reason list.

5 · Defensibility

Record why the endpoint accepts no body, which status codes distinguish unavailable from invalid recovery, and what would justify automatic retry. Keep “zero provider call/no spend” as a named invariant in code and tests.
