Cycle 60: Structured Derived Citation Research

Turn one exact companion citation into an explicit recursive-research launch whose provenance is server-verified data, never decorative prompt prose.

Spec lineage

Parent: Cycle 59 grounded companion evidence

    Outcome

    Each persisted companion citation exposes “Follow this.” The command opens ChaseThread prefilled with the bounded citation text and exact source identity but performs no launch. Only the user’s explicit second gesture posts a structured derived_source. The server authenticates the owner, reopens the immutable revision and complete index, verifies asset/revision/content/generation/citation/ordinal/text hash and exact excerpt, then emits the research start event with typed provenance. Any mismatch emits no event and starts no research.

    Authority

    Canonical source

    The revision and revision chunk rows remain authoritative. Browser provenance is a claim to verify, not evidence.

    Launch authority

    POST /investigations remains the only child launch path. Cycle 60 adds validation to it rather than creating a companion-specific launcher.

    Prompt boundary

    context contains human framing only. JSON identity is removed from prompt prose. Typed provenance travels separately and is persisted separately.

    Spend boundary

    Opening ChaseThread never calls the API. The existing explicit launch gesture and downstream budget controls remain unchanged.

    Derived source v1

    The closed object contains derived_asset_id, revision_id, content_sha256, generation, citation_id, chunk_ordinal, chunk_text_sha256, and excerpt. IDs, hashes, generation, ordinal, and UTF-8 excerpt bytes are bounded. Extra fields fail validation.

    1. Authenticate owner from server middleware; never accept owner in JSON.
    2. Reopen the named revision through DerivedAssetLibrary.reading.
    3. Require exact content hash and immutable generation.
    4. Invoke verified revision retrieval/index re-derivation before trusting chunk rows.
    5. Resolve the exact citation and require ordinal, text hash, and excerpt equality.
    6. Only after all checks emit investigation.start_requested with the typed object.

    Reader workflow

    • Every current result and hydrated saved turn renders “Follow this” beside each citation.
    • The button opens one floating ChaseThread with citation text, revision-qualified parent ID, and all structured identity fields.
    • Opening, closing, or remounting the panel performs zero startInvestigation calls.
    • ChaseThread displays the quote and editable question. On explicit launch it sends the quote as ordinary context plus derived_source separately.
    • Stale or malformed provenance gets a typed failure surface and cannot fall back to an unverified launch.

    Persistence and consumers

    InvestigationStartRequestedPayload gains optional typed derived_source. Existing investigations deserialize with null. The event’s canonical serialization makes exact provenance available to the orchestrator, twin-note pipeline, graph projection, and later artifact merge without parsing prompts. This cycle does not change retrieval behavior based on the field; consumers may use it only after preserving the exact object.

    Acceptance harness

    • Valid exact citation launches and start trajectory contains the complete typed object.
    • Foreign owner, asset, revision, content hash, generation, citation ID, ordinal, text hash, excerpt, missing index, and drift each return 404/409 with zero start/spawn events.
    • Unstructured and ordinary launches remain byte-compatible with derived_source=null.
    • ChaseThread sends plain context without identity JSON and structured provenance only after click.
    • Companion citation opens ChaseThread with exact identity and does not auto-launch.
    • Current and historical citations remain pinned after the current pointer advances.
    • Backend tests, event schema/codegen checks, focused frontend tests, TypeScript build, Ruff, HTML parse, hostile review, and HardenX pass.

    Rejected alternatives

    • Embedding source JSON in context: downstream code cannot distinguish authority from prose.
    • Trusting a valid-looking citation ID: permits foreign, cross-revision, or mutated evidence.
    • Launching directly from the companion button: collapses review into spend and violates explicit approval.
    • Creating a second research endpoint: forks lineage, caps, orchestration, and event semantics.
    • Fuzzy excerpt matching: silently changes cited evidence.
    • Requiring the revision still be current: breaks immutable historical research.

    Out of scope

    Paid companion answers, semantic retrieval, automatic subagents, budget-policy redesign, prompt routing, model selection, and synthesis entailment scoring.

    Five-values rigor

    Honesty: prompt prose is not provenance. Fairness: owner authentication gates every citation byte. Rigor: every identity component is reopened and compared. Diligence: failure precedes event emission. Defensibility: one existing launch path gains a typed optional contract without changing ordinary research.

    Harness hint

    Define the closed source model and pure verifier first, integrate it before event emission, then remove prompt JSON and wire companion handoff. Prove every mismatch emits zero events.
