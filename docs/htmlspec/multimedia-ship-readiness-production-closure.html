MSR-02: Production-Byte Cost Closure

Prove which settled provider executions contributed bytes to the current registered educational video. Keep that projection distinct from Cycle 9's total direct exact-revision spend.

Parent program

Spec lineage

Parent: Multimedia ship-readiness cost authority.

  • MSR-02A: receipt identity closure
  • MSR-02B: selected visual closure
  • MSR-02C: sealed narration closure
  • MSR-02D: immutable combined projection

Decision

Authority chain: current owner-scoped production link -> reopened MAC-verified educational-video receipt and current media bytes -> exact reviewed visual set and exactly one sealed narration run -> exact provider execution IDs -> existing claim, hold, and reservation settlement authorities.

The closure reports production_byte_contributing_spend. The existing direct_settled_provider_executions snapshot remains an independent report of all direct executions on the parent revision. Neither total may be substituted for the other.

Global invariants

  1. The current production link and reopened receipt must agree on owner, asset, revision, receipt digest, video digest, audio digest, duration, dimensions, and chapter order.
  2. A generated visual execution is admitted only after the unique reviewed set matches every receipt packet row by ordered scene identity, content digest, disclosure label, and source chunks.
  3. Sourced, archival, diagram, and operator-owned visuals contribute no provider execution ID; their rights authority remains separate and manual where required.
  4. The receipt narration artifact must equal exactly one MAC-verified sealed run artifact for the exact asset and revision.
  5. Each deterministic child revision must have exactly one text-to-speech provider execution. The ordered rows must reproduce the sealed run's authorization_set_digest.
  6. Every admitted execution must pass its provider-record MAC and existing claim, call-hold, reservation, status, integer-cent, cutoff, and identity checks.
  7. Duplicate execution IDs, missing rows, ambiguity, corruption, failed or unsettled constituents, stale links, and changed receipt/media bytes fail closed.
  8. The projection is read-only and current-time. It performs no provider call, reservation, settlement, reconciliation, route mutation, render, or publication.

Rejected alternatives

  • Filter all parent-revision spend: rejected because narration uses deterministic child revisions and non-selected attempts do not contribute bytes.
  • Match narration by asset and revision only: rejected because multiple runs or attempts can exist; artifact equality and authorization-set digest reconstruction are load-bearing.
  • Trust receipt paths as billing provenance: rejected because artifacts own bytes, not money.
  • Persist a second ledger: rejected because claim, hold, reservation, and execution rows already own settlement truth.
  • Treat no paid rows as zero: rejected; local zero requires MSR-03 completed local-run authority.

Acceptance

Pass only when the same call can reopen the current bytes, derive one complete constituent set, validate every settlement at one cutoff, sign a deterministic projection, and verify it independently.

Any unsupported or ambiguous authority returns evidence_unavailable; authenticated contradiction returns evidence_conflict. Neither becomes zero.

Five-values bar

Intellectual honesty: the two spend labels remain distinct. Fairness: sourced visual rights are not mislabeled as provider spend. Rigor: byte and money authorities meet only through exact identities. Diligence: all zero, one, and many cardinalities are tested. Defensibility: each constituent names its role, chapter or scene, revision, execution, charge, and authority source.

Harness hint

Execute 02A before 02B/02C; execute 02B and 02C independently; synthesize and adversarially verify in 02D.
