Budgeted Canonical Twin Embedding

Embed exactly one verified canonical advisory twin chunk after owner approval of a server-priced hard ceiling, without promoting its text to grounded knowledge.

Authority chain

  1. Resolve the owner, source revision, v2 publication, exact chunk text/hash, and empty embedding state before preview.
  2. Prepare one hard-ceiling fallback route. The preview binds run, owner, publication, provider, model, dimension, usage bound, rate snapshot, and maximum exposure without reserving or sending.
  3. Issue the existing durable fallback approval against the exact manifest and current run ceiling. Execution requires its approval id.
  4. The existing research provider gateway reserves before one send and owns settlement, unknown-outcome retention, authoritative reconciliation, and duplicate-charge prevention.
  5. An embedding-specific immutable journal stages only a bounded finite vector and exact typed provider evidence before settlement. It binds vector digest, operation digest, idempotency key, provider response, usage, and settled hold proof.
  6. Only a verified settled proof permits a locked DuckDB transaction to revalidate the full v2 document/chunk publication, require an empty vector, set the vector, and insert exact provider/model/dimension/fingerprint metadata atomically.

Crash and replay

A crash before send releases or retains authority according to the gateway. A crash after send reconciles without resend. A crash after settlement reuses the journaled vector and paid proof. A crash during graph application rolls back vector and metadata together. Exact replay performs no send and verifies existing bytes; substitutions conflict.

Privacy and epistemic boundary

The document remains personal_reading and retrievable only under private_research with the matching owner. Embedding creates no node, edge, finding, gap, citation, evidence status, or grounded claim.

Non-goals

No public sharing, arbitrary document embedding, fallback chain beyond one approved route, production credential, evidence promotion, merge, deployment, or unapproved live spend.

Acceptance

Tests prove preview-without-reservation, approval binding, reserve-before-one-send, exact vector/evidence validation, settlement binding, timeout reconciliation, process-death recovery, atomic graph application, free replay, owner/public retrieval policy, substitution rejection, and zero graph claims. Scoped typing, Ruff, HTML parsing, coupled tests, hostile review, and HardenX must pass.
