MSR-02C: Sealed Narration Closure

Parent MSR-02

Spec lineage

Leaf sprint under MSR-02.

    Contract

    List and MAC-verify all parent narration runs for the exact asset/revision. Require exactly one sealed run whose canonical artifact equals the receipt narration artifact. For each ordered receipt chapter, derive the deterministic child revision and require exactly one same-owner, same-asset text-to-speech execution. Recompute the ordered authorization-set digest and require equality with the sealed run.

    Reconstruction row

    [sequence, chapter_id, child_revision_id, request_body_digest, authorization_id, approved_ceiling_microdollars], byte-for-byte identical to narration admission.

    Refusals

    • Zero or multiple matching sealed runs; corrupt run MAC; admitted-only run; artifact mismatch; malformed or reordered chapter bindings.
    • Zero or multiple child executions; wrong capability, owner, asset, child revision, or chapter order; authorization-set digest mismatch; duplicate execution IDs.

    Tests

    • One-, multi-, and maximum-bounded chapter sets.
    • Unrelated parent run ignored only if valid and artifact-distinct; corrupt same-identity rows conflict.
    • Alternative authorization for one child causes ambiguity or digest mismatch, never arbitrary selection.

    Out of scope

    Voice quality, provider invocation, retry, reconciliation, and settlement.

    Five-values rigor

    Artifact equality proves the run produced the bytes; digest reconstruction proves the chosen executions were that run's authorized children. Both are required.

    Harness hint

    Enumerate cardinality and tamper cases until no new authority gap remains.
