Scene Authored Transition Palettes

Give dawn and dusk their own restrained Antiek atmosphere without changing time authority, geometry, or the reader shell.

Child specs: none. One tightly coupled implementation sprint is the honest decomposition.

Goal

Replace seed-only dawn/day and dusk/night differentiation with four explicit, static, six-role landscape palettes. Dawn should read as cold glacial air with a narrow weathered-straw horizon; dusk as deep slate with restrained desaturated teal afterglow. Day and night remain byte-identical.

Success criteria

  • Each daypart resolves a unique tuple: sky top/mid/horizon and ridge far/mid/near.
  • All runtime colors originate in named scene tokens mirrored across TypeScript, CSS, and Tailwind; ProceduralSky.tsx contains no raw colors.
  • Four-cell Storybook proof at 768, 1024, and 1280 shows distinct, legible, low-chroma transitions.

Failure mode to avoid

Technically different hexes that still look identical—or generic orange/magenta spectacle that competes with reading—would both fail.

Architecture

static scene tokens (tokens.ts ↔ tokens.css ↔ Tailwind var utilities) → pure exhaustive sceneLandscapePalette(dayPart) → ProceduralSky gradient + three SVG ridge roles → deterministic matrix tests + fixed Storybook baselines
  • Static scene roles are correct because all four plates render together under one OS theme.
  • The existing scene/palette.ts remains canvas weather authority; it must not absorb landscape roles.
  • Ridge generation, mood derivation, parallax, weather, Krea fallback, glass, shell, and accessibility semantics remain unchanged.
