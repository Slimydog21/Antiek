Master spec · WERNER-BROADCAST-01

Research completion becomes a broadcast, not a teardown

Compose authoritative deep-research state, the active arcade, and Werner into one deliberate living-TV transition.

Status: executionOwner: goal orchestrator1 sprint · 1 wave2026-07-17

Spec lineage

Root execution spec; no child subtree is warranted because the engine seam and integration shell share one serial ownership boundary.

  • None.

Goal

A newly terminal investigation must pause—but not destroy—the currently playing cartridge and surface an authored, textual Werner broadcast naming the research. Partial completion may resume the same cartridge. Final completion must remain visible until the operator explicitly returns to results.

Success criteria

  • The same cartridge instance survives pause/resume and final broadcast.
  • Repeated poll snapshots never replay a terminal transition.
  • Research lifecycle authority remains in the parent snapshot; the arcade derives presentation only.
  • Keyboard, pointer, focus return, and the existing reduced-motion exclusion are mechanically covered.
Failure mode: the game vanishes beneath the operator’s hands on the most important event, turning Werner’s world into a conditional widget instead of an asynchronous show.

Architecture

authoritative ResearchStatus[] │ derive terminal edges by investigation_id + state ▼ ResearchWaitArcadeGate ── presentation snapshot ──▶ ResearchWaitArcade │ broadcast overlay ───┼── paused=true ▼ ArcadeMount (same cartridge) View research/results ── explicit operator action ──▶ parent focus/canvas

Invariants

  • Initial terminal data is baseline, not a new arrival.
  • Only nonterminal→terminal edges enqueue broadcasts; identical snapshots are inert.
  • Pause stops simulation input/update without teardown, re-init, score loss, or focus theft.
  • Final completion never auto-navigates and never auto-dismisses.
  • Reduced-motion sessions retain the established policy: the optional arcade and its broadcast shell never mount; research cards remain the static source of completion truth.

Decision log and rejected alternatives

Decision Why Rejected
Cabinet-level persistent overlay The active canvas owns the operator’s attention and input; the transition belongs where the event interrupts play. Global toast/emote: cannot name the research or preserve an explicit return choice.
Pause the loop, preserve cartridge identity Completion is an interruption, not a new game session. Unmount/remount: destroys score and makes the broadcast feel accidental.
Text plus existing authored Werner pose State must not be encoded by animation or color, and existing art already carries the brand. New generated art/video: cost without adding product truth.
Parent-derived presentation model Polling remains the sole lifecycle authority. Arcade-owned research state: creates a second truth source.

Open integration fact

The newer goal/twin-autoload-session-alpha branch replaces portions of the wait shell with LoadingGameHost. The pure transition model and ArcadeMount paused seam are intentionally portable; integration must be rebased/cherry-picked into whichever arcade shell lands first rather than duplicating both.

Execution harness hint
