Research arrival broadcast

Preserve the game and let Werner hand the operator each completed line of inquiry.

Parent context

The deep-research monitor polls durable server snapshots. Its wait arcade currently sees only an aggregate running count and is removed immediately when all research becomes terminal. The canvas therefore disappears at the moment results arrive. This sprint adds presentation-only edge detection, a cartridge-preserving pause seam, and one cabinet overlay.

The integration may later move from ResearchWaitArcade to LoadingGameHost. Keep the transition reducer and engine pause seam shell-agnostic; do not import research APIs into arcade core.

Technical milestones

1
Define terminal-edge presentation

Create a pure reducer/model keyed by investigation id. Baseline initial data, enqueue each nonterminal→terminal edge once, retain order from the authoritative snapshot, and distinguish done, failed, stopped, and budget-halted copy.

Tests prove: identical polls inert; simultaneous edges deterministic; regression to nonterminal and a later new terminal edge is handled deliberately; episode reset clears history.

2
Pause without teardown

Add paused to ArcadeMount. Stop/start the existing loop through a live ref; keep cartridge init/teardown tied only to mount identity. While paused, clear held/edge input so resume cannot replay a stale shot or movement.

The same cartridge is initialized once, update count freezes, resume continues, stale inputs do not fire, and unmount tears down exactly once.

3
Compose the cabinet broadcast

Pass the small research presentation array through the gate. During active play, show a labelled, non-modal overlay with existing authored Werner art, textual state, the sub-question, and remaining count. Partial arrivals offer Continue game and View research; final arrival offers View results and Exit game.

Partial arrival does not steal focus; final arrival focuses the explicit results action once; Escape keeps the existing exit contract; reduced motion keeps the optional arcade absent and leaves completion truth in the static research cards; no auto-dismiss/navigation.

Rigor — operating manual

1 · Intellectual honesty

A poll snapshot proves state, not event time. Call an arrival only when this mounted episode observed a nonterminal state before the terminal state; initial terminal rows are baseline.

2 · Fairness

Steelman immediate teardown: it is simpler and restores results quickly. Reject it only because explicit active gameplay means the operator chose continuity; non-playing sessions should still terminate immediately.

3 · Rigor

Assert cartridge identity, update counts, input clearing, focus movement, duplicate polling, simultaneous completions, and final completion. A DOM snapshot without loop evidence is insufficient.

4 · Diligence

Read the loop, gate, wait shell, research types, focus-return tests, and newer LoadingGameHost history before editing. Reuse existing poses and buttons.

5 · Defensibility

Keep shell portability explicit in types and commit message. Record why final completion remains operator-dismissed and why no new image spend was warranted.
