Cycle 108: Budgeted Twin Dispatch Worker

Status: execution contract. Parent: Cycle 107 signed segment completion and parent aggregation.

1. Outcome

Antiek can execute one exact segment or aggregate twin-generation operation through the existing hard-ceiling provider gateway. Every billable send is preceded by a durable hold. A completion receipt can be issued only after authoritative settlement and only for provider output durably bound to that exact operation.

2. Existing Authorities Reused

AuthorityResponsibility

Cycle 108 MUST NOT create another spend ledger, bypass the gateway, accept caller prices, or treat a hold identifier by itself as completion evidence.

3. New Authority

A private SQLite worker journal stores commitments and canonical proposals, but never source text. Its schema is pinned and immutable. Each row binds:

  • account, asset, parent source, manifest, operation kind and segment index;
  • canonical operation digest and provider idempotency key;
  • provider/model, hold identifier and settled state;
  • canonical proposal JSON and proposal hash;
  • authoritative provider evidence hash, never private evidence bodies;
  • the exact persisted signed receipt.

4. Dispatch Protocol

  1. Reverify current source bytes, manifest, registry and existing completion state.
  2. Construct a canonical operation. A segment operation includes exact manifest/range/content commitments and the segment source text sent to the model. An aggregate operation includes the exact ordered segment binding commitments and canonical segment proposals.
  3. Require the projection request route to equal the adapter route and the pinned twin seam/operation. Usage maxima are server-validated; zero, missing, stale or unqualified pricing refuses before reservation.
  4. Call ResearchProviderGateway.dispatch_paid. The gateway reserves before marking dispatch possible and sending.
  5. A twin adapter wrapper validates the returned TwinProposal and durably journals it before returning ProviderSuccess to the gateway. Thus settlement cannot precede recoverable output.
  6. For ambiguous calls, reconciliation must return both authoritative billing disposition and the exact recovered proposal when charged. The wrapper journals charged output before reporting reconciliation to the gateway. Charged-without-output remains unknown and cannot settle or sign.
  7. After gateway settlement, reload the hold and journal. Recompute every identity. Issue and persist one deterministic signed receipt using a server-held Ed25519 key, then apply it through Cycle 107.

5. Replay and Crash Contract

Crash pointRequired recovery
Before holdNo provider call and no receipt.
After hold, before dispatch markerGateway releases as provably unsent.
After dispatch marker, before provider resultReconcile only; never blind retry.
After provider result, before settlementJournal already contains exact proposal; gateway reconciliation converges settlement.
After settlement, before receiptReplay reads settled hold plus journal and issues the same deterministic receipt.
After receipt, before completion applyReplay applies persisted receipt; no provider call and no new spend.

6. Signing and Identity

  • Signing seed is constructor-injected private bytes, exactly 32 bytes; no key is read from request data.
  • Key identifier and verify key are derived from the signing key and must match Cycle 107 verification.
  • Receipt identifier is deterministic over operation identity, hold, proposal hash and key identifier.
  • budget_authority_id and paid_hold_id equal the exact settled hold ID. Worker revalidates owner/run/provider/model/operation digest and settled state immediately before signing.
  • The v2 signed payload binds spend_run_id, provider, provider response ID, the provider-idempotency-key hash, actual cents, currency, settlement evidence hash, settlement intent hash, settlement time and ceiling-breach state.
  • Settlement proof is reconstructed from the spend ledger only when exactly one settlement event and its typed provider evidence bind the expected run, operation digest, idempotency key and output hash.
  • Legacy v1 receipts remain readable for historical Cycle 107 data but are never accepted as proof that a billable Cycle 108 dispatch completed.
  • Receipt expiry is persisted on first issuance. A journaled receipt must remain unexpired and match the active worker key until first completion apply. Once applied, historical reads authenticate its signature against the configured keyring without reapplying issuance expiry.

7. Refusals

The worker fails closed for source or manifest drift, missing segment completion prerequisites, released/reserved/unknown holds, settled holds without journaled output, provider output without settlement, proposal substitution, route/model mismatch, malformed output, key mismatch, journal corruption, schema drift, receipt expiry before first apply, or any operation whose cost cannot be conservatively bounded.

8. Acceptance Tests

  1. Segment happy path proves reserve precedes send, journal precedes settlement, receipt hold equals settled hold, and Cycle 107 applies it.
  2. Aggregate happy path is impossible until every ordered segment binding exists; then it binds the exact ordered set.
  3. Exact replay performs zero sends, zero new holds and returns the same receipt/binding.
  4. Changed source, manifest, range, proposal, provider, model, projection, run owner or approval revision refuses.
  5. Ceiling exhaustion and ineligible routes refuse before adapter invocation.
  6. Provider-not-sent releases and cannot sign. Unknown outcome retains authority and cannot sign.
  7. Charged reconciliation without exact output remains unknown. Charged reconciliation with exact output journals before settlement and recovers.
  8. Crash checkpoints cover journal-before-settle, settle-before-receipt and receipt-before-apply.
  9. Concurrent exact calls converge on one provider identity, hold, journal record and receipt; substitutions conflict.
  10. Database reopen, schema/object mutation, row corruption and signing-key rotation fail closed.
  11. Coupled Cycle104-107, spend-ledger and provider-gateway tests remain green; Ruff, strict typing, HTML parse and security review pass.

9. Explicit Non-Goals

No production provider adapter, pricing catalog entry, API/UI, automatic fleet scheduling, fallback routing, canonical parent projection, graph/search promotion, production corpus mutation, merge, deployment or live spend. This sprint builds and proves the reusable authority boundary; a provider route remains disabled until its pricing, idempotency and reconciliation-with-output guarantees are separately qualified.

10. Next Authority
