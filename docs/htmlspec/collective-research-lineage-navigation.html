Collective research lineage navigation

Status: executable. Base: Cycle 72 collective composition launch.

Outcome

An investigation launched from multiple completed investigations remains visibly connected to its exact ordered sources. From the active research view, the operator can inspect every member, return to a member investigation, and open the immutable combined HTML context that seeded the run.

Authority

  • The schema-v37 investigation.start_requested event is the lineage source of truth.
  • The client never reconstructs composition identity, hashes, order, or membership.
  • Combined HTML is served only by the existing owner-scoped composition endpoint, which revalidates repository authority and exact stored bytes.
  • No lineage surface appears for ordinary, evidence-manifest, or legacy investigations.

Interaction

  1. Render a compact “Collective sources” band above the investigation body when one valid composition provenance payload exists.
  2. Show member count and ordered member investigation links.
  3. Open the combined HTML in a new tab through the canonical API route.
  4. Disable the HTML command when the composition identity is malformed; never guess or repair it.

Acceptance

  • Exact ordinal order is preserved even when event order changes.
  • Duplicate, gapped, count-mismatched, or malformed provenance renders nothing.
  • Member navigation uses /inv/{encoded-id}.
  • The HTML URL uses /research/artifacts/compositions/{encoded-id} and opens with noopener,noreferrer.
  • Loading, running, completed, failed, and ordinary investigation behavior remains unchanged.
  • Focused unit tests, TypeScript typecheck, production build, strict security scan, and hostile review pass.

Non-goals

No composition mutation, sharing, re-launch, model selection, budget authorization, or client-side HTML reconstruction.
