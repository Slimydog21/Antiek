MSR-03E: Hardening Fallback Integration

Parent MSR-03

Spec lineage

Leaf sprint under MSR-03.

    Contract

    The hardening endpoint first attempts the existing direct paid snapshot. Only when paid evidence is unavailable may it ask the optional configured local video or audio runtime for MSR-03 evidence. A paid conflict is never routed around. Exactly one cost authority may pass and persist in the report.

    Runtime seam

    • Extend the hardening runtime with optional no-write local evidence backends composed from the already configured local video/audio runtimes. Do not re-read raw local keys from a second environment namespace.
    • The server selects the backend from the authenticated current asset mode/kind. Callers cannot choose paid, local, run kind, or run ID.
    • Preserve cost_snapshot for legacy paid reports. Add separately named local_zero_cost_evidence; strict report validation permits at most one. Legacy reports with neither still reopen as non-authoritative history.

    Gate semantics

    • Paid valid: pass with paid snapshot. Paid unavailable plus local valid: pass with local-zero evidence.
    • Paid conflict, local conflict, missing local runtime, missing local authority, both authorities, or identity/MAC failure: block with stable typed findings.
    • Do not auto-accept production-byte projection under either label; MSR-02 integration remains a separate decision.

    API semantics

    • Missing asset remains 404. Missing runtime remains 503.
    • Unavailable or conflict evidence remains stable 409 detail without leaking paths, keys, owner identifiers, raw rows, or receipts.
    • The route does no provider call, reconciliation, settlement, production, recovery, registration, route mutation, or publication.

    Acceptance tests

    • Paid path is unchanged. Local video and local audio fallback persist exact signed zero evidence.
    • Paid conflict never falls back; paid unavailable can fall back; mixed provider child rows block local zero.
    • Wrong backend kind, no optional runtime, both authorities, legacy report reopen, configured 200, typed 409, missing-runtime 503, and no-write guarantees are covered.
    • Adjacent hardening, route, read-model, coordinator, playback, and registration suites remain green.

    Files

    substrate/multimedia/hardening.py, read-model hardening adapter, hardening runtime/routes, optional local runtime protocols, and focused tests.

    Five-values rigor

    The fallback order cannot convert a paid contradiction into zero; the report names one authority and retains historical compatibility without granting it new force.

    Out of scope

    No MSR-02 hardening integration, mixed allocation, budget ceiling, rights automation, quality routing, or publication.

    Harness hint

    Use one reviewer for downgrade/fallback attacks and another for legacy/report/API compatibility.
