One-time consent + enqueue-once

Wave 2Still zero provider spend

Parent context

SPR-01 has produced a durable owner-bound intent whose exact bytes and cents are stable across restart. This sprint turns explicit user approval into one queueable operation without storing bearer authority in plaintext.

Approval is not execution. The output of this sprint is a durable queued operation and a receipt—not a provider call, answer, research artifact, or graph mutation.

Goal

Issue a one-time, exact-intent consent and atomically claim it into a unique durable queue entry.

Technical milestones

  1. Issue consent once. Add substrate/paid_operations/consent.py. HMAC key-id envelope binds owner/account, operation ID/kind, intent hash, ceiling cents, issued/expiry time and 256-bit random nonce. Return bearer once with Cache-Control: no-store, private; persist only SHA-256 token hash and metadata in the SPR-01 row. Issuance is a CAS from intent_created to consent_issued. Any later issue request—including exact response-loss retry—returns typed 409 consent_already_issued plus token-free operation status; it never rotates or returns a second bearer. The UI must tell the user to create a new operation if the one-time response is lost.
  2. Protect owner APIs. In interfaces/research/api/paid_operation_routes.py, resolve subject/account from existing authenticated request state; never accept either from body. Foreign IDs use the identical 404 schema/timing class as absent IDs. Logs/errors redact token and sensitive intent material.
  3. Claim + enqueue in one database transaction. Add paid_operation_queue to the same SQLite database, with unique primary key and foreign key operation_id, exact intent_hash, immutable canonical options bytes, enqueue timestamp and queue state. One BEGIN IMMEDIATE verifies token hash/expiry/current consent_issued state, inserts the unique queue row, writes claimed_at_ms, and CAS-transitions the authority to queued. No split store and no outbox fallback are permitted in v1.
  4. Specify crash outcomes and startup validation. Before commit: restart sees consent_issued and no queue row, so exact bearer retry may claim. After commit/before response: restart sees queued and exactly one matching row; exact run request returns queued snapshot without requiring or revealing the bearer again. At startup, scan every non-intent_created operation: queued|running|terminal requires one same-owner/account/intent queue row; consent_issued requires none; queue rows without authority, mismatched hashes/subjects, duplicate logical identity, or claimed consent without queue are fatal. Raise PaidOperationCorruptionError before route registration and log identifiers only.
  5. Prove replay behavior. Changed intent/ceiling/options conflicts; expired, wrong-owner/account, wrong-key or already-claimed bearer cannot create another queue row. Tests live in tests/test_paid_operation_consent.py, tests/test_paid_operation_queue.py and tests/test_paid_operation_routes.py.

Rigor — operating manual

1 · Intellectual honesty

A signed token is only as strong as its bindings. List the complete envelope in the decision record and mark the route unavailable if any SPR-01 intent field is reconstructed from mutable current state.

2 · Fairness

Steelman a server-side approval session without a bearer token. Compare response-loss recovery, cross-device use, CSRF surface and secret retention before retaining the HMAC design.

3 · Rigor

Force crashes at consent-write, claim, queue-write and response boundaries. Each restart must produce either zero queue entries or exactly one matching entry—never consumed authority with lost work or duplicate work.

4 · Diligence

Trace current authentication and no-store conventions plus historical spend_consent.py/operation_queue.py tests. Do not copy their split-store atomicity assumptions without a current proof.

5 · Defensibility

Persist a key-rotation and token-expiry decision with explicit clock semantics. Record why exact replay returns status while material drift returns conflict.

Dependencies

  • SPR-01 schema, canonical vectors and concurrent CAS gates are green.
  • Deployment supplies an active signing key ID and verification keyring; tests use injected deterministic secrets only.

Out of scope

  • Leasing or executing queue work.
  • Provider selection, pricing discovery, API keys, model calls.
  • Collective answer UI or Midnight Oil runner enablement.
