Generation-fenced dispatch + reconciliation

Wave 3Live remains capability-gated

Parent context

SPR-02 can durably enqueue one exact, consented paid operation. That is still insufficient authority to call a provider: workers race, leases expire, responses disappear, costs differ from projections and some providers ignore idempotency headers.

This sprint owns the only paid dispatch boundary. Product adapters submit immutable intent and later consume terminal receipts; they never receive API keys or call providers themselves.

Goal

Permit a paid network call only inside a valid generation-fenced lease with verified provider idempotency, conservative budget reservation, durable checkpointing and unknown-outcome quarantine.

Technical milestones

  1. Lease with generation fencing. Extend the same SQLite authority database with atomic queued→running lease, monotonic generation, expiry, renewal and takeover in substrate/paid_operations/worker.py. Every reserve, checkpoint, settlement and terminal mutation supplies operation+worker+generation and CAS version.
  2. Attest provider capability. A checked-in capability record binds provider, endpoint, API version and retention window and includes: authoritative provider documentation; request-body/key scope; duplicate-key same-body behavior; duplicate-key changed-body conflict behavior; billing semantics; and a separately operator-authorized two-request live smoke receipt proving one logical result/charge across the timeout window. Missing, expired or contradictory evidence keeps the route unavailable at startup. Header acceptance alone never qualifies.
  3. Make account budget authoritative. Add paid_account_budgets(account_id PRIMARY KEY, period_id, limit_cents, reserved_cents, settled_cents, version) in the same SQLite database. Settings updates create a new period or CAS the limit but may never set it below reserved+settled. Available cents equals limit-reserved-settled. Under one BEGIN IMMEDIATE, verify operation headroom and account available cents, insert the unique reserve movement, and CAS-increment account reserved cents/version; SQLite’s single writer serializes concurrent operations across the account.
  4. Use idempotent movements. Append-only paid_operation_ledger rows are uniquely keyed as {operation_id}:{step}:reserve|settle|release|retain|reconcile, each carrying cents, account/period, intent hash, lease generation and prior movement. Settle atomically decrements reserved and increments settled; release decrements reserved; retain changes no aggregate. Exact movement replay returns existing material, drift conflicts, and aggregate checks enforce non-negative values plus reserved+settled≤limit.
  5. Checkpoint then settle. Provider key derives from operation+step+intent hash. Persist returned body hash, provider receipt and observed cost under a unique step checkpoint before idempotent settle/release and terminal transition. Crash replay consumes the checkpoint and existing movement IDs without redispatch or duplicate debit.
  6. Quarantine ambiguity. Timeout/lost response writes a unique retain movement, keeps the reserve, and enters failed_reconcile. A separate operator-only route requires server-resolved operator role, operation/version, provider receipt or signed billing evidence hash, decision confirm_charged|confirm_not_charged, unique reconciliation command ID and reason. It appends an immutable audit event; exact replay converges, changed evidence/decision conflicts, and it can only terminalize or release/settle the existing hold—never redispatch.
  7. Validate startup invariants. Before serving, scan authority/queue/lease/checkpoint/ledger/budget joins: running requires one unexpired-or-recoverable lease generation; checkpoint requires matching queue+intent+step; each settlement/release requires one reserve and aggregate equality; terminal non-reconcile rows permit no unresolved reserve; failed_reconcile requires exactly one retained unresolved reserve. Orphans, mismatched owner/account/intent/generation, duplicate logical movements or aggregate drift raise PaidOperationCorruptionError. Expired valid leases are recoverable queue work, not corruption.
  8. Integrate both adapters. Collective interrogation and Midnight Oil map their immutable intents into the root’s frozen profiles; paid enablement is separate per kind and remains off unless its complete capability matrix passes. Tests live in tests/test_paid_operation_worker.py, tests/test_paid_operation_ledger.py, tests/test_paid_operation_reconciliation.py and tests/test_paid_operation_e2e.py.

Rigor — operating manual

1 · Intellectual honesty

Do not label an adapter idempotent because it forwards a header. Require operator-owned evidence for the exact endpoint/provider contract; otherwise keep that route unavailable and report the unrun live smoke.

2 · Fairness

Steelman transactional outbox/provider proxy designs that might reduce unknown outcomes. Compare operational complexity against the permanent cost of retained holds and manual reconciliation.

3 · Rigor

Race two workers, expire the first lease mid-call, crash after provider return and before settlement, and simulate a lost response. Assert the provider canary count and stable idempotency key—not only final state.

4 · Diligence

Read historical budget_ledger.py, worker.py, authorized E2E tests and the live-convergence decision at SHA 802d2e0e. Re-derive their invariants against current persistence and routing rather than porting code.

5 · Defensibility

Record the exact dispatch capability matrix, pricing snapshot source, reserve formula, reconciliation owner and reversal conditions. Production enablement must be reconstructable from checked-in evidence.

Dependencies

  • SPR-02 exact replay, secret scan and crash gates are green.
  • A durable queue consumer and operator-owned reconciliation process exist.
  • At least one provider contract has verified idempotency and observed cost semantics; otherwise execute all fake-provider proofs and leave live disabled.

Out of scope

  • Inventing external arXiv/Substack retrieval receipts.
  • Graph admission, Write promotion or automatic merge of generated answers.
  • Claiming production/live verification without a paid, explicitly authorized smoke.
  • Retrying unknown outcomes or releasing their holds heuristically.
