One paid-operation authority

Safely converge collective interrogation and Midnight Oil on a shared, owner-bound, integer-cent authorization substrate—without reviving a closed 1,429-commit historical runtime.

Executive decision

Do not extract or cherry-pick the historical runtime wholesale. Build a shared paid-operation substrate in three serial proof slices. The historical branch caffen/mo-authorization-live-convergence@802d2e0e is evidence and counterexample material, not merge authority: it is 104 commits behind and 1,429 ahead of current main; PRs #1080 and #1195 are closed, not merged.

Until all three sprints pass together, collective interrogation remains preview-only and Midnight Oil live provider dispatch remains unavailable. No route may infer approval from UI state, a prompt string, a quote, or possession of a job ID.

Non-negotiable execution chain

authenticated owner
  → immutable operation intent (kind + exact input/config hashes)
  → integer-cent quote and ceiling
  → one-time signed consent, returned once and never persisted in plaintext
  → atomic claim + enqueue-once
  → generation-fenced lease
  → reserve conservative maximum
  → provider dispatch with verified idempotency key
  → durable returned-result checkpoint
  → settle actual cost OR quarantine ambiguous outcome
  → terminal receipt + idempotent product projection

Any missing arrow is a fail-closed deployment condition, not a TODO behind an enabled button.

Frozen v1 intent profiles

Canonical bytes are UTF-8 JSON using sorted keys, no insignificant whitespace, integers/booleans/strings/arrays/objects only, NFC-normalized strings, no floats, no nulls, no implicit defaults and rejection of every unknown key. Hash domain is antiek.paid-operation.intent.v1\0 followed by those bytes. Golden vectors live in tests/fixtures/paid_operations/intent-v1.json.

Global completion gates

  • Every hostile case asserts zero provider calls, not merely an HTTP error.
  • Restart tests cross create → consent → enqueue → lease → checkpoint → settle using durable stores.
  • Plaintext consent tokens, API keys, raw provider errors and prompt secrets do not appear in databases, logs, HTML or exceptions.
  • Collective preview remains byte-for-byte zero-spend compatible throughout SPR-01 and SPR-02.
  • Deployment configuration fails before serving if a live operation kind lacks a verified idempotent provider capability, durable queue consumer, or reconciliation owner.

Spend boundary for executing this spec

SPR-01, SPR-02 and all fake-provider SPR-03 gates spend zero. A real two-request idempotency smoke is a separate operator-gated production-capability action: the executor must present endpoint, exact maximum cents and evidence plan, receive explicit approval, bind that approval through this same authority substrate, and record actual cost. Without that approval, report the smoke as NOT RUN and leave the provider/operation kind disabled.
