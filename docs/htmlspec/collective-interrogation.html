Ask the light table

Interrogate several reviewed researches as one immutable evidence corpus without flattening their identities, smuggling provenance through prompt text, or spending before approval.

Spec lineage

Root execution spec. Parent product authority: Research compose light table and Source Spine.

  • Future child: paid provider execution and durable answer receipt, specified below.

Goal and architecture

The existing compose fingerprint over ordered canonical member hashes remains the sole corpus identity. Wave 1 creates a deterministic, zero-spend interrogation preview packet. Wave 2 consumes that exact packet only after a quoted ceiling is explicitly approved and publishes an HTML answer plus receipt.

completed researches → immutable compose manifest ↓ validate member hashes question → bounded context packet → zero-spend receipt ↓ explicit ceiling approval (future child) provider execution → HTML answer + provenance receipt

Failure mode: never call cold startInvestigation with a compose ID hidden in free-text context. That path neither binds frozen member hashes nor owns per-call approval.

SPR-01 operating manual

Milestones

  1. Add compose_interrogate.py with strict prompt bounds, deterministic ordered member inclusion, whole-field truncation reporting, and manifest/member hash validation.
  2. Add POST /artifact-composes/{id}/interrogations/preview. It returns corpus receipt and estimated context size only; it imports or calls no provider.
  3. Add typed client and an “Ask these sources” area only after the immutable draft exists. “Review question” produces the zero-spend receipt; copy must say no answer has run.
  4. Test corruption, staleness, member order, prompt bounds, context bounds, route status, and zero-provider behavior.

Out of scope

No generated answer, model selection, budget quote, approval issuance, cold investigation, graph mutation, source merge, or Write mutation.

Intellectual honesty

The preview labels included and omitted fields; it never calls context bytes “tokens” or a preview an answer.

Fairness

Member order and per-member minima prevent the first long research from silently erasing later selected sources.

Rigor

Corrupt HTML, mismatched hash, wrong compose ID/fingerprint, duplicate members, oversized prompts, and exhausted context fail closed or report deterministic omission.

Diligence

Reuse load_compose_draft, parse_body_from_html, compose locking, route error vocabulary, and Evidence Passport. Do not introduce a second compose identity.

Defensibility

Constants name units and rationale. The response carries schema version, prompt hash, fingerprint, member hashes, character counts, and truncation facts.

SPR-02 future child contract

Before execution, define a server-owned provider quote and one-shot approval receipt bound to (compose_id, selection_fingerprint, prompt_hash, route, ceiling). Revalidate the packet immediately before provider dispatch. Persist pending/succeeded/failed/reconcile-needed states idempotently. Render the human answer as script-free HTML; expose a machine receipt with member hashes, model route, quoted ceiling, actual cost, and claim-to-member references. A retry must reuse the receipt or require a new quote; it cannot double-spend.

Open decisions: whether the answer becomes a new child investigation or a compose-scoped answer artifact; how owner/private-research rights are authorized across accounts; token counting per chosen provider; and which existing durable spend ledger can issue this authorization. These are blockers, not UI polish.

Rejected alternatives

  • Cold research with pasted context: provenance-by-string and fresh corpus retrieval, not collective interrogation.
  • Raw HTML to model: unbounded, script-adjacent, and biased by member length.
  • Client-only prompt assembly: lets the browser assert hashes and rights authority.
  • Immediate “Ask” button: implies cost and answer semantics that do not yet exist.

Execution harness hint

SPR-01 is inline implementation with an independent authority critic. SPR-02 must not execute until a durable spend-authority owner is identified.
