Billing Usage Observatory

Scope: Replace apps/reading/src/modes/Billing/index.tsx with a pure exported BillingView + controller pattern. Dedicated CSS. Comprehensive tests and Storybook stories. No backend changes.

1. Goal

Build an operator-facing Billing Usage Observatory page that displays the event-derived billable estimate from GET /billing/summary/{user_id}/{period}. The page must be honest about what it is (an estimate, not an invoice), honest about what it doesn't know (no completeness metadata), and rigorous about never inferring zero from absence.

2. Truth contract (from live code)

3.2 Component split

  • BillingView (named export): Pure presentational. Props: state, userId, period, data, validation errors, callbacks. No hooks that call the API.
  • Billing (default export): Controller. Owns state, validation, API calls with stale-response and unmount guards.

4. Acceptance criteria

4.1 Semantic HTML

  • Use <main>, <header>, <section>, <article>, <aside>, <dl> appropriately.
  • role="search" on the form.
  • role="progressbar" with aria-valuenow/min/max on free-tier bar.
  • aria-live="polite" on loading and empty states.
  • role="alert" on error state and validation hints.
  • aria-label on truth-boundary aside.
  • aria-invalid + aria-describedby on form inputs with errors.

4.2 Responsive layout

  • Dedicated CSS file — no Tailwind utilities (the Pricing/PayoutsAudit pattern).
  • Grid-based layout that collapses to single column at 640px.
  • Content width capped at min(960px, calc(100% - 40px)).

4.3 Validation

  • Period: strict YYYY-MM regex — months 01–12 only.
  • User ID: nonempty after trim.
  • Explicit Apply button (no refetch per keystroke).
  • Submit disabled when form is invalid or loading.

4.4 Safe payload validation

  • Integers: Number.isFinite(n) && n >= 0 && Number.isInteger(n).
  • USD strings: regex /^(?:0|[1-9]\d*)(?:\.\d+)?$/ — canonical nonnegative decimal.
  • Malformed payload → error state, never inferred zero.

4.5 Guards

  • Stale-response: monotonically incrementing request token; discard responses whose token no longer matches.
  • Unmount: cleanup effect bumps the token so in-flight responses are discarded.

4.6 Naming and boundaries

  • Total labelled "Event-derived billable estimate" — never "invoice", "charged amount", "settled amount", "API-key budget", or "full provider ledger".
  • Truth-boundary panel prominently states: what this instrument is, what it is not, current limitations.
  • Non-operator empty state explicitly noted.
  • Paid-private classification explicitly noted.

4.7 Visual

  • Werner environment image as decorative background (same pattern as Pricing/PayoutsAudit).
  • Canonical Werner moods only: idle, thinking, empty, celebrate.
  • Glass-panel stations with backdrop-filter blur.
  • Day and night theme via prefers-color-scheme.
  • Reduced-motion safe (no intrinsic animation).
