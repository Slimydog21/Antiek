Cycle 59: Exact-Revision Grounded Companion

Let a reader question the immutable derived HTML revision on screen, inspect the exact evidence pack, persist defensible outcomes, and launch deeper research without overstating model, citation, or spend authority.

Spec lineage

Parent: Cycle 58 revision indexing

    Outcome

    The authenticated owner can submit a bounded question against either the verified current pointer or one exact historical revision. Antiek produces one deterministic evidence pack containing exact revision-scoped citations, persists the revision-bound turn and outcome, and exposes citation handoff into ChaseThread. With no matching evidence it records an abstention and makes zero provider calls. Paid answer execution remains fail-closed until a route has known pricing plus qualified crash-recovery and execution-time budget authority.

    Truthful capability boundary

    Body authority

    derived_asset_revisions.canonical_html remains the only reading body. Companion rows store bounded evidence snapshots and hashes, never another full HTML copy.

    Grounding authority

    The server reopens and verifies the revision index before packing evidence. Citation membership and immutability are mechanically guaranteed; semantic entailment is not claimed.

    Route authority

    Settings decisions and cost projections are advisory. Browser-supplied provider, rates, limits, verdicts, evidence, hashes, or HTML grant no execution authority.

    Spend authority

    Configured zero placeholders mean unknown price, not free. The general synchronous dispatcher is not crash-reconcilable paid-send authority. Unsupported execution returns a typed unavailable outcome before dispatch.

    Evidence pack v1

    1. Resolve current server-side or verify the named historical revision through DerivedAssetLibrary.reading.
    2. For current submissions, compare the resolved identity to the optional screen revision/hash and refuse stale screens without silently moving the question.
    3. Call the verified lexical retrieval boundary with fixed policy and top_k. The browser never supplies chunks.
    4. Canonicalize version, asset, revision, content hash, generation, index identity, query hash, retrieval parameters, and ordered citation records containing ID, ordinal, member, anchor, path, bounded text, and text hash.
    5. Hash canonical JSON as pack_sha256. Any ordering, question, policy, revision, or text mutation changes the digest.

    Persistence

    • derived_asset_companion_threads: unique per owner, asset, and exact revision/content identity; historical threads never flow into current.
    • derived_asset_companion_turns: unique owner/client key, canonical request hash, contiguous thread ordinal, bounded question, evidence-pack digest/snapshot, state, answer envelope, failure code, requested advisory snapshot, actual dispatch receipt when one eventually qualifies, and timestamps.
    • derived_asset_companion_turn_citations: ordered exact chunk identity, text hash, and answer-use flag with revision-safe foreign keys.
    • Same idempotency key and digest replays. Same key with changed question, revision, policy, or model choice conflicts. A claimed paid turn abandoned after send becomes outcome_unknown and is never automatically redispatched.
    • Cycle 59 may persist insufficient_evidence and execution_unavailable outcomes without a provider. It must not manufacture an answer merely to fill the conversation.

    HTTP contracts

    • GET /research/derived-assets/assets/{asset}/companion and the exact-revision variant return only that revision thread, immutable scope identity, and summaries of prior revision threads.
    • POST .../companion/evidence accepts question, fixed bounded top-k, optional expected screen identity, and an opaque idempotency key. It returns the persisted evidence/abstention outcome and an advisory model/cost disclosure.
    • A future POST .../companion/turns executes only after shared execution-time model registration, known pricing, budget authorization, and crash-safe send/reconciliation qualify the route. Until then it returns 503 companion_execution_unavailable with zero dispatches.
    • Errors distinguish invalid question, unavailable asset, revision/index integrity conflict, stale current screen, idempotency conflict, budget refusal, dispatch unavailable, and unknown outcome. Every response is private, no-store.

    Reader interaction

    The derived reader receives a revision-aware companion, while ordinary document reading keeps its existing investigation projection. The rail shows current or historical scope, persisted turns, a question field, exact evidence citations, explicit abstention, and honest model/cost status such as “Cost unavailable.” Citation actions scroll only to the exact section anchor; a missing anchor reveals the verified quote instead of fuzzy navigation. Route generation guards prevent a late response from revision A rendering over revision B.

    Research handoff

    “Follow this” opens ChaseThread but never auto-launches it. The handoff carries asset, revision, content hash, generation, citation ID, and chunk-text hash as structured provenance. The research launch server reopens the citation and verifies every identity before accepting it; identity JSON is not appended to free-form prompt context.

    Execution qualification sub-spec

    Paid companion answers become executable only after all four gates are shared platform capabilities: registered model-choice resolution, non-placeholder route pricing, execution-time hard-budget reservation, and provider idempotency or reconciliation after process loss. The qualified service must persist requested choice separately from actual provider/model/fallback/usage/cost/event identity and validate a strict answer envelope where every paragraph cites only pack members. Malformed, uncited, or foreign-citation output becomes abstention without a repair call.

    Sprint sequence

    1. S1 evidence authority: extract deterministic evidence-pack construction from verified retrieval, include missing text hash/index metadata, and prove cross-process digest determinism.
    2. S2 durable outcomes: add revision-bound thread/turn/citation schema and repository with owner isolation, idempotent replay, stale-current refusal, and persisted no-evidence abstention.
    3. S3 API: add current and pinned conversation/evidence routes with typed private responses and zero-dispatch assertions.
    4. S4 reader: implement exact-revision companion UI, citation navigation, reload persistence, stale response suppression, and explicit cost-unavailable disclosure.
    5. S5 recursive research: replace derived identity-in-context with structured citation provenance and server verification before launch.
    6. S6 qualification: leave executable tests/spec seams for the future shared paid gateway; do not weaken hard-spend invariants to finish this cycle.

    Acceptance harness

    • Pack digest is stable across processes and changes for question, revision, policy, order, or citation mutation; identical text in different revisions never shares citation identity.
    • Missing, extra, reordered, altered, foreign, or cross-owner index rows fail before persistence or dispatch.
    • No lexical match persists one abstention and invokes zero dispatches. Same client key replays exactly; changed command conflicts.
    • Current screen movement refuses with the new verified identity and zero calls. Pinned history remains pinned after pointer movement.
    • Canonical HTML never appears in companion tables. Old turns appear only on their exact revision route.
    • Unknown pricing renders as unavailable, never $0.00. Forged client rates, route, evidence, and projection verdict cannot authorize execution.
    • Question/evidence survives remount; citation anchor and missing-anchor behavior are exact; “Follow this” opens but does not launch research.
    • Backend tests, focused frontend tests, TypeScript, production build, Ruff, HTML validation, hostile review, and HardenX pass before publication.

    Rejected alternatives

    • Calling dispatch() directly and calling the turn hard-budgeted: synchronous fallback lacks provider reconciliation after a lost response.
    • Treating configured zero rates as free: repository comments define them as unknown placeholders.
    • Client-built evidence packs or citations: permits cross-revision and mutated evidence.
    • A generic chat/messages subsystem: weakens revision identity and expands scope without solving the reading workflow.
    • Silently moving current questions to a newer revision: makes the visible source differ from the answered source.
    • Automatic repair or second-model citation checking: spends more while still not proving semantic entailment.
    • Embedding provenance JSON in prompt prose: identity becomes unverifiable decoration rather than structured authority.

    Out of scope

    General chat, semantic vector retrieval, automatic follow-up agents, answer streaming, multi-revision conversation synthesis, companion-only BYOK validation, guessed provider pricing, and any claim of exactly-once provider billing.

    Five-values rigor

    Honesty: unknown cost and unsupported execution are visible. Fairness: only authenticated ownership and server-derived citations expose text. Rigor: every outcome binds an exact verified revision and deterministic pack. Diligence: stale screens, duplicate commands, projection drift, and crash states fail closed. Defensibility: the first vertical remains useful without weakening the platform’s hard-spend or canonical-body boundaries.

    Harness hint

    Implement pure evidence identity first, then persistence and current/pinned API behavior, then the reader and structured research handoff. Instrument dispatch and prove zero calls for every Cycle 59 path before claiming completion.
