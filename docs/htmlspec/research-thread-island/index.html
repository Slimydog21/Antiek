Research-thread island

A persistent, passage-anchored artifact in the reader that HOLDS a research thread: it emerges from a highlight (or a free-inquiry pin), shows the thread’s live status while it runs, presents the distilled outcome when complete, and offers “dig deeper” into the same thread context — the chase, never a chat box.

    Goal and proof boundary

    The operator’s words: “highlight a section → an island emerges where I engage with an LLM deep research subagent… I can give it the context it needs… or ask that specific thread who holds that context to dig deeper.” Success is not a badge next to a highlight. Success is: an operator deep-researches a passage, closes the reader, returns tomorrow, and the passage carries a calm mark showing the thread is still running; when the run completes, expanding the mark shows the thread’s distilled findings; “dig deeper” spawns a child into the SAME thread family with the island’s anchor context as its seed — in the standalone route and in the embedded reader window alike.

    anchor (unit 1) with investigation_id set → island declares ONE anchored widget on the SAME passage anchor collapsed: passage-level status mark (live glyph, restrained motion) expanded: overlay card pinned to the passage — NOT a workspace window → status: investigation event projection (live tail + fetch) → outcome: GET /research/{id}/distill (the durable product) → actions: Open research (/inv/:id) · Dig deeper (chase | deepen) · Dismiss → dig deeper: startInvestigation(parent_investigation_id = island thread) seeded with anchor quote + thread context → one thread FAMILY view

    Key invariants

    • Anchor-bound, always: an island exists iff its unit-1 anchor exists and carries a non-null investigation_id. Deleting the anchor (owner DELETE, unit 1) removes the island; the thread itself is untouched.
    • One widget, two states: one augmentation declares one anchored widget per island; collapsed and expanded are render states of that widget, not two components fighting over one anchor.
    • Projection, not storage: the island adds ZERO persistence. Thread process truth is the event log; outcome truth is the artifact/distill projection; the link lives on the anchor row. Any island state that must survive reload is derived on load, never written.
    • Dismiss is a view act: Dismiss collapses the island for the session (and an operator-chosen “hide” is a client-side view preference keyed by anchor id); it never deletes the anchor, the thread, or the link.
    • Chase, not chat: continued engagement spawns or deepens a RESEARCH thread through the existing paths. The island contains no chat input; the one-shot Dialogue action already exists elsewhere (FloatMenu.tsx:195) and stays one-shot.
    • Cost honesty: dig-deeper (chase) and deepen (steer) are presented as what they are — a NEW child investigation with its own budget vs MORE budget on the SAME investigation — with the capacity-warning surfacing startInvestigation already provides (lib/api.ts:325-365). No dead buttons: deepen appears only when the owning session is resolvable and live.
    • Terminal honesty: failed / stopped / budget_halted threads render an honest terminal state with the distill projection of what WAS produced. Nothing spins forever.
    • One reader: standalone /read/:documentId (App.tsx:209) and the embedded reader window (openWindow.ts:106-108) share BookReader — the island is implemented once, in the reader.

    Island anatomy and the servability boundary

    Collapsed — the passage mark

    A calm passage-level mark in the SAME lane as unit-1 anchored highlights, visually distinct from a plain highlight: the highlight’s wash + underline PLUS a small status glyph (a single 8px token-coloured dot: pulsing while the thread is live — motion only from motion.ts under the design system’s reduced-motion rule — steady sun when complete with findings, steady muted when complete-empty, and an honest terminal glyph on failure). Two islands never stack on one anchor (one anchor ↔ at most one thread link, unit 1); an island and a plain highlight never coexist on one anchor either — the island supersedes the plain mark.

    Expanded — the pinned overlay card

    An overlay card positioned from LayoutMap.resolve(passage anchor), rendered by the surface (which owns the DOM), dismissed by Esc / click-away / Dismiss. It is NOT a workspace window: windows are destinations with their own fetch authority (openWindow.ts:83-108); the island belongs to the text and dies with the page. Contents, top to bottom: (1) thread status line from the event projection — question, live state, cost-so-far; (2) the distilled outcome when terminal — lead insights and open questions from GET /research/{id}/distill with refinement counts and honest empty states; when the artifact body reports synthesis_withheld (schema.py:37) the card says so rather than pretending a summary exists; (3) the thread FAMILY — root + chases as one tree (useInvestigationTree.ts:31-81) with per-node status; (4) three actions: Open research (navigate /inv/:id), Dig deeper (chase; deepen as the labelled budget alternative), Dismiss.

    The servability / at-rest boundary

    Island content is never withheld book text. On a servable book the expanded card may quote the anchor’s passage (unit 1 stored it lawfully). On a metadata-only anchor the card shows passage POSITION (page + the parent’s honest label) and thread content only — the thread’s question, findings, and notes are the operator’s own research output, produced under the gate-safe spawn (books.ts:216-220: a gated book’s full text never crosses into the research). The island introduces no new copy of book body text at rest or in transit; it renders what unit 1 and the research substrate already lawfully hold.

    Contract. Two entry flows, both ending in an anchor linked to a thread (unit 1’s write-back — consumed, not re-specified). (a) Highlight path: the FloatMenu Deep-research action over a passage (Reading/index.tsx:243-259 → spinResearch, books.ts:221-260) gains the island consequence: the auto-pinned anchor (unit 1 SPR-02) receives the spawned investigation_id via unit 1 SPR-04’s write-back, and the island emerges collapsed at the passage immediately — no navigation away from the book (today the path navigates to /inv/:id; the island makes staying-in-the-book the default, with “Open research” as the explicit jump). (b) Free-inquiry: a reader-level “Research from here” entry pins FIRST — a real passage anchor on the current page’s lead passage through unit 1’s POST (source=pin) — then spawns via spinResearch with the pin’s passage, then write-back, then the island. Failure honesty: if the pin fails (ambiguous passage → unit 1’s 422), no thread is spawned and the operator sees the pin failure — never an anchorless island. If the spawn fails after a successful pin, the plain pinned highlight remains (it is lawful unit-1 state), with an honest error; a retry reuses the SAME anchor rather than pinning a duplicate.

    Proof (real calls):
    • Vitest + API round-trip: deep-research from a highlight → POST anchor → spin → write-back → GET anchors shows the link → the island mark renders on the passage in BOTH reader mounts, and the reader did NOT navigate away.
    • Free-inquiry from a seeded page: pin (source=pin) → spawn → write-back → island; the spawned thread’s seed contains the pinned passage (asserted from the recorded spawn request), and a gated book’s flow carries no withheld text (the spinResearch gate-safe contract, exercised against the real client call shape).
    • Failure matrix: pin-422 → zero spawn calls; spawn-failure → anchor persists, honest error, retry reuses the anchor id (no duplicate pin — asserted by request count).
    • Reload after spawn: island present with live status (the SPR-01 projection path, end-to-end).

    Non-goals: dig-deeper actions (SPR-04), changing the ResearchWorkstation chase path, batch/multi-passage spawns, any FloatMenu layout change beyond the consequence wiring.
