SPR-05 — Privacy-safe usage seeds

← master

Usage outcomes may shape benchmark coverage without copying private workstation text into evaluation truth.

Contract

  1. prompt_hint is private usage context and never becomes a suite prompt.
  2. Only benchmark_seed with benchmark_seed_reviewed=true may enter a proposal verbatim.
  3. Unreviewed events produce deterministic generic prompts from closed task/source/body-state fields.
  4. Reject reviewed seeds containing credentials, contact identifiers, control instructions, URLs, or oversized text.
  5. Deduplicate equivalent generic cases and cap additions per task class so usage volume cannot redefine the suite.
  6. Proposal/Settings payloads expose policy version and reviewed/generic/redacted/dropped counts, never rejected text.
  7. Proposal digests seal the policy, rationale, suite, and audit counts; legacy rows require explicit operator-reviewed migration.

Acceptance

  • Secrets, email addresses, phone numbers, URLs, and prompt injection in prompt_hint never appear in suite JSON or HTML.
  • Explicit safe reviewed seeds round-trip; unsafe reviewed seeds fail closed to generic cases and increment redaction counts.
  • One thousand duplicate failures cannot add more than the versioned per-task cap.
  • Proposal identity is derived from privacy-safe event projections, not raw text.

Non-goals

No LLM redactor, no automatic approval, no private-text export, and no routing change.
