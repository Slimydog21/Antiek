Workstation tabs

A named project container above the window layer: each workstation owns an ordered set of tabs — surface references, never content — with exactly one active surface, server-persisted per owner, hoppable by hotkey the way the operator hops Herdr workspaces. The existing window manager stays the only window manager; the workstation is an organizer over it, not a rival to it.

Evidence-backed4 sprints + prototype gateStack base 17cf5c6ae

Spec lineage

Root spec of the mothership pillar, sibling to Anchor-first highlights (PR #3425) and Research-thread island (PR #3428). It consumes their surfaces — a reader window with its anchored highlights and islands is simply a tab whose surface is reader:{documentId} — and changes nothing about them. Unit 4 (global reading) will deepen the reading-as-tab embedding; this spec builds the container, not the embedding.

    Goal and proof boundary

    The operator’s model: “a central mothership like Herdr that includes workstations (i.e., projects) and tabs within each workstation that can be hopped between with hot keys like herdr.” Success is a keyboard-only round trip: ⌥T opens a surface picker, a new tab appears in the focused workstation’s tab bar, ⌥3 hops to the third tab, ⌘` switches to the next workstation (the whole surface set swaps), a reload restores every workstation and tab from the server — and at no point did any code path manage a window other than through windowsStore’s own actions.

    workstation (named, color token, server-persisted per owner) → ordered tabs: surface REFS only window-kind tab { surface: "reader", payload: { documentId } } route-kind tab { surface: "route", route: "/inv/:id", investigationId } → exactly one ACTIVE tab; activating it: window-kind → openWindow()/focus via windowsStore (untouched) route-kind → swaps the main surface (URL stays canonical, no ws/tab state) → ⌥1-9 hop tabs · ⌥⇧[ / ⌥⇧] cycle · ⌘` cycle workstations · ⌥T new · ⌥W close → switching workstations: reset + replay-open the focused set (default rects)

    The gap, with evidence

    A real window manager exists: apps/reading/src/workspace/windowsStore.ts:190-288 — MAX_WINDOWS = 8 with honest at-cap focus redirection (:150,201-211), focus z-restack (:244-256), stable per-instance ids that focus-instead-of-duplicate (:193-200), and keyboard move/resize in the frame (WorkspaceWindow.tsx:173-200: arrows move, ⌘/Ctrl+arrows resize, Enter/F full, Esc closes). But nothing groups windows — the top organizing unit is the ROUTE. shell/ProjectTree.tsx:17-26 is a navigation panel scoped to the active workflow’s nouns, not a container that owns surfaces; role="tab" exists only as local page tabs (Settings/index.tsx:310, Library/index.tsx:626, SpeakIndex/index.tsx:182).

    The hotkey layer tells the same story: installShortcuts (workspace/shortcuts.ts:241) wires ⌘[ / ⌘] to cycle focused panels (shortcuts.ts:334-343, bindings.ts:285-286) and ⌘J/E/Y/U to navigate routes — a full-page swap (bindings.ts:330-333). Zero window/tab hopping exists. And the obvious chord family is off-limits: the RESERVED list (bindings.ts:437-474) blocks ⌘1-9 (:463-472: “Browser: jumps to tab N”), ⌘T/⌘N/⌘W (:439-441) as browser-owned — ⌘W is only borrowed when a floating panel is focused (shortcuts.ts:344-353).

    Windows are ephemeral by design (windowsStore.ts:50-62 — session-scoped, persistence a named-but-unbuilt future task that must replay opens, never rehydrate z/order verbatim). And the two heaviest surfaces are policy-barred from windows: ResearchWorkstation owns a dock and is dense-opaque-keep, WrestleApp assumes the full viewport (openWindow.ts:42-50,78-81); the window-eligible set today is stats / library / subaction / researchArtifactReceipt / reader (openWindow.ts:83-110). Meanwhile a persistence layer with versioned localStorage envelopes and schema guards exists (workspace/persistence.ts:63-73,241-265 — the custom-hotkey precedent), and the shortcut installer already resolves ⌥-modified custom combos (shortcuts.ts:356-365). Every piece except the container itself is in place.

    Design decisions (the container model)

    • Workstation = named project container above the window layer. A workstation has a name, a color token from the design palette, and an ordered set of tabs. Each tab is a surface reference: a window-kind ref ({ surface, payload } — e.g. reader:{documentId}, stats, library) or a route-kind ref for a route-bound surface (a research session /inv/:id, a deliverable /write/:deliverableId). Exactly one tab is ACTIVE at a time.
    • Multiple workstations coexist; exactly one is focused. Switching workstations swaps the whole surface set: window tabs of the outgoing workstation are torn down (reset()) and the incoming workstation’s OPEN window tabs are replay-opened with default cascade rects — window geometry stays session-scoped (windowsStore.ts:50-62, unchanged). A window tab whose window is not open shows a calm “not open” state; hopping to it opens it.
    • Organizer, not a second window manager — the load-bearing invariant. Open/close/focus are the same windowsStore calls every surface makes today. The workstation never computes a rect, a z, or an order; MAX_WINDOWS, at-cap focus redirection, and z-restack behave exactly as they do now, per focused workstation. The existing windowsStore.test.ts must pass UNMODIFIED.
    • Hotkeys, herdr-feel, within the RESERVED constraints. ⌥1-9 hop to tab N in the focused workstation (⌘1-9 is browser-owned, bindings.ts:463-472); ⌥⇧[ / ⌥⇧] cycle tabs (including overflowed ones); ⌘` cycles workstations; ⌥T opens the surface picker (new tab); ⌥W closes the active tab (⌘W is browser-owned and already conditionally borrowed, shortcuts.ts:344-353). All are builtin rows in the existing tables — HUD-visible, conflict-guarded by detectConflict, remappable via the custom-binding machinery.
    • Persistence: server-side per owner, refs only. Unit 2’s zero-persistence discipline governs DERIVED state; a workstation is operator STRUCTURE — authored organization that cannot be re-derived from any event log or artifact, so it earns a small store. Tabs store surface refs only, never content: a reader tab stores a document id, not the book; a research tab stores an investigation id, not the thread. The client keeps no divergent local copy (the custom-hotkey localStorage pattern is the precedent for shape, not for authority).
    • Tabs are not routes; the URL stays canonical. Activating a route-kind tab swaps the main surface within the focused workstation; the URL always names the surface’s canonical route (/inv/:id as today) and NEVER encodes workstation or tab identity (no ?ws=…&tab=…). Deep-link escape hatch: every surface keeps its canonical URL; a reload lands on the canonical surface with the workstation container restored around it, and when the URL matches a tab of a restored workstation that tab is active. Workstation state is not URL state — decided, documented, and listed among the rejected alternatives below.
    • Reading is consumed, not rebuilt. A reader tab is the existing reader window kind (openWindow.ts:106-108). Unit 4 (global reading) deepens embedding; this spec changes nothing in the reader.
    • Prototype gate BEFORE the contract freezes (SPR-00). Two competing tab-model prototypes, compared side by side on the criteria below; the verdict is recorded in this spec’s decision log (the OPEN row) before SPR-01 begins. Sprints after the gate assume the winner.

    Key invariants

    • One window manager: windowsStore actions are the only window mutations; a diff grep for window-state writes outside the store finds none.
    • Refs, not content: no book body, thread event, or deliverable text is ever stored in a workstation row — ids and kinds only.
    • URL stays canonical: workstation/tab identity never appears in the URL; every surface keeps its deep link.
    • One active tab, one focused workstation: activation is a total, explicit transition; there is no “half-switched” state, and a reload converges to exactly one focused workstation.
    • The policy bar stands: ResearchWorkstation and WrestleApp are never adapted into windows to make them tabs; route-kind tabs exist precisely so the bar can stand.
    • Session geometry: window rects/z/order remain ephemeral per the store’s own docblock; persistence replays opens with default rects and never rehydrates counters (windowsStore.ts:58-62).
    • Calm chrome: the tab bar is design-system tokens only (DESIGN_LANGUAGE.md function-not-taste; FEEL_CONTRACT.md elevation/motion); one color strip per workstation, active tab signalled by the existing elevation vocabulary, no new animation engine.

    Sprint roster

    SPR-00 · Prototype gate — two tab models, one recorded verdict

    Contract. Two throwaway prototypes on spike branches, never merged. Prototype A — workstation-as-route: a workstation is itself a main-area surface with an internal tab bar; window-kind tabs float over it as today. Prototype B — workstation-as-window-supercontainer: every surface including route-bound ones renders inside window frames owned by the workstation (requires a local, prototype-only relaxation of the ResearchWorkstation/WrestleApp window bar to feel the model — the relaxation is prototype scaffolding, not a contract proposal). Both prototypes implement ONLY: two workstations, three tabs each, ⌥1-3 hopping, ⌘` switching. Evaluation, side by side, on four criteria: (1) hopping latency (keypress → surface usable, measured, both prototypes, 8+ tabs); (2) focus clarity at 8+ tabs (can the operator always name the active surface and its keyboard target — window focus, route area, tab bar must never disagree); (3) windowsStore reuse (does the model keep every window mutation inside the store’s actions — B is expected to strain here, and the strain must be MEASURED, not assumed); (4) servability/fetch-authority cleanliness (no surface fetches outside its existing owner path in either model — the reader keeps owning book fetches, the workstation fetches only its own rows). The verdict, criteria scores, and the loser’s salvageable parts are recorded in the OPEN decision-log row of this spec before SPR-01 starts.

    Proof (real runs, not write-ups):
    • Both prototypes run; latency numbers come from instrumented keypress-to-paint measurements, not estimates.
    • A keyboard-only scripted pass over both prototypes exercises 8+ tabs and records every focus-model disagreement found (zero required for a clean verdict, but each finding is recorded, not smoothed over).
    • The verdict commit edits THIS spec: the OPEN row becomes a Decision row carrying the scores and the reason.

    Non-goals: production code, persistence, the surface picker, any merge of prototype code (the winner is re-implemented cleanly in SPR-01..03).

    SPR-01 · Workstation store + server persistence

    Contract. Server: new substrate module substrate/workstations/ (schema + store) following the unit-1 conventions (additive idempotent DDL with CHECK constraints, init under the write lock — the substrate/feedback/schema.py pattern), one table workstations (workstation_id PK · owner_user_id · name · color_token CHECKed against the design-palette vocabulary · position · revision · timestamps) and one table workstation_tabs (tab_id PK · workstation_id FK · position · surface_kind CHECKed against the eligible vocabulary — the WINDOW_PAGES kinds plus route · surface_payload_json carrying ids only · timestamps). Router interfaces/research/api/workstation_routes.py (register_workstation_routes(app), owner-scoped per the books.py conventions): GET /workstations (full set for the owner), PUT /workstations/{id} (full-replace of name/color/tab list with optimistic revision check — 409 on stale, never a silent clobber), POST /workstations, DELETE /workstations/{id}. Payloads are validated to contain refs only: a payload with a text field beyond a small title label is a 422. Client: apps/reading/src/workspace/workstationStore.ts (zustand, mirrors the windowsStore action style) + api/workstations.ts on apiFetch: load-on-start, write-through mutations, focused-workstation id held client-side (per-device, honestly — the same operator may have different focus on two devices).

    Proof (real calls):
    • FastAPI TestClient against a real DuckDB fixture: create → rename → reorder tabs → GET reflects it; a second owner sees none of it; a stale-revision PUT gets 409 and the row is unchanged; a payload carrying a long text field gets 422.
    • CHECK constraints reject an unknown surface_kind and an off-palette color_token at the DB layer (test, not review).
    • Client round-trip: store mutation → PUT → reload (fresh store, real client fetch against the test server) → identical state, exactly one focused workstation.
    • Window geometry is provably absent from every persisted row (schema has no rect/z columns — asserted by introspection test).

    Non-goals: the tab bar UI, hotkeys, surface activation, multi-owner sharing, history/undo of workstation edits.

    Contract. shell/WorkstationBar.tsx, mounted at the one shell seam (AppShell.tsx:154-165, above WindowsLayer): the focused workstation’s ordered tabs (color strip, title, close affordance), the workstation switcher (name + color token per workstation), the ⌥T surface picker (window-eligible kinds from WINDOW_PAGES + route-kind entries for research sessions and deliverables). Focus model: activating a window-kind tab focuses its window (window focus drives tab activation back — the bar always agrees with the window layer); activating a route-kind tab swaps the main surface and moves DOM focus into it honestly; the active tab is always the surface holding keyboard focus.

    Proof (real calls, keyboard-only):
    • Vitest dispatching real keydown sequences through the installed handler: ⌥T → pick → tab appended; ⌥1-9 activates tab N (and tab 9+ does NOT fire ⌥1-9’s browser conflict — asserted against the RESERVED table); ⌥⇧[/] wraps across all tabs incl. overflow; ⌘` cycles workstations with full surface-set swap; ⌥W closes the active tab and activation moves to the neighbour (never orphaned focus).

    • Focus agreement: focusing a window by mouse activates its tab; closing the focused window (window chrome) returns activation to the route surface — no state where bar and focus disagree (asserted in both directions).
    • Every new binding appears in the HUD table and survives a remap→reload cycle through the existing custom-hotkey persistence (persistence.ts:241-265).

    SPR-03 · Surface integration + restore

    Contract. The activation service apps/reading/src/workspace/surfaceActivation.ts: window-kind tab → openWindow(surface, payload, { id: stable-per-tab-instance }) (openWindow.ts:142-153) so hopping focuses instead of duplicating; route-kind tab → swap the main surface to the canonical route (/inv/:id, /write/:deliverableId) without workstation state entering the URL. Workstation switch: windowsStore.reset() (:287) then replay-open the incoming workstation’s open window tabs with default cascade rects, per the store’s own rehydration rule (windowsStore.ts:58-62). Closing a window via its own chrome marks its tab “not open” (the durable ref remains); ⌥W removes the tab AND closes its live window if any. Restore-on-reload: load workstations (SPR-01), focus the last-focused workstation, activate the tab matching the current canonical URL when one matches, else the workstation’s first tab; window tabs restore as “not open” (geometry is session-scoped — a reload never fabricates stale rects). Route-kind surfaces fetch through their existing owner paths — the workstation adds no fetch authority of its own beyond its own rows.

    Proof (real calls):
    • Full keyboard round-trip against the real store + test server: ⌥T add a reader tab and an /inv/:id tab → ⌥2 opens the reader window (one window, stable id; re-hop focuses, never duplicates — asserted on store state) → ⌥1 swaps the main surface → reload → both workstations and tabs restored from the server, window tabs “not open”, activation on the URL-matching tab.
    • Workstation switch with two open window tabs: outgoing windows torn down, incoming set replay-opened with default rects; MAX_WINDOWS at-cap behavior identical to today (existing windowsStore.test.ts green UNMODIFIED — a gate, not a courtesy).
    • URL audit: across every hop and switch, the URL contains no workstation/tab parameter (asserted); a shared canonical /inv/:id link opened cold renders the surface and the restored container around it.
    • A route-kind tab whose surface is a window-barred page (research session) never enters windowsStore (the policy bar holds — asserted by store state, not code reading).

    Non-goals: window geometry persistence (the store’s named future task stays future), window-adapting barred surfaces, unit-4 embedding work, cross-device focus sync.
