Owner-scoped multimedia research plans

Cycle: 24. Status: execution contract. Base: Cycle 23 evidence-bound multimedia research intents.

Outcome

A prepared, receipt-verified multimedia research intent can be handed to an owner-private draft plan authority. The plan is independently addressable by a random opaque ID, exactly idempotent per owner and intent, and approvable only by the authenticated owner against an exact version. This cycle creates authority for planning only. It does not launch research.

Five values

ValueRequired consequence
TruthThe response says draft or approved; it never implies that research, spend, or provider work started.
OwnershipEvery lookup and mutation binds the authenticated owner digest. Foreign and absent IDs are equally unavailable.
DeterminismThe same owner, intent, and idempotency key returns the same plan; changed authority under that key conflicts.
ReversibilityApproval is version-pinned. A later edit must increment the version and restore draft state.
Least authorityNo graph node, event, investigation, provider call, spend authority, or background task is created by handoff, read, or approval.

Authority model

  • A private SQLite ledger stores plan_id, owner digest, source intent ID and digest, request digest, plan version, canonical plan JSON, and timestamps.
  • plan_id is a random mrp_-prefixed 192-bit identifier. It is not a graph node ID and reveals no owner, question, asset, or intent.
  • The initial tree contains the intent question as its root and records immutable intent/evidence provenance. It is generated locally without decomposition.
  • The graph remains a future projection target, never the access-control or approval authority. Content-deduplicated graph IDs cannot safely identify owner-private plans.
  • The stored approval principal is the authenticated owner digest. No request body accepts an approver string.

HTTP contract

OperationContract
POST /multimedia/research-intents/{intent_id}/planAuthenticated. Body contains a strong idempotency key. Resolves the exact owner-visible intent and creates or replays its draft plan. Returns 201/200.
GET /multimedia/research-plans/{plan_id}Authenticated owner read. Missing and foreign plans both return the same private 404.
POST /multimedia/research-plans/{plan_id}/approveAuthenticated. Body contains expected_plan_version. Exact CAS approves; stale or conflicting approval returns 409. Replay at the same approved version is stable.

Every response, including validation and errors, carries Cache-Control: private, no-store. Response fields include plan identity, source intent and evidence binding, state, version, canonical tree, timestamps, and literal false/null launch and spend authority fields.

Non-negotiable refusals

  • No automatic decomposition and no compatibility fallback to /research/plans/{graph_root_id}.
  • No graph persistence, event emission, investigation/session creation, provider dispatch, budget reservation, spend approval, or launchability claim.
  • No caller-authored owner digest, approver identity, source digest, tree, or approval timestamp.
  • No existence leak through status, detail text, timing-dependent alternate lookup, or cacheable response.

Compatibility boundary

Existing internal cascade planner persistence and launch callers remain unchanged in Cycle 24. Their graph-root contract is explicitly legacy and is not reused by multimedia handoff. A later migration must place all public cascade plan lifecycle routes behind this owner authority before owner plans can launch.

Acceptance tests

  1. Two owners with the same question receive distinct opaque plan IDs and cannot read or approve each other's plans.
  2. Same-owner replay is byte-stable; idempotency drift and intent/digest mismatch fail closed.
  3. Stored source intent digest and evidence digest exactly match the owner-visible Cycle 23 intent.
  4. Approval records only the server-derived owner digest, requires exact version, is replay-stable, and rejects stale versions.
  5. Malformed, missing, foreign, tampered, unsafe-path, schema-drift, and oversized records fail closed with private responses.
  6. Spies prove handoff/read/approval call no decomposer, graph writer, event emitter, investigation launcher, provider gateway, spend ledger, or background scheduler.
  7. Focused Python tests, full multimedia backend tests, multimedia frontend tests, Ruff, TypeScript, build, and HTML validation pass.

Deferred sprints

  2. Explicit graph projection with owner-safe identity and reconciliation.
  3. Migration of public cascade plan routes from graph IDs to owner plan IDs.
  4. Spend preview and launch authorization bound to an approved owner plan version.
  5. Investigation launch as a separately authorized, auditable transition.
