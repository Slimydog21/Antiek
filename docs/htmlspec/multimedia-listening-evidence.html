Inspect why a spoken claim is trustworthy

Cycle 21 extends the shared active-listening player with exact evidence for current evidence-derived claims and an honest legacy state for older valid receipts. It does not fetch arbitrary source text, mutate the graph, regenerate media, or treat a chunk identifier as proof.

Authority chain

  1. Paid audio: reopen the private MAC-verified paid receipt and narration artifact. Derive claim evidence only from the embedded transformed plan whose canonical digest and claim index are revalidated by the receipt.
  2. Cheapest local audio: reopen the private audio receipt and AudibleRun. Load the authenticated owner's current exact-revision record, then require each receipt claim's line ID, spoken text, and ordered chunk IDs to equal one factual line in that record's plan.
  3. Exact source: require one evidence derivation whose chunk/document identity, chunk digest, UTF-8 byte range, span digest, authority kind, and exact text are internally valid and equal the claim.
  4. Any duplicate, stale, mismatched, malformed, or partially migrated authority makes playback metadata unavailable. A uniformly pre-exact-extract paid plan remains playable with receipt-backed opaque source IDs and an explicit unavailable_legacy state.

Shared response

Every learned claim includes its stable line ID, ordered source chunk IDs, and evidence status. verified_exact claims carry chunk ID, document ID, optional locator, authority kind, chunk SHA-256, exact UTF-8 byte bounds, span SHA-256, and exact excerpt. The server independently recomputes digest and byte invariants. Pydantic enforces response shape; browser validation rejects empty, duplicate, structurally invalid, or cross-field-conflicting values before render.

Listening surface

  • The existing learned-claims disclosure remains grouped by verified chapter.
  • Each claim exposes an explicit Inspect evidence command, source count, canonical-graph versus operator-excerpt disclosure, document and location identity, and the exact excerpt.
  • Evidence is text-first and scannable. Internal hashes and byte bounds remain available as authority details rather than a claim of browser-side cryptographic verification.
  • Changing chapters, speed, or Media Session ownership does not alter evidence identity.

Non-goals

No graph query, source-body reload, document-title invention, external URL, deep-link navigation, source merge, claim correction, steering, provider call, spend, publication, offline cache, or receipt schema migration is introduced.

Acceptance

  • Local and paid metadata expose the same evidence shape from their distinct verified authority chains.
  • A stale local plan, wrong line ID, changed claim text, reordered chunk, mismatched document, invalid digest, or partially migrated derivation fails closed. Uniform legacy paid claims remain playable without exact excerpts.
  • The browser rejects malformed evidence before rendering and never derives evidence from source_count.
  • Keyboard and screen-reader users can inspect and close each claim's evidence without losing playback controls.
  • Focused route/runtime/UI tests, the full multimedia suite, typecheck/build, Ruff, HTML parsing, security review, and independent review pass on the exact tree.
