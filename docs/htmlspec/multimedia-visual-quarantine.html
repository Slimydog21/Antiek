Quarantine authenticated Krea visual candidates

Child of multimedia-visual-generation.html. This sprint converts ephemeral provider locators into private, byte-verified candidate authority without exposing URLs or paths.

Rematerialization

The authenticated owner supplies asset, current revision, execution ID, and visual authority request ID. The server reopens both signed authorities, requires a succeeded bound Krea execution, performs one authenticated poll, requires completed status and the configured account identity, and matches each ordered locator SHA-256 to its MAC-protected candidate row. No locator is stored by this layer or crosses HTTP.

Network boundary

A resolver returns a bounded address set. Existing quarantine policy rejects private, loopback, link-local, multicast, reserved, unspecified, mixed-family, or non-global answers. The transport connects directly to one approved IP, wraps TLS with SNI and certificate verification for the original hostname, sends the original Host header, disables proxies by construction, and does not follow redirects. Streaming bytes are bounded and structurally validated by the existing quarantine authority.

Safe catalog

POST /multimedia/assets/{asset_id}/visual-generations/{execution_id}/materialize returns only candidate ID, opaque quarantine receipt ID, declared media type, and byte count. It omits locator, path, SHA-256, receipt MAC, prompt, Krea identity, and signing material. Exact replay reopens the same receipt and does not download again.

Non-goals

No Krea POST or automatic polling, webhook authority, generated attestation, aesthetic approval, reviewed-set registration, browser preview bytes, renderer, publication, merge, or deploy.

Done bar

Tests prove DNS/peer/SNI/redirect policy, locator order/digest/account binding, owner/current authority, no second download on replay, receipt tamper failure, safe response, and all-or-nothing runtime. Broad tests, lint, HardenX, and independent review pass.
