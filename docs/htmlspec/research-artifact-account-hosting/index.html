Spec lineage

Root spec derived from the operator’s “hosted in my Antiek account” requirement and a current-state audit. It has no parent spec and no child spec trees; its sprint manuals are linked below.

    Goal

    Make every private ResearchArtifact a hosted asset owned by exactly one canonical authenticated account, without losing or silently reassigning the historic operator corpus.

    • Two accounts using the same investigation ID always resolve distinct artifacts.
    • No HTTP caller supplies or overrides owner identity.
    • Every legacy file is migrated, quarantined, or explicitly excluded with a redacted receipt.
    • Rollback can restore operator access without enabling cross-account legacy fallback.

    Failure mode to avoid: a route appears authorized while a background, compose, CLI, migration, or recovery path still resolves the old global filename.

    Evidence and failure statement

    Current invariant violation: artifact_path_for(investigation_id) resolves $ANTIEK_RESEARCH_ARTIFACTS_DIR/<investigation>.html. Artifact export, view, append-note, block listing, and persisted-note reload do not include authenticated account identity. Two accounts choosing the same investigation ID address the same private file.

    This is both an IDOR and a data-corruption boundary. The fix is not an authorization check bolted onto one route: account authority must enter the canonical storage key so every read, write, migration, compose, and recovery path shares one owner.

    Dependency graph

    SPR-01 authority/key + migration
       └── SPR-02 API owner routing

    These sprints are deliberately serial. Parallel execution would cause the API to freeze a path contract before migration semantics are proven.
