SPR-03 · Wave 3 · depends SPR-01/02 · 6 milestones

Rollout, observability, and proof

← Master spec

Parent context and goal

Storage and route authority can be correct in isolation yet lose data during activation. This sprint proves migration under real artifact shapes, stages enforcement, and removes the dangerous global fallback.

Goal: activate account scoping with measurable parity, restartable migration, operator rollback, and evidence that no account crosses the boundary.

Technical milestones

1 Build read-only inventory.
Count valid, corrupt, symlinked, multi-link, oversized, v1/v2, composed, and orphan sidecar states without rendering private text in logs.
2 Shadow dual resolution.
For __operator__, resolve scoped and legacy metadata, compare identity/content hash, serve current canonical path only, and emit bounded mismatch metrics.
3 Run restartable migration.
Dry-run receipt first; explicit operator approval for apply; bounded batches; lock lease; resume token; quarantine corrupt/ambiguous files rather than guessing.
4 Enforce scoped writes then reads.
Phase A dual-read/scoped-write operator-only; Phase B scoped-read/write; Phase C remove legacy fallback. Each phase has a reversible flag and a no-foreign-read canary.
5 Prove end-to-end workstation isolation.
Two accounts export same investigation ID, open windows, append notes, refresh, compose and re-export. Assert distinct bytes, hashes, events, paths and UI content.
6 Close and retain rollback evidence.
Legacy tombstones default to 90 days, configurable only by an explicit operator migration policy; cleanup requires a terminal-green scoped backup/restore proof. Rollback restores mapping only for operator; final verifier proves no production code path reads unscoped files.

No raw account ID, investigation ID, question, note, source text, or path is permitted in metrics/logs.

Five-values rigor

Intellectual honesty

A zero-mismatch metric is meaningful only after the inventory denominator and every skipped/quarantined file are reported.

Fairness

Rollback may restore operator access but must never broaden legacy fallback to newer accounts.

Rigor

Run the two-account canary at every rollout phase and after process restart, not merely in unit tests.

Diligence

Inspect migration receipts against source inventory counts; every file is migrated, quarantined, or explicitly excluded.

Defensibility

Retain SHA-anchored commands, receipts, metrics snapshot, and final search proving the global path is unreachable.

Dependencies and out of scope

Requires accepted SPR-01/02 and terminal-green parent CI. Non-goals: public share links, team permissions, object-store migration, deletion/export compliance beyond preserving existing semantics.

If tempted to expand scope: record it in the handoff and keep rollout serial; never combine a new sharing model with this migration.

Verification gates

  • Offline dry-run fixture includes valid/corrupt/hostile files and produces deterministic redacted receipt.
  • Crash/restart at each batch boundary.
  • Two authenticated accounts pass full browser/API canary; foreign artifact test stays indistinguishable.
  • Repository search/lint proves no unscoped production fallback.
  • Independent security ACCEPT and hardenx 0 REAL before activation.
