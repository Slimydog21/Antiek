Account key and migration substrate

← Master spec

Parent context and goal

ResearchArtifact currently maps only investigation ID to a global HTML file. This sprint establishes the single storage authority used by HTTP, CLI, export, append, compose, and migration.

Goal: implement a collision-resistant account/investigation key contract and a restartable, operator-only legacy migration without changing API routing yet.

Technical milestones

1Inventory every path consumer.
Acceptance: AST/rg-backed test enumerates export, append, blocks, persisted-note reload, compose, CLI and route consumers; unknown direct joins fail CI.
2Define ArtifactAuthority and versioned opaque key codec.
Acceptance: deterministic keyed components; raw IDs never appear in filenames; hostile Unicode/slash/dot/backslash/property corpus proves account and investigation pairs never alias. Sidecars pin key_codec_version; prior versions resolve only through an authenticated migration registry.
3Build private account layout and sidecar.
Acceptance: account directory 0700, artifact/sidecar 0600; sidecar binds schema version, account ID digest, investigation ID digest, content hash, created/migrated timestamps; symlink/hardlink/nonregular states fail closed.
4Implement storage port.
Acceptance: read/write/stat/replace interface keeps filesystem implementation swappable; atomic same-directory replace and directory fsync; no cloud vendor dependency.
5Journal operator legacy migration.
Acceptance: lock → copy → verify identity/hash → atomic publish → receipt → legacy tombstone. Crash injection at every phase restarts without duplication or loss. Truncated, reordered, checksum-invalid or identity-conflicting journals quarantine and halt that migration key; they are never truncated into a valid-looking prefix. Only explicit __operator__ migration may see unscoped files.
6Add compatibility reader in shadow mode.
Acceptance: returns both scoped and legacy resolution facts without serving legacy bytes to non-operator accounts; mismatch is observable and blocks enforcement.

Five-values rigor

Intellectual honesty

Do not claim a reversible filename codec is collision-free without property tests across normalization and hostile separators. Record platform assumptions.

Fairness

Preserve the historic operator’s ownership; do not let the first new account “claim” an unscoped file.

Rigor

Inject crashes before and after every journal transition and compare byte/hash/receipt state after restart.

Diligence

Inventory every direct path join before introducing the storage port; one missed reload path reopens the collision.

Defensibility

Produce a migration receipt whose account, investigation, old/new digests, and phase history can be audited without exposing raw private IDs.

Dependencies and out of scope

Dependency: exact #873 contract and canonical middleware identity vocabulary. Out of scope: HTTP route changes, object-store vendor, graph schema, public sharing, live migration.

If tempted to expand scope: stop, record it in the handoff, and finish the storage authority and migration proof.

Verification gates

  • Focused pytest twice; strict mypy and Ruff.
  • Property/mutation test proves raw concatenation or legacy fallback for non-operator is caught.
  • Crash/corrupt-journal matrix produces no missing, double-owned, or partially published artifact.
