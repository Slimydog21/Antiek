API authorization and owner routing

← Master spec

Parent context and goal

SPR-01 makes account identity unavoidable in storage. This sprint makes canonical middleware identity the sole HTTP authority for export, view, blocks, append-note, and import workflows.

Goal: an authenticated account can access only its scoped artifacts; forged owner inputs, missing identity, legacy guessing, and same-investigation collisions fail closed.

Technical milestones

1 Centralize request authority.
A single helper reads request.state.user_id, rejects absent/blank/invalid identity, and recognizes the legacy owner only when the canonical middleware claim equals substrate.multi_user.auth.operator_claims().user_id, currently exactly __operator__. Email, header, query, body and investigation aliases never grant operator authority. No route defines its own predicate.
2 Thread authority through every route.
Export, view, blocks, append-note and import use ArtifactAuthority. GET performs authorization before reading bytes. POST performs it before mutation or existence disclosure.
3 Remove path-based note import from web callers.
HTTP never accepts an arbitrary server filesystem path. If legacy import remains, restrict it to explicit operator CLI and canonical account root with the same safe-open rules.
4 Add two-account adversarial matrix.
Same investigation ID, guessed ID, forged body/query owner, missing identity, operator alias, stale hash, symlink and timing cases. Assert uniform 401/403/404 policy without cross-account existence oracle.
5 Preserve frontend contract.
Cookie credentials remain included; no raw account ID enters iframe payload or URL. Window identity includes a non-secret authenticated-session generation so equal investigation IDs do not dedupe across accounts. Account switch closes old private windows before accepting new workspace input; even during the race, every iframe GET re-authorizes server-side and cannot read old-account bytes.

Five-values rigor

Intellectual honesty

Distinguish authentication (who) from authorization (which artifact). A valid session alone is not proof of ownership.

Fairness

Return the same external denial shape for guessed and absent foreign artifacts so privacy does not depend on knowing IDs.

Rigor

Every mutating test must assert the foreign account’s bytes, hash, notes, events, and mtime remain unchanged.

Diligence

Exercise middleware-populated identity and machine-token identity; mocks that set arbitrary state cannot be the only proof.

Defensibility

One helper owns the mapping from request identity to storage authority, with an AST guard rejecting divergent owner predicates.

Dependencies and out of scope

Requires SPR-01 storage authority and migration shadow reader. Non-goals: session issuance redesign, public sharing, team ACLs, account switcher visual design, graph tenancy.

If tempted to expand scope: record it in the handoff; do not weaken the owner boundary or delay its two-account proof.

Verification gates

  • Two-account full route suite twice.
  • Mutation test plants a direct global artifact_path_for(id) route call and proves the boundary lint fails.
  • Strict type/lint/security gates; independent IDOR critic.
