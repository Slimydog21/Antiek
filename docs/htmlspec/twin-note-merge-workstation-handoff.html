CYCLE 55

Twin-note merge workstation handoff

Make exact recursive notes selectable, comparable, reviewable, and explicitly applicable through Antiek's single canonical derived-asset authority.

Lineage and pinned prerequisite

Parent: Cycle 51 bridge contract. Runtime prerequisite: Cycle 54 commit 966e3934e3030123a9cbd54c0668a7e549be3b40. Generic merge draft, review, apply, CAS, and restore remain the only derived-asset authority.

Outcome

An authenticated owner chooses one verified document-owned ready HTML projection and one verified V21 revision or V22 composition, compares both inert HTML assets, selects exact notes in explicit click order, creates one bridge projection, then creates, previews, reviews, and explicitly applies one canonical derived asset. Every stage remains distinct and every upstream edit invalidates all downstream authority.

Read-only merge context

GET /research/twin-notes/merge-context
-> {
  source_projections: [{projection_id, source_asset_id, source_document_id, label, preview_url}],
  twin_sources: [{kind, id, label, html_url, revisions: [{member_ordinal, revision_id,
    notes: [{note_ordinal, text, source_count}]}]}],
  limits: {source_projections, twin_sources, notes}
}
  • The request is parameter-free: query keys and bodies are rejected. Owner derives only from authenticated request state.
  • Source projections are document-owned, ready, unique, bounded, and reopened through the canonical merge member verifier before inclusion. Synthetic bridge projections never appear as sources. Labels come from the owned document title with a stable non-secret fallback.
  • V21 and V22 sources are rebuilt through whole-chain verifiers in one read snapshot. Note text and source counts come from authoritative structured bodies, never HTML parsing. The response omits body/HTML hashes, locators, manifests, event/window/investigation IDs, provider/model metadata, timestamps, confidence, and source-event identities.
  • Malformed, oversized, duplicate, foreign, or unverifiable state fails the complete response closed; it is never silently skipped.

Inert comparison transport

GET /research/twin-notes/merge-context/source-projections/{projection_id}/preview
GET /research/twin-notes/merge-context/{revision|composition}/{id}/preview
  • Both routes re-run the same owner and integrity verifier used by context discovery and return exact immutable bytes only.
  • Responses are private, no-store, nosniff, referrer-free, and CSP-sandboxed with scripts, navigation, forms, network, and same-origin privilege disabled while allowing framing only by Antiek's own origin. Missing and foreign IDs are indistinguishable.
  • No filesystem path, object locator, redirect, query, fragment, or caller URL enters the contract.

Command chain

  1. Bridge: existing POST /research/twin-notes/merge-projections with IDs, ordinals, and one retained idempotency key.
  2. Draft: existing POST /research/derived-assets/merge/drafts with the exact echoed two-member projection order, intent=create, and explicit title/kind.
  3. Preview: existing inert preview route for the current draft.
  4. Review: existing POST .../drafts/{draft_id}/reviews; response must bind the current draft hashes.
  5. Apply: existing POST .../reviews/{review_id}/apply with a retained operation ID. Apply is never automatic.

The twin-note router never creates drafts, reviews, revisions, heads, restore records, graph nodes, or Write mutations.

  • One monotonic generation token guards context refresh and every command. Late success and failure responses cannot modify newer state.
  • While any context, bridge, draft, review, or apply request is pending, all Cycle 48-50 and merge controls are globally frozen.
  • Source and twin comparison use two uncredentialed-by-DOM iframe sandbox="" elements. URLs are constructed only from strict route templates and canonical IDs.
  • The UI shows exact note text, attribution count, revision identity, ordinal, and click order. It never sends note text or counts as authority.
  • Draft preview, reviewed preview, and apply are visibly separate. Creating a review cannot call apply; opening a preview cannot mutate state.

Acceptance

  • Two-account fixtures prove context and both previews are owner-bound with value-free 404 behavior.
  • Ready/pending/failed, foreign, malformed JSON, duplicate identity, missing object, symlink, hardlink, oversized object, hash drift, revision/member/composition/body/HTML tamper matrices fail the entire context or preview closed.
  • Structured revision and composition fixtures prove stable note ordinals, arbitrary explicit cross-member order, source counts, limits, and omission of forbidden metadata.
  • Frontend tests prove no merge command before complete selection; exact note click/reorder request; exact two-projection draft order; full downstream invalidation; retained-key retry; stale context/bridge/draft/review/apply refusal; global freeze; empty-sandbox frames; separate preview/review/apply; explicit apply only; and unchanged Cycle 48-50 tests.
  • Run focused backend merge-context/bridge/route/draft/apply/restore and twin serving tests; Cycle 48-50 plus Cycle 55 frontend tests; TypeScript typecheck; production build; changed-Python compilation; Ruff; HTML parse; diff hygiene; heterogeneous hostile review; and strict HardenX with zero real findings.

Rejected shortcuts

  • Opaque ID text inputs: not an ergonomic owner-scoped workstation.
  • Parse twin HTML in React: turns presentation bytes into authority and loses exact source counts.
  • Return locators or raw projection JSON: leaks storage and internal integrity metadata.
  • Create bridge and draft in one twin endpoint: forks transaction and authority ownership.
  • Auto-review or auto-apply: collapses evaluation into irreversible authority transfer.
  • Reuse current no-frame HTML routes in iframes: produces blank comparison and invites CSP weakening.

Harness hint

Build the read model and previews first, then the typed client and isolated workstation component, then integrate into Twin Notes. Use separate ownership/integrity, frontend-race, authority-boundary, and completeness critics.
