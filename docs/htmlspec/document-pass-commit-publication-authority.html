Publish live note identities only from committed graph state

Replace connection-presence inference with an explicit transaction contract so the live ingest path exposes challengeable graph-backed notes without allowing a caller-owned rollback to leave durable events pointing at nonexistent nodes.

Observed defect

  • run_document_pass currently writes note.emerged.node_id = null whenever a connection is supplied.
  • The universal research-ingest caller supplies an ordinary autocommit connection. Its graph node is committed before the note event, but the live workstation still receives an unchallengeable note with no node identity.
  • Connection presence does not prove transaction ownership. A caller-owned transaction can roll back after promotion; publishing note or graph events from that path would create false durable authority.

Contract

  1. No supplied connection means the existing internally owned promotion transaction. The returned node is committed before note.emerged publishes it.
  2. Every supplied connection declares exactly one mode: autocommit or caller_owned. Omission or an unsupported value fails before distillation, graph writes, embeddings, or events.
  3. autocommit permits existing event publication and includes the promoted insight node in note.emerged.node_id.
  4. caller_owned permits promotion only when both external note events and graph events are disabled. Any publication request fails before distillation or mutation.
  5. The caller that owns commit may publish committed effects after commit through its own verified bridge. Cycle 89 does not guess commit success, install callbacks, or emit during rollbackable work.

Call-site decisions

  • Universal ingest: declare autocommit. Its connection has no explicit BEGIN; promotion statements are committed before the live event is emitted.
  • Multimedia twin registration: declare caller_owned. It already disables both event classes, commits explicitly, and runs a separate post-commit graph-event verifier.
  • Scheduler/direct callers: supply no connection and retain internally committed behavior.

Acceptance

  • Universal ingest emits one note.emerged whose node_id equals a committed insight row and whose observation relation preserves the same local note identity.
  • The emitted live note can be challenged by exact observation identity and appears in authoritative history.
  • A supplied connection without a mode fails before the distiller runs.
  • A caller_owned request with note or graph publication enabled fails before the distiller runs and leaves zero nodes/events.
  • A valid caller_owned request with publication disabled may be rolled back and leaves no graph rows or external events.
  • Multimedia registration behavior and post-commit event recovery remain unchanged.
  • Focused async-note-taker, universal-ingest, multimedia-registration, graph, event-schema, frontend generated-contract, typecheck, build, Ruff, compileall, and diff gates pass.

Non-goals

No generic transaction callback framework, no event schema bump, no question-node identity field, no provider call, no new graph operation, no outbox migration, and no client-side reconstruction. A broader atomic document-pass outbox requires a separate design if a caller later needs note events and graph promotion in one caller-owned transaction.
