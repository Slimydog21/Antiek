BRK-03: Provider broker worker lease

Status: Executed transport-free worker-fencing boundary. It qualifies no provider and does not determine provider outcomes.

Spec lineage

Parent: durable provider broker. Authority: BRK-02 primary ledger.

Corrected ownership model

ProviderWorkerLeaseCoordinator.session returns a context-managed WorkerLeaseSession. Acquisition opens one per-operation advisory flock and the session holds that same descriptor continuously through every state read, prepare_dispatch, the future adapter action, and context exit. The same-user application filesystem is trusted, while acquisition still fails closed on a symlinked or untrusted lock directory, a symlink/non-regular/multiply-linked lock file, or a post-flock descriptor/path inode mismatch. Methods reject another thread, a stale fence, expiry before preparation, and all use after exit. Database expiry is only a liveness bound; it never bypasses a live flock.

Sidecar integrity

A separate SQLite sidecar stores current monotonically increasing fences and canonical append-only lease events. Exact table and trigger SQL is checked on every transaction. Triggers prohibit event mutation/deletion, row deletion, fence rollback, marker rollback, and recovery-to-active rollback. Each event includes operation, sequence, event type, holder, fence, deterministic attempt, canonical UTC time, previous hash, and SHA-256 event hash; verification recomputes every chain. The primary ledger schema and implementation remain unchanged and are the sole outcome authority.

Classification and permit rule

AUTHORIZEDPrimary is exactly authorized with no marker.Only while the exact current fence and unexpired session are proven.

TERMINALPrimary is charged or not-found.Never.

prepare_dispatch conditionally commits the primary dispatch_possible marker, records the sidecar observation, and returns one immutable DispatchPermit. Attempt and command identities are deterministic functions of operation identity and purpose only; holder, fence, time, randomness, and process identity are excluded. A future adapter must call session.assert_permit_active immediately before consumption; that check binds the permit to the creating process, thread, live flock, fence, validity window, and exact primary marker. A pre-existing marker, including exact marker recovery after a crash, can never manufacture a new permit.

Failure boundaries

  • Normal exit, cancellation, or any BaseException before the marker durably releases or cancels the fence before dropping the flock.
  • After any marker, context exit persists recovery-only status; successors remain recovery-only regardless of expiry.
  • A crash releases the kernel flock. A successor advances the durable fence, but marker state still forbids resend.
  • Schema, trigger, chain, primary lookup, identity, or transaction uncertainty fails unavailable, never dispatchable.
  • This module exposes no SDK, HTTP, send, retry, request, or transport method. A later qualified adapter may consume a permit while the session remains open.

Verification

Tests cover threads, spawned processes, abrupt process death, expiry under a live flock, cancellation, marker/sidecar crash boundaries, deterministic IDs, successor classification, terminal classification, stale/use-after-exit rejection, symlink lock substitution, exact schema and trigger substitution, event-chain corruption, orphan history, terminal-history regression, separate-database proof, and absence of transport.
