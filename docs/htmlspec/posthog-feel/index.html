Decision · “PostHog feel” is interaction physics, not PostHog architecture PostHog’s MIT frontend/src/layout/panel-layout/ is a fixed shell (left nav + one resizable tree panel + right SidePanel) — not the multi-floating z-stack window manager described in docs/ui_redesign_posthog/sprint_03_panel_layout.html. This programme does not re-clone their nav. It ships the feel the operator asked for: opaque chunky cards, offset shadows that scale with stack depth, hover-lift on manipulable surfaces, a visible cascade, and crisp focus rings — in Werner’s sun-yellow outline, on top of the existing dual-store layout (panels + glass windows).
Predecessor gates (hard) Do not start FEEL-S1 until docs/ui_redesign_posthog/RETRO.md is closed on main and docs/ams-v2/mountain-shell-v2-verification.md is green (npm run e2e:ams). AMS glass windows must stay glass; this programme strengthens panels and cascade — it does not reverse AMS-v2.

1 · Goal

Close the gap between what S3 promised (“shadows that scale with z-depth and a hover-lift micro-interaction”) and what shipped (binary focus shadows only; no hover-lift on floating panels). Make the operator’s daily stack — floating panels inside Research/Wrestle and glass workspace windows over the scene — feel as crisp and legible as PostHog’s product chrome, without importing PostHog’s hedgehog, yellow, or left-nav IA.

Success criteria (programme exit)

  • apps/reading/src/design/elevation.ts maps stack depth → shadow tier; unit-tested.
  • Three floating panels in a real or harness route show ≥20px cascade + monotonic shadows by z.
  • Three glass windows still pass e2e/ams-v2-experience-matrix.spec.ts criterion windows; cascade corners are visibly separated.
  • ResearchWorkstation dense IDE remains opaque; exempt surfaces pass feel-rw-ide-exempt.spec.ts.
  • npm run e2e:feel matrix green; npm run e2e:ams still green.

Failure mode to avoid

Claiming “we shipped PostHog’s UI” or converting AMS glass windows to opaque cards to “unify” the stack. That breaks the mountain-shell proof and confuses two intentional stores.

2 · Context

ui_redesign_posthog S0–S12 built WorkspaceStore + PanelLayout and motion tokens (press, cardLift in src/design/motion.ts), but floating PanelLayoutPanel never wired hover-lift and never mapped zIndex to shadow tier. AMS-v2 then shipped windowsStore + transparent WorkspaceWindow frames — a different, valid stack over the scene. The operator experiences “windows don’t layer like PostHog” because (a) panel feel was incomplete, (b) windows are glass not chunky opaque, and (c) Research IDE is deliberately dense-opaque, not a floating stack.
