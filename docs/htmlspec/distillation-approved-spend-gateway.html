Approve exact distillation spend before transport

Connect wrestling distillation to the existing hard-ceiling gateway without claiming that generic model adapters are idempotent, reconcilable, or budget-safe.

User outcome

A request with a qualified route first prepares exact provider, model, workload, rates, manifest, maximum exposure, and run ceiling. The workstation says that approval is required and points to Settings. After the operator approves those exact terms, replay may reserve and send once. An unqualified or unconfigured route never creates a hold or provider call.

Authority chain

  1. The immutable request event and complete assembled prompt bind one Cycle 91 command.
  2. Preparation creates or reopens an owner-bound run and persists one exact fallback manifest. Preparation cannot reserve or send.
  3. A separate typed approval-required event uses its own deterministic identity; it cannot masquerade as delivery.
  4. Only an exact durable approval yields an approved execution ticket. Wrestling moves the command from reserved to sending immediately before ticket execution.
  5. The existing gateway revalidates route authority and approval under its process/database guard, reserves the maximum, marks dispatch possible, supplies provider idempotency identity, then settles or retains ambiguity from authoritative evidence.
  6. Cycle 91 persists normalized delivery before publication. Any uncertain post-send outcome remains ambiguous and is never blindly retried.

Refusals

  • No configured authority: emit a truthful unavailable state and make zero holds/sends.
  • Missing approval: retain the command as reserved, expose exact terms, and make zero holds/sends.
  • Changed prompt, request, route, rates, ceiling, manifest, owner, run, or approval: fail closed.
  • Adapter without durable idempotency, authoritative reconciliation, disabled hidden retries, or exact billing units: fail before hold/send.
  • Recovered terminal execution cannot fabricate a response value; it requires product-level reconciliation.

Acceptance

  • Preparation and unqualified-route tests prove zero holds and zero sends.
  • Approval-required replay is physically idempotent and leaves the delivery identity unused.
  • Working-memory integrity refusal is a journaled proven-unsent completion with one deterministic delivery identity, zero provider calls, and replay repair after publication interruption.
  • Exact approval proves hold-before-send and conservative settlement.
  • Concurrent/restart replay preserves one provider operation.
  • Schema, generated TypeScript, NotesPanel copy, focused tests, lint, types, build, security, and heterogeneous hostile review pass.
