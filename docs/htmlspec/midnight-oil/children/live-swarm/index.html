    Goal and measurable success

    The live worker must execute four differentiated roles for each goal, preserve every role boundary durably across crashes, constrain each role by signed budget and route authority, and synthesize only from attributable gathered evidence plus explicit verifier findings.

    • A crash after any paid role call resumes without repeating that provider effect.
    • No synthesizer prompt can cite evidence absent from a durable source receipt or omit a verifier contradiction.
    • The sum of confirmed and unknown role exposure never exceeds the approved operation ceiling.
    • Terminal HTML exposes claims, citations, contradictions, confidence limits, role receipts, and twin questions without leaking prompts or credentials.

    Failure to avoid: four differently named model calls that still behave like one opaque synthesizer, multiply cost, and manufacture an appearance of research depth.

    Evidence-backed current gap

    contracts.py and runner.py already define the closed role order and conservative role budgets, but the production plan in live.py signs only the synthesizer route and LiveOperatorCorpusStep performs one retrieval followed by one synthesizer call. The durable worker checkpoints only whole goal steps, so it cannot honestly resume within a multi-role goal.

    approved operation ceiling → signed per-role route + budget envelope → durable planner receipt → parallelizable gather tasks + source receipts → durable verifier findings / contradiction ledger → synthesizer constrained to accepted evidence → canonical HTML + twin + graph projection
