Stage authority and replay ledger

Make every planner, gatherer, verifier, and synthesizer effect independently restart-safe and budget-accountable before enabling the multi-call live engine.

Wave 1Status: readyOwner: primary6 milestones

Parent context

PR #1191 makes the production runtime reachable through ephemeral consent, durable enqueue, owner-safe lifecycle polling, and canonical HTML opening. The remaining live implementation in substrate/midnight_oil/live.py retrieves once and calls only the synthesizer for each goal.

This sprint changes no provider behavior. It introduces the durable authority needed so the following sprint can add paid role calls without repeating effects, exceeding the ceiling, or fabricating stage completion after a crash.

Position: first and mandatory. SPR-08.2 cannot begin until every stage transition and crash window has executable proof.

Goal

Represent a live research goal as a closed, durable sequence of role-stage receipts with exact effect identity and conservative exposure.

A stage is complete only when its typed output, provider effect receipt, route receipt, source/evidence references, and budget outcome agree. Mutable presentation state may project this ledger but may not substitute for it.

Technical milestones

1
Define closed stage identity and outputs

Add strict models for goal index, role, gather shard, deterministic effect ID, input lineage, status, typed output digest, and predecessor receipts.

  • Unknown roles/statuses/fields fail validation.
  • Planner, gatherer, verifier, and synthesizer payloads cannot be confused or reordered.
  • Effect identity is stable across restart and excludes worker identity/clock.

2
Persist an append-only stage ledger

Add durable storage keyed by owner, operation, goal, role, shard, and effect ID with exact insert/replay semantics and immutable completed receipts.

  • Same-effect replay returns the same receipt; conflicting payload/digest is rejected.
  • Restart reconstructs the next legal stage without consulting in-memory job spawns.
  • Cross-owner and cross-operation joins are impossible.

substrate/midnight_oil/stage_store.py · runtime store composition · durable tests

3
Encode the role transition machine

Permit planner → gather shards → verifier → synthesizer only, with a committed gather barrier and explicit blocked/unknown outcomes.

  • Synthesis before complete verification is impossible.
  • Missing gather shards remain visible rather than silently shrinking the plan.
  • Expired leases cannot advance stages.

substrate/midnight_oil/stage_machine.py · state-table tests

4
Allocate conservative per-role exposure

Convert the approved integer-cent ceiling into server-owned role/shard caps; join confirmed, reserved, and unknown outcomes to the existing ledger.

  • Cent allocation sums to at most the approved ceiling with an explicit remainder.
  • Unknown planner/gatherer exposure reduces later-stage availability.
  • No float enters authority or ledger boundaries.

substrate/midnight_oil/budget_ledger.py · stages.py

5
Project owner-safe stage status

Extend lifecycle status with bounded stage counts and sanitized current-role facts without prompts, raw model output, filesystem paths, or credentials.

  • Status distinguishes planned, gathering, verifying, synthesizing, and stage reconciliation.
  • Corrupt ledger/authority disagreement fails closed.
  • Existing polling remains backward compatible.

substrate/midnight_oil/status.py · route/status tests

6
Prove every crash window

Inject crashes before dispatch, after possible dispatch, after provider receipt, after stage persistence, and before worker checkpoint.

  • No paid effect repeats after a persisted provider receipt.
  • Unknown provider outcome is never released as zero.
  • Two workers converge on one legal next stage.

tests/test_midnight_oil_stage_recovery.py · runtime concurrency tests

Rigor — operating manual

1 · Intellectual honesty

Do not equate a checkpoint with an effect

For each injected crash, record whether network I/O was impossible, possible, or receipt-confirmed. Never mark a stage retryable merely because its stage row is absent.

2 · Fairness

Steelman whole-goal checkpoints

The current whole-goal checkpoint is smaller and easier to reason about. Reject it only with a test demonstrating that a paid planner receipt followed by process death would otherwise force either duplicate spend or permanent abandonment.

3 · Rigor

Enumerate the transition matrix

Test every legal role edge, every illegal skip, gather-barrier incompleteness, stale lease, duplicate effect, conflicting replay, and unknown-cost path. A passing happy-path swarm test is insufficient.

4 · Diligence

Reuse existing fences

Read operation_queue.py, job_store.py, budget_ledger.py, and worker terminal recovery in full. Stage authority must compose with their generation/CAS semantics rather than invent a second lease system.

5 · Defensibility

Make effect identity reconstructable

Document why each field belongs in the deterministic stage effect ID and which change would require a schema version. Future maintainers must be able to prove why a replay is the same paid action.

Dependencies

  • Base commit 2d7fdb2be / PR #1191.
  • Existing operation queue, owner authority store, budget ledger, and worker lease generation.
  • No provider credentials or paid smoke required; use deterministic fake idempotent providers.

Out of scope

  • No live planner/gatherer/verifier calls; this sprint builds authority and synthetic recovery proofs only.
  • No arXiv/Substack/web connector and no general workflow engine.
  • No UI redesign, model router, benchmark mutation, or deployment.

If implementation starts prompting a provider, stop: SPR-08.1 has exceeded its safety boundary.
