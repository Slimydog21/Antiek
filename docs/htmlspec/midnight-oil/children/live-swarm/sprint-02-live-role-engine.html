Live role engine and evidence synthesis

Execute a causally real planner → bounded gather fan-out → verifier → synthesizer pipeline through signed routes, then deposit evidence-auditable HTML and twin notes.

Wave 2Status: waits on 08.1Owner: primary7 milestones

Parent context

The current live step signs one synthesizer route, queries the operator corpus once per goal, and sends all evidence directly to a synthesizer. SPR-08.1 introduces durable role-stage authority, exact effect IDs, per-role cent exposure, and crash-safe transitions.

This sprint activates those stages. It must improve epistemic quality rather than merely multiply model calls: planner output defines bounded questions, gatherers return attributable evidence, verifier output records support and contradiction, and the synthesizer is forbidden to invent or silently discard those findings.

Position: begins only after SPR-08.1 is independently accepted. It is the production swarm engine; external-source connectors remain subsequent adapters.

Goal

Produce a canonical HTML research asset whose claim/evidence/verification lineage proves that four differentiated live roles executed within approved authority.

The operator should be able to inspect what was planned, what evidence was gathered, which claims were challenged, what remains uncertain, what each role cost, and how every conclusion maps back to durable receipts.

Technical milestones

Sign per-role dispatch plans

Extend live planning from the synthesizer tier to all configured role tiers, with route allowlists, context/output caps, conservative maximum cents, model-choice constraints, and one canonical plan hash.

  • Missing or non-idempotent role route blocks readiness before queue claim.
  • The signed plan covers every role and gather shard cap.
  • Runtime config drift blocks before provider dispatch.

Prompt the planner with the user goal and bounded corpus inventory metadata, returning a strict plan of questions, inclusion/exclusion criteria, expected evidence types, and falsifiers.

  • Malformed/free-form output fails closed without starting gather.
  • Question count is bounded by approved fan-out and stage budget.

3
Run bounded gather shards

For each committed plan question, retrieve operator-corpus chunks and have the gatherer select/annotate evidence under prompt-injection isolation.

  • Every accepted excerpt has document/chunk/hash scope and plan-question lineage.
  • No source receipt means no evidence item.
  • Shard failures are explicit; the barrier cannot silently shrink.

Verify claims and contradictions

Build a verifier input exclusively from committed plan and gather receipts; return typed supported, contradicted, insufficient, and source-conflict findings.

  • Each finding joins exact evidence receipt IDs.
  • Contradictions and insufficient evidence cannot be omitted from synthesis input.
  • Verifier cannot introduce new source text.

Synthesize under evidence constraints

Generate structured claims, caveats, open questions, and citation joins from verifier-approved evidence only; validate output before accepting the paid effect.

  • Unsupported claim IDs fail deposit validation.
  • Every contradicted claim is addressed or excluded with an explicit reason.
  • Confidence is categorical and derived from verifier state, not model self-rating.

Rigor — operating manual

1 · Intellectual honesty

Calls are not evidence of quality

Report exact role outputs rejected by schema or evidence gates. Do not call the swarm “deep research” merely because four provider calls occurred; acceptance depends on citation joins, contradiction handling, and falsifier coverage.

2 · Fairness

Preserve inconvenient evidence

The verifier must receive supporting and conflicting excerpts with stable source order controls. Steelman direct retrieval→synthesis as the lower-cost alternative and measure which acceptance fixture actually requires the extra roles.

3 · Rigor

Attack attribution boundaries

Inject evidence-like prompt instructions, duplicate chunks, conflicting sources, empty shards, malformed structured outputs, and unsupported synthesis citations. Each must fail or surface explicitly at the named stage.

4 · Diligence

Compose existing contracts

Reuse canonical dispatch receipts, retrieval hashes, budget exposure, deposit digests, twin seeding, and graph effect receipts. Before adding a new schema, prove that RouteReceipt or existing research evidence models cannot carry the requirement.

5 · Defensibility

Make research decisions replayable

The terminal artifact and handoff must explain why a gather question existed, why evidence was accepted/rejected, how verifier findings constrained prose, and which config/model revision produced each role receipt.
