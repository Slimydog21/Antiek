    Goal and non-negotiable proof

    A terminal, owner-authorized live job has one durable HTML/twin deposit and one idempotent DuckDB projection. A crash at any boundary can resume without provider replay. The stored effect receipt names every graph identifier and content hash used to support a persistence claim.

    paid evidence checkpoint → budget settlement → terminal authority → idempotent HTML/twin deposit → idempotent graph projection → durable effect receipt → query/deep-link verification
    • Provider/network work never runs under the DuckDB write lock.
    • Projection is downstream of exact durable step evidence and a completed deposit.
    • A successful provider call without graph receipt never reports graph_projection_state=complete.
    • Retry after commit-before-checkpoint reuses deterministic IDs and emits no duplicate graph rows.
