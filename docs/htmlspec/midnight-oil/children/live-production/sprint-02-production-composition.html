Production runtime composition

Make the durable live chain launchable and observable without weakening provider, consent, lease, or graph gates.

Wave 2Depends on SPR-06b.16 milestones

Parent context

The API factory intentionally refuses guessed Midnight Oil dependencies and the live consumer currently has no daemon call site. This sprint adds an explicit composition root and worker process. Production still refuses to create live plans unless an exact provider endpoint has an operator-recorded idempotency guarantee.

The worker claims one durable operation, constructs retrieval/dispatch from the same signed plan, consumes it, deposits HTML/twins, projects the graph, and exits or polls according to explicit CLI policy. It never runs as a request-scoped background task.

Technical milestones

1. Configuration contract. Parse bounded paths, consent keyring, graph path, provider verification record, poll/lease settings; reject unknown/missing production fields before app or worker startup.
No secrets printed or serialized; no implicit in-memory fallback.
2. Shared composition root. Construct the API dependency bundle and worker dependencies from one immutable runtime config.
API plan resolver and worker dispatch hash the same route config.
3. Worker lifecycle. Claim authorized operations, renew/fence leases, consume/deposit/project, handle SIGTERM between phases, and expose once/poll dry-run-safe commands.
Two processes cannot execute the same generation; shutdown never turns an unknown provider outcome into retryable work.
4. Observability. Emit secret-free structured phase/result records keyed by job, operation, generation, and receipt hashes.
Logs distinguish no-work, blocked-provider, failed, reconcile-required, deposit-pending, projection-pending, and complete.
5. Production entrypoints. Supply explicit API and worker launch commands plus deployment configuration without changing the default networkless app import.
Default app = create_app() remains non-spending; production opts in explicitly.
6. Restart/system proofs. Exercise real durable stores/queue/DuckDB with a verified fake provider and controlled crashes.
One provider call, one settlement, one deposit, one projection across restarts; all static gates clean.

Rigor: five values

Intellectual honestyA runnable worker with no verified real provider is production composition, not production spend enablement. Surface blocked-provider as a healthy fail-closed state.
FairnessSteelman an API background task: fewer processes and simpler deploy. Reject it because request-worker restarts and concurrency obscure lease ownership; revisit only with a durable framework-managed task lifecycle.
RigorProve two-worker contention, lease expiry, SIGTERM after provider return, config drift, and graph retry using subprocess or equivalent lifecycle tests—not only direct function calls.
DiligenceRead the actual deployment service and environment conventions before naming variables. Reuse the existing queue, stores, retrieval factory, dispatch config, and logging envelope.
DefensibilityEvery operator assertion that enables a provider records endpoint identity, evidence reference, verification time, and config hash. A boolean environment flag alone is insufficient.
