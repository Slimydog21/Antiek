Durable receipt binding narration, visual, and render authorities

Stacked on PR #802. Issue a deterministic, atomically-published receipt that binds three nested authorities (NarrationProductionArtifact, VisualSelectionPacket, KenBurnsRenderArtifact) into one HMAC/MAC-verified composite for downstream consumption.

Contract

Input is EducationalVideoProductionArtifact from PR #802. Receipt carries schema version, bounded asset and revision identifiers, the exact typed nested authorities, and a composite HMAC using a separate >=32-byte receipt key. All Pydantic models are frozen, extra=forbid, revalidate_instances=always, allow_inf_nan=false, Python 3.11 compatible.

Cross-binding verification

Issue must independently reopen all nested authorities using narration/visual/render keys, then cross-bind: all asset/revision equal; visual packet timeline digest equals render timeline digest; render narration path+sha equal narration output; visual packet rows exactly equal render input rows (scene,path,sha,label,source chunks); narration chapter IDs and cumulative millisecond boundaries equal render captions; total duration matches.

Atomic publication

Fully reopen staged bytes before publishing one canonical JSON receipt into a private 0700 output root with a 0600 file. The bundle name is a fixed-length SHA-256 identity over asset and revision, so maximum valid identifiers remain filesystem-safe. Fsync then rename atomically. Exact replay returns the reopened artifact; a valid conflicting receipt fails without overwrite. Concurrent identical calls converge to one valid result with no staging residue.

Reopen

Reopen from payload and a convenience reopen-from-file both enforce bounded size, receipt MAC, all nested authority reopen/file checks, all cross-bindings, canonical bundle identity, regular single-link private file requirements, and file/bundle inode continuity through the final trust decision.

Failure model

Missing, tampered, aliased, public, oversized, symlinked, MAC-invalid, detached, or cross-boundary-inconsistent inputs produce no successful receipt. Failure before rename leaves no final receipt; successful publication is never destructively rolled back by pathname.

Non-goals

No media bytes duplication, no embedded keys/secrets, no TTS generation, network, routing, spend, HTTP route, frontend, campaign mutation, merge, or deploy.

Threat model

Adversary may tamper receipt or media bytes, substitute nested artifacts, replay with wrong keys, replace paths, create public or linked files, or race identical and conflicting issuers. The receipt must fail closed without deleting unrelated replacement paths.

Acceptance

  • Real PR #802 FFmpeg production issues and reopens
  • Wrong each key fails independently
  • Composite and nested model-copy tamper fail
  • Media and chapter-boundary drift fail
  • Private modes, symlink, hardlink, and detached-path races fail
  • Staged validation failure leaves no residue
  • Exact replay and concurrent identical issuance converge
  • Two valid conflicting receipts produce an exact conflict
  • Python 3.11 and 3.14 gates pass
