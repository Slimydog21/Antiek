Semantic Scholar durable corpus cache

Status: implemented as a stacked extension of acquisition-corpus bridge PR #782.

User outcome

Semantic Scholar enrichment survives process restart and becomes researchable through the same immutable search → fetch boundary as arXiv, OpenAlex, and Substack.

Authority and ordering

  1. The wrapper calls PR #760's governed S2Client with fixed title and abstract fields.
  2. It validates a complete one-record-per-request response and stamps the batch once.
  3. Under a process lock it merges canonical paper IDs into one sorted generation.
  4. It fsyncs a content-addressed snapshot, then atomically swaps CURRENT.
  5. Only a digest-verified generation reloaded from disk may construct the corpus adapter.
  6. After a successful swap it prunes every superseded/orphan generation, bounding steady-state storage to one snapshot.

Failure contract

A partial generation is never authoritative. Invalid responses, duplicate IDs, hostile clocks, tampered files, symlinks, non-private directories, malformed JSON, and failed pointer swaps refuse. Persistence failure propagates; it is never returned as enrichment success.

Non-goals

No live request, API-key handling change, provider routing, PDF fetch, production wiring, parent-branch mutation, merge, deployment, or spend.
