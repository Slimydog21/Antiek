Antiek / Research / Write

Turn a verified research composition into a reviewable Write draft

Create an editable analysis workspace from multiple completed investigations without treating concatenation as synthesis or losing immutable source identity.

Status: executable · Parent: Cycle 40 composition

Decision

Import source authority; do not generate prose. One explicit command creates a draft deliverable with a blank Analysis section and ordered source sections. Exact Cycle 40 member snapshots seed graph-backed blocks. The existing cited creative-writer command remains the only model-generation boundary and must be invoked separately.

Five values

Intellectual honesty

source_scaffold is not called a synthesized analysis. Empty evidence is reported, never filled.

Fairness

Composition order is retained. Every member remains visible even when it contributes no blocks.

Rigor

Import reopens the canonical index and every immutable member, verifies both hashes, and persists the exact ordered tuples.

Diligence

One owner-scoped idempotency receipt binds the complete request. Database creation is atomic and replay-stable.

Defensibility

Every imported block records composition, member, hash, snapshot text, and source node identity; later citations can resolve both immutable and current graph authority.

Durable contract

  • deliverable_compositions binds deliverable, authenticated owner, idempotency key, request digest, composition ID, ordered digest, schema version, analysis section, and import time.
  • deliverable_composition_members binds member index, investigation ID, semantic hash, rendered hash, source section, evidence count, and an explicit insufficient-evidence bit.
  • The composition tuple order is immutable import provenance. A writer may reorder presentation sections later without changing it.
  • Imported graph blocks retain node_id provenance and carry exact snapshot text plus the complete member tuple in trusted metadata. Draft generation reads snapshot text for this profile rather than mutable graph labels.
  • The deliverable's singular investigation_root_id remains null; it must not lie about a multi-investigation source.

Failure semantics

  • Malformed/unknown composition is 404. Integrity or member disagreement is 409. Invalid input is 422.
  • Same owner and idempotency key with exact request replays the original result. Different request terms conflict.
  • Index/member tamper, missing bytes, duplicate snapshot node IDs within one member, unsafe IDs, request drift, or stored receipt drift creates nothing.
  • A graph node deleted after composition remains an explicit dangling source block. Snapshot text is retained; current trace reports the deletion.
  • No provider, model, graph-node creation, source mutation, publication, spend, approval, or automatic generation occurs.

Acceptance criteria

  1. Two verified members create one draft, one blank Analysis section, two ordered source sections, exact normalized tuples, and snapshot-backed outline blocks in one transaction.
  2. Analysis contains the deterministic ordered union of member evidence; source sections contain only their own evidence.
  3. Zero-evidence members remain as sections and appear in insufficient_evidence_members.
  4. Exact replay returns identical IDs and counts; changed title, kind, composition, or key terms under the same key returns 409.
  5. Index, member, semantic hash, rendered hash, investigation identity, or member JSON tamper leaves no deliverable rows.
  6. Generation context uses immutable snapshot text for imported blocks and retains ordinary behavior for all existing blocks.
  7. The browser freezes both commands while pending, reports one actionable failure, opens the Write route on success, and never confuses HTML review with draft creation.
  8. Existing single-investigation promotion, manual deliverables, generation, editing, and export tests remain green.

Known boundary

Cycle 40 research storage is authenticated single-operator state because its event records lack owner identity. This import derives the authenticated deliverable owner but cannot prove historical per-member ownership. Multi-user enablement requires an owner-bearing research-event migration and composition owner binding; this sprint does not manufacture that claim.
