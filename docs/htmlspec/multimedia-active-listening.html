Antiek Multimedia / Cycle 20

Make verified audio usable on a walk, run, or workout

Turn both cheapest-local and paid Audible lessons into one chapter-aware listening surface without weakening receipt authority.

Outcome

An authenticated owner can play either registered audio lane through one responsive player with exact chapter navigation, 15-second seek controls, bounded playback speeds, learned-claim review, and browser Media Session controls.

Verified timeline projection

  • Add ordered chapter metadata containing chapter ID, title, sequence, start seconds, and end seconds to the shared audio playback projection.
  • Local playback projects the already verified AudibleRunManifest.chapters exactly.
  • Paid playback derives contiguous windows from receipt-bound narration source durations and titles from the embedded transformed plan.
  • Every projection independently requires contiguous sequence, start at zero, positive windows, exact chapter-ID order, no gaps or overlap, and final end equal to verified total duration within one millisecond.
  • The HTTP response and TypeScript client reject malformed, duplicate, reordered, non-finite, negative, gapped, overlapping, or duration-drifting chapter timelines.
  • Existing receipt, owner, current revision, byte digest, size, duration, marker, claim, source, and durable-link checks remain mandatory.

Shared player

  • One ActiveListeningPlayer renders local and paid audio. It owns the audio element and does not duplicate playback in route-specific panels.
  • Controls include play/pause through native semantics, previous and next chapter, back and forward 15 seconds, and a segmented speed control limited to 1x, 1.25x, 1.5x, and 2x.
  • The current chapter follows verified media time. Chapter buttons seek to exact verified starts and expose title plus bounded elapsed range.
  • Seeking clamps to zero and verified duration. Asset/revision or source change resets UI state and cannot reuse a stale chapter timeline.
  • Learned claims remain available for both local and paid playback, grouped by exact chapter identity. No claim is invented from a title or plan.

Media Session

  • When supported, register play, pause, seek backward, seek forward, previous track, and next track handlers against the current audio element.
  • Metadata uses the current asset title and literal Antiek product identity; it never exposes owner, receipt, source, provider, or filesystem data.
  • Playback state and position state follow real media events and verified duration. Invalid browser position-state calls are ignored without breaking playback.
  • Unmount, asset/revision change, and source replacement clear every installed handler and stale metadata owned by the component.
  • Unsupported Media Session browsers retain the complete on-screen player.

Accessibility and responsive behavior

  • Icon controls have visible tooltips or accessible names; speed is a radiogroup; chapter selection identifies the current chapter.
  • Stable control dimensions prevent time, speed, and chapter changes from shifting the layout.
  • The player stacks on narrow screens and remains operable by keyboard. Text cannot overlap media controls.

Acceptance

  • Local and paid runtime tests prove exact chapter projection and reject timing drift.
  • Both HTTP routes return the same bounded chapter schema and preserve all owner/revision/link checks.
  • Client validation rejects malformed timelines before rendering or seeking.
  • Component tests cover chapter seeking, 15-second clamping, speed changes, active chapter tracking, learned claims, Media Session registration, and cleanup.
  • Local production UI and the general multimedia player both use the shared component; video playback remains unchanged.
  • Broad multimedia tests, focused frontend tests, typecheck, production build, Ruff, HTML parse, diff hygiene, HardenX, and independent review pass.

Non-goals

No offline download, service worker cache, public sharing, transcript editing, continuous microphone steering, automatic playback, route mutation, provider call, spend, receipt issuance, publication, or video-player redesign.
