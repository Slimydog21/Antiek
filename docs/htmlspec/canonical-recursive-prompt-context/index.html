Recursive knowledge substrate · correction spec · base a7473e44

Canonical recursive prompt context

Replace count-only, caller-supplied “ready” packs with bounded canonical content and provenance that downstream research prompts actually consume.

Spec lineage

Root correction spec derived from the operator’s recursive note-taker vision and the downstream audit on PR #913. No child spec trees.

    Goal

    Every future research prompt can receive the most relevant, owner-readable insights, open questions, and artifact notes as exact provenance-bearing content—within an explicit token budget and without treating caller text as canonical.

    • pack_ready implies at least one returned content unit or resolvable canonical reference.
    • Every unit names canonical authority, asset/twin/artifact identity, kind, ordinal, digest and source event.
    • The real prompt/context consumer proves receipt of the content, not merely pack metadata.
    • Outcome feedback can improve ranking without rewriting historical evidence or leaking private content.

    Failure mode: counts and readiness flags look complete while every usable string is discarded before dispatch.

    Context & motivation

    The operator’s recursive note-taker requires useful prior thinking to inform later prompts. PR #913 names that intent but implements a count-only envelope, so the context substrate remains semantically empty.

    Current-state red proof

    At #913: compose_recursive_twin_session_pack validates each insight/question, increments counters, then returns no insight/question text and no canonical refs. It reads caller-supplied members, not the twin store or ResearchArtifact notes. A mutation deleting all strings from the returned object changes no readiness output.
