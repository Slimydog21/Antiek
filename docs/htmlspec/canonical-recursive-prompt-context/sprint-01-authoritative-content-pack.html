Authoritative content pack

← Master

Parent context and goal

#913 returns counts and discards content. This sprint replaces readiness-by-count with a canonical bounded payload.

Goal: resolve owner-readable twin/graph content into deterministic ContentUnit[]; artifact notes remain an explicit gated resolver until #914 lands.

Where this sits: no prompt integration may start until content survives this layer with provenance.

Technical milestones

1 Write the red mutation.
Delete all returned text/refs while preserving counts; the old #913 implementation must fail because ready cannot be true with zero consumable units.
2 Define ContentUnit v1.
Fields: unit_id, authority, account_scope_digest, asset_id, twin/artifact ID, kind, ordinal, text or exact resolvable ref, text_digest, source_event_ids, created_at, rights/readability label. Strict per-field/list bounds.
3 Resolve canonical twins and graph notes.
Request contains IDs/goals only. Resolver reads canonical stores under authenticated account authority; missing, foreign, malformed and duplicate units become metadata-only exclusions.
4 Add artifact-note resolver gate.
Interface exists but fails closed until PR #914 authority is integrated. It never reads the current global artifact path for a non-operator account.
5 Bound and order.
Deterministic priority: explicit selection, relevance, unresolved questions, recency, stable unit ID. Apply per-asset diversity, per-unit bytes and aggregate token estimate; return exclusions and truncation facts.
6 Separate advisory preview.
Caller-supplied text may produce authority=caller_supplied_advisory and can never set canonical pack_ready or enter dispatch without explicit user quoting semantics.

Five-values rigor

Intellectual honesty

Do not call a ref consumable until the same resolver proves it can return bytes under current authority.

Fairness

Diversity caps prevent one prolific asset from erasing quieter contradictory sources.

Rigor

Mutation tests must drop text, swap owner digest, duplicate ordinals and overflow every bound.

Diligence

Inventory twin, graph and artifact-note authorities before adding another store reader.

Defensibility

Every included/excluded candidate must be reconstructable from IDs, digests and deterministic ordering facts.

Dependencies

Out of scope
