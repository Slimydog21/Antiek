Multimedia Reconciliation Operations

Status: executable sub-spec. Parent: multimedia TTS reconciliation.

Outcome

Give an authenticated operator a redacted diagnosis and explicit recovery action for a crashed chapter narration without exposing provider credentials, recovery keys, signatures, audio bytes, or private filesystem paths.

Contracts

  • The read projection verifies the signed provider execution and signed chapter attempt before deriving status.
  • Unknown ownership and missing state return the same opaque unavailable error.
  • Sending becomes quarantine-eligible only after the configured stale interval; outcome-unknown always remains fully charged.
  • Provider evidence is required for unknown-send recovery and for resuming a received receipt whose provider success observation crashed.
  • Sealing remains wait-only until the signed seal lease reaches the configured stale threshold; legacy attempts without lease evidence fail closed.
  • Commands accept short-lived signed operator authority and delegate to the canonical recovery state machine. They never invoke provider transport.

Acceptance

  1. Status progresses from wait to quarantine, recover, narration resume, and no-action states deterministically.
  2. Read responses contain booleans and safe codes, never secrets or raw paths.
  3. Wrong-operator reads and commands fail closed.
  4. Focused tests, multimedia regression tests, Ruff, strict mypy, HTML parsing, and security review pass.
