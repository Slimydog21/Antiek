Distillation reserved-hold release

User outcome

An authenticated owner can inspect an ambiguous distillation request, review its complete run, chain, manifest, fallback index, hold identity, and reserved amount, then deliberately restore budget only when the ledger proves that exact current hold never crossed the provider-send boundary.

Authority boundary

  • The read model remains evidence-only and never executes an action.
  • The release command accepts only expected_command_state=ambiguous and expected_hold_state=reserved.
  • The per-request process flock spans the final command comparison, atomic ledger mutation, and refreshed response, preventing fallback-correlation advance during compare-and-act.
  • The ledger atomically validates owner, run, chain, manifest, fallback route, every private hold-intent field, projected maximum, and current reserved state before subtracting held cents.
  • dispatch_possible and unknown require authoritative provider lookup and can never use this command. Local abandonment never restores budget.
  • One deterministic command key makes exact retries idempotent; changed terms conflict without mutation.

Operator interaction

  1. An ambiguous delivery offers only “Review held budget.”
  2. The first gesture fetches authoritative evidence. Raw transport errors are never shown.
  3. For a reserved hold, the UI displays complete run, chain, manifest, hold, and amount. A separate second gesture submits exactly those reviewed terms.
  4. Pending release disables duplicate submission. Success reports restored headroom. Failure keeps budget described as held and requires a fresh evidence check.
  5. Provider-possible evidence displays “Provider verification required” and renders no release control.

Acceptance evidence

  • Exact owner release changes one hold and one ledger event, restores only its projected cents, and exact replay adds nothing.
  • Foreign owner, stale manifest, substituted hold, skipped fallback index, malformed body, changed command state, and private route-intent substitution fail closed.
  • Dispatch-possible and unknown holds retain their full held amount.
  • Frontend tests prove two gestures, complete term disclosure, exact body reuse, pending behavior, safe failure copy, and no release button for provider-possible exposure.
  • Coupled tests, Ruff, strict types, production build, HardenX, and independent hostile review pass.

Non-goals

No provider lookup, settlement, retry, abandonment, adapter qualification, generic spend release, event schema, live provider call, merge, or deployment.
