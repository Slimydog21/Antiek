Werner Listening Beat

Status: executable implementation contract.

Intent: when Antiek has proof that microphone capture began, Werner becomes an attentive listener. A click or permission prompt alone is not proof.

Hard-to-vary event contract

  1. The canonical experience is voice_recording_started.
  2. Its authored reaction is the existing thinking pose; no redundant bitmap is introduced.
  3. The single emission boundary is immediately after MediaRecorder.start() returns successfully in the shared recorder hook.
  4. Permission denial, stale permission resolution, unmount, constructor failure, and synchronous start() failure emit nothing.
  5. Choreography is observational: an observer failure after recorder start must not stop the stream or rewrite the recorder state as an error.
  6. One successful start emits exactly once. Re-rendering and recorder-state observation never emit.

Coverage and ownership

The shared hook carries the beat into Reading voice notes, Research voice chase, Multimedia steering, and shared capture flows. Consumers must not add parallel start emissions. The separate invitee recorder remains explicitly outside this sprint.

Accessibility and motion

The event changes no focus, label, live region, microphone consent, or keyboard behavior. The already-centralized Werner stage owns reduced-motion downshifting and latest-wins interruption.

  • Reaction allowlist and exhaustive map tests.
  • Signal helper event test.
  • Recorder success, synchronous failure, stale permission, and unmount tests.
  • Focused Vitest, TypeScript, production build, heterogeneous review, and hardenx.
