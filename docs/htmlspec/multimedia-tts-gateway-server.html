Multimedia TTS Gateway Server

Child execution spec of multimedia-tts-gateway-runtime.html. This sprint supplies the trusted machine-to-machine server behind that fixed HTTPS client.

Five values

  • Honesty: a provider request ID is captured from the provider; it is never invented.
  • Spend safety: one durable sending transition precedes the only paid call.
  • Identity: bearer credential, account digest, request digest, and idempotency key must all agree.
  • Replay: completed bytes are sealed and replayed locally; ambiguous sends are never automatically repeated.
  • Containment: credentials, source text, filesystem paths, and internal errors never enter HTTP responses.

State machine

absent -> sending -> completed. Any callback exception or crash observed during a later replay yields unknown. Exact completed replay verifies row MAC, file ownership/mode, SHA-256, and byte ceiling before returning. Conflicting key reuse is rejected. There is intentionally no unknown -> sending transition.

Provider contract

The server accepts only the configured account, provider openai, endpoint capability text-to-speech, configured model, logical voice, speed 0.25-4, and text up to 4096 characters. It calls the fixed OpenAI HTTPS speech origin once with redirects and environment proxies disabled, a deterministic X-Client-Request-Id, and bounded response streaming. Success requires a bounded provider X-Request-Id and an allowed audio content type.

HTTP contract

POST /multimedia/tts-gateway/synthesize requires the configured bearer and exact Idempotency-Key: antiek-tts-{request_body_digest}. A completed response exactly matches antiek.tts-gateway-response.v1. Conflict is 409, unknown is 503, malformed authority is 422, and disabled runtime is 503.

Crash table

Non-goals

No automatic retry from sending/unknown, no claim that X-Client-Request-Id proves completion, no provider result lookup that OpenAI does not document, no browser credential surface, no arbitrary provider URL/model/account, no reconciliation mutation, no visuals, publication, merge, or deploy.

Done bar

Tests prove exact auth/account/body/idempotency binding, one-call concurrency, completed cache replay, conflicting replay, sending/unknown refusal, provider request-ID capture, byte bounds, no redirects/proxies, private sealed files, startup all-or-nothing, and response redaction. Broad multimedia tests, lint, HardenX, and independent review pass.
