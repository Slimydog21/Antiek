Cycle 58: Derived HTML Revision Indexing and Companion

Make canonical derived HTML queryable and discussable with immutable section citations, without turning retrieval projections into a second body authority.

Spec lineage

Parent: Cycle 57 first-class reading

    Outcome

    Every committed derived revision receives a deterministic, transactionally complete section index. The authenticated owner can retrieve or ask against the current head or one immutable pinned revision. Every result identifies the exact asset, revision, content hash, revision generation, chunk, section anchor, and normalized text hash.

    Authority model

    Canonical body

    derived_asset_revisions.canonical_html remains the sole body authority. Chunk text and vectors are disposable projections and are accepted only after complete re-derivation from canonical bytes.

    Immutable citation

    Chunk identity hashes asset, revision, content hash, ordinal, section anchor, text hash, policy, and version. Identical text in two revisions has different citation identity.

    Explicit scope

    Stable reading asks resolve the verified current pointer at request time. Historical reading asks name an exact owned revision. No caller supplies owner, HTML, content hash, generation, or chunk rows.

    Dedicated projection

    Global chunks remain source-document atoms and are unchanged. Only the verified derived retrieval service reads revision-index rows; shared ranking utilities may be reused without weakening the global contract.

    Index schema

    • derived_asset_revision_chunks: immutable ordered revision-scoped citation row containing member index, section anchor/path, normalized projection text, text hash, token count, and chunker policy/version.
    • derived_asset_revision_chunk_embeddings: optional projection vectors with exact provider/model/dimension/fingerprint identity; never the citation or body authority.
    • derived_asset_revision_indexes: one completion receipt per revision binding content hash, exact chunk count, canonical ordered index digest, chunker identity, and embedding fingerprint.
    • Both tables have exact foreign keys to the revision/content tuple and chunk rows. No update/delete authority is added.
    • Revision create, revise, and restore insert the complete projection before advancing the current pointer, in the same DuckDB transaction. Any parse/index/constraint failure rolls back the revision and document identity.

    Deterministic HTML chunker

    1. Parse only the closed canonical merge vocabulary, require the exact policy/version wrapper, and require contiguous top-level member indexes.
    2. Walk semantic block order. Heading levels establish a bounded section path; rewritten canonical heading IDs are preferred anchors, otherwise a deterministic synthetic anchor is derived.
    3. Normalize text with HTMLParser-decoded characters and collapsed Unicode whitespace. Empty and whitespace-only blocks disappear.
    4. Pack whole blocks to a fixed token ceiling without ever crossing a member or section anchor; split oversized blocks deterministically by word windows. Table rows, list items, blockquotes, preformatted blocks, and paragraphs remain attributable.
    5. Enforce ceilings for HTML bytes, nodes, headings, blocks, chunks, text bytes, token count, and path bytes. Overflow fails the merge transaction rather than truncating silently.

    Embedding posture

    Commit publishes complete lexical rows only and never loads an embedding model or makes a provider call while holding the writer transaction. Verified retrieval provides immediate deterministic token-overlap ranking. Optional semantic embeddings publish later with their own exact fingerprint; the UI must not label lexical retrieval semantic.

    Service and API

    • POST /research/derived-assets/assets/{asset_id}/reading/search: bounded question and top-k; resolves current.
    • POST /research/derived-assets/assets/{asset_id}/revisions/{revision_id}/reading/search: same contract pinned to exact history.
    • POST .../reading/ask: retrieves through the same verified service, dispatches only when grounded chunks exist, and returns model-labelled prose plus exact citations. No context means no model call.
    • All responses are private/no-store. Foreign and missing are identical. Index absence, incompleteness, drift, or incompatible embedding returns an integrity conflict, never partial results.

    Reader companion

    The derived reader gains a persistent conversation surface scoped to the exact model already on screen. Current and pinned routes call distinct endpoints. Citation commands scroll to the exact canonical section anchor when present and otherwise expose a bounded quote without inventing a location. Route or revision changes cancel stale requests and reset the active thread; an answer from one revision can never land in another revision's UI.

    Acceptance harness

    • Parser/chunker determinism across processes, entities, nested sections, lists, tables, preformatted text, oversized blocks, duplicate headings, empty bodies, malformed HTML, and every ceiling.
    • Two revisions containing identical text receive distinct chunk IDs; restore receives new IDs while preserving the selected canonical text.
    • Index receipt reopens and re-derives every tuple. Missing, extra, reordered, altered, foreign, orphaned, or provider-drift rows fail closed.
    • Create/revise/restore faults at every index stage leave no revision, chunk, sidecar, pointer, document, receipt, or outbox residue.
    • Generic brute-force and VSS retrieval remain byte-for-byte unchanged because derived projections never enter chunks. Dedicated current and pinned searches return only the exact verified revision.
    • Owner isolation, query bounds, no-context no-dispatch, exact citation response, stale frontend responses, anchor navigation, TypeScript, production build, hostile review, and HardenX pass.

    Rejected alternatives

    • Plain text-hash chunk IDs: collapse identical passages across revisions and make citations drift.
    • Only indexing the current head: destroys historical citation reopenability after revise or restore.
    • Putting all revisions into generic search: silently mixes obsolete and current claims.
    • Deleting old chunks on pointer movement: breaks notes, citations, audit, and immutable deep links.
    • Copying canonical HTML into documents.raw_text: creates a second mutable body authority.
    • Loading sentence-transformers or calling a provider inside merge commit: extends writer lock duration and couples content authority to optional infrastructure.
    • Trusting persisted chunks without re-derivation: lets a disposable projection become de facto truth.

    Five-values rigor

    Honesty: hash retrieval is labelled lexical and ungrounded asks do not dispatch. Fairness: only server-derived ownership can expose text. Rigor: citations bind exact immutable identity. Diligence: every index is completely re-derived before use. Defensibility: generic retrieval remains closed until shared semantics are explicit.

    Harness hint

    Implement parser and pure identities first, then schema and transactional indexing, verified retrieval, HTTP, and UI. Refute projection drift and cross-revision leakage before publication.
