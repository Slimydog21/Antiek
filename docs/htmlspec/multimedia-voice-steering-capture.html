Capture reviewable voice steering without bypassing revision authority

Status: executable sub-spec. Parent: Antiek Multimedia SPR-07 Steering and Revisions, milestone 2.

Contract

The authenticated Multimedia workstation reuses Antiek's shared browser recorder and ASR client. Recording and transcription only populate the steering editor. They never apply a revision, call a media provider, or spend money. The operator can correct the transcript before the existing explicit Apply steer command.

The mutation sends the reviewed editor text as prompt, the ASR result as raw_voice_transcript, and a distinct corrected_voice_transcript only when the operator changed the transcript. The existing backend persists these fields inside the structured steering intent and child revision. Discarding voice provenance returns the editor to text-only steering without deleting its text.

Failure model

  • Microphone denial leaves typed steering available and states the denial.
  • Empty audio, empty ASR text, timeout, unavailable ASR, and malformed responses produce no steering mutation and no invented transcript.
  • Record, stop, and transcription states cannot race an Apply command.
  • Asset or revision changes clear voice provenance so a transcript cannot attach to another authority.

Acceptance

  • Record, stop, transcribe, review, correct, discard, and typed fallback states are accessible and tested.
  • A corrected voice steer sends raw and corrected transcript fields exactly once; an unchanged voice steer omits the correction.
  • A typed steer sends neither voice field.
  • No steering API call occurs during capture or transcription.
  • Focused Multimedia tests, TypeScript, production build, HTML parse, security review, and independent review pass.

Non-goals

No audio persistence, streaming ASR, wake word, continuous playback steering, model-generated transcript correction, provider execution, publication, merge, or deploy.
