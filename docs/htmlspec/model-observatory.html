Turn canonical Settings into Antiek's Model Observatory

The existing route already owns model inventory, encrypted BYOK registration, budget truth, prompt-cost projection, advisory model comparison, weekly Antiek-bench evidence, environment facts, and passkeys. Author that working control room without inventing readiness, prices, rankings, benchmark evidence, or dispatch authority.

Five values

  1. Intellectual honesty: unknown spend, pricing, budget effect, and benchmark evidence remain explicitly unknown; decorative imagery never depicts a winner.
  2. Fairness: candidate readiness, budget eligibility, measured evidence, and static priors remain visibly distinct; no provider gets a visual endorsement.
  3. Rigor: preserve all existing fetches, payloads, tab keyboard behavior, stale-decision invalidation, write-only credential clearing, and server-owned ranking.
  4. Diligence: prove overview, decision, loading, empty, known-budget, unknown-budget, private-safe failure, long-data, constrained-scroll, and production-art states.
  5. Defensibility: live HTML owns every model, price, score, task, credential control, benchmark row, and security action; generated art is decorative and inert.

Correctness and privacy

  • Top-level model, budget, projection, decision, and passkey failures use fixed private-safe messages; raw paths, HTTP status, exception text, key material, and provider responses never reach the page.
  • When budget percentage is unknown, the meter has no numeric aria-valuenow and announces that usage is unknown; it must never masquerade as 0%.
  • The advisory decision tab remains server-owned and never dispatches a model.
  • The AppShell owns the route-level main; the Model Observatory is a fixed-height scrolling div.

Visual contract

A quiet polar instrument observatory—with edge-weighted brass selectors, glass prisms, cables, and aurora—frames a broad live HTML console. It contains no text, prices, logos, model names, charts, scores, keys, winner symbols, controls, mascot, or interface screenshots. A strong veil keeps the cards primary. The tabs read as two views of one instrument, not separate products.

Acceptance

  • Tests pin existing fetch/action authority, keyboard tabs, stale-decision suppression, safe top-level errors, unknown progress semantics, decorative art, and landmark ownership.
  • Production, wide, tablet, and mobile stories prove the live surface at its responsive bounds; focused tests cover behavioral states.
  • Forced-light and forced-dark axe, exact CSS-variable audit, TypeScript, token/type/parity gates, Storybook, production build/budgets, hardenx, constrained overflow, and heterogeneous hostile review are green.

Non-goals

No settings API/schema, provider registration semantics, secret storage/transport, readiness or tier binding, budget ledger/enforcement, projection math, decision response, benchmark generation/evolution, passkey ceremony/removal behavior, route, backend, shell, Werner, cursor, merge, or deploy changes.
