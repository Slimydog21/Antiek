BRK-02: Provider broker primary ledger

Status: Executed persistence boundary. It performs no provider transport and qualifies no route.

Spec lineage

Parent: Antiek Durable Provider Broker. Protocol parent: BRK-01 canonical authority.

    Outcome

    One primary SQLite ledger durably accepts canonical BRK-01 authorization before any future upstream boundary, serializes create and lookup on the same process-crossing tenant/key lock, executes version-conditional commands, and distinguishes authoritative missing from every unavailable or corrupt condition.

    Five-values rigor

    ValueBRK-02 obligation
    HonestyPrimary persistence is not signature verification, provider qualification, worker recovery, or proof that an upstream request ran.
    FairnessClient charge is capped at approved cents; a larger assessed provider charge is recorded separately as broker loss.
    RigorExact authorization and command bytes, resulting snapshots, state sequence, versions, identities, and evidence are canonical and hash-bound.
    DiligenceLock, database, migration, integrity, stale-version, substitution, and malformed-state failures all fail closed.
    DefensibilityDatabase triggers enforce append-only commands/audit and terminal immutability; the verifier independently recomputes protocol and history authority.

    Transactional contract

    1. ensure_schema applies schema version 1 atomically under a global migration lock and refuses unknown versions or missing immutability triggers.
    2. authorize accepts only currently valid canonical authority. Exact committed bytes replay to the same operation even after expiry; changed key bytes conflict; one tenant cannot bind one operation digest to multiple keys.
    3. lookup can return authoritative_missing only after acquiring the same tenant/key file lock as create, opening the primary database in read-write mode, beginning IMMEDIATE, and passing exact schema-version plus trigger-definition checks.
    4. Lock timeout/failure, absent database, unknown schema, transaction failure, or corrupt authority raises unavailable/integrity and never returns missing.
    5. Every transition exact-matches command ID and canonical bytes, expected version, closed source/target state, immutable attempt identity, and state-specific evidence. Delayed exact replay returns its originally committed historical result.

    Integrity evidence

    Each immutable command stores canonical JSON and its SHA-256 digest. Each audit sequence stores source/target state, command digest, canonical resulting-row JSON and digest, prior event hash, and event hash. Startup and explicit verification run full SQLite and foreign-key integrity scans; ordinary transactions use bounded schema/trigger checks. Verification recomputes BRK-01 authorization/route digests, row semantics, command bytes, result bytes, command-to-event joins, closed transitions, chain order, count, and final result-to-row equality.

    Rejected alternatives

    • Replica-backed missing: rejected because lag can fabricate absence.
    • Lookup without the create lock: rejected because an uncommitted create can race a false not-found.
    • Opaque audit hashes: rejected because altered outcomes could remain structurally plausible without canonical command and result bytes.
    • Current-state command replay: rejected because later transitions must not rewrite the original result attributed to an earlier command.
    • Rejecting provider overage: rejected because it strands terminal truth; the user pays only the cap and the broker records its loss.
    • Transport in BRK-02: rejected because lease, retry, provider identity, and crash recovery belong to later qualified sprints.

    Out of scope and next sprint

    No HTTP API, authentication, signing key, receipt signature verification, worker lease, provider SDK, upstream request, retry, pricing evaluator, artifact storage, adapter qualification, resolver injection, merge, or deployment. BRK-03 may consume the exact conditional dispatch marker and operation identity, but may not weaken tenant/key serialization, rewrite terminal rows, or infer provider outcome from local state.

    Harness hint

    Race exact and conflicting creates against missing lookup, kill between row/command/audit writes, mutate coherent money outcomes, remove triggers, replay old commands after terminal advancement, exhaust file locks, and prove every uncertainty remains unavailable rather than missing.

    Execution seam

    Preserve this ledger as the only primary authority and execute BRK-03 without adding any provider transport to this module.
