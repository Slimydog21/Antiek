Master spec · ANT-ESP-01

Source Spine / Evidence Passport

Make source custody visibly survive Antiek’s Read → highlight → Chase → compose → Write loop without pretending that document identity is exact passage anchoring.

Ready1 serial sprintzero model calls2026-07-15

Spec lineage

Root spec derived from the operator’s professional-research workflow and the executed research-compose/Write chain. No child specs: provenance vocabulary, shared component, and three hosts are one tightly coupled visual contract.

  • No child specs.

Goal

The researcher should be able to answer, at every transition, “what source is this from, what exactly has Antiek verified, and what is still unresolved?” One compact, reusable HTML component renders that answer in Read selection, distilled research, and compose/Write receipt contexts.

Success criteria

  • Document identity, optional locator, custody state, and anchor precision are visually distinct—not compressed into one green “verified” badge.
  • A null chunk identifier is rendered as “exact passage anchor pending”; no ID or confidence is invented.
  • Raw document, investigation, chunk, and hash identifiers never become the primary user-facing label.
  • The existing highlight, Chase, compose, and Write actions remain behaviorally unchanged.

Failure mode to avoid

A beautiful provenance badge that launders “we know the document” into “we know this exact passage,” or a strip that displays unstable live metadata as though it were the immutable compose snapshot.

Architecture

host-owned facts document title? · locator? · document id? · chunk id? · custody event ↓ pure EvidencePassport view model (closed states; no fetch; no inference) ↓ shared semantic HTML strip SOURCE · LOCATOR · CUSTODY · PRECISION ↓ Read FloatMenu context · Distill grounding · Compose/Write source spine

Key invariants

  • The shared component presents facts; each host retains fetching, permission, selection, and action authority.
  • Visible source, hash reviewed, and exact passage anchored are separate states and may never imply one another.
  • Restricted/unavailable content can retain a safe title/custody label while never exposing withheld body text.
  • No model dispatch, spend, graph mutation, Werner event, route, game, raster, or runtime-generation dependency is added.
