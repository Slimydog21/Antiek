Build the evidence passport and mount the source spine

Give three existing workflow transitions one shared, truthful visual account of source custody and anchor precision.

Wave 1Ready5 milestonesOwner: primary executor

Parent context

Antiek already supports highlight actions in Read, inline/floating Chase, named claim sources in the synthesis viewer, immutable multi-research compose drafts, and zero-spend promotion into Write. Do not rebuild those capabilities. The gap is presentation continuity: Read knows the document but no chunk; Distill reduces known sources to generic copy; Compose exposes raw IDs/hashes before a count-only Write receipt.

The visual component has no authority. Host adapters provide already-known facts, permissions stay in existing APIs, immutable compose hashes remain server-owned, and actions remain in their current components.

Position: stacked after Home PR #2158 exact head 3336a51a3; avoid all Brainstorm, Home, Werner, atmosphere, scene, and global shell files.

Goal

Ship one semantic EvidencePassport component and use it to make source visibility, locator, custody, and precision inspectable at Read selection, Distill grounding, and compose/Write review.

The component must be visually distinctive enough to become part of Antiek’s trustworthy-instrument brand: a compact paper spine with explicit labels, never a generic green pill or decorative graph.

Rigor — operating manual

1 · Intellectual honesty

Write tests that distinguish document-known/chunk-null from exact anchoring. If a title comes from current list metadata rather than the immutable compose manifest, label it as display context and keep the server hash as custody authority; never round that up to snapshot metadata.

2 · Fairness

Steelman the raw-ID/hash view: it is exact and excellent for debugging. Preserve full hashes behind details, but reject them as the primary researcher label because they obscure rather than explain custody.

3 · Rigor

Mechanically exercise the state cross-product most likely to lie: restricted+named, known-document+null-chunk, unavailable+hash-reviewed, selection drift after preview, and reused compose. A screenshot of the happy state is insufficient.

4 · Diligence

Reuse MasterMdViewer’s gate-aware named-source semantics, FloatMenu’s optional host contract, and ComposeTray’s existing freshness checks. Do not create a second resolver, action menu, compose store, or color vocabulary.

5 · Defensibility

Record the exact mapping from each passport label to its source field and authority. Any new threshold, cache, or visual baseline must name its origin; document why “hash reviewed” never means “claim verified.”
