Cycle 33 / Cycle 34

Bedrock S3 namespace lease

Qualify a time-bounded invariant that the unversioned input key cannot be superseded, without claiming an observed Bedrock read or production readiness.

Status: executableLive AWS evidence requiredProduction: refused

Spec lineage

Cycle 33 proves one exact COMPLIANCE-retained version is immutable and current at verification. Bedrock accepts only an unversioned S3 URI. This child governs every route that can replace the current key during the requested lease.

  • A later child may wire independently administered live AWS evidence and production qualification only after operational key custody, revocation, audit, and renewal are proven.

Verdict

A bucket policy is necessary but insufficient. AWS documents that bucket policies cannot prevent S3 Lifecycle actions. Qualification therefore requires an exact key mutation deny, no lifecycle or replication configuration, and a separately administered organization lease that authenticates lifecycle-history clearance, validated guard semantics, alternate access-path denial, and data/control denial for the entire timeout-plus-margin window.

Threat model

  • Prevent new versions from PUT, copy, multipart completion, restore, and replication.
  • Prevent delete markers and current-version changes from delete and replication.
  • Prevent lifecycle expiration or transitions from acting on the prefix.
  • Prevent mutation or removal of bucket policy, lifecycle, replication, versioning, ownership, public-access, and Object Lock controls.
  • Bind exact account, bucket, prefix, key, workload, version, policy digest, organization guard digest, lease interval, and verifier identity.
  • AWS service compromise and organization-management-account compromise remain outside the software proof; the receipt names this trust root explicitly.

Truthful receipt

Canonical redacted JSON records version_immutable=true, current_for_lease=true, exact_key_mutation_denied=true, lifecycle_absent=true, replication_absent=true, independent_control_lease_verified=true, bedrock_version_selected=false, and bedrock_read_observed=false. The lease-backed future claim is limited to the exact Bedrock input key. The last two remain false because stable name resolution is not provider-read telemetry.

Protocol

  1. Read an injected trusted clock and require the caller observation time to match exactly.
  2. Parse and authenticate the independent lease before S3 reads; reject caller-generated or self-signed assertions.
  3. Require lease start at or before verification and expiry at or after Bedrock timeout plus publication margin; require publication retention at least through lease expiry.
  4. Fetch policy and every bucket subresource with expected owner; classify only documented not-found errors as lifecycle/replication absence.
  5. Canonicalize policy structurally, verify the exact mutation deny, and bind its digest to the lease and Cycle 33 profile.
  6. Reverify the Cycle 33 receipt last so current-key evidence is observed after static controls.
  7. Read the trusted clock again and recheck the complete time/retention window so evidence collection cannot silently consume the lease.
  8. Persist only the qualification receipt and digest. Reverify the complete lease before create/replay while the job can still consume input.

Acceptance

  1. Exact evidence deterministically yields one qualification receipt; any account, bucket, key, prefix, version, checksum, policy, guard, verifier, or time substitution changes identity or fails.
  2. Every missing mutation action, conditional deny, non-star principal, wrong resource, policy parse/canonicalization conflict, and policy-digest mismatch fails.
  3. Lifecycle/replication present, unreadable, ambiguous, or wrong error code fails.
  4. Suspended versioning, absent Object Lock, any false public-access flag, or non-enforced ownership fails.
  5. Expired, not-yet-valid, short, overlong, unsigned, wrong-scope, or incomplete independent lease fails.
  6. A version substitution before final reverify fails. A post-verification mutation is excluded only under the authenticated independent lease claim, not inferred from local observation.
  7. No production client factory, AWS credential source, organization signer, route, scheduler, worker, exhaustion, settlement, release, event, graph, or UI is added.

Official evidence

  • S3 bucket policies: bucket-policy denies do not stop Lifecycle.
  • Deleting S3 objects: deny both delete APIs and lifecycle-configuration mutation.
  • S3 replication permissions: replication uses ReplicateObject and ReplicateDelete.
  • S3 API permissions: PutObject authorizes PUT, copy destinations, multipart upload parts, and multipart completion.
  • S3 service authorization: canonical IAM action names include PutLifecycleConfiguration and PutReplicationConfiguration.
  • IAM policy evaluation: explicit denies override allows; SCPs and resource policies participate in effective permission.

Out of scope

No Terraform/CloudFormation, organization management account mutation, live credential discovery, automatic policy installation, Bedrock-read attestation, output ingestion, billing closure, production eligibility, exhaustion, settlement, or release. Static/test evidence cannot stand in for live independently administered AWS proof.

Harness hint

One builder implements strict canonical evidence and an injected verifier protocol. Critics attack policy semantics, not-found classification, trust-root self-assertion, lease timing, and final-reverify order. Require two sharpen rounds and HardenX.
