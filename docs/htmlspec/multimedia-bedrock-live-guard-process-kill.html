Cycle 38 / Cycle 39

Live guard process-kill certification

Prove durable forensic state and fresh-process recovery under real operating-system termination.

Status: executableSIGKILL matrixSimulation-only

Spec lineage

Cycle 38 explicitly leaves process-kill behavior unproved. This child certifies local SQLite and coordinator crash semantics using separate interpreters and real parent-issued SIGKILL. It adds no runtime hook, credential, network adapter, deployment, or production authority.

  • A future child may execute the same checkpoint protocol against an independently deployed account only after a concrete credential-provider and externally authenticated checkpoint transport exist.

Verdict

An exception is not a crash test. A child writes and fsyncs one checkpoint marker, then blocks without unwinding Python or SQLite. The parent observes that exact marker and sends SIGKILL. A new interpreter reopens the database and reports only integrity-verified facts.

Harness contract

PartExact behavior
ChildA test-only module accepts an absolute private root, one allowlisted mode, one allowlisted checkpoint, and an absolute marker path inside a separate private control root. It creates no shell, network, credential, production route, or caller-selected import.
CheckpointThe child exclusively creates and fsyncs one mode-0600 JSON marker containing schema version, mode, checkpoint, PID, command ID, and attempt ID, then creates and fsyncs a separate readiness token binding its SHA-256, PID, and checkpoint. It blocks in signal.pause() only afterward. Existing, linked, writable, substituted, or out-of-root control artifacts fail.
ParentThe pytest parent launches a fresh interpreter with a bounded environment and timeout, waits for the readiness token, opens both artifacts without following links, verifies owner/mode/link/inode/canonical bytes, checks digest and child PID, sends kill(), and requires a negative signal return code. Timeout, natural exit, wrong PID, wrong marker, or surviving process fails.
InspectorA second fresh interpreter opens the real Cycle 37 journal, runs full integrity traversal, reads exact intent when present, and emits bounded canonical JSON containing only counts, derived status, IDs, and false production capability.
RecoveryA third fresh interpreter invokes the real Cycle 36 coordinator over deterministic credentialless fakes and the same journal. In-progress attempts recover with their original nonce/start and current trusted evidence time. Completed attempts are reported historical and are not reacquired.

Acquisition matrix

Kill after intent and immediately before each deterministic fake boundary: each of four initial Organizations calls, attestation, qualification, each of four final Organizations calls, revocation observation, revocation verification, completion insert/commit, and post-commit acknowledgment. Every pre-commit case reopens as one in-progress attempt and a fresh interpreter reacquires the full protocol. Post-commit reopens as one exact historical completion.

Acceptance

  1. Every listed checkpoint is reached exactly once, fsynced, parent-killed, and observed as a negative signal exit. No injected exception or child self-exit counts.
  2. Every fresh inspector runs schema, trigger, index, SQLite, foreign-key, canonical artifact, scalar, and relationship verification before emitting state.
  3. All pre-intent-commit journal cases expose zero rows. All post-intent/pre-completion cases expose exactly one in-progress attempt. Post-completion commit exposes one exact completed receipt.
  4. Every in-progress acquisition kill recovers in another interpreter to the same attempt ID using current evidence time, not a frozen clock; the next inspection sees one completion.
  5. Recovery of completed history is refused without external calls. Re-running inspection never mutates bytes.
  6. Marker symlink, hard link, permissive mode, replacement, stale marker, wrong PID, unsupported checkpoint, timeout, natural child exit, malformed inspector output, and database corruption fail closed.
  7. The helper is test-only and cannot be imported by production multimedia modules. No SDK, credential, network, IAM qualification, independent-account claim, deployment, scheduler, route, production authority, settlement, release, event, graph write, or UI is added.

Five Values

  • Truth: only an observed OS signal death supports the crash claim.
  • Care: bounded timeouts and forensic inspection prevent hung CI and silent corruption.
  • Agency: checkpoint inventory and expected state are explicit data, not hidden timing assumptions.
  • Craft: fsynced handshake, fresh interpreters, exact byte reopening, and full traversal make the proof hard to vary.
  • Restraint: local crash durability does not imply cloud deployment safety.

Out of scope

No power-loss or kernel crash claim, disk-cache flush certification, filesystem matrix, Windows support, network partition, credential provider, independent AWS account, infrastructure deployment, live attestor, production daemon, route, billing closure, settlement, release, event, graph mutation, or UI.

Harness hint

Implement one test-only child CLI and one pytest orchestrator. The child uses production Cycle 36-38 code and deterministic existing fakes. Parent process owns SIGKILL. Require full checkpoint coverage, bounded waits, no production imports of the helper, two sharpen rounds, and HardenX.
