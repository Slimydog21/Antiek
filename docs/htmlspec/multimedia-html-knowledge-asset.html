Multimedia HTML Knowledge Asset

TT executable sub-spec. Stacked on PR #960. A completed media revision becomes a readable Antiek information asset and can enter canonical graph/twin authority without pretending the multimedia JSON store is itself the graph.

Five Values

  1. HTML is the information form: transcript, chapters, sources, disclosure, route, cost, and media manifest are available in deterministic standalone HTML.
  2. Owner is one fact: normalized authenticated owner, durable asset owner, envelope owner digest, and registration receipt must agree.
  3. Provenance remains exact: each spoken line carries exact cited chunk IDs; source rows preserve document, locator, and quote digest.
  4. No invented graph: projection is pure; only an injected canonical registrar may return graph-node and twin-document identities.
  5. Tamper evidence: HTML bytes are SHA-256 bound and every registration receipt repeats owner, asset, revision, and digest.

Registration Port

MultimediaKnowledgeRegistrar.register(envelope) -> receipt is the sole integration boundary. The caller verifies the HTML digest before invocation and verifies receipt owner/asset/revision/digest plus bounded graph/twin identifiers afterward. The port may later be implemented by Antiek's canonical graph event writer and recursive-note twin service; this sprint does not fork either authority.

Acceptance

  1. Hostile title/prompt/URI text remains inert and escaped.
  2. Wrong owner, non-ready revision, forged owner field, HTML tamper, receipt substitution, and invalid graph/twin IDs fail closed.
  3. Focused and complete multimedia tests, Ruff, strict mypy, HTML parse, diff-check, hardenx 0 REAL, and independent adversarial review pass.

Non-Goals And Next Seam

No live providers, spend, publication, frontend redesign, direct graph mutation, or fabricated twin content. Next, implement this port using the canonical event/graph writer and generate the twin's insight/question body through the existing research substrate.
