Resolve visual evidence from real authority records

Receipt IDs and rights labels become renderer authority only after durable-store and public-key verification.

Trust split

The runtime resolver holds an Ed25519 public verification key and a downstream packet-verdict key. It holds neither the operator private signing key nor the quarantine HMAC key. Operator issuance and runtime verification are therefore separate capabilities, not two names for one shared secret. Reviewer identities must also belong to the resolver's bounded allowlist.

Generated visuals

Production quarantine_artifact() creates the receipt. A separate operator step first verifies that receipt's canonical HMAC and exact private bytes, then signs an immutable receipt digest. The runtime resolves the explicit receipt columns, verifies the operator signature, reviewer, execution, media type, canonical path, size, and digest. A copy or hard-link alias is rejected.

Sourced and archival visuals

An operator signs one durable decision binding source-locator digest, content digest, canonical authority path, disclosure label, explicit rights basis, reviewer, and UTC decision time. Exact replay is idempotent; changed or concurrent conflict fails closed. The runtime verifies the signature and every selection binding before issuing downstream evidence.

Denied authority

Diagram selections remain denied until Antiek has a canonical graph-chunk resolver. No license is inferred from a URL, filename, provider payload, or model output.

Non-goals

No network calls, downloads, generation, spending, routing, publication, route mounting, UI, automatic license inference, or diagram approval.

Verification

Use the real quarantine producer; test signed-record tamper, wrong keys, unauthorized reviewers, copies, hard links, cross-execution and sourced-path substitution, model-copy bypasses, exact replay, threaded issuance/conflicts, strict types, complete multimedia compatibility, hardenx, and heterogeneous refutation.
