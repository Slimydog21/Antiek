Cycle 31 / Cycle 32

Bedrock pre-dispatch workload bound

Prove the reservation maximum from immutable workload bytes and exact rate arithmetic before any provider call.

Status: executableSchema: unchangedProduction: refused

Spec lineage

Cycle 31 proved that provider metering and account billing cannot establish exact final per-job invoice USD. Architecture review found that conservative authorization exhaustion could be honest only if the original reservation is first proven to be a maximum. Cycle 30 currently binds an S3 URI, opaque projection digest, arbitrary rate string, and caller integer; that is insufficient.

  • A future child may implement conservative authorization exhaustion only after this workload bound and a separate immutable S3 publication contract both pass.

Verdict

Do not exhaust, settle, release, qualify, or production-enable Bedrock in this cycle. Materialize one exact JSONL workload and a conservative maximum contract before dispatch. Bind both into the deterministic Bedrock request/submission identity. This proves what Antiek intended and reserved; it does not prove which bytes Bedrock read, what AWS billed, or that the AWS bill cannot exceed the Antiek ceiling.

Five load-bearing values

  1. Bytes before authority: the exact JSONL bytes exist before projection and their digest participates in every downstream identity.
  2. Maximum, not estimate: input uses the model context limit for every record and output uses each explicit request cap; expected usage, historical averages, and post-job metering cannot lower the reservation.
  3. Exact arithmetic: rates are canonical non-negative decimals per one million tokens and cents round upward once after summing all dimensions.
  4. One route identity: provider model, Antiek model, region, rate tier, workload, token ceilings, operation, hold, client token, and submission cannot be substituted independently.
  5. Refusal composes: a valid local contract does not imply immutable S3 publication, provider ingestion, billing settlement, result success, or production eligibility.

Canonical workload contract

Records

Accept a non-empty bounded sequence of objects containing exactly one unique non-empty recordId and one object modelInput. The selected model profile names the exact output-cap field. Reject floats, non-string keys, duplicate IDs, extra top-level fields, booleans as integers, excessive depth/items/text, and missing or out-of-range caps.

Bytes

Serialize each record as sorted compact ASCII JSON followed by one LF, including the final record. Persist no prompts in the spend ledger. Return immutable bytes only to the caller plus a redacted contract containing byte length, SHA-256, record count, ordered record-ID digest, and output-cap digest.

Profile

Bind provider model ID, Antiek model, region, rate tier, context-token ceiling, maximum records, maximum output tokens per record, output-cap field, and profile version/digest. Profiles are server-owned typed values, never request JSON.

Rates

Bind canonical input/output USD-per-million-token decimals, optional fixed request USD, currency USD, effective timestamp, source digest, and rate version. Reject negative, exponent, float, NaN, infinity, excessive precision, unknown currency, and stale/mismatched identity.

Maximum calculation

DimensionConservative rule
Input tokensrecord_count * context_tokens. Do not subtract requested output, infer tokenization, or use byte/token averages.
Output tokensSum the exact validated per-record output caps.
Variable USD(input_ceiling * input_rate + output_ceiling * output_rate) / 1_000_000 with arbitrary-precision decimal arithmetic.
Total USDAdd the server-owned fixed-request USD before rounding.
Reservation centsRound positive total upward to a whole cent once. Zero is allowed only when every bound rate and fixed charge is exactly zero and the route is explicitly non-paid.

The contract stores all operands, exact unrounded decimal USD, and resulting integer cents. Recalculation must be byte-stable.

Adapter binding

  • Add the canonical redacted workload-bound JSON and digest to BedrockBatchRequest. Its deterministic seed, client token, submission ID, hold operation digest, and adapter contract version must include the digest.
  • prepare() receives no free-form projection digest, rate string, or independently trusted projected cents for the bound path. It derives the projection digest and rate snapshot from the contract and either derives cents or requires an equality assertion that cannot influence authority.
  • Zero-cost explicitly non-paid bounds remain valid pure artifacts, but this paid Bedrock hold adapter must refuse them before ledger mutation.
  • The S3 input URI key must contain the workload SHA-256 as a full path segment. This is naming evidence only. Cycle 32 does not claim that the current S3 object is immutable or that Bedrock read those bytes.
  • Persist the redacted bound in existing immutable submission/hold intent surfaces; never persist workload JSONL, prompts, model input, credentials, role bytes, or raw source content in the spend ledger.
  • Advance and recovery re-open and revalidate the bound before any create call. Legacy Cycle 30 requests without it remain test-only and ineligible for conservative exhaustion or production.

Required public types

  • BedrockBatchModelProfile: strict server-owned model/context/output constraints.
  • BedrockBatchRateSnapshot: strict exact rate identity and canonical serialization.
  • BedrockBatchWorkloadBound: redacted immutable calculated contract with canonical JSON and digest.
  • materialize_bedrock_batch_workload(records, profile, rates): pure function returning (jsonl_bytes, bound).
  • BedrockBatchRequest bound constructor/path: validates URI digest segment and cross-model/region identity.

Acceptance criteria

  1. Same records/profile/rates produce byte-identical JSONL, bound JSON/digest, projected cents, client token, submission ID, hold intent, and create request across process/time/order-independent mapping construction.
  2. One changed prompt byte, record order, ID, output cap, context ceiling, model, region, tier, rate digit, fixed charge, effective time, source digest, or URI digest segment changes the appropriate identities and conflicts on replay.
  3. Input ceiling is exactly full context per record; output ceiling is exactly cap sum; exact Decimal calculation and one upward cent rounding match independent fixtures at zero, sub-cent, exact-cent, large, and maximum boundaries.
  4. Malformed JSON scalars, float values, booleans as caps, duplicate IDs, empty workloads, oversized records, unknown fields, excessive nesting, negative/exponent/over-precise decimals, overflow, and identity mismatch fail before ledger mutation or provider call.
  5. Caller-supplied lower cents, expected tokens, actual tokens, metering, CUR totals, tags, credits, refunds, taxes, or invoice claims cannot reduce or authorize the bound.
  6. Legacy unbound requests remain constructible only through an explicitly named test-authority compatibility path or are migrated in tests; no production registry or default runtime gains an adapter.
  7. All Cycle 30 identity/recovery and Cycle 31 billing-refusal tests remain green. Submission, hold, run, operation, billing assessment, event, graph, task, scheduler, and qualification state are unchanged by pure materialization.
  8. No AWS/S3 client, upload, HEAD, object-lock assertion, provider call, result ingestion, settlement, release, exhaustion, event, graph write, route, UI, task, or background worker is added.

Rejected alternatives

  • Exhaust the existing hold now: rejected because the current projected integer is caller-provided and not mechanically a maximum.
  • Use output manifest metering as the maximum: rejected because it is post-dispatch and cannot justify the original authorization.
  • Tokenize prompts locally: rejected for v1 because Bedrock model tokenization equivalence is not established; full context per record is looser but defensible.
  • Trust a content-addressed S3 key: rejected as publication proof because keys can be overwritten and Bedrock create does not select a version ID.
  • Ship a local zero-cost adapter instead: deferred to a sibling child; financially simpler, but it needs quality, resource quota, isolation, cancellation, and result-recovery contracts and does not close the paid Bedrock bound.

Likely files

substrate/multimedia/bedrock_workload_bound.py, substrate/multimedia/bedrock_batch_adapter.py, package exports, and focused tests. Avoid spend-ledger schema changes unless implementation proves the existing immutable intent cannot carry the redacted bound.

Out of scope

No S3 publication or verification, object lock, provider credentials/client factory, production registry, request dispatch from product routes, output-manifest download, result artifact, exact billing, observed spend, settlement, release, conservative exhaustion, qualification flip, events, graph projection, tasks, scheduler, background work, or UI.

Harness hint

One builder owns the pure typed workload/rate contract and adapter binding. A separate critic tries to lower the maximum through token estimates, output-cap omission, decimal rounding, model/region substitution, record reordering, legacy fallback, content-addressed-key overclaim, and caller-provided cents. Require two sharpen rounds and proof of zero provider/spend side effects.
