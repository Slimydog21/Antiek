SPR-01 · Wave 1 · ready

Make provider API keys genuinely first class

Goal: an authenticated owner can connect OpenAI or Anthropic, select an exact model for Talk-to-Book, execute without house fallback, see actual provider/model and held/available spend, rotate/delete the key, and make the stale authority unusable.

Parent context

Antiek already has owner-bound encrypted BYOK storage, a model registry, call-time key resolution, frozen request authority, and one production consumer. This sprint extends that existing path; it does not add global bootstrap keys or another router.

Technical milestones

  1. Add server-owned OpenAI and Anthropic catalog presets with exact provider-owned endpoints, current model IDs, pinned prices, source URLs, and expiry.
  2. Keep qualification REFUSED for provider hard ceilings; label Antiek’s enforcement as a local reservation.
  3. Expose presets through the existing Settings model inventory and password-field onboarding. Never accept endpoint, payer, credential ID, or owner authority from the browser.
  4. Register owner providers through the existing call-time decrypt mixin; verify endpoint, adapter kind, model, fingerprint, and owner immediately before send.
  5. Render provider-billed usage, held reservations, and available-to-authorize amounts without claiming a provider balance where no native balance API exists.
  6. Prove rotation/delete invalidates old frozen authority and a resolved provider cannot send with deleted/replaced ciphertext.

Files

runtime/research_runner/byot_provider_catalog.py, Settings model API/UI, focused catalog/settings tests, and the existing Talk-to-Book owner-model contract tests.

Five-values rigor

  • Intellectual honesty: the OpenAI/Anthropic rows may authorize local spend but must remain refused for provider-authoritative hard ceilings until idempotency and reconciliation are proven.
  • Fairness: retain custom endpoints for expert users, but do not label them certified or let them inherit first-party pricing.
  • Rigor: tests must mutate owner, fingerprint, endpoint, model, ciphertext, and adapter registration between selection and send.
  • Diligence: extend the model registry and BYOK store already in production; do not resurrect PR #3000’s process-global resolver.
  • Defensibility: every model and rate includes an official source and dated expiry so a future maintainer can distinguish stale pricing from invalid credentials.

Dependencies

Request authority contract; authenticated owner model registry; Talk-to-Book operation journal. No OAuth or provider partnership.

Out of scope

Consumer subscription login, house-key bootstrap replacement, arbitrary unqualified endpoints, and every-action UI rollout.

Verification gates

  • Owner A’s OpenAI/Anthropic key wins for the selected action and cannot be read or selected by B.
  • No-choice response remains byte-compatible.
  • Provider failure produces no house/config fallback.
  • Secrets are absent from HTTP, events, exceptions, logs, repr, and receipts.
  • Usage settlement is idempotent; unknown outcomes retain their hold.

Handoff packet

Return model/rate source snapshot, exact test commands, authority mutation matrix, screenshots of desktop/mobile onboarding, and any unverified provider behavior.

Harness hint

One builder, independent authority critic, then a second failure-boundary sharpen round.
