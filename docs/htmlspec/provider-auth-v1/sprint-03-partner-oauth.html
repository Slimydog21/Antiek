SPR-03 · Wave 3 · externally blocked

Implement web OAuth only with provider authority

Goal: activate a true Antiek OAuth connection only after the provider grants Antiek a registered client, documented scopes, inference entitlement, refresh/revoke contract, and written third-party permission.

Parent context

Native Codex, Claude Code, and Grok Build flows do not confer permission to impersonate their client registrations. PR #2997 is a useful mocked RFC 8628 experiment but must not ship: it copies Grok CLI identity, lacks owner-safe API/UI/refresh, and assumes an unverified inference endpoint.

Entry gates

  1. Provider-issued Antiek client ID/redirect registration.
  2. Documented scopes that explicitly cover third-party inference and billing identity.
  3. Written confirmation that Antiek may offer the flow to its users.
  4. Sandbox/test tenant and revoke endpoint.
  5. One live login plus minimal inference proving endpoint, model entitlement, usage identity, and logout.

Technical milestones after gates pass

  1. Implement state + PKCE or RFC 8628 using exact registered endpoints and bounded typed responses.
  2. Keep authorization/device code server-side, owner-bound, single-use, and expiring; browser receives only safe display fields.
  3. Atomically replace encrypted refresh/access bundles with generation/CAS locking; omit identity tokens unless identity verification requires them.
  4. Refresh at call time with rotation and crash recovery; never return tokens to the browser.
  5. Disconnect deletes Antiek custody and invokes provider revoke; UI explains any provider-console cleanup still required.
  6. Register an OAuth-specific provider adapter only for the verified inference protocol.

Five-values rigor

  • Intellectual honesty: absence of public documentation is not permission; this sprint remains blocked until all five entry gates have artifacts.
  • Fairness: provider denial or tier ineligibility must route the user to API-key onboarding, never to copied client credentials.
  • Rigor: state/PKCE replay, device-session theft, refresh races, rotation crashes, revoke failure, and cross-owner enumeration are mandatory hostile tests.
  • Diligence: use provider discovery and registered configuration; do not retain #2997’s broad *.x.ai pin or blocking 600-second poll.
  • Defensibility: preserve the provider approval, client registration, scope contract, live-smoke receipt, and revocation proof in the handoff.

Out of scope

First-party client impersonation, consumer cookie/token import, auth-file scraping, and calling API-key onboarding OAuth.

Verification gates

  • Owner isolation on begin/poll/status/disconnect.
  • Bounded one-shot polling; no worker sleeps for the grant lifetime.
  • Concurrent refresh yields one authoritative token generation.
  • All provider and HTTP errors are value-free.
  • Revoked/deleted/replaced bindings refuse before inference transport.

Handoff packet

Return every entry-gate artifact, registered redirect/scopes, threat-model results, refresh/revoke fault injection, and the opt-in live smoke.

Harness hint

Classify each provider as approved or blocked before any code execution; blocked providers produce no implementation branch.
