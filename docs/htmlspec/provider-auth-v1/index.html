Decision + execution spec · 2026-08-12

Provider authentication without borrowed identities

Antiek v1 will connect server-side inference through owner-scoped API keys. It will not copy consumer OAuth tokens, first-party client IDs, browser cookies, auth.json, or Keychain material. A future local harness may invoke official Codex and Claude processes while those processes retain custody of their own credentials.

Spec lineage

Root spec derived from the 2026-08-12 Antiek v1 brief and current provider documentation.

    Decision record

    Supported now

    OpenAI, Anthropic, xAI, DeepSeek, Kimi, GLM, and MiMo API keys. Keys are encrypted per owner, decrypted only at send time, and selected through frozen request authority.

    Supported later

    A user-owned local Codex/Claude harness. Antiek speaks typed local process protocols; official clients own login, refresh, logout, and secure storage.

    Prohibited

    Routing Claude Pro/Max credentials through Antiek, impersonating Codex/Grok CLI registrations, importing provider credential files, or presenting subscription OAuth as API billing authority.

    Why this differs from T3Code

    T3Code does not implement OpenAI or Anthropic OAuth. It launches official Codex app-server and Claude Agent SDK/CLI processes. That architecture is safe inspiration for a local harness, but its users’ subscription tokens are not reusable bearer credentials for Antiek’s direct REST adapters.

    Rejected alternatives

    Copy the xAI Grok CLI client ID: rejected because it impersonates a first-party registration and its OAuth inference endpoint differs from api.x.ai.

    Read Codex/Claude credential files: rejected because it breaks provider custody, refresh, revocation, and account-isolation guarantees.

    Call Claude with Pro/Max OAuth: rejected because Anthropic explicitly prohibits third-party routing of consumer subscription credentials.

    Wait for OAuth before shipping keys: rejected because documented provider API keys already satisfy the server-side product and keep payer authority legible.

    Open assumptions

    • Antiek remains a server-hosted web product for v1; local harness work is optional and must not silently spend the operator account for friends.
    • No provider partnership/client registration currently exists. Sprint 03 is blocked by external authority, not engineering effort.
    • Model pricing snapshots expire and must be refreshed independently from credential validity.

    Executor hint

    Execute sprint 01 now. Classify sprint 02 by deployment topology. Keep sprint 03 dormant until its external gates are evidenced.
