Autonomous diligence activation

Flagged concepts, open questions, and key insights become autonomously diligenced: a one-click flag writes a queue row, the existing continuous daemon — which today scores and stops — gains its spawn wiring through the orchestrator’s own capped launch path, behind hard caps, a no-deploy kill switch, and a prod-safety gate that ships DISABLED.

    Goal and proof boundary

    Success is: an operator flags an open question from a research artifact; the flag appears in a calm queue rail; the daemon — on its next iteration, inside hard caps — spawns a real child investigation through the SAME capped launch path every other spawn uses; the investigation appears in the monitor with the existing “found by the loop” badge; the queue row transitions queued → spawned → done with a receipt of why. And: with the kill switch off (the shipped default), the daemon is byte-for-byte its current self — it scores and stops.

OWNER FLAGS (explicit human request — always outranks) 2. scored gaps ≥ threshold (existing scoring, existing dedupe — untouched) → caps checked (per-spawn $2 · daily $5 · 3/iteration · concurrency · depth) → spawn_fn emits investigation.start_requested via the broadcaster — the EXACT mechanism chase mode uses (orchestrator.py:2355-2375) → the orchestrator's ONE start handler runs it (caps, tier, chase params) → badge "found by the loop" flows to existing surfaces · queue shows the receipt

    The gap, with evidence

    Evidence-gap flagging and scoring EXIST and are read-only honest: orchestration/continuous/scoring.py:1-21 scores gaps recency × co-occurrence × operator-interaction with a chase-exhaustion decay (MAX_CHASE_COUNT = 3, :38; score_gap :198); the suggestions surface is deliberately pure read (orchestration/continuous/suggestions.py:1-57 — “surfacing costs nothing”, deduped two ways against already-chased gaps, :25-31) behind GET /research/suggestions (interfaces/research/api/cascade_routes.py:569-570, read-only invariant :575); the client renders them (getSuggestions apps/reading/src/api/research.ts:226, SuggestedResearch.tsx:11-40 — no auto-launch, launch = the existing capped path) and daemon-spawned research already carries a translated badge (spawned_by_daemon lib/api.ts:375-380, rendered at MyResearch.tsx:457, ConnectResearch.tsx:207).

    But the prod daemon never spawns. Its own docblock says so: the default no_op_spawn returns None, “no live spawning until that wiring lands” (daemon.py:9-15; SpawnFn :49, no_op_spawn :52); the CLI entrypoint calls run_forever(config=config) with NO spawn_fn (daemon.py:324-334), so the spawn call inside the iteration (:253) is dead code in production. It scores and stops. Meanwhile the orchestrator’s chase mode ALREADY auto-spawns child investigations from the strongest open question with depth/duration/budget halts (orchestrator.py:549-554 chase params, :2248-2270 question selection, :2273-2375 halt-or-spawn, investigation.chase_halted emitted at :2337, terminal-honest as stopped per app.py:3026-3033) — and its spawn mechanism is not an HTTP call but an emitted investigation.start_requested event through the broadcaster (:2355-2375, policy_id="orchestrator-chase"), which the orchestrator’s ONE start handler picks up and runs with every cap threaded (:2083-2096). And nowhere in the product can an operator flag a concept for diligence — flagged concepts are not first-class objects anywhere. The queue, the wiring, and the flag are the three missing pieces; everything they connect already exists.

    Key invariants

    • Flags outrank scores: a flag is an explicit human request; every daemon iteration drains eligible flags (oldest first) before considering scored gaps. A scored gap can never preempt a queued flag.
    • Caps are hard and config-driven: per-spawn $2.00 (budget.py:32), daily $5.00 (:36), 3 spawns/iteration (daemon.py:63), topic depth 5 (budget.py:34), plus the new concurrency cap (default 2 in-flight daemon investigations). A cap failure is an honest investigation.chase_halted-class event, never a crash, never a bypass.
    • Kill switch without deploy: ANTIEK_DAEMON_SPAWN_ENABLED (default unset = OFF). Off ⇒ run_forever receives no_op_spawn — the current production behavior, bit-for-bit. The activation config SHIPS DISABLED; enabling is an explicit operator act (prod-safety gate).
    • Refs-only queue: a queue row carries kind, the object’s stable ref (node id / normalized concept key), an optional short note, source investigation/document ids, and status — never the object’s text beyond its ref, never book body, never thread content.
    • Gate-safe seeds unchanged: a flagged object whose source is non-servable/withheld spawns only with what the existing gate-safe spawn paths lawfully carry (the spin-research rule, unchanged). The queue never becomes a side channel for withheld text — enforced at flag-write time, not at render time.
    • Suggestions stay suggestions: the read-only surface (suggestions.py:1-57) is not edited; an operator who never flags sees zero behavior change beyond the queue rail’s presence.
    • Writer-lock discipline: every daemon write follows the batch-and-yield convention (arxiv_oai_sync.py:44-47,105-107) — short scopes, bounded hold, no lock across iteration sleep or spawn waits.

    SPR-02 · Daemon activation — spawn_fn, priority, caps, kill switch

    Contract. Wire daemon.py:334: when ANTIEK_DAEMON_SPAWN_ENABLED is truthy, run_forever receives a real spawn_fn; otherwise no_op_spawn (shipped default). The spawn_fn emits investigation.start_requested through the event broadcaster — the chase mechanism’s exact shape (orchestrator.py:2355-2375) with policy_id = DAEMON_SPAWN_POLICY_ID (suggestions.py:48) — arriving at the one start handler (:2083-2096) so runner caps, tier, and chase-halt semantics apply unchanged. Candidate order per iteration: (1) owner flags — queued rows, oldest first, each spawned as a child of its source_investigation_id when present (else a cold start with the object as question), with spawned_investigation_id written back and status → spawned in the SAME short write scope; (2) scored gaps ≥ min_score_to_spawn (daemon.py:64) via the existing scorer, untouched. Caps, all hard: DaemonBudget.reserve per spawn (budget.py:146-175 — $2/spawn, $5/day), 3/iteration (daemon.py:63), topic depth 5 (budget.py:34), and a new config max_concurrent_daemon_investigations (default 2) counted read-only from in-flight investigations carrying the daemon policy id. Dedupe: skip flags already spawned/dismissed, gaps already chased (both existing dedupe paths, suggestions.py:25-31), and any candidate whose normalized question matches an in-flight investigation. Every daemon write (status transitions, spawn bookkeeping) holds the write lock in bounded scopes per the arXiv lesson (arxiv_oai_sync.py:44-47,105-107) — never across an iteration, never across the broadcast wait.

    Proof (real calls):
    • Daemon iteration tests (the existing run_one_iteration seam, daemon.py:186): a queued flag produces exactly one emitted investigation.start_requested with the daemon policy id and the flag’s question — asserted on the emitted payload, against a real event-log fixture; the row transitions to spawned with the investigation id in the same scope.
    • Priority: one flag + one higher-scored gap in the same iteration ⇒ the flag spawns first (order asserted on emitted events).
    • Caps: per-spawn reserve failure ⇒ zero emission + honest halt event; concurrency at cap ⇒ zero emission with a skipped-reason receipt; the daily-cap path (budget.py:166-175) exercised with a fabricated sidecar.
    • Kill switch: env unset ⇒ the iteration emits nothing and matches today’s no-op behavior byte-for-byte (the current daemon test suite passes UNMODIFIED); env set ⇒ spawns flow.
    • Dedupe: an already-spawned flag, an already-chased gap, and an in-flight question match each produce zero emission (three distinct tests).
    • End-to-end through the REAL launch path: a flagged concept against a test server running the orchestrator handler results in a real investigation row carrying spawned_by_daemon server-side.

    Non-goals: the receipts view polish (SPR-03), scoring/threshold changes, cap re-tuning, flag UI (SPR-01), any change to the orchestrator handler itself.

    SPR-03 · The loop closed — statuses, receipts, operator visibility

    Contract. Status completion: spawned → done when the spawned investigation reaches a terminal event (investigation.completed | .failed | .chase_halted — the terminal set the monitor already trusts, cascade_session.py:21), projected from the event log on queue read (no poller of the daemon’s own; the projection is read-only and lazy). Receipts: each queue row exposes WHY — for spawned: the spawn iteration’s receipt (which caps were checked, the reserve amount); for skipped candidates an honest skip reason (cap hit, dedupe, concurrency) recorded as daemon bookkeeping in the same bounded write scopes; the rail surfaces “what the daemon did and why” per flag, and a calm summary line (“2 flags diligenced this week · $1.03 of $5.00 daily cap”) sourced from the budget sidecar (budget.py:63-64) and the event log — never from new counters. Spawned investigations flow into the existing surfaces unchanged: monitor rows with the translated badge (lib/api.ts:375-380), MyResearch (MyResearch.tsx:457), artifact/twin-notes flows. Terminal-honest: a budget-halted spawn reads stopped (app.py:3026-3033), and its flag reads done-with-honest-outcome, never “running”.

    Proof (real calls):
    • Projection test: a spawned flag whose investigation completes (fixture events) reads done on GET; a failed one reads done with the honest failed outcome; a chase_halted one reads done/stopped — never in-flight forever.
    • Receipts: a cap-skipped flag carries the skip reason; a spawned flag carries the reserve receipt (amount + caps checked) — both asserted from real store rows after a real iteration.
    • Rail end-to-end: flag → iteration → spawned with badge-visible investigation → terminal → done, rendered at each step (vitest over the rail against the test server).
    • The summary line’s numbers reconcile against the sidecar + event log fixtures (no parallel counters — a test greps the implementation for new spend counters and finds none).
    • Operator-who-never-flags: with the kill switch off and no flags, the system is indistinguishable from today (suggestions identical, daemon idle) — asserted by the unchanged suites plus a suggestions-parity test.

    Non-goals: notifications/pushes on completion, retry policies, flag re-queueing, cross-owner visibility, analytics dashboards beyond the rail.
