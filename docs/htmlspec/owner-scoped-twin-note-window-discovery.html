CYCLE 50

Owner-scoped twin-note window discovery

Replace opaque asset and window ID entry with a navigable owner-derived candidate surface while preserving Cycle 49 preview/apply as the only creation authority.

Spec lineage

Parent: Cycle 49 twin-note creation and Write import. Evidence authority remains Cycle 47 V21 compression. This cycle adds a pure advisory read model, not a capability.

Outcome

An authenticated operator can browse every bounded owner-derived document/investigation binding, distinguish deeply valid completed V20 windows from safely classified owned exclusions, assemble an explicit ordered selection, preview it through Cycle 49, and apply only that frozen preview. No caller submits an owner, asset, investigation, window, limit, cursor, sort, or search value to discovery.

Five values

Precision

Asset identity comes from the document primary key; investigation authority comes from the same-owner notebook binding; eligibility comes from the shared V20 row validator.

Exhaustiveness

Owner mismatch, duplicate notebooks, every V20 state, digest drift, malformed/canonical JSON, cross-field drift, invalid note output, bounds, concurrency, and stale UI responses are covered.

Craftsmanship

One row validator feeds discovery, preview, apply, and compression. One owner-derived snapshot feeds each discovery response. No weaker parser or per-row connection exists.

Honesty

Discovery is advisory. Individually eligible windows may still fail aggregate preview; evidence changes require refresh and never auto-rebase or auto-apply.

Information

The operator sees stable asset labels, investigation/window identity, order, note/source counts, and useful reasons for owned exclusions without seeing raw evidence or foreign existence.

HTTP contract

GET /research/twin-notes/revision-candidates

200 {
  assets: [{
    asset_id, asset_label,
    windows: [{window_id, investigation_id, consumer_version,
               window_ordinal, note_count, source_count,
               eligibility: "eligible" | "excluded",
               exclusion_reason: null | "evidence_incomplete" |
                 "evidence_digest_mismatch" | "evidence_noncanonical" |
                 "evidence_binding_mismatch" | "evidence_output_invalid"}
    ], truncated
  }],
  truncated,
  limits: {assets, windows_per_asset, total_windows, selection_members}
}
  • The route accepts no query or body identity. Unknown query parameters return one value-free private no-store 422.
  • Account derives only from authenticated request.state.user_id. Empty and foreign-only databases return the same 200 body for that account.
  • Every response, including 401/409/422/503, is Cache-Control: private, no-store. Bodies contain no submitted values, owner IDs, raw/request/source JSON, source IDs, digests, provider/model/policy, attempts, uncertainty, timestamps, paths, or hidden totals.
  • Global schema/snapshot/invariant corruption fails the whole GET with one value-free integrity conflict. Candidate-local evidence corruption becomes one safe exclusion only after the complete owner join succeeds.

Owner derivation

documents d
JOIN notebooks n
  ON n.document_id = d.document_id
 AND n.owner_user_id = d.owner_user_id
JOIN note_taker_windows w
  ON w.investigation_id = n.investigation_id
WHERE d.owner_user_id = authenticated_account
  AND n.owner_user_id = authenticated_account
  AND n.document_id IS NOT NULL
  AND n.investigation_id IS NOT NULL
  • documents.investigation_id, window request metadata, labels, and caller input never establish authority.
  • Duplicate notebook bindings deduplicate by exact (asset_id, investigation_id, window_id) before limits. A window legitimately bound to two owned assets appears under both.
  • Asset order is document_id; window order is (investigation_id, consumer_version, ordinal, window_id). Titles and timestamps never affect identity or order.
  • Empty titles use a fixed display fallback. Labels are bounded and display-only.

Shared eligibility

Extract Cycle 49's row checks into one pure validate_window_evidence(row) primitive. build_window_admission invokes it for every ordered member and retains aggregate deduplication/ceilings; discovery invokes it on owner-derived rows in the same read snapshot. It verifies completed state, stored raw output, all source/request/raw digests, canonical JSON, non-empty string source IDs, request investigation/source cross-fields, parser validity, and note source attribution. Discovery counts only validated parser output. There is no Cycle 50 parser, digest implementation, or SQL-only eligibility shortcut.

Safe reasonClassification
evidence_incompleteNon-completed state or missing raw output/raw digest.
evidence_digest_mismatchSource, request, or raw digest mismatch.
evidence_noncanonicalMalformed or noncanonical source/request JSON.
evidence_binding_mismatchRequest investigation or source list differs from stored authority.
evidence_output_invalidRaw note output or attribution fails the canonical parser.

Purity and bounds

  • A dedicated discovery service opens one read-only connection and never constructs workflow/compressor services, initializes or repairs schema, opens a writer, accesses publication files, dispatches/reconciles events, calls a provider/model/network, or schedules background work.
  • Fixed constants bound assets, windows per asset, total owner-derived deduplicated windows, raw bytes validated per candidate, and returned label bytes. Limits apply after owner filtering and notebook deduplication. Foreign rows never consume capacity.
  • Discovery reads one extra canonical row at each bound only to set truncated, emits deterministic prefixes, and exposes no exact hidden total. Validation stops at the bounded prefix.
  • Repeated GET over unchanged state is byte-identical. Concurrent writes cannot mix snapshots in one response.

Workstation

  • Replace raw asset/window text inputs with an owner-derived asset selector and candidate list. Eligible windows use Add; excluded owned rows are disabled and show concise mapped reasons.
  • An ordered selection tray exposes move up, move down, and remove. Clicking Add appends in click order; duplicates are impossible.
  • Asset change, add, remove, reorder, and discovery refresh invalidate preview and rotate the apply command key. Preview receives the exact selected asset and ordered IDs.
  • Discovery never enables Apply. Only a successful Cycle 49 preview does. Stale preview retains selection and offers refresh; ambiguous apply retains exact selection, predecessor, digest, and key.
  • Async discovery and preview responses carry request-generation identity so late responses cannot overwrite newer asset/selection state. Discovery, preview, apply, import, compose, history, opening, refresh, and selection controls share the global freeze.
  • Successful apply refreshes history and discovery, then exposes the exact revision without silently changing the successful command beforehand.

Acceptance

  • Signed two-account fixtures with equal titles, investigations, ordinals, and similar window IDs prove strict separation. Foreign-only and empty-owner responses are byte-equivalent.
  • Notebook-only, document-only, mismatched-owner, null-binding, and duplicate-binding fixtures prove the complete join and deduplication. No route input can probe an identity.
  • Every returned eligible singleton succeeds in Cycle 49 preview without mutation. Each V20 corruption class maps to its exact safe exclusion; excluded foreign rows never appear.
  • Instrumentation proves discovery and admission call the same row validator and no parallel parser/digest logic exists.
  • Database byte snapshot, writer/schema/filesystem/provider/model/event seam guards, repeated-byte equality, and concurrent snapshot tests prove GET purity.
  • Adversarial insertion order, equal labels, exact/over bounds, foreign capacity, bounded validation-call count, and deterministic truncation tests prove ordering and resource ceilings.
  • Frontend tests prove no raw ID fields, owned asset/window display, disabled exclusions, click-order selection, reorder/remove, exact preview call, every invalidation, stale/ambiguous retry behavior, late-response refusal, global freeze, successful refresh, and Cycle 48/49 regressions.
  • Authoritative twin-note backend suites, focused frontend suites, TypeScript typecheck, production build, changed-Python compilation, diff hygiene, hostile review, and strict security gate pass.

Rejected alternatives

  • Asset-parameterized GET: creates a guessed-ID oracle and makes absence/error behavior part of authority.
  • Use existing twin-note revisions as asset discovery: hides owned assets that have eligible windows but no revision yet.
  • State equals completed: ignores the cryptographic, canonical, cross-field, and parser authority.
  • Expose digests/timestamps/provider details: unnecessary for selection and leaks internal evidence metadata.
  • Per-row validator connections: mixes snapshots and multiplies database work.
  • Automatic preview/apply: converts advisory discovery into mutation authority and removes explicit operator intent.
  • Keep raw IDs as primary UI: preserves the exact workflow gap this cycle exists to close.

Harness hint

Build one pure row validator, one owner-derived snapshot service, and one request-generation-safe selection UI. Use separate owner-oracle, validator-equivalence, purity/bounds, UI-race, and regression critics.
