MSR-02A: Receipt Identity Closure

Parent MSR-02

Spec lineage

Leaf sprint under MSR-02.

    Contract

    Read the current owner-scoped asset, require its current video production link, reopen the exact receipt through VerifiedPlaybackRuntime, verify current video/audio bytes, then compare every production-link field to fresh metadata. Return the receipt only inside the backend authority boundary.

    Refusals

    • No production link, stale revision, wrong owner, audio-mode asset, receipt digest mismatch, media digest mismatch, dimension/duration/chapter mismatch, unsafe file, malformed nested artifact, or changed bytes.
    • No fallback to a receipt discovered only by asset/revision when the current link disagrees.

    Tests

    • Happy path reopens one exact receipt.
    • Each link field conflicts independently.
    • Receipt and media mutation, symlink, owner mismatch, and revision advance fail.
    • The function performs no writes and makes no provider call.

    Out of scope

    Visual selection identity, narration-run discovery, cost settlement, and publication.

    Five-values rigor

    The link is not decorative metadata: removing any compared field must make a negative test fail.

    Harness hint

    Implement a narrow public verified-receipt reader, then refute every link-to-receipt binding.
