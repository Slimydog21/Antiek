Owner-private output compliance and isolated sinks

Define a genuinely new capability-v2/receipt-v5 lane that turns exact returned bytes into a recomputable owner-bound compliance receipt, then permits only encrypted owner-private HTML, evidence, twin/context, and graph effects—without opening transport, generic deposits, public/export/training paths, or reinterpreting the deny-all v1 lane.

1. Falsifiable goal and repository truth

Goal: given exact canonical role-output bytes in volatile memory, the role-appropriate ordinal OwnerPrivatePublicationSourceReceiptV5 roster, the exact stage-plan-derived predecessor receipt/taint roster, one closed harness response receipt, and a live signed PrivateProviderProcessingCapabilityV2 that directly binds output policy v2, recompute the role’s frozen compliance rule and atomically persist a PASS receipt plus verified taint v2 before any durable generated byte. Every allowed sink independently repeats the owner/policy/output/topology join at its final compare-and-swap boundary.

Current plumbing is not an upgrade target. Generic stage checkpointing writes plaintext into both effect evidence and job JSON before compliance; rejection receipts persist content-derived hashes; generic deposit, session flywheel, and graph projection copy raw output into unscoped stores. They must resolve durable job/stage/effect authority and reject owner-private provenance even if a caller strips a type or content-class field. Optional fields or private=true do not repair readers, recovery, telemetry, or partial writes.
Version boundary: capability v1, policy v1, receipt v4, prepared envelope v1, and taint v1 remain byte-identical and authorize zero durable generated-byte sinks. V1 contains no successor or amendment key; no new signature can override it. E introduces new hash/signature domains for capability v2, policy v2, receipt v5, prepared envelope v2, harness response receipt v1, compliance receipt v1, and taint v2. Capability v2 is verified by the existing configured offline capability-issuer trust root under a distinct key-purpose/domain and directly pins policy v2. Its rollback-floored live revocation registry covers v2 hashes. Existing v4 material may be used only as a negative/cross-version test input.

The overlap thresholds below are a conservative product-control baseline, not a legal safe harbor or proof that an output is non-infringing. Changing normalizer, extractor, checker, corpus, or thresholds requires a new policy identity and newly issued capability v2.

4. Normative OverlapCheckerV1

4.1 Closed extraction, traversal and provenance

  1. Accept exact bytes only. Check the byte cap before strict UTF-8 decode; reject BOM, duplicate JSON names at any depth, NaN/Infinity, trailing whitespace or a second value, unknown fields, coercion, wrong role discriminator, and any upstream parser detail. Revalidate the closed role model, serialize with sorted keys, compact separators and Unicode unescaped, and require byte-for-byte equality. The aggregate validation-JSON-schema hash, declared field-order material, and exact live_roles.py code hash are parser/checker identity, so custom uniqueness, cross-field, cardinality and aggregate-size validators cannot drift under an unchanged policy. Before exemptions, the compliance caller must complete the role-specific receipt/topology semantic joins; identifiers that merely satisfy a string schema are not trusted structural data.
  2. Traverse the validated role model in declared schema-field order, tuples by ascending numeric index, never canonical wire-key order. Root depth is zero and every field/index edge increments depth; the maximum visited value depth is 32. RFC 6901 escapes ~ as ~0 then / as ~1. Exempt patterns are compared as pointer-segment tuples and * matches exactly one numeric array segment. Every non-exempt string is a content leaf, including an empty string, and counts toward 256. Normalize each content leaf independently; concatenation assigns global content-token indexes but never creates a denominator token. Thus a contiguous run cannot cross a leaf while fragmented unions retain both sides. HTML/Markdown remains raw lexical text.
  3. SourceExtractorV1 accepts only an internally resolved receipt-v5 owner_supplied_local_excerpt_utf8_v1 DTO produced after exact CoreV2/V5/V4 owner, role, stage, effect, policy, extractor, ordinal, byte-length and digest joins. Checker ordinals must be exactly 1..N in roster order. Bytes come only from the committed local excerpt; no metadata field, refetch, rerender, entity decode or media expansion is permitted. Planner requires zero sources and returns not_applicable without invoking matching; every non-planner requires one through eight sources.
  4. Comparison order is literal NFKC → full casefold → NFKC → CR/LF-to-space → frozen whitespace/quote/dash mapping → frozen default-ignorable+bidi removal → tokenization. Both NFKC stages use the Unicode 16.0.0 UAX #15 attributed-scalar algorithm: recursively apply compatibility decomposition (including algorithmic Hangul), retain each emitted scalar’s ordered original half-open UTF-8 span set, perform stable canonical combining-class reorder, then canonical composition with the UAX blocking and Hangul rules while unioning contributor spans. Casefold/map expansions inherit their input span set; composition unions, reorder preserves, and removal drops contributor sets. The produced string must equal the locked runtime’s whole-string transform at each stage or offset-map failure rejects. Per-codepoint normalize(), prefix-quadratic normalization and covering a removed gap as matched provenance are forbidden.
  5. Token provenance is an ordered, sorted, coalesced tuple of disjoint half-open spans relative to the decoded leaf re-encoded as strict UTF-8; source provenance is relative to exact committed source bytes. Tokens are maximal Unicode category L* or N* runs and carry the union of contributing scalar spans. Unmapped C0/C1 controls, NUL, surrogates, noncharacters FDD0..FDEF or any scalar ending FFFE/FFFF, invalid UTF-8, non-monotone spans, or empty aggregate normalization reject. CR and LF are mapped individually to spaces; whitespace runs are not collapsed. Unicode version, table hash, exhaustive mapping/removal tables and attributed-normalizer algorithm identity are checker material.
  6. Bounds are policy material: at most 1,000,000 output bytes, eight sources, 32,000 bytes/source, 256 content leaves, value depth 32, 200,000 output tokens, 256,000 aggregate source tokens including every duplicate ordinal, 100,000 canonical match rows, 25,000,000 candidate pairs, and 1,000,000 canonical ledger bytes. Candidate pairs are computed before matching as sum(content_leaf_token_count × source_token_count) across every leaf and every ordinal; boundaries are absent and duplicates count. Exceeding any bound raises one fixed content-free rejection with no partial result.

4.2 Exact start-anchored enumeration and thresholds

For every equal (output_start, source_ordinal, source_start) pair inside one output leaf, emit exactly one start-anchored row whose length is the longest equal-token prefix from that pair—even if the row can extend left or is contained by another row. Unequal starts emit no row. Therefore output [a,a,a] against source [a,a] emits the six exact tuples (0,1,0,2), (0,1,1,1), (1,1,0,2), (1,1,1,1), (2,1,0,1), (2,1,1,1). Sort by (output_start, source_ordinal, source_start, descending_length); preserve every overlapping and subsumed row. Duplicate exact source bytes retain every ordinal’s rows and per-source arithmetic but the lowest ordinal alone represents that byte sequence in all-source unions; normalized-equal but byte-distinct sources remain distinct. Derive fragmented coverage from rows of at least two tokens and isolated-token mosaic coverage from rows of exactly one token, including a position also present in a longer row; count each output position once per measure. PASS requires every strict inequality:

MeasurePASS boundaryFAIL boundary
Any contiguous run (independent leaf tokenization breaks adjacency)< 12 tokens≥ 12 tokens
Per-source fragmented coverage from runs ≥2< 24 tokens and < 20% of output≥ 24 or integer test 5×covered ≥ output_tokens
All-source fragmented union from runs ≥2< 32 tokens and < 20% of output≥ 32 or 5×covered ≥ output_tokens

Repeated fragments count each covered output location once; the same span matching multiple sources contributes once to union coverage while retaining all private diagnostic rows. The fragmented rule catches unique four- and two-token copying; the isolated-token rule catches one-token mosaics only when they dominate the output. No threshold short-circuit may omit a bounded ledger row.

4.3 Canonical private match ledger

The PASS-only ledger is compact sorted-key Unicode-unescaped JSON. Its digest is exactly SHA-256(b"antiek.midnight-oil.owner-private-overlap-ledger.v1\0" + ledger_bytes); no length prefix, second canonicalization or alternate framing is allowed. The closed top-level fields and types are: schema_version: 1, lowercase-hex checker_sha256, nonnegative integer output_byte_count, nonnegative integer output_token_count, ordered source array sources, nonnegative integer candidate_pair_count, ordered row array rows, closed object metrics, and literal lowercase verdict: "pass". Each source object is exactly {ordinal:int 1..8,source_byte_count:int 0..32000,source_token_count:int 1..256000,representative_ordinal:int 1..8}, ordered by contiguous ordinal. Each row is exactly {output_start:int,output_end:int,output_pointer:str,output_origin_spans:[[start,end],...],source_ordinal:int,source_start:int,source_end:int,source_origin_spans:[[start,end],...],run_tokens:int}; each origin-span array is the sorted/coalesced union of all token-origin spans in that row, not a per-token nested array. All coordinates are nonnegative, ends are exclusive, each span has end>start, span arrays are strictly ordered/disjoint, and output_end-output_start == source_end-source_start == run_tokens > 0. Metrics has exactly max_contiguous_tokens:int, per_source_fragmented_tokens:[[ordinal,count],...] in source order, all_source_fragmented_tokens:int, isolated_union_tokens:int, and match_row_count:int. All counts are nonnegative JSON integers, never strings/floats; candidate_pair_count == output_token_count × sum(source_token_count), candidate pairs are ≤25,000,000, and rows/count are ≤100,000. The one-megabyte cap covers the entire top-level ledger bytes. Ledger bytes, digest, pointers, spans and metrics never enter logs, errors or routine representations. Rejection returns no ledger or digest.

Golden corpus: a strict discriminated executable corpus must provide canonical role bytes, ordered exact source bytes and exact expected tokens, pointers, disjoint spans, six-row repetition oracle, coverage, verdict, full ledger bytes and the exact domain-prefixed digest. Unit vectors may retain direct threshold/bound observations, but every declared behavior must also execute through production primitives; unknown/missing fields reject and two independent runs must be byte-identical. The current declarative corpus remains bound only as golden_corpus_sha256, while the current contract/policy binds executable_corpus_sha256=null and execution_ready=false; a successor contract version must bind a non-null executable corpus before checker execution. Checker, extractor, normalizer, ledger and successor-corpus identities are independently bound.

5.1 Sealed decrypt authority

Private stores expose no general decrypt method and never return a naked str, bytes object, role model, generic WorkerStepResult, or caller-controlled callback plaintext. A terminal operation accepts a store-resolved OwnerPrivateSinkCapabilityV1 containing a CSPRNG handle, real owner scope, checkpoint/provider_effect_key, literal sink purpose, row revision, key version, exclusive expiry, and HMAC/signature under a process-private sink-authority key. The store selects one implementation from a closed store-owned OwnerPrivateSinkAdapterV1 registry keyed by that literal purpose and an adapter-contract hash pinned by OutputPolicyV2. Each reviewed adapter is terminal—checkpoint comparison, encrypted child materialization, owner-authenticated HTTP body stream, or encrypted graph write—receives plaintext only inside the store boundary, and returns only a closed content-free proof. The HTTP adapter streams to an already authenticated private response; it does not return body bytes to route code. Adding/substituting an adapter requires new policy/capability identity. Import/lint boundaries forbid adapters from importing generic engagement, artifact/export, event/log/bench, training, WorkerStepResult, public graph writers, or accepting arbitrary callables. Generic sinks require positive generic-stage provenance; absence of a private marker is insufficient. Copied bytes+public job, forged handle/MAC, wrong purpose/owner/revision/expiry, registry/hash substitution, arbitrary callable, plaintext return/capture, exception laundering, and WorkerStepResult conversion reject.

5.2 Encrypted-envelope closure

The only plaintext private-store columns are random/authority-derived opaque row id, owner-path discriminator, categorical state, AEAD suite/key version, bounded non-content timing/cost categories, ciphertext length, nonce, and ciphertext. AEAD encrypts every output byte, rendered HTML, twin/context/graph payload, source/parent roster, private hash, receipt, taint, harness response, match diagnostic, content-bearing effect, child identity set, and outbox payload. Ciphertext schema/type and all permitted plaintext columns are canonical AAD. SQLite/DuckDB indexes contain no private commitment. Tests scan main DB, WAL, journal, shared-memory, temp, backup, index and outbox bytes for raw and encoded content plus every private hash.

7. Rejected alternatives and explicit non-goals

Rejected: amend or mutate v1

V1 precommits no successor key and denies every sink. Adding PASS, attaching an external activation, or interpreting v1 through v2 rewrites signed meaning. Only new capability-v2/receipt-v5 authority can enter this lane.

Rejected: generic optional fields

Generic readers, recovery, hashes, deposits, flywheel, graph, and telemetry remain leak paths even if a checkpoint accepts optional taint. Guards resolve durable authority.

Rejected: hash-only compliance

A caller output hash, PASS boolean, paraphrase score, semantic similarity, or first-match scan cannot authorize a sink.

Rejected: tags or shared plaintext

personal_reading, owner filename hashes, privileged tags, shared engagement roots, and per-owner paths without content encryption are not sufficient owner-private storage.

Out of scope

No production transport/admission, provider-response recovery API, public/share/export, marketplace, team ACL, cross-owner merge, or legal-clearance claim. These remain denied or F/later work.

Movability

Capability/policy, extractor/normalizer/checker, storage envelope, sink receipts, and graph projection have separate identities. Later checkers, key rotation, or shared ACLs cannot silently alter them.
