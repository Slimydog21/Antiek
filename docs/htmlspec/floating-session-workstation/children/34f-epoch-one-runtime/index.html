Repository truth and falsifiable goal

Dependency correction. Cycle 35 currently states that epoch-one cutover is green. The implementation contradicts that premise: pinned_epoch1 and forward_recovery_epoch1 reject, commit_fixture_cutover and resume_fixture_cutover_forward_only are stubs, and _require_fixture_writer_authority always rejects. Admission cannot be linearizable through a writer that cannot exist. Prospective cutover/admission prose in the frozen 11B-E parent is design intent, not certification evidence; 34A–34E executable boundaries win until 34F passes.

Goal: given the exact signed copied_epoch0 lifecycle state and authenticated sealed root, atomically install a signed cutover marker, externally pin it, prove the legacy root read-only, publish readiness, preflight-open the target without writer authority, release and durably attest the barrier, then freshly reopen the same target as the only writer-authorized pinned epoch-one runtime.

no rollback after cutover_intent_prepared; no marker replacement; no second pin/readiness identity

The existing SignedMigrationLifecycleStateV1 cannot acquire new phases without changing its frozen semantic meaning. Add SignedCutoverLifecycleStateV2 as an additive successor with sequences 5–11. It binds the terminal V1 state hash; target/root/barrier/source/audit/path pins; predecessor and successor semantic plus contract identities; marker, pin, root-state, ready, preflight-audit, and release hashes with phase-bound nullability; previous state hash; timestamps; issuer generation; signature; and its own state hash.

cutover_intent_prepared signs every immutable marker input but deliberately has no marker hash, signature, or commit timestamp. The marker is created once inside the SQLite transaction with a trusted transaction time, inserted, and returned from COMMIT; response-loss recovery reads the exact marker from SQLite. This keeps marker_committed_at_ms truthful without regeneration.

The marker transaction atomically records the predecessor→successor semantic and contract identities. Existing Cycle 34 hashes remain valid historical evidence; no constant is silently rotated. Preparing the signed V2 intent is the point of no abort: before it, the certified V1 abort route remains legal; after it, issuer loss or divergent durable evidence is permanent safe-unavailable and recovery is forward-only.
