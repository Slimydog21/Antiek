Signed cutover and pinned epoch-one runtime

Convert only a certified copied epoch-zero target into the one authenticated runtime writer Cycle 35 requires.

Parent context and goal

Cycle 34E certified the signed migration journal, sealed/copy recovery, and recoverable abort. Its own boundary kept marker, forward recovery, pinned runtime, admission, transition, and backup closed. Current production code preserves that denial.

Goal: implement the forward-only post-copy lifecycle, prove every crash boundary, reopen a genuine pinned epoch-one store, and activate only its fixture authority writers. Do not implement paid admission in this sprint.

Technical milestones

1
Freeze post-copy state and marker contracts

Add signed lifecycle phases, marker material, predecessor identities, exact temporal ordering, collision/replay rules, and forward-only recovery inputs.

Accept: mutation of any root/target/barrier/manifest/audit/schema/contract/time/key field rejects; the marker is byte-identical on replay.
2
Commit the target marker atomically

Under target BEGIN IMMEDIATE, reauthenticate copied_epoch0, copied rows, zero runtime rows, floor chains, schema and audit; insert one proof row and CAS the singleton to epoch one.

Accept: faults before COMMIT leave exact epoch zero; faults after COMMIT expose exact epoch one and can only move forward. Partial proof/singleton states are impossible or reject as corruption.
3
Install external pin and legacy read-only evidence

Persist an immutable pin after marker commit; revalidate sealed sources; transition the authenticated root to legacy-read-only. Exact replay returns original records.

Accept: target-ahead, pin-ahead, root-ahead, divergent replay, replaced pin store, wrong root, and stale source evidence have deterministic outcomes.
4
Publish readiness and preflight-open pinned epoch one

Write the ready record only after pin and legacy-read-only proof. Open with open_mode='pinned_epoch1' and construction_purpose='preflight', exact expected identities, and a fresh complete audit; every writer still rejects.

Accept: copied-but-unmarked, marked-but-unpinned, pinned-but-not-ready, wrong marker/manifest/audit/pin/ready, replaced file/inode, schema drift, authority corruption, or any writer call rejects.
5
Release, attest, reopen, and activate fixture writers narrowly

Pass the exact preflight store to the root’s existing readiness verifier, release the barrier once, then commit a signed barrier_released lifecycle successor. Discard the preflight object. Freshly open open_mode='pinned_epoch1', construction_purpose='runtime' against that successor and replace unconditional writer denial with a sealed predicate bound to this new object, PID, boot nonce, construction MAC, pin, ready record, and lifecycle identity.

Accept: the preflight object never gains writer authority; journal-only claims cannot resurrect it. Fabricated/object-new/copied/subclassed/reopened-with-drift/precutover/recovery/pre-release stores and module-global mutation cannot call any writer. Only the fresh post-release runtime store can execute existing fixture writers while all admission/transition APIs still reject.
6
Implement forward recovery

Resume from each durable post-marker phase using the signed journal and live issuer. Never invoke abort or regenerate completed identities.

Accept: response loss and faults around marker commit, journal CAS, pin write, root read-only, ready write, pinned reopen, and barrier release converge to one result with no rollback or duplicate mutation.
7
Certify privacy, reachability, and compatibility

Run schema/semantic identity gates, all prior abort/recovery suites, crash matrices, path attacks, and import/reachability checks.

Accept: exact 18-table SQL remains unchanged; runtime tables remain zero; no admission, transport, callback, response, plaintext/canary, key, or secret becomes reachable or leaks into DB/journal/pin/root/errors/logs.

Marker transaction and exact zero surface

One target BEGIN IMMEDIATE reauthenticates the copied corpus, schema hash, authority floors, source manifest, copy audit, and exact target identity; inserts exactly one migration_cutover_proof row; and CASes the singleton epoch, marker, semantic identity, and contract identity from the certified predecessor values to the exact successors. The existing 18-table SQL remains byte-for-byte unchanged; its schema-label columns have defaults but no CHECK constraints.

At cutover, each of logical_effects, paid_admissions, budget_holds, paid_attempts, paid_effect_transitions, and paid_attempt_events is exactly zero rows. The proof table is exactly one row after commit. Any other cardinality rejects.

Five-values rigor

Intellectual honestyCall the marker COMMIT a target transition, not full readiness. Pin, legacy read-only, fresh reopen, and barrier release remain separate evidence until each is durable.
FairnessPreserve copied owner authority rows byte-for-byte. Before V2 preparation, retain the authenticated V1 abort route; after the exact successor is durably prepared, retain that choice through forward recovery even if SQLite has not committed it yet.
RigorFor every injected fault assert target singleton, proof row, lifecycle journal, external pin, root state, ready record, barrier state, open-mode reachability, and replay identity—not merely the returned DTO.
DiligenceRecompute schema, copy audit, floor chains, signatures, file identities, runtime-zero counts, external records, and construction seal on both preflight and post-release opens. No cached pre-COMMIT validation or journal claim substitutes for a live process-bound object.
DefensibilityStore-local fixture writer authority exists only on the sealed runtime object. No returned DTO confers portable checkpoint or transition authority; admission, transport, accounting effects, sinks, and production use stay false and mechanically unreachable.

Out of scope and rejected shortcuts

  • No CandidateV2, Cycle 35 admission clock, CapabilityV4 successor ingestion, provider request, permit, output, accounting transition, backup, production migration, or sink. A store-injected fixture cutover clock is in scope solely for truthful lifecycle and marker times.
  • No in-memory mode toggle, caller-asserted pin/readiness, second SQLite root, ATTACH, schema rewrite, or rollback after V2 intent preparation.
  • No barrier release before a fresh writer-denied preflight open independently audits the complete target. The post-release writer-capable runtime open is necessarily a second fresh object.

Historical-vector and live-authority split

The checked-in 34E vector proves frozen wire compatibility: current code must verify its historical signature, typed corpus, SQLite bytes, source manifest, and copy audit without mutation. Because V1 deliberately binds filesystem device/inode, relocating that artifact cannot confer operational authority. The positive cutover test must therefore be produced by the detached certified 34E implementation on the live test path and handed to current code with the same inode, signed journal, authenticated issuer/recovery admission, and pinned verification key. Current code must never “repair” relocation by accepting a caller-selected key or re-signing the old facts.

Intent CAS exchange recovery

The V1→V2 no-abort CAS uses one distinct .cutover-swap-v2.<nonce>.swap artifact and atomic pathname exchange, never replacement rename. The candidate file and its directory entry are durable before exchange. The only recoverable pairs are exact signed {journal=copied_epoch0, swap=cutover_intent_prepared} and {journal=cutover_intent_prepared, swap=copied_epoch0}; the issuer authenticates both complete documents, canonicalizes the second layout, re-audits target path/inode/content under the retained write lease, retires V1 authority, then unlinks and fsyncs the displaced predecessor. Multiple, malformed, substituted, alternate-successor, unknown-key, or non-exact pairs remain fail-closed without deleting either authority record. Ordinary journal readers reject any swap artifact.

Issuer/process death with an unresolved exact pair is safe-unavailable, matching the unavailable-issuer rule above; no fresh issuer may generate a replacement key or infer authority. The later resume_fixture_cutover_forward_only implementation must accept only the externally pinned old verification authority and exact recovery ticket, classify the same two layouts, and complete this existing signed transition without minting a new intent, timestamp, nonce, or signature.
