Issuer-owned copy custody

The issuer retains its authenticated target BEGIN IMMEDIATE lease after independently committing the durable copy_prepared journal. Its copy command accepts only that exact committed state hash and no caller row material. Under the same sealed-root transition lock it re-extracts the corpus, requires the signed manifest/audit pins, and classifies the target as either all ten migration tables empty or byte-for-byte exact-complete. Empty executes plain INSERTs in canonical table/row/model-field order inside the retained transaction; nonempty executes observed-target verification without rewriting. Any partial, extra, divergent, runtime, singleton, schema, foreign-key, signature, chain, floor or audit state rejects. The issuer reproduces the signed CopyAuditV1 before COMMIT, commits the target, immediately reacquires BEGIN IMMEDIATE, reproduces the observed audit again, and retains custody through reserve/replay and independent durable-journal verification of copied_epoch0. Only that committed CAS releases the lease. A lost copy response retries as exact-complete without rewriting; a zero-row sealed corpus uses issuer state to distinguish first execution from replay because its durable target image is intentionally identical.

Deterministic CopyAuditV1 intent

The sources_sealed→copy_prepared CAS commits the hash of one deterministic CopyAuditV1; callers may not provide its counts, row hashes, budget digest, or chain digest. The issuer re-extracts the sealed corpus, cryptographically verifies every capability/revocation/source document against the exact construction keyrings and floor pins, and authenticates the epoch-zero target singleton (singleton=1,schema_version=1,migration_epoch=0,store_id,semantic_source_sha256,contract_sha256,cutover_marker_sha256=null,created_at_ms=0). Every row hash is SHA256(migration-row-domain || u32be(table-name-byte-length) || table-name || canonical-json([[column,type,value],...])). Corpus rows use their closed model field order and semantic types; the target singleton uses the column order above. ordered_table_row_sha256s follows the exact eighteen-table PaidLaneTableRowCountsV1 order: singleton hash first, the ten corpus collections in canonical corpus order, then empty tuples for all runtime and cutover-proof tables. Counts are the tuple lengths; foreign-key rows are empty.

Abort-origin pin inheritance

Every transition into abort_prepared preserves the originating phase's five-field pin tuple byte-for-byte through every abort_* record; normalization is forbidden. No abort_origin_phase field is added: the tuple's nullability class is the signed origin oracle. The allowed classes are exactly: all-null from schema_only; barrier/freeze/witness only from barrier_acquired; those plus manifest from sources_sealed; or all-five from copy_prepared|copied_epoch0. Any other null pattern or any pin change during abort rejects.

The pre-release/already-released replay rule in 34E-01 applies to every barrier-bearing class. It does not permit inventing a barrier for the all-null class.

Recovery API override

open_recovery_epoch0 accepts a tagged pin bundle whose fields must match this table and the abort-inheritance rule exactly; it covers all four pre-copy phases plus abort_*. Supplying a value where null is required, omitting a required value, or disagreeing with authenticated root/journal state rejects. It exposes only recover_seal_and_copy and authenticated abort. Crash tests are required on both sides of barrier acquisition, root seal, every external CAS, and every abort-origin class.

The executable admission foundation is Epoch0RecoveryAuthorityPinsV1 plus _authenticate_epoch0_recovery_state_v1: for every pre-abort epoch-zero phase it closes the exact phase/version/issuer-sequence/nullability tuple and pins signed state hash, root/store identity, parent device+inode, target basename/device+inode and all five phase pins. Authentication requires the caller's already-open parent and no-follow target descriptors, canonical signed journal under the pinned parent, exact pathname-to-fd inode equality before and after journal verification, and the pinned issuer verification key. SignedMigrationRecoveryTicketV1 is issued at the issuer's authenticated initial bind and domain-binds that issuer generation, root directory, root manifest, target store, parent directory, target basename/inode, maximum sequence and a random nonce. The complete ticket material is a bearer handoff capability and must not be published or treated as identity by signature alone. SignedEpoch0RecoveryAdmissionV1 domain-binds one exact ticket, authenticated socket peer PID, fresh caller/handle nonces, descriptor mode and the complete authority-pin object. The isolated fixture now has a distinct supervisor process: supervisor exit terminates the issuer generation, while initial-store exit or fork revokes that PID's ordinary command channel without killing the issuer. A fresh replacement PID may call only recover_open; it must present the bearer ticket and all three exact descriptors. The issuer independently reauthenticates those descriptors on first issuance and exact replay, binds cached replay to the same replacement PID, rejects nonce equivocation, and rejects inherited initial-store streams after fork. These artifacts grant no recovery or runtime authority. The public opener remains closed until a dedicated process-bound recovery-only object retains the admitted socket and duplicated descriptors.
