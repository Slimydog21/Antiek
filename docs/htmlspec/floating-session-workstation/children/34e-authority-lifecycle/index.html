Cycle 34EStatus: executable specification

Non-spoofable migration authority and recoverable abort

Close the three contracts that intentionally keep production seal, copy and abort disabled: root-issued witness authenticity, complete genesis-row provenance, and restart-safe destructive cleanup.

Goal and success

Success is not “methods return.” Success is a single auditable lifecycle in which no caller-created Python object can authorize migration, every non-schema target row has exactly one sealed source row hash, and every crash point before marker either resumes forward or completes abort without deleting a different path.

  • Authority derives from an OS-backed root file descriptor and a root-owned keyed witness, never module/name/path strings.
  • Provider and source genesis heads/currents are extracted as typed rows and copied from the sealed corpus.
  • Abort is a durable phase machine with idempotent restart recovery and directory-fd-relative operations.
  • Cutover, runtime admission, transition and backup remain disabled in this cycle.

Architecture and threat model

Claim boundary: this synthetic ceremony resists fabricated/copied/stale Python values, process restart, filesystem replacement and untrusted migration inputs. It does not claim secrecy against arbitrary same-UID code with debugger or memory-read authority. Witness signing custody lives in a separately spawned fixture issuer process whose private key is generated after spawn, never serialized or written to disk; production receives only its pinned Ed25519 public key. Compromise of that issuer process is outside this synthetic proof and cannot authorize real predecessor stores.

isolated fixture witness issuer process (memory-only Ed25519 private key)
  └─ pinned public key → production store open

mode-0700 root directory fd
  ├─ durable signed root state (0600, no-follow, single-link)
  ├─ child adapters → typed sealed corpus (including genesis)
  └─ target directory fd
       ├─ target.sqlite3
       ├─ .target.sqlite3.migration-state-v1.json (external signed lifecycle state)
       └─ .target.sqlite3.abort-v1 (database tombstone; sidecars must be absent)

root witness = Ed25519 signature over domain-separated canonical material:
  root inode + target parent inode + target basename + target database inode + store id +
  store boot nonce + handle nonce + manifest + inventory + barrier + freeze)

schema_only → barrier_acquired → sources_sealed → copy_prepared → copied_epoch0
  → abort_prepared → abort_renamed_to_tombstone
  → abort_rename_fsynced → abort_tombstone_unlinked → abort_deletion_fsynced
  → abort_sources_revalidated → abort_barrier_released

The issuer is supervised independently of the store process and survives store-process restart. Recovery is supported only while that exact issuer process/key id remains live; issuer death or restart loses the key and fails closed without further target mutation. This synthetic limitation is explicit and must not be described as host-restart recovery.

Rejected alternatives

Re-enable only empty-corpus copyThe target floor pins require genesis rows; a schema-only success would certify a different end state.

Open questions resolved by implementation evidence

  • Use a spawned fixture issuer with a memory-only Ed25519 key; pin its public key during store creation and require signed root/witness records. No secret file exists.
  • Keep the witness process-local and one-shot, but verify its signature against fresh durable root/barrier and root/parent/target device+inode measurements at each transition.
  • Immediately before every renameat/unlinkat, require opened-target fstat to equal no-follow fstatat(parent_fd,basename) and the signed witness inode.
  • Timestamp seal from one store-supplied now_ms committed into root evidence and corpus manifest; no second public timestamp source.
