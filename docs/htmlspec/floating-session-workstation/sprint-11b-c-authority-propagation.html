Owner-private authority propagation without execution

ID: FSW-SPR-11B-C · Status: implemented and accepted · Parent: FSW-SPR-11B sprint 11B-C · Cycle: 24 · Boundary: durable propagation and recomputation only; consent, delivery, lease, acquisition, and dispatch remain denied.

1. Falsifiable objective

A complete mixed manifest-v2 authority may be persisted as one canonical non-conferring carrier, cross-bound into a context-v2 hash, owner payload, job-config-v6 hash, and prospective queue commitment, then independently recomputed at every seam. Any missing, substituted, downgraded, stale, revoked, extra, or divergent material fails closed. The API must reject before issuing spend consent and the worker must reject before the QUEUED→RUNNING owner CAS or lease acquisition.

Non-goal: this sprint does not make the public prepare route accept Substack, issue mixed spend consent, insert a mixed queue row, read excerpt bytes, acquire sources, construct retrieval, dispatch a model, create receipts/taints, persist outputs, deposit, project graph/twins, serve/share/export, run ads, or feed evaluation/training.

2. Canonical carrier

OwnerPrivatePublicationAuthorityV1 uses literal domain bytes antiek.midnight-oil.owner-private-publication-authority.v1\0, maximum 128,000 canonical UTF-8 bytes, and at most eight selections. Canonical JSON is json.dumps(model_dump(mode="json"), sort_keys=True, separators=(",",":"), ensure_ascii=False); parse rejects duplicate keys and any raw encoding unequal to that canonical encoding. Selections sort uniquely by capability_sha256.

4. Validation-only injection and live reload

LivePrivateProviderAuthorityResolver wraps PrivateProviderComposition but exposes only resolve(manifest, now_ms, required_until_ms); it has no dispatch method. PrivateProviderComposition.live_reference_registry(now_ms) calls the durable store’s transactional current(now_ms), fully re-audits the latest chain/freshness, and rebuilds a reference registry from immutable signed capabilities plus the newly current snapshot. This accepts a valid newer cumulative head without changing durable carrier/context/consent hashes.

The API passes this resolver as a separate optional keyword through create_app → register_midnight_oil_routes and stores it under a distinct private app-state key; it never enters MidnightOilDependencies. Production supplies it only when private composition exists. Worker runtime constructs the same resolver and supplies the pre-CAS guard callback. A v2 transition with no resolver fails closed; legacy does not consult it.

11B-C calls require_reference_available, not the dispatch matcher: it verifies identity, signature, revocation freshness, not-before/expiry, constraints, policy, and horizon without fabricating role or byte counts. Required roles are cross-bound to the signed swarm topology and capability allowed-role set. Exact private input bytes and per-dispatch role matching remain 11B-D. Horizon is exactly now + CONSENT_TTL_MS + duration_minutes*60_000 + publication_completion_margin_ms at persistence/consent, and now + duration_minutes*60_000 + publication_completion_margin_ms at prospective delivery/pre-lease.

5. Transition sequence and production entry

The sole 11B-C persistence entry is an internal service function create_owner_private_job_authority. It accepts a server-parsed manifest v2 plus validation-only resolver, derives carrier/context material itself, and delegates the durable write/replay mechanics to create_job_authority. It is production code but has no HTTP route in this sprint; the current public engagement prepare remains v1-only and rejects Substack.

  1. Parse owner manifest JSON with duplicate-key rejection and exact schema dispatch; recompute its identity.
  2. Resolve each declared Substack capability reference against the live private-provider registry for identity/revocation/horizon only; derive the canonical carrier.
  3. Hash context v2 over the immutable product tuple plus manifest, carrier, and output-policy hashes.
  4. Persist canonical manifest/carrier JSON plus hashes and version tags in the closed owner payload; replay compares every field.
  5. Reconstruct JobConsentConfig with the shared helper and derive job-config v6.
  6. Stop before SpendConsentStore.issue with stable private no-store denial.
  7. Purely derive the prospective queue commitment and prove exact replay/substitution behavior; do not enqueue it.
  8. A synthetically injected mixed queued row is rejected before owner state transition, queue lease, legacy job projection, retrieval, acquisition, or dispatch.

6. Legacy invariants

Hash stability

Literal context-v1, job-config-v1–v5, manifest-v1/v2, consent receipt, swarm plan, queue option, and publication receipt vectors remain unchanged.

Absence semantics

Legacy payloads and queue JSON omit all v2 fields. Adding dataclass defaults must not insert nulls into canonical legacy material.

Name separation

publication_capability_sha256 remains the arXiv connector-egress capability. Private processing uses names containing private_provider.

V2 dual-authority rejection

For manifest v2, outer publication_preflight_ready, publication_capability_sha256, id, and expiry must be absent. Per-arXiv authority stays only inside manifest v2. Any divergent or merely present legacy outer value rejects at reopen, context, config, and queue derivation.

Type separation

V2 manifest rows wrap source plus authority. They are never flattened into or passed as ReviewedPublicationSource to v1 acquirers.

7. Adversarial acceptance

Canonical identity

Reordered selections canonicalize identically. Capability/provider/model/route/role/constraint/policy/manifest substitution changes identity or rejects.

Completeness

Missing JSON/hash/version/context/policy member, extra selection, unknown field, duplicate key, downgrade, noncanonical JSON, or unavailable-reference promotion rejects.

Durability

Store reopen recomputes the same carrier/context/config. Direct payload tamper fails before consent or delivery.

Consent denial

Mixed spend-consent returns stable 409 with Cache-Control: no-store; spies prove zero issue, stage-plan, queue, acquisition, retrieval, or provider calls.

Pre-lease denial

Synthetic mixed QUEUED authority remains QUEUED; state version and lease generation do not change; no legacy projection or retrieval is constructed.

Queue replay

Exact prospective commitment replays; any substituted commitment conflicts. No mixed row exists after the real route denial.

Live registry

Unknown, revoked, stale, forked, signature-invalid, wrong-purpose, wrong-policy, or horizon-short capability fails. Valid newer revocation state does not alter durable hashes.

Leakage

Private source canaries, URLs, excerpt hashes/bytes, signatures, raw paths, and keys are absent from errors, logs, queue/status responses, and public readiness.

8. Collision and crash protocol

Owner creation uses existing put/re-read reconciliation; identical carrier replay converges and different material conflicts. Consent denial happens before consent-store writes. Queue derivation is pure; future delivery must recompute under enqueue_once_guarded. The worker’s callback executes on the just-read owner row before the existing QUEUED→RUNNING CAS; the CAS version fence rejects a concurrent owner mutation. Worker denial cannot strand a mixed operation in RUNNING or create a lease. No repair path may infer authority from readiness booleans or a partially written tuple.
