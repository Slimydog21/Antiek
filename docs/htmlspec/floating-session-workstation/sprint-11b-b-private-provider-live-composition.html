Rollback-floored private-provider composition

ID: FSW-SPR-11B-B · Status: accepted 2026-07-13 · Parent: FSW-SPR-11B sprint 11B-B · Cycle: 23 · Boundary: authenticated composition only; no execution consumer.

1. Falsifiable objective

API and worker must independently load the same exact private-provider capabilities and latest locally durable revocation head, prove that head descends from an externally pinned signed floor through an unbroken cumulative chain, and derive one identical non-conferring composition fingerprint. Missing, partial, stale, forked, rolled-back, corrupt, key-colliding, or divergent state fails before provider registration or worker polling.

Non-goal: this sprint does not change mixed readiness, prepare, context, consent, queue payloads, acquisition, model selection, dispatch, receipts, deposit, twins, retrieval, graph, HTML serving, sharing, export, ads, evaluation, or training.

2. Trust model

Offline issuers

Capability and revocation artifacts use Ed25519. Online API/worker environments receive only 32-byte public keys and cannot mint accepted artifacts.

Separate roles

Capability-issuer and revocation-issuer key ids, environment names, and public-key bytes are disjoint and must also not reuse consent or Substack authority material.

External floor and current pin

An exact signed floor and an exact expected-current head each have a SHA-256 and artifact path outside the state database. Current state must descend from the immutable floor and equal the deployment current pin. Restoring the database, floor, and deployment pin together is explicitly outside this local proof.

Single shared state

SQLite locking is authoritative only when API and worker share the same canonical local persistent filesystem. This is not distributed consensus and does not claim unsafe NFS semantics.

4. Durable current-head transaction

  1. A fresh database is schema-created but remains unusable until the exact externally pinned, signed floor is explicitly admitted.
  2. Every read uses one SQLite transaction and walks predecessor rows from current to the trusted floor, bounding and cycle-checking the chain while recomputing every nested and wrapper signature/hash and matching each signed document to its persisted primary key, epoch, predecessor, and issuance columns.
  3. A writer uses BEGIN IMMEDIATE, re-reads current, requires the exact expected predecessor, exact next epoch, strictly later issuance, and a cumulative revoked-hash superset. At 1,024 retained rows it rejects before insert and requires re-anchor, so row 1,025 can never commit.
  4. History insert and singleton current-pointer update commit atomically. Exact replay is idempotent; a competing child loses without insertion or pointer change.
  5. At composition, the externally pinned expected current may be the persisted current or its exact one-step signed successor. The latter is admitted by the same CAS; any rollback, skip, alternate child, or older deployment pin is fatal.
  6. Before the 1,024-row audit bound, an operator advances the external trusted floor to an already-current signed head. Admission proves that exact head is in the one linear current history, then atomically prunes only older ancestors. Reverting to the pruned floor is rejected. This rollback-safe re-anchor makes the bound operational rather than self-expiring.
  7. SQLite uses WAL, foreign keys, full synchronous durability, busy timeout, a canonical non-symlink database path, restrictive file mode, and exact schema checks.

6. Runtime isolation

The shared builder runs independently in build_midnight_oil_api_runtime and build_worker_runtime. Both roots independently inventory consent, attested-provider API-key, and Substack key aliases/material and reject same-alias, exact-raw, or normalized 32-byte reuse before composing. Each preflights the externally pinned composition fingerprint from parsed signed artifacts and the canonical state path before constructing or mutating the store, then rechecks after admission. The result exists only on their outer runtime records and on private app state for internal diagnostics; capability and registry fields are repr-redacted. Runtime-facing validation/store/filesystem failures are generic and suppress nested raw values. The composition is forbidden from MidnightOilDependencies, publication capability selection, acquirers, route registration, readiness-green logic, stage execution, or any outward sink. Substack key loading receives the private key environment/material set as a forbidden purpose.

7. Adversarial acceptance

Cryptography

Reject unknown key, wrong role, public-bytes-as-private forgery, signature/hash substitution, validation-bypassed mutation, duplicate JSON, and oversized artifacts.

Chain

Reject wrong/missing predecessor, epoch reuse/skip/regression, time regression/future/staleness, revocation omission, cycle, missing floor, fork, pointer corruption, valid signed row substitution, schema lookalikes without constraints, and altered stored JSON.

Transactions

Restart observes old or complete new state. Concurrent API/worker composition of one pinned successor converges on one row; exact replay is idempotent; no orphan losing child remains.

Composition

Reject partial env, duplicate key/path, role/cross-purpose alias or material reuse, head/composition pin mismatch, capability/keyring/path divergence, and stale restart.

Leakage

No private key, API key, excerpt, prompt, output, source identity, evidence URL, raw filesystem path, or content-derived private hash enters errors, logs, routes, readiness, or public receipts.

Legacy

All-private-env-absent preserves runtime JSON, route surface, manifest v1/v2, consent v1–v5, Substack rejection, queue, worker, deposit, graph, and output policy vectors.

8. Deferred operating requirements

The deployment now has an exact one-step signed rotation seam and rollback-safe floor re-anchor/pruning procedure. Operators must re-anchor before 1,024 retained heads. The five-minute freshness policy still requires a real issuer/distribution operating model before execution: either a tightly scoped online revocation signer or a deliberately revised signed freshness contract. Production provider evidence and keys do not yet exist, so production remains unconfigured. Future 11B-D must reload current state immediately before dispatch; a startup composition is never lasting authority.
