Exact owner-private reader and closed dispatch boundary

Prove exact local-byte resolution, private source receipt v4, and a no-tools/no-fallback exact-route boundary while keeping every production transport and output sink mechanically unreachable.

Wave: after 11B-CStatus: execution-ready draftOwner: primary orchestratorBudget: 6 milestonesTransport: disabled

1. Parent context and falsifiable goal

11B-A signed the provider-processing capability and deny-all derivative policy; 11B-B added a rollback-floored live revocation head; 11B-C propagated a complete manifest-v2/carrier/context/config tuple while leaving consent_enabled=false, delivery_enabled=false, and owner_private_execution_state=propagated_disabled. Substack review already persists exact owner-scoped receipt text, authorization, and overlay records. The legacy execution path remains manifest-v1/T1 and must remain byte-identical.

Goal: given the complete canonical Substack-private subset of one server-derived manifest v2, resolve only its exact durable owner-private receipt bytes, bind those bytes and every authority identity into a distinct publication receipt v4, and return an inert exact-route dispatch envelope after revalidating all inputs. A test-only wrapper may pass that envelope to one spy. Any omission, substitution, expiry, revocation, capability drift, role drift, byte drift, fallback/tool surface, or production entry must fail before the spy is called.

Hard boundary: no production module in this sprint accepts or invokes a transport callback. API, queue, worker, stage engine, and replay make no provider call. A check followed by a call is not atomic revocation admission, and current output policy permits no response checkpoint. Production transport remains closed until a later contract supplies (1) a linearizable admitted-before-revocation protocol and (2) a compliant owner-private output sink. 11B-E owns sinks; 11B-F owns enablement.

Key invariants

  • Raw owner-private text exists only in the pre-existing owner receipt and bounded volatile memory; v4 stores commitments, never text, URL, path, key, signature, or source identity in public telemetry.
  • SubstackUseAuthorizationV2 is required literally. The reader reloads exactly one owner-scoped overlay id/hash through a new public exact helper, independently rereads authorization and receipt, and never reads draft selection_text. Manifest v2 never enters manifest_from_authority, PublicationAcquirer, connector registries, retrieval, corpus, or generic cache.
  • private_input_bytes is the aggregate sum of actual excerpt UTF-8 byte lengths passed to the capability matcher. Framing bytes affect only the separate private-source commitment, never the cap.
  • The boundary consumes the complete canonical Substack-private subset, rejects an omitted or duplicate private row, and binds membership jointly through the full manifest-v2 hash, per-row v4 identities, and framed input commitment. It makes no claim that arXiv or the full mixed stage input is ready.
  • A request with zero private bytes or multiple distinct private capability hashes fails closed until a later spec defines and signs a broader rule.

Normative private-source framing

order = manifest-v2 canonical source order, filtered to Substack rows
member = u16be(len(ref_id_utf8)) || ref_id_utf8
      || u16be(len(receipt_id_utf8)) || receipt_id_utf8
      || u64be(len(excerpt_utf8)) || excerpt_utf8
material = b"antiek.midnight-oil.private-input.v1\0"
        || u32be(source_count) || member_1 || ... || member_n
private_input_commitment_sha256 = SHA256(material)
private_input_bytes = sum(len(excerpt_utf8))

The ordered roster and algorithm version are bound into receipt v4. Empty members, reversed canonical order, duplicate refs/receipts, invalid UTF-8, and framing overflow reject. The capability cap applies to aggregate private_input_bytes; the full provider request has its own role-plan/request-size bound.

Normative prepared provider request

PreparedOwnerPrivateProviderRequestV1 is a closed frozen model with exactly: schema_version=1; canonical role; exact output-schema literal; tools_enabled=false; instruction; question; and private_sources in manifest order. Each private source contains only a request-local ordinal alias formatted private-source-%04d starting at one and the exact excerpt text. No durable ref/receipt/auth/hash/URL/range or auxiliary/retrieval/arXiv material enters provider bytes. Instruction, question, and text preserve exact Unicode code points without normalization and must already satisfy the platform’s canonical control/size rules.

Serialization is exactly json.dumps(request.model_dump(mode="json"), sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8"). The closed model makes duplicate and unknown fields impossible. provider_request_sha256 = SHA256(b"antiek.midnight-oil.provider-request.v1\0" || serialized_bytes); the inert envelope carries that exact immutable byte string and a future transport must not reserialize it. Local-only alias-to-v4 mapping proves partition and lineage without disclosing durable identities. private_input_commitment_sha256 separately commits and meters the owner-private excerpts.

5. Revocation and admission semantics

Honest guarantee in 11B-D: production performs synchronous final rereads and a live-registry match, then returns an inert envelope without transport. The test-only wrapper invokes its spy immediately after validation with no intervening operation. This structure minimizes test drift but makes no production timing or atomicity claim and cannot eliminate a cross-process revocation race.

Production enablement requires one named linearization point shared by source authorization and provider-capability revocation. The preferred future design is a durable dispatch-admission CAS written under the same authority serialization boundary: a revocation committed before admission prevents the call; a revocation committed after admission prevents later calls but cannot retract bytes already accepted by the provider transport. If a single admission record cannot atomically cover both authority stores, 11B-F must specify lock ordering, crash recovery, and conservative orphan handling before removing any execution-denied literal.

Both normal provider crossing and CallKeyReplay adoption must pass through the same eventual admission wrapper. A worker-CLI-only check or a guard only in _provider_call is insufficient.
