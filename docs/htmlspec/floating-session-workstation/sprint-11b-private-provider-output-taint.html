Private provider capability and owner-private output taint

ID: FSW-SPR-11B · Status: 11B-A implemented; 11B-B–F unexecuted · Parent: FSW-SPR-11A milestone 3 · Stance: HTML-native owner-private research; no public/share/training path.

1. Falsifiable objective

A mixed manifest may become execution-eligible only when the exact provider route and model have a live, operator-signed capability for processing personal_reading excerpts under the fixed Substack provider constraints, and every produced byte is durably bound to an owner-private derivative policy before reaching a sink.

Non-goal: the first slice does not enable acquisition, prepare, consent, queue, worker, provider dispatch, deposit, graph, sharing, or export. It freezes types and hash domains only. Existing arXiv v1/v5/v3 vectors and production Substack rejection remain unchanged.

2. Current truth and gap

Source authority exists

Manifest v2 binds owner, unit, revision, source, overlay, authorization, and receipt. Cycle 21 previews immutable binding and liveness without conferring authority.

Provider proof does not

Current dispatch plans authorize cost/routes, not private-content handling. A route or API key is not evidence of no-training, no-retention, or no-provider-logging behavior.

Output taint does not

Job evidence, HTML deposit, twins, session flywheel, and graph receipts lack a content-class/policy commitment. They cannot consume mixed outputs until versioned private sinks exist.

Legacy is T1-only

The current publication execution path requires v1 T1. Substack not_applicable rights need distinct v2 consumers, never a weakened T1 check.

5. Selection and routing

  1. Model choice stays visible. A model is eligible only if its exact route/model capability covers the proposed horizon.
  2. Automatic routing, including Not Diamond, may choose only among capability hashes already committed by consent. No fallback outside the closed set.
  3. A router recommendation is not provider authority or consent. Router telemetry cannot receive private content without its own exact capability.
  4. Route/model changes invalidate readiness and require new preview and consent authority.
  5. If no exact route exists, UI says private processing is unavailable; it never omits the source or silently uses a generic model.

6.1 Revocation reference versus live authority

The 11B-A object authenticates one bounded revocation reference and rejects future-dated or older-than-five-minute references during a match. It cannot establish that the reference is the latest or that a later epoch preserves every earlier revocation. Before propagation, 11B-B must add a live persisted current-head loader that requires an exact predecessor hash, strictly increasing epoch and issuance time, a cumulative revoked-hash superset, rollback-resistant storage, API/worker parity, and a final reload immediately before dispatch. Tests must cover omission, fork, rollback, stale replay, future timestamp, restart, and concurrent rotation.

7. Adversarial acceptance

Substitution

Reject route, model, provider, region, mode, compiled contract, evidence, constraint, output-policy, time, key, hash, or signature drift.

Routing escape

Reject wildcards, uncommitted fallback, router-added candidates, endpoint/account drift, and expiry during delay.

Authority confusion

Reject egress keys, spend keys, excerpt grants, API keys, UI booleans, or readiness JSON as provider capability.

Taint laundering

Reject missing policy, downgrade, owner removal, T1 relabel, detached output, partial receipts, public redaction, and copy-to-new-document.

Leakage

Canaries stay absent from logs/errors/telemetry/public graph/export/ads/training. Current sinks reject private output.

Legacy

Manifest v1, context v1, consent v1–v5, queue, worker, receipt v3, deposit, and graph vectors remain unchanged.

8. Execution sprints

  1. 11B-A — pure types: signed provider capability and signed revocation snapshot, reference-only matcher, derivative policy, strict parsing, golden/substitution tests, and explicitly unverified taint-material constructor. No I/O; no consumer accepts them; every sink denies while compliance is pending.
  2. 11B-B — composition: distinct keyring and exact provider evidence loader with API/worker registry parity. Still no mixed prepare.
  3. 11B-C — authority propagation: context v2, consent v6, owner payload and queue recomputation. Consent remains disabled until sinks exist.
  4. 11B-D — reader/dispatch: exact local receipt bytes, last-moment revocation/capability checks, no tools/fallback, receipt v4.
  5. 11B-E — private outputs: version job evidence, HTML deposit, twins/context, owner-filtered graph; a content-bound compliance receipt resolves and recomputes every source receipt, parent taint, exact output byte hash, normalization/checker version and threshold result before any persistence; public/export/training denial.
  6. 11B-F — narrow enablement: expose mixed prepare/consent only after restart, revocation, all-source, sink, and canary E2E proof.
Cycle 22 closure: 11B-A is implemented as an isolated pure module with no runtime consumers. Any change to prepare, consent, queue, worker, acquisition, dispatch, deposit, flywheel, graph, serve, export, ads, or training remains out of scope until later sprints close their complete authority chains.

9. Rejected shortcuts

A boolean private=true; content class without lineage; provider-family allowlists; UI-selected capability hashes; router scores; provider self-description without evidence; post-generation redaction as the only gate; logging then deleting; prompt-only restrictions; arXiv-capability reuse; weakened T1 checks; and current unversioned graph output are rejected.

10. Five-values closure

Intellectual honesty: operator authorization is reviewed configuration evidence, not proof a provider can never misbehave. Fairness: private research utility does not turn paid text into public/training inventory. Rigor: closed hashes replace intent strings. Diligence: every transition is recomputed and live-checked. Defensibility: old execution stays unchanged until the entire new chain is executable.
