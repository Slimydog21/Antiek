Cycle 86: Shared Node Investigation Membership

Status: executable specification.

Problem

Insight and question node identifiers are content-addressed and deliberately reused across investigations. A graph insert conflict therefore means "existing shared knowledge", not "this investigation did not produce the knowledge". Today investigation discovery and challenge authorization depend on the first node-insert event or the single investigation identifier in node metadata. Reuse can consequently hide a valid result and reject a valid challenge.

Decision

Add an append-only relational membership between a global node and every investigation that produced or adopted it. Canonical node text and refinement ordering remain global in the current single-operator graph. Investigation membership authorizes disclosure and mutation; it does not create divergent node copies.

  • Membership identity is unique on node id plus investigation id; presentation order is deterministic by creation time and node id.
  • Membership records node kind, optional owner, and the investigation-local emerged-note identity used by live event folding.
  • Promotion records membership for new inserts, exact content-address collisions, and near-duplicate survivor returns.
  • Existing insight and question metadata is backfilled only where it proves a non-empty investigation identifier.
  • No membership is inferred from mere node visibility or user input.

Read And Write Semantics

  • Distillation discovers nodes from ordered memberships, while escalation state still comes from the investigation trajectory.
  • A living-note challenge must find an insight membership before resolver invocation or durable request claiming.
  • Refinement events use the requesting membership's local origin note id so the correct live note folds the outcome.
  • History disclosure first authorizes the requested investigation, then reads all committed outcomes for the global node aggregate.
  • Every outcome's source investigation must itself be a member. Digest, event identity, authority tuple, chain, and graph reconciliation remain mandatory.
  • History entries expose source investigation identity through the API; the compact UI need not display internal identifiers.

Compatibility And Boundaries

  • Legacy node metadata remains readable but is no longer an authorization source after migration.
  • Current deployment semantics are a single operator and one graph. The owner column preserves a future account-isolation seam but does not claim multi-tenant isolation.
  • Global canonical text means a refinement from one member investigation is visible in every member investigation.
  • Deleted nodes may leave historical soft memberships; reads skip absent nodes and never fabricate content.

Acceptance Criteria

  1. Two investigations promoting identical text receive the same node id and each receives one membership.
  2. The reused node appears in both completed distillation views even when only the first promotion emitted a graph insert event.
  3. Both member investigations may challenge the node; a non-member is rejected before resolver execution and before idempotency-journal mutation.
  4. A refinement initiated from the second investigation emits that investigation's local origin note id.
  5. History requested by either member returns the same global authoritative chain and identifies each entry's source investigation.
  6. A history event attributed to a non-member fails closed as an integrity error.
  7. Near-duplicate survivor paths record membership without inserting a duplicate node.
  8. Schema initialization and upgrade are idempotent, and proven legacy metadata memberships are backfilled.
  9. Focused backend and UI tests, full relevant suites, lint, type checking, and production build pass.
