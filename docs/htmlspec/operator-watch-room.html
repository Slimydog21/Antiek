Operator Watch Room

An authored, evidence-honest oversight surface whose four instruments stay independent and whose only mutation records an externally completed notification.

Status: executableOwner: Codex Infinite1 inline sprint · 6 milestonesBase: PR #2743 @ 68d7d85c4

Spec lineage

Root cycle spec derived from the full Antiek branding/UI mandate and a live audit of canonical /operator. No child specs: the component, state seam, tests, stories, CSS, asset, and audit extension form one tightly coupled sprint.

    Egghead verdict

    Proceed, with high confidence, only if the visual metaphor refuses the usual mission-control lie. The strongest counterargument is that decoration can make partial or unavailable systems feel healthy. The surviving design is a quiet watch room with four separately labelled instruments: publisher roster is required; stats, deletions, and payouts are independently optional; no aggregate health state exists.

    What would reverse this: evidence that the backend already exposes a single authoritative composite health contract. It does not on this head.

    Goal and failure mode

    Make the operator able to inspect publisher notification state, substrate counts, pending deletions, and recent payouts without confusing absence with zero, or recording the same notification twice while a request is in flight.

    Failure mode: a polished dashboard that invents composite certainty, implies this UI sends email or clears counsel, exposes transport internals, or turns unavailable counts into zero.

    Authority topology

    GET /publishers ─ required ─┐ GET /stats ─────── optional ─┤ GET deletion requests optional ├─ view-only typed projection ─ HTML watch room GET payout transfers ─ optional ┘ operator click ─ exact publisher id ─ POST /publishers/:id/notify │ └─ records externally sent notice; sends nothing
    • Each optional response becomes available | unavailable, never a shared success boolean.
    • Publisher failure blocks the roster but does not fabricate empty publisher buckets.
    • Notification is single-flight per publisher ID and reloads authoritative state after success.
    • Stories inject fixtures with executionEnabled=false; no HTTP is possible.

    Technical milestones

    1 · Freeze typed state

    Export view props and fixture-friendly state. Represent optional instruments with null/unavailable, and preserve unknown counts as “Unknown.”

    2 · Preserve transport authority

    Keep the four exact GET paths and the exact POST path/method. Bound errors to fixed safe copy. Suppress stale reload results after unmount/new request.

    3 · Single-flight receipt action

    Track the notifying publisher ID; disable only that row; label the action “Record external notice”; say explicitly that Antiek does not send email or clear counsel.

    4 · Author the watch room

    Use the ChatGPT Image raster only as pointer-inert decorative atmosphere. Build semantic instruments, roster buckets, navigation, and states in HTML/CSS.

    5 · Deterministic state matrix

    Add loading, partial, safe failure, empty, populated, notifying, night, and narrow Storybook states with transport execution hard-locked off.

    6 · Mechanical proof

    Test exact requests, partial availability, unknown rendering, safe errors, POST single-flight/encoding/reload, decorative asset semantics, and run build/a11y/security gates.

    Rigor — sprint-specific operating manual

    1 · HonestyNull is not zero.

    Every absent stats.counts[key], failed optional GET, and unparsed response remains visibly unknown/unavailable. Never infer “no transfers” from a failed payout request.

    2 · FairnessDo not bias the operator toward outreach.

    The pre-onboarded action gets no celebratory prominence over invited, claimed, or opted-out records. Steelman retaining plain chrome: reject it only because it currently leaks and misstates authority, not because it is unfashionable.

    3 · RigorProve each authority separately.

    Mock all four GETs and the POST independently. Tests must show one optional failure cannot erase another instrument, and a double click cannot issue two notification records.

    4 · DiligenceReuse the Stats unknown contract.

    Read StatsView, the existing apiFetch credentials behavior, and publisher backend route semantics before editing. Do not invent a generic dashboard data layer.

    5 · DefensibilityKeep the receipt boundary in copy and code.

    The action label, authority note, exact POST assertion, and non-goal list must let a later maintainer reconstruct why this surface records an external act but sends no communication.
