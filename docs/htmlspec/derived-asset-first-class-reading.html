Cycle 57: Derived Asset First-Class Reading

Open committed canonical HTML in Antiek's reading workflow without flattening it, copying its authority, or losing exact revision provenance.

Spec lineage

Parent: Cycle 56 derived asset library and restore

    Outcome

    An authenticated owner can open a stable current-reader URL or an immutable revision URL, select real rendered HTML, send that selection into Antiek's shared note and deep-research actions, and see the exact asset/revision/hash/generation identity that grounds those actions.

    Identity model

    Stable context

    derived_asset_id is the long-lived reading and companion context. Revision changes do not strand the operator's conversation.

    Immutable grounding

    Every read response names revision_id and content_sha256. Selection actions carry that tuple as provenance metadata.

    One byte authority

    derived_asset_revisions.canonical_html remains the only canonical body. No copy is written to documents.raw_text, book storage, browser persistence, or a projection cache.

    Current resolution

    The stable route resolves and verifies the current pointer on each load. An exact revision route never follows the pointer and clearly identifies historical content.

    Read API

    • GET /research/derived-assets/assets/{asset_id}/reading returns the verified current title, kind, revision tuple, generation, member count, canonical HTML, and stable/exact reader paths.
    • GET /research/derived-assets/assets/{asset_id}/revisions/{revision_id}/reading returns the same model for an immutable revision and reports whether it is current.
    • Both endpoints are authenticated, owner-derived, parameter-free, body-free, bounded by the Cycle 56 complete-chain verifier, JSON encoded, and private, no-store.
    • Foreign and missing assets/revisions are indistinguishable. Integrity failures are typed conflicts and never return partial HTML.

    Reader contract

    1. /read/derived/:assetId resolves the current verified model; /read/derived/:assetId/revisions/:revisionId resolves immutable history.
    2. The canonical fragment is rendered as selectable semantic HTML inside the reader scope. The server's closed sanitizer policy is the admission authority; the client never sanitizes into different bytes or trusts caller HTML.
    3. The header shows title, asset kind, current/historical state, generation, and a short exact revision/hash identity. Historical reading offers a return-to-current command.
    4. The shared FloatMenu is reused. Its provenance resolver binds stable asset ID plus exact revision/hash/generation metadata and refuses actions until a verified model exists.
    5. The existing reading companion follows the stable asset context. A current-head refresh replaces the rendered model atomically and collapses stale browser selections.

    Graph boundary

    This cycle establishes a typed read/provenance bridge, not a fake book or mutable graph-body projection. Search chunks and durable graph document registration require deterministic HTML section chunking plus revision-aware citation semantics; until that child spec lands, the reader may launch selection-grounded research but must not claim whole-document graph indexing.

    Acceptance harness

    • Current and exact endpoints return only owner-visible, fully verified canonical models and reject query strings and GET bodies.
    • Current revise/restore resolution changes the exact tuple; immutable URLs continue to return their original tuple and bytes.
    • Corrupt bytes, hashes, manifests, members, policy, acknowledgement, lineage, pointer, or generation fail closed.
    • The UI renders nested canonical HTML as selectable DOM, not escaped text or an iframe, and never calls book/full-text APIs.
    • FloatMenu receives stable and immutable provenance; stale loads cannot overwrite a newer asset/revision request.
    • Library entry opens the stable reader. Historical entries open immutable reader URLs. Frontend tests, TypeScript, production build, backend tests, hostile review, and HardenX pass.

    Rejected alternatives

    • Registering a derived asset as a book: invokes unrelated rights, marketplace, ad, pagination, and plain-text contracts.
    • Copying HTML into documents.raw_text: creates a mutable second body authority and destroys HTML structure.
    • Iframe-only reading: blocks native selection, annotation anchoring, and shared reader interactions.
    • Revision ID as the only conversation identity: strands companion history after every revise or restore.
    • Stable asset ID without revision provenance: lets later content silently reinterpret old selections and citations.
    • Client-supplied owner, HTML, title, revision, hash, or generation: expands authority and creates cross-account or stale-content paths.

    Deferred child specs

    • Revision-aware deterministic HTML section chunking and graph document projection.
    • Durable DOM-range highlight anchors with re-anchoring across derived revisions.
    • Whole-document companion retrieval over verified current or explicitly pinned revision context.

    Five-values rigor

    Honesty: the UI names exact persisted identity and does not claim indexing that is absent. Fairness: ownership is server-derived and foreign equals missing. Rigor: stable context and immutable grounding are separate typed fields. Diligence: every read reuses complete-chain verification. Defensibility: one byte authority and immutable deep links preserve auditability.

    Harness hint

    Implement verified service model, owner-only routes, typed client, dedicated reader, and library links in dependency order; then refute ownership, integrity, stale-response, rendering, and provenance claims.
