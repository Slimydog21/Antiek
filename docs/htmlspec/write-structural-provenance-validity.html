Cycle 43: structural provenance validity

Status: executable master sprint spec. Base: Cycle 42 reviewed commit 7a3d21632.

Problem

Cycle 42 binds paragraph provenance to exact prose, but outline blocks can be placed, reordered, moved, or removed while the prose remains byte-identical. Generation consumes the ordered section block set. A paragraph must therefore not remain current after that generating input changes.

Identity

The structural fingerprint is SHA-256 over canonical compact JSON containing the section's ordered tuples of outline block ID, integer index, block kind, provenance kind, node ID, source kind, source ID, content, cluster ID, and canonical metadata. Ordering is by block index then outline block ID. This proves exact input identity, not semantic equivalence.

Mutation contract

OperationRequired behavior
PlaceInsert and invalidate the destination section in one explicit transaction. An ignored duplicate is a true no-op.
Move or reorderReject cross-deliverable ownership. Invalidate source and destination once each in the same transaction. An identical section and index is a true no-op.
RemoveDelete and invalidate the former section in one transaction. A missing block is a true no-op.
InvalidationChange current paragraphs to stale, remove their current mappings, preserve prose and non-current statuses, record reason and post-mutation fingerprint.

Atomicity and events

Each public structural primitive owns an explicit DuckDB transaction and rolls back both structural and validity writes on failure. The already-atomic composition import explicitly delegates transaction ownership to its enclosing transaction. Typed JSONL events are emitted only after commit. They are not atomically durable with DuckDB; a transactional outbox remains a separate future authority boundary.

Acceptance

  1. Fresh generation records the exact current structural fingerprint.
  2. Place, intra-section reorder, cross-section move, and remove stale all previously current paragraphs in every affected section and expose no current source mapping.
  3. Duplicate placement, identical move, and missing removal do not alter validity.
  4. Cross-deliverable moves fail before mutation.
  5. Injected invalidation failure rolls back the structural mutation and emits no event.
  6. Legacy or malformed validity remains fail-closed.
