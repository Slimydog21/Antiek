BYOK model route authority foundation

Status: executable substrate slice. Parent: docs/specs/byok-model-route-authority.md.

Finding

The existing generic text dispatcher is not a hard-ceiling provider gateway. Its fallback may execute a route different from the selected route, while generic OpenAI-compatible and Anthropic adapters provide neither provider idempotency nor authoritative billing reconciliation. A picker wired directly to provider_override would therefore overstate execution authority.

Outcome

  • One shared server resolver accepts only {authority:user_model, provider_id, model_id}.
  • Resolution reopens the durable registry and credential metadata and requires exact enabled record, exact model, exact credential pipeline/account binding, and live registration.
  • Inventory distinguishes registered, tier-ready, route-authoritative, pricing-known, and hard-ceiling-executable states.
  • All failures are value-free and no credential is decrypted during resolution.

Execution gate

Resolved generic BYOK routes remain hard_ceiling_eligible=false until a text provider adapter supports send-once idempotency, authoritative reconciliation, exact-route holds, and fallback as a separately projected/reserved attempt. Start Research and collective launch must not expose the picker before that gate exists.

Acceptance

  • Exact enabled binding resolves deterministically.
  • Unknown model pair, deleted/disabled record, stale registration, changed credential reference, unrelated credential, and malformed choice fail before provider calls.
  • Responses and durable files contain no key material.
  • Concurrent reads do not cache stale authority.
  • Focused tests, lint, strict security scan, and hostile review pass.

Next sub-spec

  1. Add hard-ceiling adapters only for providers with stable idempotency and billing-status APIs.
  2. Project and reserve each fallback route independently; never reuse the selected-route hold.
  3. Persist requested route, resolved route, hold, actual dispatch route, and fallback index.
  4. Then wire the existing ModelDecisionBar into Start Research and collective launch.
