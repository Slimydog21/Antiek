Preview multimedia revisions before granting mutation authority

Status: executable sub-spec. Parent: Antiek Multimedia SPR-07 Steering and Revisions. Depends on: Multimedia Voice Steering Capture.

Product contract

Text and voice steering first produce a non-mutating, owner-scoped preview. An ambiguous request returns the parser's concrete clarification questions. A ready request returns the exact operations, affected segments, reuse proof, route policy, and deduplicated incremental cost. The operator must issue a separate Apply command before Antiek creates a child revision.

Apply carries an expiring HMAC authority generated by the server. It binds the owner, asset, exact parent revision, prompt, raw voice transcript, corrected voice transcript, and canonical preview plan. Apply reparses and replans under the store's exclusive lock and fails closed if any bound content or plan changed.

Five-values rigor

  • Truth: clarification and cost are computed by the same parser and planner used during Apply; no speculative client reconstruction.
  • Utility: the operator sees what changes, what is reused, and the incremental spend before mutation.
  • Agency: preview has zero persistence and zero provider execution; only the explicit Apply command creates a child revision.
  • Auditability: authority binds exact semantic inputs and the canonical plan, while the child keeps existing lineage, intent, and job history.
  • Safety: owner scoping, expiry, signature verification, constant-time digest checks, and revision compare-and-swap prevent substitution, replay, and stale application.

API contract

  • POST /multimedia/assets/{asset_id}/steering-preview accepts expected_parent_revision_id plus the prompt and optional raw/corrected voice fields. Valid clarification and ready outcomes return HTTP 200 as a discriminated union.
  • A ready response contains preview_token, expiry, operations, affected segment IDs, segment reuse with file hashes, changes, route policy, proposed revision ID, and authoritative total cost.
  • POST /multimedia/assets/{asset_id}/steer requires the same exact request snapshot and its preview token. It returns the persisted child record only after authority verification under the exclusive store lock.
  • Stable conflicts include multimedia_steering_stale_parent, multimedia_steering_preview_expired, multimedia_steering_preview_content_mismatch, and multimedia_steering_preview_plan_mismatch.

Failure and race model

  • Preview takes a shared lock and performs no save, job append, link clearing, provider call, or mutation of store bytes or mtime.
  • Apply loads the owner-scoped asset and checks the current revision inside one exclusive lock before any mutation.
  • Editing text or voice, switching asset/revision, or receiving a late response invalidates the client preview.
  • One authority can succeed at most once because successful Apply advances the revision; concurrent or replayed Apply fails stale.
  • Corrected voice remains the parser input, but prompt, raw transcript, and correction are all authority-bound.

Deployment contract

  • Every production API worker must share ANTIEK_MULTIMEDIA_STEERING_PREVIEW_KEY_HEX, or share a stable ANTIEK_AUTH_SECRET from which a domain-separated key is derived. The process-ephemeral fallback is local-development-only because another worker cannot verify its tokens.
  • The canonical plan digest includes the complete child manifest as well as operations, scope, reuse, changes, route policy, cost, and proposed revision identity.

Rejected alternatives

  • Unsigned deterministic digest: rejected because a client could forge a value that appears server-authorized.
  • Persist preview records: rejected because preview must be observational and replay protection already follows from revision CAS.
  • Trust the returned plan at Apply: rejected because current parent state and deterministic planning must be revalidated under the write lock.
  • Keep one-click public steering: rejected because it bypasses informed cost and scope consent.

Acceptance

  • Clarification is structured, exact, visible, and cannot be applied.
  • Ready preview exposes exact cost, scope, route policy, and reuse proof without changing persisted bytes, jobs, links, revision, or mtime.
  • Apply succeeds with one exact authority and rejects stale, replayed, expired, tampered, cross-owner, cross-asset, and modified prompt/voice requests without mutation.
  • Two concurrent applies produce exactly one child revision.
  • Multi-segment incremental cost is deduplicated by segment rather than multiplied by operation or nested iteration.
  • Frontend tests cover clarification, ready review, explicit Apply, invalidation on edits/voice/asset/revision, late responses, and conflicts.
  • Focused Python and Vitest suites, TypeScript, production build, HTML parse, hardening, and independent review pass before merge.

Non-goals

No provider execution, paid rendering, preview persistence, collaborative approval, continuous voice interaction, background jobs, publication, or model-generated clarification answers.

Execute backend authority and mutation-proof tests first, then client state and stale-response tests, then independent security and product review.
