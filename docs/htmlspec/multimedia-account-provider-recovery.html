Account-Bound Provider Recovery

TS executable sub-spec. Stacked on PR #947. A provider-account recovery credential is authority for exactly one Antiek account, never a process-global capability.

Five Values

  1. Explicit owner: configuration includes the SHA-256 digest of one normalized authenticated Antiek owner.
  2. Zero-call denial: a foreign execution is rejected before gateway transport, token use, or response parsing.
  3. Two identities: Antiek owner identity and external provider-account identity remain separate mandatory digests.
  4. Fail closed: legacy four-field or partial recovery configuration cannot construct a runtime.
  5. Honest canary: deterministic injected transport proves binding and evidence signing without network, credentials, or spend.

Configuration Contract

VariableAuthority
ANTIEK_MULTIMEDIA_RECOVERY_OPERATOR_SHA256Canonical lowercase SHA-256 of the normalized authenticated Antiek owner ID.
ANTIEK_MULTIMEDIA_RECOVERY_ACCOUNT_SHA256Independent digest of the external provider account queried by the gateway.
Endpoint, allowed host, tokenOne fixed HTTPS gateway and credential. All five recovery values are all-or-none.

The adapter hashes the persisted execution operator ID using the same stripped UTF-8 normalization as the owner-scoped asset store. A mismatch returns an opaque recovery-unavailable error before invoking transport.

Non-Goals And Next Seam

No live provider request, credential provisioning, paid spend, refund, model routing, settings UI, merge, or deploy. Multi-account installations may later replace the single environment binding with an encrypted owner-indexed registry; the adapter owner check remains mandatory.
