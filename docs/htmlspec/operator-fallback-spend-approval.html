Carry exact fallback approval terms to the operator boundary

Project immutable owner-scoped approval terms through the existing history route and strict browser client without granting execution authority.

Outcome

An authenticated Settings consumer can inspect one validated unattempted fallback chain and submit its exact manifest digest and run ceiling to the existing durable approval endpoint. The response is accepted only when every identity and economic term matches the preview.

Authority

  1. The server derives USD currency, run ceiling, maximum sequential exposure, and eligibility from owner-bound persisted state.
  2. Eligibility is true only for an entirely unattempted chain with no prior approval.
  3. The browser posts only the exact chain path, manifest digest, and ceiling from that validated preview.
  4. Approval creates no hold and grants no dispatch, send, retry, reconciliation, or provider-selection command.

Transport contract

  • History uses an exact response shape and rejects invalid currency, bounds, route exposure, eligibility, approval identity, or calendar timestamp.
  • The approval receipt uses an exact response shape and must match chain, manifest, currency, ceiling, maximum exposure, approval-ID format, and a real timestamp.
  • HTTP failures expose status only; provider bodies and private ledger values are not reflected.

Ownership boundary

The active Model Observatory lane owns the Settings component, tests, stories, and CSS. This direct-main sprint intentionally stops at the typed API client. The two-gesture review interaction is an integration follow-up on that owner branch, not a parallel UI.

Acceptance

  • Owner-derived history exposes exact terms before and after approval.
  • Malformed and substituted browser responses fail closed.
  • Exact approval replay remains durable and creates zero spend holds.
  • Focused backend/frontend tests, types, lint, build, security, and heterogeneous review pass.

Non-goals

No Settings UI mutation, hold, paid execution, automatic dispatch, retry, reconciliation, provider routing, merge, or deployment.
