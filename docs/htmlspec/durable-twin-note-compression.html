CYCLE 47

Durable twin-note compression

Turn explicit ordered sets of completed recursive-note windows into immutable, HTML-native, cross-document twin revisions without another model call.

Spec lineage

Parent: Cycle 46 durable note replay. Related pure advisory substrate: substrate/twin_note_taker.

  • No child specs; publication and revision identity form one atomic boundary.

Outcome

Given an authenticated account, target asset, exact expected predecessor, and an explicitly ordered non-empty tuple of completed V20 windows, create or replay exactly one immutable twin-note revision whose database bytes, member ledger, static HTML path, and completion event all bind the same deterministic identity. No provider, dispatcher, budget authority, or signed-generation receipt is invoked or fabricated.

Five values

Precision

Order, investigation, window identity, source digest, raw-result digest, account, asset, predecessor, renderer, and compressor versions enter revision identity.

Exhaustiveness

Crash tests cover transaction commit, temporary write, file fsync, link, directory fsync, event append, and receipts.

Craftsmanship

V20 remains immutable. ResearchArtifact HTML, DuckDB locking, physical note evidence, and the shared event outbox are reused.

Honesty

Output authority is window_note_compression_v1, not grounded truth and not the signed model-generated twin authority.

Information

Every note remains attributable to its member window and underlying source-event set; no semantic truncation or invented synthesis.

Authority boundaries

  • An injected authoritative resolver must prove each investigation belongs to the authenticated account and target asset. V20 document_id is not ownership proof.
  • Only completed windows are eligible. Recompute request, source-list, and raw-result digests before admission.
  • Parse stored raw output with the existing parser. Never call a model. Preserve member order then note order; deduplicate exact canonical note identities by first occurrence only.
  • Output uses ResearchArtifactBody.agent_notes; graph insights/questions and synthesis remain withheld until separate evidence-backed promotion.
  • Static compression HTML omits the shared renderer's mutable textarea and JavaScript.

Schema V21

twin_note_revisions(
 revision_id PRIMARY KEY, account_id, asset_id, supersedes_revision_id,
 compressor_version CHECK = 1, renderer_version CHECK = 1,
 membership_sha256, body_json, body_sha256, html_bytes BLOB, html_sha256,
 relative_path, note_count, source_event_count, created_at,
 UNIQUE(account_id, asset_id, membership_sha256, supersedes_revision_id),
 UNIQUE(account_id, asset_id, relative_path),
 CHECK(supersedes_revision_id IS NULL OR supersedes_revision_id != revision_id)
)
twin_note_revision_members(
 revision_id, member_ordinal, investigation_id, window_id,
 consumer_version, window_ordinal, source_digest, raw_result_sha256,
 PRIMARY KEY(revision_id, member_ordinal), UNIQUE(revision_id, window_id)
)
twin_note_publication_effects(
 effect_id PRIMARY KEY, revision_id UNIQUE, expected_path, expected_sha256,
 state CHECK IN ('pending','published'), attempt_count, published_at, created_at
)

All revision/member columns are append-only. Only effect state may advance. Strict full fingerprints and empty-only repair are mandatory.

Identity

membership_sha256 = sha256(canonical ordered member fingerprints)
revision_id = "tnr-" + sha256(account, asset, predecessor, membership, versions)[:32]
effect_id = "tne-" + sha256(revision, path, html_sha256)[:32]
relative_path = sha256(account)[:24] / sha256(asset)[:24] / revision_id.html

Changing order creates a different revision. An exact retry with the same predecessor must byte-compare every immutable field. A stale predecessor fails; it cannot create a fork. Current means no same-account/asset successor references that revision.

Acceptance

  • Two investigations in A,B versus B,A order produce different revisions and preserve display order.
  • Exact retry returns identical DB and HTML bytes, one file, one event, and no model call.
  • Duplicate, missing, uncertain, materialized-only, corrupted, cross-account, or wrong-asset members fail before insertion.
  • Equal asset IDs across accounts have isolated paths and current revisions.
  • Successor requires exact current predecessor; stale concurrent attempts permit one successor and retain predecessor bytes.
  • Every crash checkpoint recovers one exact final file; conflicting path bytes fail closed.
  • HTML contains attribution and no mutation script, timestamp, random ID, or environment-derived bytes.
  • Source/note/byte ceilings fail without truncation.
  • V21 empty partial schema repairs; populated incompatibility fails.
  • Cycle 46 replay, twin generator/search/promotion, renderer, and outbox suites remain green.

Rejected alternatives

  • Mint a local signed twin receipt: would counterfeit authority owned by the dispatch signer.
  • Use V20 document ID as ownership: it is metadata, not authenticated account authority.
  • Mutable current.html: creates replacement and rollback ambiguity; current is a DB query.
  • Overwrite one twin row: destroys history and makes supersession unverifiable.
  • Call a summarizer: adds cost and provider uncertainty to a deterministic transport boundary.
  • Best-effort file write: loses the human-viewable twin after a committed revision.

Out of scope

HTTP/UI workflows, remote object storage, model-authored cross-document synthesis, semantic clustering, deletion, graph promotion, and serving authorization are later cycles.

Harness hint

Implement schema and service as one boundary; then kill or interrupt every external-effect checkpoint and independently audit identity reuse and ownership.
