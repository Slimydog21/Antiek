Provider reconciliation without provider execution

Outcome

An authenticated product command can eventually ask one qualified provider adapter about one exact persisted paid hold without gaining authority to send, retry, or advance a fallback chain.

Current provider fact

Ordinary synchronous OpenAI-compatible and Anthropic chat APIs are not qualified merely because they expose request identifiers. Production remains fail-closed until an adapter proves durable caller idempotency, authoritative lookup by that identity, disabled hidden retries, exact billing units, and current server-owned route authority.

Authority contract

  1. The caller supplies a persisted hold identity and a server-composed adapter, never provider evidence or a desired outcome.
  2. The gateway first proves in one read transaction that one owner-scoped hold belongs to the exact persisted chain route and its immutable approval receipt, then locks that reservation and repeats the complete transactional proof.
  3. It exact-matches the canonical projection digest, provider, model, hard-ceiling capabilities, billing units, endpoint, and mandatory manifest route-authority digest.
  4. reserved is rejected because no provider outcome exists. Terminal holds return without lookup.
  5. dispatch_possible and unknown invoke exactly one authoritative lookup after database identity verification.
  6. charged settles exact provider cents; not_found releases; unknown, malformed evidence, contradiction, and lookup failure retain the full hold.

Structural non-execution

The method accepts no operation payload and no fallback route list. It cannot call send_once, reserve a new hold, or continue to another route. Provider reconciliation is evidence-only.

Future composition

A later authenticated distillation action may resolve the current manifest-bound hold through a server-owned adapter registry and then refresh the Cycle 94 read model. It must not accept an adapter name, endpoint, idempotency key, evidence, status, or cents from request JSON. Legacy holds without persisted route authority remain held.

Non-goals

No HTTP or UI action, generic adapter qualification, provider implementation, retry, fallback continuation, ledger schema, live provider call, merge, or deployment.
