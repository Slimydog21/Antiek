Antiek Multimedia / Cycle 23

Preserve a learned claim as an evidence-bound research intent

Let a listener capture what they want to investigate without losing exact provenance or accidentally launching unowned, unbudgeted research.

Decision

A verified multimedia claim may create only a private, owner-scoped research intent. The server reopens the current registered audio authority and snapshots its exact claim evidence. Intent creation does not create an investigation or cascade plan, call a model/provider, reserve or approve spend, write the knowledge graph, or imply that research has started.

HTTP Contract

OperationContract
POST /multimedia/assets/{asset_id}/research-intentsBody contains only expected revision, line ID, a 3–2000 character question, and a 16–128 character idempotency key. Returns 201 for first creation and 200 for exact replay.
GET /multimedia/research-intents/{intent_id}Returns only the authenticated owner's immutable intent. Foreign and missing IDs are the same opaque 404.

Responses are private, no-store. A legacy/unverified claim returns 409. Missing, foreign, stale, unregistered, or malformed audio authority returns an opaque 404 or an integrity 409 without exposing another owner.

Durable Intent

  • Persist beneath the multimedia store root in a dedicated SQLite authority ledger with transactional uniqueness on (owner_identity_digest, idempotency_key).
  • Store a random opaque intent ID, owner digest, question, asset/revision, receipt and audio hashes, chapter and line IDs, trusted claim text and follow-up prompt, every exact evidence source, canonical evidence digest, canonical request digest, creation time, and immutable state prepared.
  • Same owner/key/request/evidence returns the original intent. Same owner/key with any question, claim, revision, receipt, audio, or evidence drift returns 409. Different owners may reuse a key.
  • Every create re-resolves current owner playback metadata and selects the line server-side. The browser cannot submit claim text, source IDs, excerpts, byte ranges, hashes, receipt identity, owner, status, plan ID, authority digest, budget, provider, or model.
  • Evidence digest covers asset/revision, receipt/audio hashes, chapter/line identity, claim/follow-up text, ordered source identities, exact text, byte ranges, and chunk/span hashes.

Plan Boundary

The projection reports plan_handoff_status=blocked_unowned_plan_store, provider_launch_authorized=false, spend_authority_digest=null, and a server-derived plan seed containing the question plus immutable intent/evidence digests. It does not expose raw owner identity.

Cycle 24 must owner-scope cascade plan create/get/edit/approve/preview/spend-approve/launch, remove caller-authored approver identity, and preserve intent provenance in the plan digest before this handoff can become executable.

Workstation

  • Only verified_exact learned claims offer Research this. Legacy claims retain their unavailable-evidence state and cannot create an intent.
  • The action opens an editable question initialized from the trusted follow-up prompt while the immutable claim and source evidence remain visible.
  • Prepare research creates the intent once, disables duplicate submission, recovers exact retries, and reports that plan review is the next step but currently unavailable.
  • No mount, evidence expansion, typing, voice capture, or successful preparation calls /investigations, plan approval, spend approval, or launch.

Refusals

  • No intent for video, legacy claims, unknown line IDs, stale revisions, foreign assets, missing registration, receipt/link drift, malformed exact evidence, or unsafe/corrupt ledger state.
  • No graph-node inference substitutes for the exact receipt-verified learned claim. No client evidence is merged with authority.
  • No deterministic public ID derived from owner or evidence. No owner ID, filesystem path, receipt body, signing material, or historical revision row is returned.

Acceptance Evidence

  • Ledger tests cover owner isolation, exact replay, drift conflict, concurrency, persistence, private database permissions, bounded canonical records, and corrupt schema refusal.
  • Route tests cover auth, local and paid exact claims, legacy refusal, foreign opacity, stale revision, unknown line, schema rejection, no-store success/error responses, and zero provider/event/spend calls.
  • Browser tests cover exact-only action, trusted default question, editable question with immutable evidence, duplicate-click prevention, retry, identity reset, and no execution endpoints.
  • Focused and broad multimedia suites, TypeScript, production build, Ruff, HTML parsing, diff hygiene, independent adversarial review, and HardenX strict pass on the exact tree.

Harness Hint

One critic attacks playback/evidence re-resolution and owner/key races. Another attacks browser identity changes and verifies that preparation never becomes execution.
