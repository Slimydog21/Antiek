Distillation Provider Check Control

Status: Cycle 98 implementation contract.

Purpose

Expose the Cycle 97 provider-check action to the authenticated reading workstation only when the server has composed qualified reconciliation authority.

Capability truth

  1. A reserved hold reports executable because its ledger-proven release action is available.
  2. A dispatch-possible or unknown hold reports executable only when the runtime contains a server-owned provider authority resolver.
  3. A settled or released hold never reports executable.
  4. Reading the capability never invokes the resolver or provider.

Operator interaction

  1. The client derives immutable expected command, run, chain, manifest, route, hold, and state terms from one authoritative response.
  2. The client cannot submit provider, model, endpoint, credential, evidence, outcome, or cents.
  3. One explicit gesture invokes the provider-check endpoint; an in-flight guard rejects duplicate local gestures.
  4. Charged and not-found outcomes render terminal ledger truth. Unknown remains held and may be checked again explicitly.
  5. Conflict or transport failure discards all prior terms, redacts details, retains the budget warning, and requires a fresh evidence read.

Acceptance criteria

  • Backend tests prove state-derived capability with and without a resolver and zero resolver calls during reads.
  • Client tests prove strict response consistency, exact request shape, unavailable suppression, settlement, unknown retention, and stale-term discard.
  • No code path sends, retries, advances fallback, or restores unknown exposure locally.
  • Backend and frontend tests, typecheck, build, diff hygiene, HardenX, and hostile review pass before transport.
