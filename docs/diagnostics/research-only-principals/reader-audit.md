# Direct-reader correction

The 560e46267 verification overstated coverage of citation projections. The three
mounted explain routes read chunks directly and leaked licensed bodies. The export
refusal also rejected ordinary Phase 2 event logs. Prior ACCEPT statements describe
the earlier review, not acceptance of the corrected implementation.

## Scope and discovery

`reader-inventory.json` records the production Python SQL expressions and literal
`chunks` table bindings discovered by `tools/lint/chunk_reader_census.py`. The scan
covers aliases, wildcard projections, concatenation, f-strings, whole database
export, and dynamic table-name bindings. It includes metadata-only queries and
write-only matches so omissions remain visible. Tests and benchmarks are excluded.
A separate tracked non-Python search for FROM/JOIN chunks and chunks.text found no
readers in SQL, TypeScript, JavaScript, shell, Go, or Rust files.

Every listed expression has an audience, disposition, and evidence. The test suite
compares SQL and enclosing-function fingerprints against the inventory. It refuses
new or changed readers until their review is renewed. Additional source dependency
fingerprints cover the dynamic merge consumer and downstream context/serialization
code. This is a review trigger, not a proof against arbitrary generated SQL.

The owner-provider probe established reachability under the buyer's credential
before correction. Checking chunk IDs in a composite prompt was insufficient:
question text could confuse the parser, and a public ID could accompany forged
body text. The final path accepts the typed request, re-reads canonical allowed
bodies, reconstructs the prompt, and discards the historical graph block. Missing,
restricted, and unclassifiable source contexts refuse before buyer dispatch.

## Adjacent readers and trust limits

Sidecar document raw_text was included because it is another body representation.
The session evidence-pack function hashes supplied chunks and returns a digest.
The dynamic staging merge copies table rows into a server database; its CLI reports
counts. The admin investigation smoke CLI prints a short source excerpt and the
reembedding CLI sends bodies to the configured embedding service. They require host
access and are not exposed to the authenticated product owner. Restricting host
administrator access is outside this principal split.

Wrestling can also accept an excerpt from an owner-originated region-selection
event. Its database resolution is now restricted. This change does not attempt to
classify text already supplied by the owner. Derived note and model-result output
remains available; these checks do not establish that model-generated prose always
obeys a quotation contract. Historical derived prose is not scrubbed.

No production activation, deployment, or successful live provider call is part of
this verification. This inventory covers the repository at the reviewed revision;
new dynamic SQL mechanisms or new body representations require extending discovery.
