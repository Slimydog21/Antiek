## PR #3033 — feat(rlm): metered Prime Agent execution foundation

**Branch:** `feat/prime-agent-metered-foundation` → `main`
**Files:** 12 (+2,889 / −132)
**Verdict:** **APPROVE**

### Findings

1. **DuckDB invariant: CLEAN.** The new module (`prime_ledger.py`) is a **SQLite** database (`owner-launches.sqlite3` pattern), not DuckDB. It never touches `antiek.duckdb` or any DuckDB write path. Its writes are serialized through `BEGIN IMMEDIATE` transactions, which is the correct SQLite concurrency primitive. `orchestration/rlm/prime_ledger.py:138` — `connection.execute("PRAGMA journal_mode=DELETE")` avoids WAL sidecars, keeping permission auditing simple.

2. **Secret hygiene: STRONG.** The `PrimeSecret` class (`orchestration/rlm/prime_authority.py:448-466`) is intentionally non-serializable — `__repr__` returns `"PrimeSecret([REDACTED])"`, `__str__` returns `"[REDACTED]"`, and the raw value is only accessible via `.reveal()`. Tests (`test_prime_rpc_evidence.py:2669-2670`) verify that secret text never appears in repr, str, or serialized output.

3. **Credential binding: CORRECT.** `ResolvedPrimeCredential.matches()` (`prime_authority.py:498-505`) verifies all six identity facts (owner_id, payer_id, provider, credential_id, credential_fingerprint, env_name) before the secret is revealed. The fingerprint is SHA-256 and checked against the authorization request. `orchestration/rlm/prime_rpc_evidence.py:1203-1210` — the resolved credential is validated before the process launches.

4. **Environment isolation: WELL-DESIGNED.** The old code passed only `PATH, HOME, LANG, LC_ALL, TMPDIR` via `_PASSTHROUGH_ENV`. The new code passes the full environment to the backend config, but the process layer (`runtime/prime_agent/process.py:210-231`, `_isolated_environment`) reconstructs a minimal environment from only `PATH, LANG, LC_ALL`, adds isolated `HOME/TMPDIR/XDG_*` directories, and injects exactly ONE allowlisted provider credential. The full env never reaches the subprocess. `runtime/prime_agent/process.py:254-259` — `PrimeAgentProcessConfig.__post_init__` enforces exactly one recognized provider credential key.

5. **Spend cap: NON-BYPASSABLE.** The ledger enforces a hard `PRIME_SESSION_CAP_MICRO_USD = 5_000_000` ($5.00). The cap is checked atomically against `SUM(charged) + SUM(held)` within the same `BEGIN IMMEDIATE` transaction that inserts the new reservation. `orchestration/rlm/prime_ledger.py:723-730`.

6. **Overrun protection: PRESENT.** The ledger has an `UNKNOWN` state with a "frozen session" check: if any call in the session entered `UNKNOWN` with `observed_cost > max_cost`, the entire session is frozen until manually resolved. `orchestration/rlm/prime_ledger.py:737-744`.

7. **Immutable replay protection: CORRECT.** Authorization requests carry `request_id`, `idempotency_key`, and `nonce` — all three are UNIQUE in the schema. Replay with mismatched immutable facts raises `PrimeReplayMismatch`. `orchestration/rlm/prime_ledger.py:703-712`.

8. **Honest state: PASS.** The RPC outcome reports exact terminal states (SUCCEEDED, FAILED, CANCELLED, UNKNOWN) — no fabricated success. `orchestration/rlm/prime_rpc_evidence.py:125-128`. Usage that doesn't match the authorization (wrong provider/model/version or over-budget cost) transitions to `UNKNOWN` with the hold retained, never silently succeeded. `prime_ledger.py:902-920`.

### Nits
- `orchestration/rlm/prime_authority.py:269` — `PRIME_PROVIDER_CREDENTIAL_ENV` is a `MappingProxyType` (immutable), but `PrimeAuthorizationRequest.__post_init__` at L358 reads from it with `.get()`. The mapping includes only `anthropic`, `openai`, `google` — adding a new provider requires editing this constant. Consider documenting the extension point.
- `runtime/prime_agent/process.py:1947` — `_PROVIDER_CREDENTIAL_KEYS` hardcodes five provider env var names. If a new provider is added to `PRIME_PROVIDER_CREDENTIAL_ENV`, this frozenset must also be updated. These two constants should be derived from a single source of truth.
