Status: PR #465 implementation record. Generated campaign inventories and session transcripts are

## Product contract

Antiek’s product loop is:

`acquire → canonical HTML → read/wrestle → branch research → preserve provenance → merge/draft →`
`twin insights/questions → knowledge graph → write/publish → learn from outcomes`.

Reading and research share this loop. PDF may be an ingest source but is never the canonical human
view. Model choice, spend, suite changes, and production mutations remain operator-controlled.
NotDiamond and Antiek-bench provide advisory evidence; neither is routing authority.

## Recursive twin-note completion rule

Every durable information asset should expose a twin document of insights and questions. A new
surface is complete only when it proves:

1. canonical HTML identity and provenance;
2. offline-honest empty/live seed state;
3. selective promotion without invented body text;
4. merge/reference/search participation;
5. parity between reading and research entry points;
6. usage learning that proposes benchmark changes but never auto-promotes them.

## Marketplace and book rule

- Search free/public-domain sources before presenting purchase.
- Never count a purchased title as free.
- Never host paid content without a confirmed entitlement or explicit manual receipt.
- Convert the acquired asset to canonical HTML before it enters the library.
- Preserve source, license/rights, receipt, conversion, and account-host provenance.
- Keep live payment disabled until an operator-approved adapter and legal/product contract exist.

## Collective research rule

Offline cohesive-unit merge remains the fallback. Live multi-agent execution must be explicitly
enabled, budget-reserved before fan-out, provenance-complete, and able to return to the same merge/
draft/twin substrate. Outputs never auto-merge into a source asset or auto-promote into the graph.

## NotDiamond decision

NotDiamond is useful as an advisory comparison beside measured Antiek-bench evidence. It must not:

- silently choose the production model;
- bypass the decision-tree/manual model control;
- hide prompt-cost projections;
- promote its weekly suggestion into a default driver;
- become required for offline operation.

An assisted action may later be specified as an explicit per-prompt “use this suggestion” choice,
still showing cost and retaining manual override. That is not automatic routing.

## Execution discipline for future agents

1. Read the control-plane directive and active ownership board before mutation.
2. Prefer a real product-loop connection over another adapter, checklist, or scorecard.
3. Preserve one authority per concern: budget, idempotency, provenance, routing, and suite promotion.
4. Label paid/live/prod gates `RUN` or `NOT RUN` precisely.
5. Use HTML specs for executable future work and decision records for durable conclusions.
6. Never commit inventory splits, session arcs, test transcripts, or orchestration run state.

The next highest-value work is product wiring after operator integration: synthesis spans → evidence
floor → citation gate, then research brief gates at real launch entry points. Do not build parallel
libraries while the providing stacked PRs remain unmerged or actively owned.
