1 · Goal

Port WrestleApp (the PDF wrestling surface) onto the panel system. Critically, prove the panel-layout shell does not degrade pdf.js performance. A 1200×900 floating PDF panel must scroll at ≥ 45 fps on M1 with a 200-page PDF loaded. If it cannot, the panel system's animation strategy needs adjustment before S7 builds the notebook on top.

2 · Why this sprint exists

PDF rendering is the worst-case workload for any layout primitive that animates or re-parents children. Validating pdf.js inside the panel system here, before S7 builds the notebook with embedded PDF regions, prevents a late-stage discovery that the abstraction can't hold the heaviest tenant.

3 · Non-goals

  • No new PDF features (annotations, OCR, etc.). Pure port.
  • No PDF library swap. pdf.js stays. The 2.2 MB pdf.worker bundle is not in the main-chunk budget.
  • No region-embed → notebook integration. That's S7.
  • No mobile PDF surface (mobile fallback is S11).

5 · Work packages

WP-6.1

PDF render stability inside floating panels

File: src/components/PdfViewer.tsx, src/workspace/PanelLayoutPanel.tsx Effort: 1.0 d

pdf.js renders pages into <canvas> at a viewport-scale derived from CSS pixel dimensions. When a panel resizes, the canvas needs to re-render at the new resolution. The animation hand-off is the risk zone — naively, every frame of a Framer Motion resize triggers a re-render.

Implementation:

  • Add a debounced (120 ms) "size settled" hook to PanelLayoutPanel that fires only after a resize gesture ends.
  • PdfViewer subscribes to that hook and re-renders at the new pixel ratio after the gesture, not during.
  • During the gesture, the canvas keeps the previous rasterisation; CSS scales it (slightly blurry mid-resize, sharp again after). This is the standard pdf.js handover strategy.
// in PanelLayoutPanel.tsx — new ResizeObserver+debounce
export function usePanelSizeStable(id: string) {
  const ref = useRef<HTMLDivElement>(null);
  const [stableSize, setStableSize] = useState<{ w: number; h: number } | null>(null);
  useEffect(() => {
    const el = ref.current; if (!el) return;
    let t: ReturnType<typeof setTimeout> | null = null;
    const ro = new ResizeObserver((entries) => {
      const r = entries[0].contentRect;
      if (t) clearTimeout(t);
      t = setTimeout(() => setStableSize({ w: r.width, h: r.height }), 120);
    });
    ro.observe(el);
    return () => { ro.disconnect(); if (t) clearTimeout(t); };
  }, []);
  return [ref, stableSize] as const;
}

export default function WrestleApp() {
  const { documentId } = useParams<{ documentId?: string }>();
  const open = useWorkspace(s => s.open);

  const onInspectClaim = useCallback((claimId: string) => {
    open("ClaimInspector", { claimId }, { mode: "floating", title: "Claim" });
  }, [open]);

  return (
    <PanelHost starters={ documentId ? [
      { kind: "Notes",     mode: "docked-left",  props: { documentId }, title: "Notes" },
      { kind: "CrossDocs", mode: "docked-right", props: { documentId }, title: "Cross-doc" },
    ] : [] }>
      {documentId
        ? <PdfViewer documentId={documentId} onInspectClaim={onInspectClaim} />
        : <EmptyDocumentState />}
    </PanelHost>
  );
}

6 · Acceptance criteria

  • Visiting /wrestle/<id> renders PDF in main slot with Notes + CrossDocs docked.
  • Floating panel mode works for PdfViewer: cmd-click a chunk citation in MasterMdViewer → PDF opens floating over the trajectory.
  • PDF text selection still works; HighlightToolbar still anchors correctly.
  • Resizing the floating PDF panel does not crash pdf.js (the debounce hook works).
  • Performance benchmark passes: ≥ 45 fps p50 on M1, 1200×900 floating panel, 200-page PDF.
  • Bundle main chunk grows ≤ 10 KB gzipped (PDF code stays code-split).
  • Lost-Pixel: WrestleApp screenshots updated.

7 · Risks & mitigations

  • pdf.js canvas blanks mid-resize. Mitigation: the previous canvas stays mounted until the new one renders; CSS scales it as a placeholder.
  • Floating PDF panel loses focus on click, dropping text selection. Mitigation: PanelLayoutPanel only calls bringToFront on mousedown — selection state inside the panel is preserved.
  • Two floating PDF panels open simultaneously double the pdf.worker memory. Mitigation: pdf.js worker is a singleton (already is in current code); each viewer creates its own document but shares the worker. Document for future: ≥ 4 simultaneous PDFs may force a multi-worker upgrade.
  • Bench is flaky on CI. Mitigation: bench runs locally only; CI runs a smoke version (≥ 30 fps p50). Real perf gate is the manual bench.

8 · Open questions

  1. Should the PDF route auto-pin Notes + CrossDocs across documents? Default: yes (pin survives across :documentId changes).
  2. When opening a PDF from a chunk citation, should it open floating (workspace) or in the existing /wrestle/:id?page=N URL (route navigation)? Default: floating, because that's the headline UX; if the operator wants full-page, the kebab → "Open as route" navigates.
  3. Multi-PDF popout (S9): is 2 simultaneous popouts the max? Default: soft cap at 4 via toast warning, hard cap at 8.

9 · Verification protocol

  1. Load a real 200-page PDF; verify rendering inside main slot.
  2. Cmd-click a chunk citation in another route's MasterMdViewer; verify floating PDF panel opens at the right page.
  3. Drag the floating PDF panel; verify text rendering remains sharp after gesture ends.
  4. Open NotesPanel kebab → Float → drag aside → re-dock-left. Confirm state preserved.
  5. Open two ClaimInspector panels for two different claims; arrange side-by-side; both responsive.
  6. Run node scripts/bench_pdf_panel.ts; confirm fps numbers.

10 · Rollback plan

WrestleApp port is independent of RW port (S5). Rollback flips the ANTIEK_UI=v2 flag at the route level. PDF code is unchanged from substrate's perspective; only its container changed.
