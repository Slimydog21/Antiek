1 · Goal

Ship ten PostHog-Lemon-style primitive components — Button, Card, Modal, Input, Textarea, Tag, Select, Dropdown, Table, Toast — living in apps/reading/src/components/lemon/, each with a *.stories.tsx and strict-TS clean. No mode or route uses them yet; that's S5+.

2 · Why this sprint exists

Every later sprint reaches for buttons, cards, modals, dropdowns. If S3 (panel layout) starts before primitives exist, it inlines its own button styles and we end up with two flavours of LemonButton. S1 ships the primitives before consumers, so consumers compose, never re-invent.

3 · Non-goals

  • Not migrating existing components. ChatInput, ClaimCard, NotesPanel stay untouched in S1. Their migration is S5/S6/S10.
  • Not building complex composites: no LemonDataTable, no LemonForm. Just the ten primitives.
  • No light/dark mode toggle in components. Tokens permit it; S1 only ships light.
  • No animation library yet. Hover-lift uses Tailwind transition-transform + CSS. Framer Motion enters in S3.

WP-1.1

LemonButton

File: src/components/lemon/LemonButton.tsx Effort: 0.5 d

Four variants: primary (yellow + ink border + z1 shadow), secondary (white + ink border + z1 shadow), tertiary (no border, hover-tints), danger (red + ink border). Three sizes: sm / md / lg. Two states: idle, hover-lifted. Disabled state drops shadow + reduces opacity. Hover lifts by 2px and goes to z3 shadow. 

// src/components/lemon/LemonButton.tsx
import { forwardRef } from "react";
import type { ButtonHTMLAttributes, ReactNode } from "react";

type Variant = "primary" | "secondary" | "tertiary" | "danger";
type Size    = "sm" | "md" | "lg";

type Props = ButtonHTMLAttributes<HTMLButtonElement> & {
  variant?: Variant;
  size?: Size;
  icon?: ReactNode;
  iconRight?: ReactNode;
  fullWidth?: boolean;
};

const base =
  "inline-flex items-center justify-center gap-2 font-mono font-semibold " +
  "border-2 border-ink rounded-hog transition-transform duration-75 " +
  "active:translate-x-[2px] active:translate-y-[2px] active:shadow-none " +
  "disabled:opacity-50 disabled:pointer-events-none";

const variants: Record<Variant, string> = {
  primary:   "bg-hog-yellow text-ink shadow-z1 hover:-translate-x-[2px] hover:-translate-y-[2px] hover:shadow-z3",
  secondary: "bg-card text-ink shadow-z1 hover:-translate-x-[2px] hover:-translate-y-[2px] hover:shadow-z3",
  tertiary:  "border-transparent shadow-none hover:bg-paper-soft",
  danger:    "bg-hog-red text-white shadow-z1 hover:-translate-x-[2px] hover:-translate-y-[2px] hover:shadow-z3",
};

const sizes: Record<Size, string> = {
  sm: "h-7  px-2.5 text-[12px]",
  md: "h-9  px-3.5 text-[13px]",
  lg: "h-11 px-5   text-[14px]",
};

export const LemonButton = forwardRef<HTMLButtonElement, Props>(
  ({ variant = "secondary", size = "md", icon, iconRight, fullWidth,
     className = "", children, ...rest }, ref) => (
    <button ref={ref}
      className={`${base} ${variants[variant]} ${sizes[size]} ${fullWidth ? "w-full" : ""} ${className}`}
      {...rest}>
      {icon && <span className="shrink-0">{icon}</span>}
      {children}
      {iconRight && <span className="shrink-0">{iconRight}</span>}
    </button>
  )
);
LemonButton.displayName = "LemonButton";

Stories: all variants × sizes grid, disabled state, icon + label combinations, fullWidth.

Tests: RTL — primary onClick fires; disabled prevents click; icon renders before children.

WP-1.2

LemonCard

File: src/components/lemon/LemonCard.tsx Effort: 0.4 d

Container card with optional title row + footer slot. Elevation prop selects shadow (z1 | z2 | z3); colour prop selects background (card | yellow | blue | red | teal). Wrapper for all panel content in S3 + S5+. 

type Props = {
  title?: ReactNode;
  footer?: ReactNode;
  elevation?: "z1" | "z2" | "z3";
  colour?: "card" | "yellow" | "blue" | "red" | "teal";
  className?: string;
  children: ReactNode;
};

const bg: Record<NonNullable<Props["colour"]>, string> = {
  card:   "bg-card",
  yellow: "bg-hog-yellow",
  blue:   "bg-hog-blue text-white",
  red:    "bg-hog-red-soft",
  teal:   "bg-[#DDFAF3]",
};

const elev = { z1: "shadow-z1", z2: "shadow-z2", z3: "shadow-z3" } as const;

export function LemonCard({ title, footer, elevation = "z2", colour = "card",
                           className = "", children }: Props) {
  return (
    <section className={`border-2 border-ink rounded-hog ${bg[colour]} ${elev[elevation]} ${className}`}>
      {title && (
        <header className="px-4 py-2.5 border-b-2 border-ink font-mono text-xs uppercase tracking-wider">
          {title}
        </header>
      )}
      <div className="px-4 py-3">{children}</div>
      {footer && (
        <footer className="px-4 py-2.5 border-t-2 border-ink">{footer}</footer>
      )}
    </section>
  );
}
WP-1.3

LemonModal

File: src/components/lemon/LemonModal.tsx Effort: 0.7 d

Centered modal with backdrop, ESC + outside-click close, focus trap, optional sizes (sm / md / lg / full). Slots: header, body, footer. Uses React portal to document.body so it floats above any panel z-stack introduced in S3.

Implementation notes: no external focus-trap library; use a small hand-rolled trap (~20 LoC) inside the component. aria-modal=true, role="dialog". ESC handler attached on open, detached on close. 

type Props = {
  open: boolean;
  onClose: () => void;
  title?: ReactNode;
  footer?: ReactNode;
  size?: "sm" | "md" | "lg" | "full";
  children: ReactNode;
};

const widths = { sm: "max-w-md", md: "max-w-2xl", lg: "max-w-4xl", full: "max-w-[96vw]" };

export function LemonModal({ open, onClose, title, footer, size = "md", children }: Props) {
  useEffect(() => {
    if (!open) return;
    const h = (e: KeyboardEvent) => e.key === "Escape" && onClose();
    window.addEventListener("keydown", h);
    return () => window.removeEventListener("keydown", h);
  }, [open, onClose]);

  if (!open) return null;
  return createPortal(
    <div className="fixed inset-0 z-[100] flex items-center justify-center"
         onMouseDown={onClose}>
      <div className="absolute inset-0 bg-ink/30" />
      <div role="dialog" aria-modal="true"
           onMouseDown={(e) => e.stopPropagation()}
           className={`relative w-full ${widths[size]} mx-4 bg-card border-2 border-ink rounded-hog-lg shadow-lift`}>
        {title && (
          <header className="px-5 py-3 border-b-2 border-ink flex items-center justify-between">
            <h2 className="font-mono text-sm uppercase tracking-wider">{title}</h2>
            <button onClick={onClose} aria-label="Close" className="text-ink-soft hover:text-ink">✕</button>
          </header>
        )}
        <div className="px-5 py-4">{children}</div>
        {footer && <footer className="px-5 py-3 border-t-2 border-ink">{footer}</footer>}
      </div>
    </div>,
    document.body
  );
}

LemonInput

File: src/components/lemon/LemonInput.tsx Effort: 0.4 d

Single-line text input. Slots for left icon, right icon, and a kbd hint (e.g. ⌘K badge on the right) used by the command palette. Focus state: thicker border + z1 shadow. 

type Props = InputHTMLAttributes<HTMLInputElement> & {
  iconLeft?: ReactNode;
  iconRight?: ReactNode;
  kbdHint?: string;
  sizing?: "sm" | "md" | "lg";
};

export const LemonInput = forwardRef<HTMLInputElement, Props>(
  ({ iconLeft, iconRight, kbdHint, sizing = "md", className = "", ...rest }, ref) => {
    const h = { sm: "h-7", md: "h-9", lg: "h-11" }[sizing];
    return (
      <label className={`inline-flex items-center gap-2 px-3 ${h} bg-card border-2 border-ink rounded-hog
                         shadow-none focus-within:shadow-z1 transition-shadow ${className}`}>
        {iconLeft}
        <input ref={ref}
          className="flex-1 bg-transparent outline-none font-sans text-[13px] placeholder:text-ink-mute"
          {...rest} />
        {iconRight}
        {kbdHint && (
          <kbd className="border border-ink rounded px-1.5 text-[10.5px] font-mono shadow-[2px_2px_0_0_#1D1F27] bg-card">
            {kbdHint}
          </kbd>
        )}
      </label>
    );
  }
);

6 · Acceptance criteria

  • All ten files exist under src/components/lemon/ with paired *.stories.tsx.
  • src/components/lemon/index.ts barrel exports every primitive.
  • npm run typecheck passes with strict TS.
  • npm run storybook renders all 10 stories without error.
  • Bundle size of lemon/ chunk < 12 KB gzipped (verified by vite build --report).
  • No primitive imports a colour hex directly; every reference goes through design/tokens.ts or a Tailwind class.
  • RTL unit tests for the four primitives with non-trivial behaviour: Button (click), Modal (ESC + outside-click), Select (keyboard nav), Toast (queue ordering).
  • A second moodboard story Design / Primitives Showcase renders one of each component on a single page, for visual review.

7 · Risks & mitigations

  • Hand-rolled focus trap in LemonModal misses an edge case. Mitigation: keep it small + covered by a Vitest that tabs through a sample modal and asserts focus does not escape.
  • LemonSelect popover positioning bugs. Mitigation: ship a basic position-below implementation in S1; reposition logic in S11 if it surfaces.
  • 10 components in 5 days is tight. Mitigation: the four large ones (Modal / Select / Dropdown / Table) are sequenced first; if S1 overruns, Toast (smallest) slips to S2 and is non-blocking.
  • Operator sign-off fails after the showcase. Mitigation: gate is the Primitives Showcase story; revisions touch one component file at a time.

8 · Open questions

  1. Should LemonButton's default variant be primary or secondary? Default proposal: secondary (matches PostHog; "primary" reserved for the one main action per page).
  2. Should LemonInput ship a built-in label-above? PostHog's does. Proposal: no — Antiek's existing forms wrap labels explicitly. Add later if a real consumer needs it.
  3. Should LemonTable support row drag-reorder? Proposal: no in S1 (not needed). Add in S10 if migration requires it.

9 · Verification protocol

  1. npm run typecheck — must be clean.
  2. npm run storybook — open every primitive story, confirm hover-lift / focus-shadow / disabled / colour variants all render.
  3. npm run test — RTL suite passes.
  4. npm run build — bundle report shows lemon chunk < 12 KB gzipped.
  5. Operator opens the Primitives Showcase story and signs off.

10 · Rollback plan

S1 is additive. Rollback is git revert of the S1 PRs. No consumer touches these yet, so no broken imports cascade.
