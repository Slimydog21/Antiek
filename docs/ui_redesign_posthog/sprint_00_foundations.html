1 · Goal

Land the three things that every later sprint depends on: a ratified design token system, a settled answer to "which Lemon UI strategy", and an empty but conventionally-named home (src/design/ + src/components/lemon/ + src/workspace/) for the redesign code to live in.

2 · Why this sprint exists

Without S0, every subsequent sprint argues about palette in PRs, copies shadow rules ad-hoc, and litters lemon-style components across whatever directory the author picked that day. The redesign needs a single source of truth for tokens; the redesign needs a settled answer on whether @posthog/lemon-ui is a dependency or a reference; the redesign needs a directory convention so that a Storybook scan or a grep is meaningful. S0 closes all three. It is short by design.

3 · The Lemon-UI decision (the key fork)

The prior spec (integration_posthog.md §5.1b) gated Lemon UI adoption on a spike that has not been executed. Rather than execute that spike now — which would burn 2–3 days on a bundle-size + visual-fit check that could still go either way — we settle this by picking the option that has the lowest reversibility cost.

Option Pros Cons Verdict
A · Install @posthog/lemon-ui Fastest to a finished look. Free upgrades. Componentry is battle-tested in PostHog itself. Brings Kea + own CSS layer. Strict-TS gate is unverified. Bundle delta unknown (prior gate was < 80 KB gzipped). Visual fit may be too SaaS-dashboard for Antiek's reading prose. REJECT for v1.
B · Fork-and-paste from posthog/posthog Closest pixel-fidelity to PostHog. No dependency. Strip Kea bindings as we go. Mass-copying their MIT components front-loads a lot of unfamiliar code. Maintenance is now ours. Visual fit still unverified. REJECT — too much unfamiliar code, too early.
C · Custom Tailwind, PostHog visual language Stays in current Tailwind + strict-TS world. Bundle delta tiny (5–10 KB for the new components). Each primitive is small + readable. Visual fit tuned to Antiek's prose-reading context as we go. We write the components. ~5 days in S1. ACCEPT.
S0 verdict Build a custom src/components/lemon/ in Tailwind matching PostHog's visual language. Do not take a dependency on @posthog/lemon-ui. The cost of writing the components is bounded; the cost of an aesthetic mismatch on a reading product is not. If a specific Lemon component is genuinely irreplaceable, we fork-and-paste that one file at the time we need it.

4 · Non-goals

  • No production components ship in S0. Only tokens + directory scaffold + design moodboard.
  • No routes change. No App.tsx diff in S0.
  • No Tailwind config rewrite. We extend the existing config (which already adds JetBrains Mono).
  • No HeaderBar rewrite. That's S4.
  • No dark mode. Token system permits one in S12 stretch.

5 · Architecture

apps/reading/src/ ├── design/ ◀ new in S0 │ ├── tokens.ts — typed palette + shadow + spacing │ ├── tokens.css — CSS-var sibling for non-TS contexts │ └── moodboard.stories.tsx — the palette + shadow + type demo ├── components/ │ ├── lemon/ ◀ new in S0 (empty) │ │ └── README.md — directory contract, S1 fills it │ └── (existing components untouched) ├── workspace/ ◀ new in S0 (empty) │ └── README.md — panel-system home, S3 fills it └── (everything else untouched) tailwind.config.js — extend with tokens imported from design/tokens.ts

Directory scaffold + READMEs

Files: src/design/README.md, src/components/lemon/README.md, src/workspace/README.md Effort: 0.5 d

Empty directories with READMEs that name the contract each will fill. The READMEs are short but binding — they prevent S1/S3 authors from inventing new locations. 

# src/design/README.md
Design-system source of truth.

# src/components/lemon/README.md
PostHog-Lemon-style primitives, built custom (no @posthog/lemon-ui dep).

Files appear here as Sprint 1 lands them:
- LemonButton.tsx   variant: primary, secondary, tertiary, danger
- LemonCard.tsx     elevation 1 / 2 / 3 + colour variants
- LemonModal.tsx    layered modal with backdrop, used by workspace popouts

- LemonTag.tsx      pill chip
- LemonSelect.tsx
- LemonDropdown.tsx

Panel-layout substrate (the 3D layered window manager).

7 · Acceptance criteria

  • apps/reading/src/design/tokens.ts exists, exports palette + shadow + radius + type, compiles under strict TS.
  • tailwind.config.js exposes bg-hog-yellow, shadow-z2, rounded-hog, font-mono — verified by a one-page render in dev.
  • storybook runs and the Design / Moodboard story renders palette + shadows + type + before/after-ChatInput.
  • Operator signs off the moodboard story. Without this signature, S1 does not start.
  • The three new directories exist with their READMEs. grep -r "import.*from.*design/tokens" returns 0 hits in components (nobody has consumed it yet — that's correct in S0).
  • integration_posthog.md carries the SUPERSEDED banner.
  • npm run build produces no new TS errors compared to baseline.

8 · Risks & mitigations

  • Operator dislikes the palette after the moodboard. Mitigation: changes are one-edit, in tokens.ts + tailwind.config.js + shared.css. Allocate up to 0.5 d for one palette round-trip inside S0's budget.
  • Tailwind config syntax error breaks the dev server. Mitigation: WP-0.2 lands behind a separate commit with a working npm run build as the gate.
  • The custom path forecloses a real Lemon UI eval forever. Mitigation: explicit revisit point in S12. If Lemon UI proves more attractive in the future, we still have it as an option — we just haven't paid for it speculatively.

9 · Open questions

  1. Serif font for prose: Charter (free-ish, ships on macOS), Iowan Old Style (Apple), or Lora (Google Fonts, web-loadable)? Default: Charter with Iowan + Georgia fallback. Operator: ratify or override.
  2. Border-rule colour: the spec uses near-black #1D1F27 for hard borders; this is what gives the "stamp-printed" PostHog feel. Operator: accept or soften to a true grey?
  3. Shadow direction: currently bottom-right (PostHog convention). Bottom-left would also be valid; affects perceived light direction. Default: bottom-right.

10 · Verification protocol

  1. cd apps/reading && npm run storybook
  2. Open Design / Moodboard / Palette. Confirm all 16 swatches render with the chunky-shadow look and JetBrains Mono labels.
  3. Open Design / Moodboard / BeforeAfter / ChatInput. Confirm the after-render is recognisably PostHog-shaped (yellow accent, hard border, offset shadow) while the before-render is the current flat version.
  4. npm run build succeeds. Bundle delta < 1 KB (no new components, only config).
  5. Operator confirms aesthetic. The literal artefact is a checkbox in the Sprint 0 PR description.

11 · Rollback plan

S0 is additive-only: new files, no edits to existing components. Rollback is a single git revert of the S0 commit. No state migration, no runtime config changes. The supersession banner in integration_posthog.md stays even on rollback (it documents the failed attempt), with an "experiment paused" note appended.
