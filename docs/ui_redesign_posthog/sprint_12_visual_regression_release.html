4 · Work packages

WP-12.1

Lost-Pixel CI blocker

File: .github/workflows/visual.yml or equivalent CI config Effort: 0.3 d

Lost-Pixel runs on every PR that touches apps/reading/; diffs failing the 1% threshold fail the PR. Baseline updates require an explicit commit titled chore(visual): update baseline by the operator or designated reviewer.

The 1% threshold (from S2) ratchets to 0.4% in S12. Tighter than typography slop, but loose enough to absorb sub-pixel rendering differences between Chromium runs.

WP-12.2

Bundle-size budget enforcement

Files: vite.config.ts, scripts/check_bundle.ts (new), CI Effort: 0.5 d

A post-build script that asserts main-chunk gzipped size ≤ 700 KB (programme-wide commitment). Per-chunk budgets:

  • main.js ≤ 700 KB gzipped
  • workspace.js ≤ 60 KB gzipped (lazy chunk)
  • lemon.js ≤ 14 KB gzipped (lazy chunk)
  • notebook.js ≤ 120 KB gzipped (lazy chunk, includes TipTap)
  • pdfviewer.js ≤ 40 KB gzipped (lazy chunk; pdf.worker separate)
// scripts/check_bundle.ts
import { gzipSync } from "node:zlib";
import { readFileSync, readdirSync } from "node:fs";

const budgets: Record<string, number> = {
  "main": 700_000,
  "workspace": 60_000,
  "lemon": 14_000,
  "notebook": 120_000,
  "pdfviewer": 40_000,
};

const dist = "dist/assets";
const files = readdirSync(dist).filter(f => f.endsWith(".js"));
let fail = false;
for (const [name, budget] of Object.entries(budgets)) {
  const f = files.find(x => x.startsWith(name + "-"));
  if (!f) { console.warn(`No file for chunk ${name}`); continue; }
  const gz = gzipSync(readFileSync(`${dist}/${f}`)).length;
  const over = gz > budget;
  console.log(`${name}: ${(gz/1024).toFixed(1)} KB ${over ? "✗ OVER" : "✓"}`);
  if (over) fail = true;
}
process.exit(fail ? 1 : 0);
WP-12.3

Cutover flag + rollout

Files: src/main.tsx, .env.example Effort: 0.5 d

Cutover strategy:

  1. The new shell ships under env flag VITE_ANTIEK_UI=v2.
  2. The flag defaults to v2 in development, and (after the operator's daily-driver sign-off) in production.
  3. The old shell (HeaderBar + legacy ResearchWorkstation/WrestleApp wrappers) is kept in the tree for one sprint after cutover, gated by VITE_ANTIEK_UI=v1. Rollback is a single env-var flip.
  4. After one sprint of zero rollbacks, the legacy code is deleted (S13 — out of this programme, but tracked).
// src/main.tsx
const uiVersion = (import.meta.env.VITE_ANTIEK_UI ?? "v2") as "v1" | "v2";
const root = createRoot(document.getElementById("root")!);
root.render(
  <StrictMode>
    <BrowserRouter>
      {uiVersion === "v2" ? <AppV2 /> : <AppLegacy />}
    </BrowserRouter>
  </StrictMode>
);

AppLegacy is the pre-S4 App.tsx, kept as a sibling file (src/AppLegacy.tsx) so the diff is auditable.

5 · Acceptance criteria

  • Lost-Pixel runs as a CI blocker at 0.4% threshold; PR with intentional change must include the baseline-update commit.
  • npm run build followed by node scripts/check_bundle.ts passes; all chunks under budget.
  • Production build with VITE_ANTIEK_UI=v2 renders the new shell.
  • Production build with VITE_ANTIEK_UI=v1 renders the old shell (smoke test only).
  • Operator daily-driver sign-off after one workday on v2 with no rollback needed.
  • apps/reading/README.md documents the new architecture in < 200 lines and links to this spec directory.
  • The programme-level exit criteria (index §8) all hold.

6 · Risks & mitigations

  • Production cutover surfaces a bug invisible in dev. Mitigation: env flag + 1-sprint overlap. Rollback is one var flip; no migration to undo.
  • Lost-Pixel flakes on CI breaking unrelated PRs. Mitigation: pre-flight pass in S12 — run on 10 unrelated branches; if > 1 false-fail, raise threshold to 0.6% or rebaseline.
  • Bundle budget breached late by a careless import. Mitigation: check_bundle.ts is CI-blocking; offenders are visible in the PR.
  • Dark-mode stretch drags the sprint. Mitigation: WP-12.6 is explicitly scoped as drop-if-late; sprint exit doesn't depend on it.

7 · Open questions

  1. Should the flag flip be staged? E.g., dev → operator's personal env → production. Default: yes — already implied; codify in .env.example comments.
  2. How do we measure "the UI is cool now"? Default: this is operator-judgment, no metric. The programme exit criterion is intentionally subjective.
  3. Public design-system marketing page (à la posthog.com/design): post-SOC 2, post-auth, post-multi-user. Not S12.

8 · Verification protocol

  1. Run the full test suite + Storybook + Lost-Pixel + bundle check locally — all green.
  2. Build with VITE_ANTIEK_UI=v2 and serve via vite preview; spend 30 minutes clicking around.
  3. Flip env to v1; build and confirm legacy shell renders.
  4. Submit a PR with a 10-px shift to a primitive; confirm Lost-Pixel blocks until baseline updated.
  5. Operator spends a full workday on v2 — final sign-off captured as a checkbox in the S12 close-out commit.

9 · Rollback plan

Set VITE_ANTIEK_UI=v1 in the deployment environment. Service redeploys with the legacy shell. No data migration, no state reset, no API change. Reversal of the flag flip restores v2 instantly with all S0–S11 code intact.

10 · Programme-level retrospective (for the post-S12 commit message)

At the end of S12 the operator commits a retrospective at docs/ui_redesign_posthog/RETRO.md covering:

  • What shipped on the original 13-sprint plan vs what slipped.
  • Which design decisions held up; which would be reversed if rebuilding.
  • Per-sprint actual-vs-estimated effort.
  • Net change: bundle size, route count, time-to-feature for new modes after the panel system existed.
  • Operator subjective verdict: "is the UI cool now?"

The retro feeds into the next UX-track planning (notebook v2, workspace presets, dark mode, multi-user shell).
