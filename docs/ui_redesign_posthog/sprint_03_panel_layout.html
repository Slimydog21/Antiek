1 · Goal

Build the layered-window manager: a workspace store + a panel orchestrator + an individual panel primitive that can render in four modes — docked-left, docked-right, floating (z-stacked, draggable), and popout (separate OS window) — with chunky offset shadows that scale with z-depth and a hover-lift micro-interaction. At the end of S3, a Storybook-only demo scene contains three independent panels that can be docked, undocked, dragged, resized, z-shuffled, and closed. No production route uses it yet (that's S5).

2 · Why this sprint exists

This is the central technical bet of the entire redesign. Every later sprint either feeds into the panel system (S5 ports a mode onto it, S7 builds the notebook as a panel) or feeds off of it (S9 persists its state, S11 makes its keyboard story accessible). If the panel primitive is wrong, ten sprints downstream are wrong with it.

S3 is deliberately budgeted longer than its neighbours. The day-budget spent here is recovered five times in S5–S10.

3 · Non-goals

  • No URL or localStorage persistence in S3. The workspace is in-memory only; S9 bolts persistence on top.
  • No keyboard shortcuts in S3 beyond ESC-to-close-focused-panel. Cmd+B (rail), Cmd+Shift+P (palette), Cmd+/ (AI) all land in S8.
  • No animation library other than Framer Motion. We do not bring in react-spring, react-rnd, or react-grid-layout.
  • No real consumer migration in S3. The exit artefact is a Storybook story, not a route.
  • No tab-bar inside a panel. A panel = one surface; multi-tab inside a panel is a S10 stretch only if migration requires it.

4 · Architecture

4.1 · The mental model

A panel is the smallest independently-positioned piece of UI: an InvestigationSidebar instance, a PDF viewer instance, a notebook instance, a Max chat. The workspace is the set of currently-open panels plus their positions, sizes, z-orders, and pinned/floating status. The PanelLayout is the orchestrator that reads the workspace and renders the panels in three zones: the left dock, the right dock, and the floating layer.

┌──────── PanelLayout (orchestrator) ──────────┐ │ │ reads ───▶ │ WorkspaceStore ◀── actions from │ │ panels[] dropdowns / dragging│ │ zOrder / drag handles │ │ focusedPanelId │ │ dockLeftIds / dockRightIds │ │ floatingIds │ └──────────────────────────────────────────────┘ │ ┌────────────────────────────────┼──────────────────────────────┐ ▼ ▼ ▼ ┌── dock-left ──┐ ┌── main slot ──┐ ┌── dock-right ──┐ │ PanelHandle │ │ rendered if │ │ PanelHandle │ │ Panel A │ │ no panel │ │ Panel C │ │ ──────────── │ │ owns center, │ │ ───────────── │ │ Panel B │ │ shows route │ │ Panel D │ └───────────────┘ └───────────────┘ └────────────────┘ floating layer (absolutely positioned over everything): ┌─ Panel E (z=5) ─┐ ┌─ Panel F (z=7) ─┐ │ drag handle │ │ drag handle │ │ ────────────────│ │ ────────────────│ │ content │ │ content │ └──────────────────┘ └──────────────────┘ popout layer (rendered into window.open() targets via portal): off-screen.

4.2 · State model

// src/workspace/panel.types.ts

export type PanelMode = "docked-left" | "docked-right" | "floating" | "popout";

export type PanelDescriptor = {
  /** stable id. e.g. "inv-sidebar:default", "chat:investigationId:1234" */
  id: string;

  /** what to render — a key into the PanelRegistry */
  kind: PanelKind;          // "InvestigationSidebar" | "Trajectory" | "Chat" | …

  /** props passed to the renderer */
  props: Record<string, unknown>;

  /** layout state */
  mode: PanelMode;
  zIndex: number;            // floating: real z; docked: order within dock; popout: ignored
  rect:   { x: number; y: number; width: number; height: number };  // floating only
  size:   { width: number; height: number };                        // docked only
  pinned: boolean;
  title:  string;
};

export type WorkspaceSnapshot = {
  panels: Record<PanelDescriptor["id"], PanelDescriptor>;
  dockLeftIds:  string[];    // top-to-bottom order
  dockRightIds: string[];
  floatingIds:  string[];    // bottom-to-top z order (last = highest z)
  focusedPanelId: string | null;
  /** monotonic counter so a new floating panel sits on top */
  zCounter: number;
  /** layout snapshot version; bumped when persistence schema changes */
  schemaVersion: 1;
};

export type PanelKind =
  | "InvestigationSidebar"
  | "Trajectory"
  | "MasterMdViewer"
  | "Chat"
  | "Chase"
  | "PdfViewer"
  | "Notes"
  | "CrossDocs"
  | "ClaimInspector"
  | "Notebook"
  | "AISidecar"
  | "CommandPalette"
  | "Stats"           // etc.; one entry per consumer added later
  ;

4.3 · Why Zustand, not Kea

PostHog uses Kea. Antiek does not, and we don't want to. Zustand is ~1 KB gzipped, has zero dependencies, plays well with React 18, and is trivially debuggable. Trade-off: no auto-generated route-side-effects layer like Kea's, but we don't have a router-tied state machine to encode here — workspace state is local UI state, not domain state.

WP-3.1

Workspace store

File: src/workspace/WorkspaceStore.ts Effort: 1.0 d

Zustand store holding the WorkspaceSnapshot shape + actions: open, close, focus, setMode, setRect, setSize, reorderDock, bringToFront, pin / unpin, popout / undock-popout. 

// src/workspace/WorkspaceStore.ts
import { create } from "zustand";
import type { PanelDescriptor, PanelKind, WorkspaceSnapshot } from "./panel.types";

type Actions = {
  open: (kind: PanelKind, props?: Record<string, unknown>, opts?: { mode?: PanelMode; title?: string }) => string;
  close: (id: string) => void;
  focus: (id: string) => void;
  setMode: (id: string, mode: PanelMode) => void;
  setRect: (id: string, rect: Partial<PanelDescriptor["rect"]>) => void;
  setSize: (id: string, size: Partial<PanelDescriptor["size"]>) => void;
  reorderDock: (side: "left" | "right", fromId: string, toId: string) => void;
  bringToFront: (id: string) => void;
  pin: (id: string) => void;
  unpin: (id: string) => void;
  reset: () => void;
};

const initial: WorkspaceSnapshot = {
  panels: {},
  dockLeftIds: [], dockRightIds: [], floatingIds: [],
  focusedPanelId: null, zCounter: 1, schemaVersion: 1,
};

export const useWorkspace = create<WorkspaceSnapshot & Actions>((set, get) => ({
  ...initial,

  open: (kind, props = {}, opts = {}) => {
    const id = `${kind}:${cryptoRandomId()}`;
    const mode = opts.mode ?? "floating";
    set((s) => {
      const z = s.zCounter + 1;
      const desc: PanelDescriptor = {
        id, kind, props, mode, zIndex: z,
        rect: { x: 120 + (z*22)%200, y: 120 + (z*22)%200, width: 560, height: 420 },
        size: { width: 320, height: 0 },
        pinned: false, title: opts.title ?? kind,
      };
      return {
        ...s,
        panels: { ...s.panels, [id]: desc },
        floatingIds:  mode === "floating"     ? [...s.floatingIds, id]  : s.floatingIds,
        dockLeftIds:  mode === "docked-left"  ? [...s.dockLeftIds, id]  : s.dockLeftIds,
        dockRightIds: mode === "docked-right" ? [...s.dockRightIds, id] : s.dockRightIds,
        focusedPanelId: id,
        zCounter: z,
      };
    });
    return id;
  },

  close: (id) => set((s) => {
    const { [id]: _gone, ...rest } = s.panels;
    return {
      ...s,
      panels: rest,
      dockLeftIds:  s.dockLeftIds.filter(x => x !== id),
      dockRightIds: s.dockRightIds.filter(x => x !== id),
      floatingIds:  s.floatingIds.filter(x => x !== id),
      focusedPanelId: s.focusedPanelId === id ? null : s.focusedPanelId,
    };
  }),

  focus: (id) => {
    const s = get();
    if (s.panels[id]?.mode === "floating") get().bringToFront(id);
    else set({ focusedPanelId: id });
  },

  bringToFront: (id) => set((s) => {
    if (!(id in s.panels)) return s;
    const z = s.zCounter + 1;
    return {
      ...s,
      zCounter: z,
      focusedPanelId: id,
      panels: { ...s.panels, [id]: { ...s.panels[id], zIndex: z } },
      floatingIds: [...s.floatingIds.filter(x => x !== id), id],
    };
  }),

  setMode: (id, mode) => { /* … move id between docks/floating arrays … */ },
  setRect: (id, rect) => { /* … merge rect, only if mode==="floating" … */ },
  setSize: (id, size) => { /* … merge size, only if mode in "docked-…" … */ },
  reorderDock: (side, fromId, toId) => { /* … swap inside dockLeftIds/dockRightIds … */ },
  pin:   (id) => set(s => ({ panels: { ...s.panels, [id]: { ...s.panels[id], pinned: true } } })),
  unpin: (id) => set(s => ({ panels: { ...s.panels, [id]: { ...s.panels[id], pinned: false } } })),
  reset: () => set(initial),
}));

function cryptoRandomId() {
  return Math.random().toString(36).slice(2, 9);
}

Tests: 12+ Vitest cases covering every action, including reorderDock edge cases (drag a panel onto itself, drag past list bounds), bringToFront idempotency, popout-from-floating, undock-back-to-floating.

WP-3.3

PanelLayout orchestrator

File: src/workspace/PanelLayout.tsx Effort: 1.2 d

The shell. Reads useWorkspace, lays out three zones: left dock, main slot, right dock. The floating layer is a sibling portal absolutely positioned over the dock row. Receives an optional mainSlot child — that's where the React Router <Outlet /> renders when no panel occupies the main slot. 

// src/workspace/PanelLayout.tsx
import { Suspense } from "react";
import { useWorkspace } from "./WorkspaceStore";
import { PanelLayoutPanel } from "./PanelLayoutPanel";

type Props = { mainSlot: React.ReactNode };

export function PanelLayout({ mainSlot }: Props) {
  const dockLeftIds  = useWorkspace(s => s.dockLeftIds);
  const dockRightIds = useWorkspace(s => s.dockRightIds);
  const floatingIds  = useWorkspace(s => s.floatingIds);
  const panels       = useWorkspace(s => s.panels);

  return (
    <div className="relative h-screen w-screen flex bg-paper overflow-hidden">
      {/* left dock */}
      <div className="flex flex-col border-r-2 border-ink bg-paper-soft min-w-0
                       transition-[width] duration-150"
           style={{ width: dockLeftIds.length ? 320 : 0 }}>
        {dockLeftIds.map(id => (
          <Suspense key={id} fallback={null}>
            <PanelLayoutPanel id={id} />
          </Suspense>
        ))}
      </div>

      {/* main */}
      <main className="flex-1 min-w-0 relative overflow-hidden">
        {mainSlot}

        {/* floating layer is a sibling, absolutely over main + docks */}
        <div className="absolute inset-0 pointer-events-none">
          {floatingIds.map(id => (
            <div key={id} className="pointer-events-auto">
              <Suspense fallback={null}>
                <PanelLayoutPanel id={id} />
              </Suspense>
            </div>
          ))}
        </div>
      </main>

      {/* right dock */}
      <div className="flex flex-col border-l-2 border-ink bg-paper-soft min-w-0
                       transition-[width] duration-150"
           style={{ width: dockRightIds.length ? 320 : 0 }}>
        {dockRightIds.map(id => (
          <Suspense key={id} fallback={null}>
            <PanelLayoutPanel id={id} />
          </Suspense>
        ))}
      </div>
    </div>
  );
}
WP-3.4

PanelLayoutPanel — individual panel

File: src/workspace/PanelLayoutPanel.tsx Effort: 1.5 d

The panel primitive: header bar (drag handle in floating mode, kebab menu always), body slot rendered via PanelRegistry[kind], edge handles for resize in floating + docked modes. Renders one of three z-class chrome treatments by panel mode:

  • docked-left / docked-right: flat — no shadow, no border-radius (the dock is the frame).
  • floating: border-2 border-ink rounded-hog shadow-z3, lifted to z2 + reduced shadow when not focused.
  • popout: rendered into a portal that targets a window.open() document; chrome reduced (the OS window is the frame).
// src/workspace/PanelLayoutPanel.tsx
import { useRef } from "react";
import { useWorkspace } from "./WorkspaceStore";
import { PanelRegistry } from "./PanelRegistry";
import { PanelHandle } from "./PanelHandle";
import { motion } from "framer-motion";
import { LemonDropdown } from "../components/lemon/LemonDropdown";
import { LemonButton } from "../components/lemon/LemonButton";

export function PanelLayoutPanel({ id }: { id: string }) {
  const panel = useWorkspace(s => s.panels[id]);
  const isFocused = useWorkspace(s => s.focusedPanelId === id);
  const actions = useWorkspace.getState;
  const ref = useRef<HTMLDivElement>(null);

  if (!panel) return null;
  const Renderer = PanelRegistry[panel.kind];

  if (panel.mode === "floating") {
    return (
      <motion.div
        ref={ref}
        layout
        initial={{ scale: 0.96, opacity: 0 }}
        animate={{ scale: 1, opacity: 1, x: panel.rect.x, y: panel.rect.y }}
        exit={{ scale: 0.96, opacity: 0 }}
        transition={{ type: "spring", stiffness: 320, damping: 28 }}
        style={{
          width: panel.rect.width, height: panel.rect.height,
          zIndex: panel.zIndex,
          position: "absolute", top: 0, left: 0,
        }}
        className={`bg-card border-2 border-ink rounded-hog
                    ${isFocused ? "shadow-z3" : "shadow-z2 opacity-95"}
                    flex flex-col overflow-hidden`}
        onMouseDownCapture={() => actions().bringToFront(id)}>
        <PanelHandle id={id} draggable resizable />
        <div className="flex-1 min-h-0 overflow-auto">
          <Renderer {...panel.props} />
        </div>
      </motion.div>
    );
  }

  // docked-left / docked-right
  return (
    <div ref={ref}
         className="flex flex-col bg-card border-b-2 border-ink min-h-0"
         style={{ flex: "1 1 0" }}>
      <PanelHandle id={id} draggable={false} resizable />
      <div className="flex-1 min-h-0 overflow-auto">
        <Renderer {...panel.props} />
      </div>
    </div>
  );
}
WP-3.5

PanelHandle — drag + resize + actions menu

File: src/workspace/PanelHandle.tsx Effort: 1.0 d

Top strip of every panel. Holds title, drag-grip (floating only), pin toggle, kebab → actions menu (dock-left / dock-right / float / popout / close), and an X close button. Implements pointer-event drag (no library) writing to setRect. Edge resize is a 1-px hit area on bottom + right (floating) or right only (docked). 

function useDrag(id: string, onDrag: (dx: number, dy: number) => void) {
  const start = useRef<{ x: number; y: number } | null>(null);
  return {
    onPointerDown: (e: React.PointerEvent) => {
      (e.target as Element).setPointerCapture(e.pointerId);
      start.current = { x: e.clientX, y: e.clientY };
    },
    onPointerMove: (e: React.PointerEvent) => {
      if (!start.current) return;
      const dx = e.clientX - start.current.x;
      const dy = e.clientY - start.current.y;
      start.current = { x: e.clientX, y: e.clientY };
      onDrag(dx, dy);
    },
    onPointerUp: () => { start.current = null; },
  };
}

The kebab uses LemonDropdown (S1) and emits setMode / close / pin / popout actions. Popout opens a new window pointing at /_panel/<id>; S9 implements the portal-into-popout side. In S3, popout is stubbed (toast: "popout lands in S9").

PanelHost — opt-in wrapper for routes

File: src/workspace/PanelHost.tsx Effort: 0.3 d

A tiny wrapper a route component renders to live inside the panel shell. The route says "I want to be the main slot; open these starter panels"; PanelHost handles the open-on-mount, close-on-unmount. 

type Props = {
  starters?: Array<{ kind: PanelKind; props?: any; mode?: PanelMode; title?: string }>;
  children: React.ReactNode;
};

export function PanelHost({ starters = [], children }: Props) {
  const open = useWorkspace(s => s.open);
  const close = useWorkspace(s => s.close);
  useEffect(() => {
    const ids = starters.map(s => open(s.kind, s.props ?? {}, { mode: s.mode, title: s.title }));
    return () => ids.forEach(close);
  // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);
  return <PanelLayout mainSlot={children} />;
}

  • The Workspace / Demo Storybook story renders three independent fake panels.
  • Each panel can be dragged when floating; viewport edges clamp the position.
  • Each panel can be docked to the left or right via its kebab; the dock width animates open/close.

  • ESC closes the focused floating panel.

  • Vitest suite for WorkspaceStore + panelLayoutLogic passes (≥ 25 cases).

  • Strict TS clean.
  • Lost-Pixel runs without crashing on the new stories (baselines added).

7 · Risks & mitigations

  • Pointer-event capture is browser-flaky. Mitigation: WP-3.5 ships a 5-browser manual test matrix (Chrome / Safari / Firefox / iPad Safari / Edge) before signing off. Known quirk: Safari sometimes loses pointer capture on iframe load; we ship a re-attach on visibilitychange.
  • Framer Motion's layout animation fights with our animate={{x,y}} drive. Mitigation: only use layout on mode transitions; drag animations are direct animate.
  • Memory leak from lazy-loaded panel renderers. Mitigation: registry uses React.lazy + Suspense; unmount on close.
  • Z-index war with existing modals. Mitigation: LemonModal (S1) lives at z-[100]; panels use 1..50; the dock chrome uses z-0. Documented at the top of WorkspaceStore.ts.
  • Operator hates the chunky-shadow lift micro-interaction. Mitigation: the lift is a single CSS class (hover:shadow-z3); easy to tune down to shadow-z2 if the feel is too cartoony.
  • Scope creep: someone tries to add tabs-in-a-panel. Mitigation: tabs-in-panel explicitly out-of-scope in §3. Reopen in S10 if a real mode demands it.

8 · Open questions

  1. Floating snap-to-grid? When dragging, snap rects to a 16-px grid for a tidier feel? Default: no in S3; revisit if drags feel sloppy.
  2. Dock max-width? Currently fixed 320 px. Should the operator be able to resize the dock? Default: yes — the resize handle on the inner edge of each dock lets the operator widen up to 50% of viewport. Implementation lands in this sprint.
  3. Multiple panels stacked in one dock side? Yes — that's the design (dock-left contains a vertical stack of panels). Open: should the stack be reorderable by drag? Default: yes; implemented in reorderDock.
  4. What renders in the main slot when no panel claims it? The current React Router <Outlet />. So routes that have not been migrated to PanelHost still render in the main slot as today, surrounded by the panel chrome. Smooth migration story.

9 · Verification protocol

  1. npm run storybook → open Workspace / Demo.
  2. Drag the FakeNotebook floating panel around; release; verify it stays where dropped.
  3. Resize its bottom-right corner; verify content reflows.
  4. Open the kebab → "Dock right"; verify the panel slides into the right dock and the floating instance disappears.
  5. Click the still-floating FakeChat panel; verify shadow deepens and it sits above FakeSidebar.
  6. Hit ESC; FakeChat closes.
  7. Open the kebab on FakeSidebar → "Popout"; verify toast appears.
  8. npm run typecheck + npm run test + npm run build all clean.
  9. Operator signs off the demo. Without sign-off, S5 does not start.

10 · Rollback plan

S3 is additive: a new src/workspace/ directory and two new dependencies. No existing component or route references the workspace in S3 (that's S5+). Rollback = git revert + npm uninstall zustand framer-motion. The legacy shell is untouched.

11 · S3 → S4/S5 contract

The S3 deliverable that S5 consumes: PanelHost, useWorkspace, PanelRegistry entries for the ResearchWorkstation panels. S4 consumes PanelLayout by embedding the new nav rail inside it. Both contracts are forward-compatible: panels can be added by extending PanelKind and registering one component, with no change to the orchestrator.
