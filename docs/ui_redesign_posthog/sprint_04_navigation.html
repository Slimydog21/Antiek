1 · Goal

Replace modes/shared/HeaderBar.tsx with a PostHog-style composite navigation: a slim left rail (icon-only, always visible), a collapsible Project Tree panel (recent investigations, pinned items, "everything else"), and a topbar showing breadcrumbs + command-palette trigger + account. The rail sits outside the PanelLayout dock zones so it stays present even when both docks are empty.

2 · Why this sprint exists

The current HeaderBar is a horizontal strip of NavLinks ("Research / Wrestle / Sources / Create / Brainstorm" + "Privacy / Pricing / Operator / Trust") plus a "investigation id" chip. It is the visual origin of the "this UI is lame" complaint: zero hierarchy, no recents, no project tree, no surface for the operator's open investigations. S4 builds the structure that S5–S10 plug their nav surfaces into.

3 · Non-goals

  • No URL/router changes. The same React Router paths still resolve; only the chrome around them changes.
  • No new auth UI. Account avatar is a placeholder until auth lands (Sprint 22+ per master spec).
  • No mobile drawer in S4. That's S11.
  • No "global search" yet. Cmd+K lands in S8.

4.1 · Two-tier nav

The rail is a fixed 60-px column of icons on the left, outside the dock system. The ProjectTree panel is a standard PanelLayoutPanel docked-left that the operator can pin or hide. This means the panel-system pattern is the navigation pattern — the same primitives that hold the InvestigationSidebar hold the ProjectTree. Consistency by construction.

6 · Acceptance criteria

  • Visiting / shows the NavRail + Topbar + main slot (current ResearchWorkstation content still renders).
  • Active route highlights in the rail with the yellow accent + ink left bar.
  • Topbar renders breadcrumbs for the current route; LemonInput shows the placeholder "search · ⌘K" (no behaviour wired yet).
  • ProjectTree opens as a docked-left panel on Cmd+B (placeholder shortcut binding; S8 finalises shortcuts).
  • The legacy HeaderBar is no longer rendered anywhere.
  • Strict TS clean.
  • Existing modes still render their content (S4 is chrome-only).
  • Lost-Pixel baselines updated; intentional diff committed.

7 · Risks & mitigations

  • Modes break when their pages re-render inside AppShell. Mitigation: AppShell renders a plain Outlet in the main slot — no new wrappers. Any mode that depended on full h-screen rendering may need to drop the wrapper; tracked per-route in S10.
  • Breadcrumb extension API gets noisy. Mitigation: useBreadcrumbsOverride takes a plain array; only modes that want custom crumbs call it.
  • NavRail icons are illegible to new users. Mitigation: every icon has a tooltip via the native title attribute in S4; switch to a styled tooltip in S11.
  • Two scrollbars (Topbar + Page). Mitigation: AppShell uses min-h-0 + overflow-hidden at every flex parent; scrolls only inside the main slot.

8 · Open questions

  1. Icons — emoji placeholders or a Lucide-react import? Default: emoji in S4, swap to a tiny custom SVG set in S11. Avoids the dependency.
  2. NavRail width: 60 px vs 72 px? PostHog uses 60. Default: 60.
  3. Should the ProjectTree be open by default for first-time visitors? Default: yes; auto-collapses if the operator closes it once (state from S9).

9 · Verification protocol

  1. Run dev server, visit each top-level route, confirm NavRail highlights correctly.
  2. Open ProjectTree, click a recent investigation: route navigates, breadcrumb updates.
  3. Resize the browser to 1280×800: confirm nothing clips.
  4. Lost-Pixel: confirm the only diffs are the new chrome on existing route screenshots (intentional).

10 · Rollback plan

Revert App.tsx to the pre-S4 form (un-wrap routes). The PanelLayout, NavRail, Topbar, ProjectTree files can stay; they become orphan code until S5 re-adopts. Substrate untouched.
