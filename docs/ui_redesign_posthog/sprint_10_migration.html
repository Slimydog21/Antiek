1 · Goal

Convert every remaining route onto PanelHost with Lemon-styled internals. By end of S10, the legacy HeaderBar is removed and zero route uses its own bespoke chrome. The 25+ pages catalogued below are each their own work package; we sequence in 4 tiers by operator-visibility and risk.

2 · Why this sprint exists

After S5–S7 the redesign exists on three highest-traffic routes. The remaining ~25 routes are still flat. Without S10 the app feels inconsistent: the operator's daily-driver routes are PostHog-shaped, but operator-dashboard / trust / payouts / loop-3 are still 2025-era grey-on-white. S10 closes the gap.

3 · Non-goals

  • No new functionality. Pure visual + layout port.
  • No deep refactoring of any route's domain logic. If a route has poor logic, fix it elsewhere.
  • Not migrating internal admin routes that were never operator-visible (none currently).

4 · Migration template

Every route migration follows the same pattern. We codify it once so the 25+ migrations are mechanical work, not 25 individual designs.

For each route in apps/reading/src/modes/<Mode>/index.tsx: 1. Identify the mode's surfaces: - the "main" surface (the central content) - "side" surfaces (lists, filters, details that today live in sidebars or modals) - "ephemeral" surfaces (modals, slide-overs) 2. Wrap the route component in <PanelHost starters={...}>: - Side surfaces become docked-left or docked-right starter panels - Main surface goes inside the children (main slot) 3. Convert ephemeral surfaces to floating panels: - openPanel("ClaimInspector", { claimId }, { mode: "floating" }) instead of setState({modalOpen: true}) 4. Restyle internals to Lemon primitives: - <button> → <LemonButton> - tables → <LemonTable> - <input> → <LemonInput> - cards/panels → <LemonCard> 5. Add the route to the navigation rail (S4) if not already. 6. Add screenshots to the Storybook story for the route. 7. Update Lost-Pixel baseline. Each route is its own WP; estimated 0.3 - 0.5 day per route depending on complexity.

7 · Common patterns & gotchas

  • List → Detail flows (e.g. /investigations → /inv/:id): the list can become a docked-left panel that survives the navigation, so clicking a row updates the main slot without unmounting the list. Implement by registering the list itself as PanelKind = "InvestigationsList" and starting it docked-left in both the list route and the detail route.
  • Existing modals: every existing modal becomes either a LemonModal (truly transient) or a floating panel (operator may want to keep it open while doing other things). Default the rule: if the modal blocks other interaction (delete confirm), use LemonModal; if it's content (claim detail, region zoom), make it a floating panel.
  • Empty states: every route gets a real empty state. Today many routes render whitespace. After S10, the empty state is a LemonCard with a clear CTA — operator action affordance, not silence.
  • Page-level scroll: PanelHost's main slot has its own scroll. Make sure each migrated route does not set h-screen on its own root; the AppShell already owns that.
  • Routes inside routes: /skill-rules and /skill-rules/:id share a starter (the rules list). Share by extracting starter spec into the route file's module scope; both render PanelHost with the same starter array.

8 · Acceptance criteria

  • All 28 routes render under the new shell.
  • HeaderBar.tsx is no longer imported anywhere in the codebase.
  • Strict TS clean across the whole app.
  • Bundle main chunk ≤ 700 KB gzipped (the explicit programme-wide budget).
  • Lost-Pixel baseline complete: every route has at least one story or page-level screenshot committed.
  • Operator daily-driver sign-off across at least 6 routes per tier.
  • No regressions in existing route behaviour (manual smoke pass per tier).

9 · Risks & mitigations

  • Some routes have inherited domain logic that breaks when wrapped in PanelHost. Mitigation: each WP starts by mounting the route inside PanelHost without any starters as a smoke test; if that breaks, fix container-side first.
  • Stamina: 10 days of similar visual work is fatiguing; aesthetic consistency drifts late in the sprint. Mitigation: each tier closes with a 30-min review of all migrated routes against the moodboard; the boundary between tiers is the polish + review checkpoint.
  • Forgetting a route. Mitigation: this catalogue is the canonical list; CI grep at the end of S10 fails the build if any modes/*/index.tsx imports the old HeaderBar.
  • Substrate adds a new route during S10. Mitigation: substrate-track convention: new routes wrap in PanelHost from day one. PanelHost is documented in src/workspace/README.md as the required wrapper.

10 · Open questions

  1. Should the /_panel/:id popout route surface a top-bar at all? Default: minimal — just panel title + close. The OS window chrome carries the rest.
  2. Should index routes (/investigations, /notebooks, etc) share a common "list page" template? Default: no — too restrictive; the template exists implicitly via LemonTable usage.
  3. Per-route layouts that are saved by S9 — does S10 ship default presets? Default: no, the route's starter array is the default; persisted state overrides it.

11 · Verification protocol

  1. Per tier: walk every route in the catalogue; confirm header shows breadcrumbs, NavRail highlight, no HeaderBar, Lemon styling.
  2. Run the cross-route smoke test: navigate from / → /wrestle → /notebooks → /create → /operator → /trust → /. Confirm no console errors.
  3. Bundle audit: npm run build -- --report; main chunk ≤ 700 KB.
  4. Lost-Pixel: zero unintentional diffs.
  5. Operator sign-off: use the app for one workday end-to-end; report any inconsistency.

12 · Rollback plan

Each WP is independent. Reverting one route returns it to the old shell while leaving others migrated. The flag ANTIEK_UI=v2 introduced in S12 can be route-scoped if needed during cutover.
