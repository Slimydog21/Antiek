1 · Goal

Bring every Antiek component (existing + new lemon primitives + future panel-system pieces) under Storybook coverage, and wire visual-regression via Lost-Pixel so structural drift fails CI rather than slipping in invisibly during S5–S10's bulk migration.

2 · Why this sprint exists

Storybook is already in devDependencies (storybook ^8.4.7) and 8 stories exist. But coverage is partial (no stories for many panels, none for the new primitives, no visual-regression). During S5–S10 we will rebuild every mode; without a screenshot-diff signal we will unknowingly regress visuals on the modes we touch later in the run. Sprint 2 closes the gap, before the riskiest sprints start.

This sprint executes the integration_posthog.md §5.1a commitment that was always "pure-upside hygiene, no reason to defer". It is short, low-risk, and high-leverage.

3 · Non-goals

  • Not running Chromatic. Lost-Pixel is local + self-hosted; we don't bring on a paid SaaS.
  • Not building MDX docs pages for every component. Stories are the doc; one MDX overview page only.
  • Not blocking new feature work on screenshot diffs. Diffs are advisory in S2 → become CI-blocking only in S12.

WP-2.1

Storybook preview + brand polish

Files: .storybook/preview.tsx, .storybook/manager.ts Effort: 0.3 d

Wrap every story in a paper-coloured background + Inter/JetBrains-Mono font load, so stories render the same as in production. Brand the Storybook chrome with the Antiek wordmark + yellow accent. 

// .storybook/preview.tsx
import type { Preview } from "@storybook/react";
import "../src/index.css";
import "../src/design/tokens.css";

const preview: Preview = {
  parameters: {
    backgrounds: {
      default: "paper",
      values: [
        { name: "paper",      value: "#FBFBFA" },
        { name: "paper-soft", value: "#F2F2EE" },
        { name: "ink",        value: "#1D1F27" },
      ],
    },
    layout: "padded",
  },
  decorators: [
    (Story) => (
      <div className="font-sans text-ink">
        <Story />
      </div>
    ),
  ],
};
export default preview;

WP-2.3

Lost-Pixel visual regression

Files: lostpixel.config.ts, .github/workflows/visual.yml (if CI exists) Effort: 0.5 d

Lost-Pixel uses a Playwright runner to screenshot every Storybook story and diff against committed baselines. Run locally with npm run visualtest; baselines update with npm run visualtest:update. 

// lostpixel.config.ts
import { CustomProjectConfig } from "lost-pixel";

export const config: CustomProjectConfig = {
  storybookShots: {
    storybookUrl: "./storybook-static",
  },
  imagePathBaseline:  ".lostpixel/baseline",
  imagePathCurrent:   ".lostpixel/current",
  imagePathDifference: ".lostpixel/diff",
  generateOnly: false,
  threshold: 0.01, // 1% delta tolerance (typography anti-aliasing slop)
};

package.json additions:

"scripts": {
  "visualtest":         "storybook build && lost-pixel",
  "visualtest:update":  "storybook build && lost-pixel update",
}

Advisory in S2, blocking in S12. S2 commits the initial baselines after a sign-off pass. From then on, any PR that wants to change baselines must include an explicit visualtest:update commit — making accidental drift visible in code review.

6 · Acceptance criteria

  • Storybook builds clean (npm run build-storybook).
  • Every component in src/components/ has ≥ 1 story.
  • Every primitive in src/components/lemon/ has ≥ 1 story (from S1).
  • npm run visualtest runs end-to-end and produces a diff report. Baseline committed under .lostpixel/baseline/.
  • STORYBOOK.md exists.
  • The Design / Primitives Showcase story (S1) renders correctly through Lost-Pixel without flakes (run twice, no diff).

7 · Risks & mitigations

  • Lost-Pixel flakes on font load. Mitigation: preview wrapper preloads Inter + JetBrains Mono synchronously; Lost-Pixel waits for fonts via Playwright's document.fonts.ready.
  • Mode-level stories balloon in scope. Mitigation: this sprint ONLY adds stories for the sub-components listed in WP-2.2. Full-mode "page" stories arrive sprint by sprint as modes are ported.
  • CI cost. Mitigation: Lost-Pixel runs only on PRs that touch src/ or stories; not on docs-only PRs.

8 · Open questions

  1. Should Storybook ship at app.antiek.ai/storybook in production? Default: no — local-only artifact. (Revisit in S12 if the operator wants a "design system" public page.)
  2. Lost-Pixel threshold: 1% tolerance is generous. Should we go to 0.5%? Default: 1% in S2, ratchet down in S12.

9 · Verification protocol

  1. npm run storybook → side-bar shows every legacy + primitive component grouped under Components / Modes / Design.
  2. npm run visualtest → produces .lostpixel/current/ screenshots, no diffs against baseline.
  3. Manually break one component (change a colour); rerun visualtest; confirm the diff is flagged.
  4. Revert the change; confirm clean run.

10 · Rollback plan

Stories are pure additions. Lost-Pixel config can be deleted without side effects. Rollback = git revert. No consumers depend on S2 artifacts; S2 is a safety-net for later sprints, not a build dependency.
