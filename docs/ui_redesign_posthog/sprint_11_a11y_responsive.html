1 · Goal

Bring the redesigned shell to WCAG 2.1 AA, give keyboard users an equally good (or better) story than mouse users, respect prefers-reduced-motion, and produce a credible tablet fallback layout. This sprint is the "stop being a desktop-only, pointer-only toy" gate.

2 · Why this sprint exists

Through S10, we've optimised for a single operator on a wide monitor. Before cutover (S12) we owe a basic accessibility + responsive pass. Two reasons: (a) operator works on multiple devices; (b) the panel system's whole pitch is "lots of windows" which is hostile to small screens unless we explicitly handle the collapse case.

3 · Non-goals

  • No screen-reader-first redesign of complex surfaces like the notebook block editor or PDF viewer (those are aria-rich already via TipTap / pdf.js; we add labels but don't rebuild).
  • No mobile-native UI. The responsive cut targets ≥ 768 px width. Phone-portrait gets a "use a larger screen" notice.
  • No internationalisation. English-only. (Tracked separately.)
Note · dark mode is no longer a stretch goal Following the Werner brand spec (brand_werner.html), day and night are both first-class from S0 onward. S11's accessibility pass therefore verifies both modes — not just one patched onto the other.

4 · Work packages

WP-11.1

Keyboard focus inside panels

Files: PanelLayoutPanel.tsx, PanelHandle.tsx Effort: 0.8 d

Each panel becomes a role="region" with aria-label={panel.title}. Cmd+[ / Cmd+] (S8) cycles focus across visible panels. A focused panel renders a 2-px ink outline around its border (visible focus ring).

Within a panel, normal Tab order applies. Tab does not escape the panel until the operator reaches the kebab + close buttons in the handle, then continues to the next panel. Shift+Tab reverses.

Floating panel close: Cmd+W or Esc when focused.

WP-11.2

Screen reader labelling

Files: NavRail, Topbar, every primitive in lemon/ Effort: 0.6 d

Audit pass. Each rail icon gets a real aria-label in addition to the visual icon. LemonButton needs an aria-label when only an icon is rendered. LemonModal needs aria-labelledby bound to its title. Toast queue is a role="status" live region. ProjectTree is role="tree".

No automated tool catches every gap; this WP includes a manual VoiceOver pass over RW, Wrestle, Notebook routes.

WP-11.3

Contrast + colour-blind audit

Files: design/tokens.ts if changes needed Effort: 0.3 d

Verify every text-on-background pair meets WCAG AA (4.5:1 for body, 3:1 for large), in both day and night. The yellow-outlining brand creates one explicit known weak spot: the sun-on-ice border has low intrinsic contrast (≈ 1.4:1 against ice). Mitigation strategy is structural, not colour: we lean on the chunky offset shadow (5px ink) and the 2.5-px stroke width to register the edge perceptually. WCAG only requires 3:1 for UI non-text components anyway, and our border is decorative; the contained content carries its own contrast against the fill.

Day-mode body-text pairs (must all hit 4.5:1)

  • ink on ice-0 (#0F1419 on #FFFFFF): 18.2:1 ✓
  • ink on ice-2 (#0F1419 on #F4F7FA): 16.4:1 ✓
  • ink on ice-4 (#0F1419 on #DCE5ED): 12.4:1 ✓
  • ink on glacial-1 (#0F1419 on #C2D1DD): 9.1:1 ✓
  • ink on sun (#0F1419 on #F5DF24): 13.3:1 ✓ — yellow fill always pairs with ink, never with white
  • shadow-1 (#64778A) on ice-2: 4.6:1 ✓ — secondary text floor
  • ice-1 on ink (#FBFCFD on #0F1419): 17.9:1 ✓ — code blocks, topbar text
  • ice-1 on emperor (#FBFCFD on #E33C2D): 4.6:1 ✓ — danger UI only, reserve for short labels

Night-mode body-text pairs

  • bright on space-2 (#EEF1F6 on #0D1019): 18.1:1 ✓
  • bright on charcoal-2 (#EEF1F6 on #1B202A): 14.5:1 ✓
  • bright on slate-1 (#EEF1F6 on #252B36): 11.9:1 ✓
  • starlight on space-2 (#C4CCD7 on #0D1019): 12.5:1 ✓ — body text default
  • moonlight on space-2 (#6B7585 on #0D1019): 4.8:1 ✓ — muted text floor
  • ink on sun (#0F1419 on #F5DF24): 13.3:1 ✓ — yellow fills remain pure-ink on text, day and night
  • sun on void (#F5DF24 on #040508): 16.0:1 ✓ — yellow label on deep background reads well
  • sun on charcoal-2 (#F5DF24 on #1B202A): 12.8:1 ✓ — sun used as accent text at night

Brand-outline ratios (decorative, target 3:1 where possible)

  • sun border on ice-2 (#F5DF24 on #F4F7FA): 1.4:1 — below 3:1; mitigated by 2.5-px stroke + 5-px ink shadow + chunky offset that registers the edge perceptually rather than by colour contrast alone.
  • sun border on ink card (#F5DF24 on #0F1419): 13.3:1 ✓
  • sun border on charcoal-2 (night card): 12.8:1 ✓
  • sun border on void (night page): 16.0:1 ✓ — strongest pairing; this is why the night mode feels "stitched."

Result: the brand outline is high-contrast in night mode and low-contrast in day mode, by design. Day mode borders read as "stitched into" the surface; night mode borders read as "drawn." Both are intentional. The colour-blind check still holds — yellow is unambiguous across deuteranopia + protanopia + tritanopia (it is the colour with the highest cross-deficiency constancy in practice).

Colour-blind check: red/green not used as the only signal anywhere. Status indicators (running/done/failed) pair colour with an icon.

WP-11.4

prefers-reduced-motion

Files: workspace/PanelLayoutPanel.tsx, workspace/PanelLayout.tsx, Tailwind config Effort: 0.4 d

When prefers-reduced-motion: reduce is set:

  • Framer Motion transition drops to { duration: 0 }.
  • Hover-lift translate transforms are no-ops.
  • Dock expand/collapse animation is instant.
  • Toast slide-in becomes fade-in.
// utility hook
export function usePrefersReducedMotion() {
  const [reduce, setReduce] = useState(false);
  useEffect(() => {
    const mql = window.matchMedia("(prefers-reduced-motion: reduce)");
    setReduce(mql.matches);
    const h = (e: MediaQueryListEvent) => setReduce(e.matches);
    mql.addEventListener("change", h);
    return () => mql.removeEventListener("change", h);
  }, []);
  return reduce;
}
WP-11.5

Tablet (≥ 768 px) fallback layout

Files: workspace/PanelLayout.tsx, components/navigation/NavRail.tsx Effort: 1.0 d

Breakpoints:

WidthBehaviour
≥ 1280 pxFull desktop: both docks side-by-side with main; floating panels free.
≥ 1024 pxOnly one dock visible at a time; opening a right-side panel auto-collapses the left dock (with a toast). Operator manually toggles via kebab.
≥ 768 pxNo docks; panels open as full-width overlays that the operator dismisses to see the main slot. Floating panels disabled (they become docked-as-overlay).
< 768 pxNavRail collapses to a hamburger; main slot only; an "open a larger screen" notice for any panel-system action.

Implementation: a useViewportTier hook reads window width via a debounced listener; PanelLayout reads the tier and adjusts rendering. Floating panels switch to docked-as-overlay on tier ≤ "md".

5 · Acceptance criteria

  • VoiceOver pass: an operator using VoiceOver can navigate RW, open a panel, type into Chat, dismiss a modal. Manual sign-off.
  • All tab-order chains complete and visible (focused panel border ring + focused element ring inside the panel).
  • Cmd+[ / Cmd+] cycles focus between visible panels.
  • Axe-core finds zero "serious" or "critical" violations on the primitive stories.
  • Resizing browser to 1024 / 768 / 600 widths produces sensible layouts at each breakpoint.
  • prefers-reduced-motion: reduce verified via macOS System Settings → Accessibility → "Reduce motion": animations vanish without UI breakage.
  • WCAG AA contrast pass for every text-on-background pair documented in WP-11.3.
  • Lost-Pixel baselines updated for breakpoint screenshots (≥ 1280, 1024, 768).

6 · Risks & mitigations

  • Focus traps in modals interact badly with focus traps in popouts. Mitigation: only one focus trap active at a time; the popout window has its own, decoupled.
  • Tablet layout regression breaks desktop. Mitigation: breakpoint switch only kicks in < 1280; desktop default unchanged.
  • Reduced-motion makes the panel system feel disconnected. Mitigation: even with motion off, hover gets a 1-px translation + shadow change (instant, not animated) — still conveys depth.

7 · Open questions

  1. Below 768 px: show the app at all, or block with "use a larger screen" splash? Default: show, but most workspace features disabled; investigation list + chat readable.
  2. Should focus ring use yellow (matches accent) or blue (browser convention)? Default: ink-coloured 2px outline + 1px yellow inset for visibility on dark backgrounds.
  3. Storybook a11y CI: blocking or advisory in S11? Default: advisory in S11; blocking in S12.

8 · Verification protocol

  1. Open System Settings → Accessibility → Reduce motion; reload app; animations gone.
  2. VoiceOver: navigate /, open a panel, tab through, close. No dead-ends.
  3. Resize browser slowly from 1600 → 600 px. Verify layout adapts at each breakpoint without overflow or clipping.
  4. Run npm run storybook, click the a11y addon panel on each primitive; confirm zero serious violations.
  5. Use axe DevTools browser extension on the rebuilt RW; review report.

9 · Rollback plan

Reduced-motion + a11y improvements are additive (extra attrs, extra hooks). Removing them is harmless. Tablet fallback is a hook + conditional rendering; removing collapses to "all panels everywhere", which still works on a tablet just less elegantly.
