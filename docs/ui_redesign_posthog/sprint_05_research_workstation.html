PROPOSED · PILOT MODE PORT

1 · Goal

Port modes/ResearchWorkstation/ — the operator's highest-traffic route — onto the panel system. After S5 the operator sees the same investigation flow as today, but each piece (InvestigationSidebar, Trajectory, MasterMdViewer, ChatInputArea, ChaseSlideOver, HighlightToolbar) is an independently dockable, floatable, popoutable panel.

2 · Why this sprint exists

ResearchWorkstation is the route the operator lives in. Porting it first does three things: (a) proves the panel system holds up under a real consumer; (b) gives the operator immediate visceral payoff for the entire S0–S4 investment; (c) surfaces missing primitives or store actions before the bulk migration of S10. If S5 trips, S6/S7 are cheaper to defer; S10 is cheaper to plan around.

3 · Non-goals

  • No changes to investigation domain logic (useInvestigation, parseSynthesis, the streaming hook). They stay byte-identical.
  • No new investigation feature in S5. Pure UI port.
  • No window-state persistence. Resetting the browser clears panel positions; S9 fixes this.
  • No popout-into-OS-window for any RW panel; popout is still stubbed until S9.

4 · Architecture

4.1 · Current shape (pre-S5)

4.2 · Target shape (post-S5)

<ResearchWorkstation> (the route component) └─ <PanelHost starters=[ { kind: "InvestigationSidebar", mode: "docked-left", title: "Investigations" }, { kind: "Chat", mode: "docked-bottom", title: "Chat" }, // Trajectory / MasterMdViewer render in the MAIN SLOT, not a panel ]> <CenterContent /> ← main slot content: TrajectoryView | MasterMdViewer </PanelHost> └─ HighlightToolbar stays a floating DOM overlay (anchored to selection), not a workspace panel; selections are anchored to text, not workspace coords. └─ ChaseSlideOver becomes a workspace panel opened on demand (action: openChase(text)) — mode: "floating".

Note: S5 introduces a fifth panel mode value: "docked-bottom" for the Chat surface. S3's PanelLayout ships dock-left + dock-right; this WP adds the bottom dock.

WP-5.6

ResearchWorkstation/index.tsx — orchestration only

File: src/modes/ResearchWorkstation/index.tsx Effort: 0.7 d

The route component shrinks dramatically. Its job is:

  1. Read the route param (investigationId).
  2. Open the right starter panels in PanelHost.
  3. Render <CenterContent /> in the main slot.
  4. Expose an action (onChaseThis) that opens a Chase panel.
// src/modes/ResearchWorkstation/index.tsx (post-S5)
export default function ResearchWorkstation() {
  const { investigationId } = useParams<{ investigationId?: string }>();
  const open = useWorkspace(s => s.open);

  const onChaseThis = useCallback((text: string) => {
    open("Chase",
         { spawnContext: text, parentInvestigationId: investigationId },
         { mode: "floating", title: "Chase" });
  }, [open, investigationId]);

  return (
    <PanelHost starters={[
      { kind: "InvestigationSidebar", mode: "docked-left",   title: "Investigations" },
      ...(investigationId
          ? [{ kind: "Chat", mode: "docked-bottom",
               props: { investigationId },                   title: "Chat" }]
          : []),
    ]}>
      {investigationId
        ? <CenterContent investigationId={investigationId} onChaseThis={onChaseThis} />
        : <EmptyState />}
    </PanelHost>
  );
}

HighlightToolbar continues to live inside the main-slot DOM (it is anchored to text selection, which is in the main slot's scroll container). Its onChaseThis callback now goes through the workspace action above.

6 · Acceptance criteria

  • Visiting / with no investigationId renders the EmptyState in the main slot, InvestigationSidebar docked-left.
  • Visiting /inv/<id> additionally docks the Chat panel at the bottom.
  • The operator can pin Investigations to remain when navigating away (pin button on its panel header).
  • Highlighting text in MasterMdViewer + clicking "Chase this" opens a floating Chase panel anchored over the main slot.
  • Opening a second Chase panel works — both render side-by-side with independent state.
  • Dragging the top edge of the bottom dock resizes the Chat surface.
  • All existing investigation streaming behaviour is unchanged: same events shown, same MASTER.md renders.
  • Bundle delta: main chunk grows by < 25 KB gzipped (mainly the new Chase + Sidebar lazy imports that load on demand).
  • Lost-Pixel: ResearchWorkstation screenshots updated; intentional diff committed.
  • Operator daily-driver sign-off: spends one workday in the rebuilt RW with a live investigation, no regressions, "this is the UI I wanted".

7 · Risks & mitigations

  • HighlightToolbar positions wrong when the Chase panel covers the trajectory. Mitigation: toolbar positions are computed against the selection's getBoundingClientRect + main slot scroll position; the floating Chase panel is in a sibling DOM subtree, so toolbar positions don't shift when Chase opens. Verified manually.
  • Investigation streaming UI flickers when Chat re-renders. Mitigation: ChatInputArea uses a memo'd transcript; messages are append-only.
  • Operator confused by "where did the chat go" when no investigation is loaded. Mitigation: EmptyState includes an explicit "Start a question" composer that calls the same submit, then auto-opens the bottom-docked Chat once an investigation id exists.
  • Chase panel content depends on a parent investigation context that disappears on navigation. Mitigation: Chase panel snapshots parentInvestigationId + spawnContext at open time; surviving navigation is intentional (operator can navigate away while chase runs).

8 · Open questions

  1. Should pin-on-navigation persist InvestigationSidebar across routes (e.g. visiting /wrestle keeps it docked)? Default: yes. The pinned panel is workspace-global, not route-scoped.
  2. Default bottom-dock height: 220 px or 280 px? Default: 220 px; operator can drag.
  3. Should MasterMdViewer also be popoutable (so the operator reads it on a second monitor)? Default: yes — registered with kind: "MasterMdViewer" so an explicit "Open in popout" action exists from S9.

9 · Verification protocol

  1. Start a fresh investigation; watch trajectory stream; confirm InvestigationSidebar updates, Chat scrolls, no flicker.
  2. Highlight a chunk in MasterMdViewer → Chase this → confirm a floating Chase panel opens with the right context.
  3. Open a second Chase from a different highlight → both render independently.
  4. Drag InvestigationSidebar's kebab → Float → confirm it pops out as a floating panel, then dock-right → confirm it lands in the right dock.
  5. Reload the page → investigation state reloads (it always did); panel layout resets (S5 has no persistence — expected; S9 fixes).
  6. Run Lost-Pixel; review the intentional diffs.
  7. Operator works a full day inside the new RW. Sign-off is a checkbox in the S5 PR description.

10 · Rollback plan

S5 changes: App.tsx wraps RW in PanelHost (line-level change); the RW components are visually refreshed but still byte-compatible with their pre-S5 callers. Rollback = revert the RW route's PanelHost wrap; visual refreshes can ship anyway because they do not depend on the panel system to render.

In practical terms: S5 lands behind ANTIEK_UI=v2 env flag from S12, so partial rollback is a flag flip.
