1 · Goal

Make the workspace durable across reloads, navigations, and OS-level popout windows. Three deliverables: (a) localStorage persistence keyed by route + investigation, (b) shareable URL params encoding panel layout, (c) window.open-backed popout that renders a real panel into a separate OS window with a live React tree sharing state via BroadcastChannel.

2 · Why this sprint exists

Through S8, every reload nukes the operator's panel layout. That's fine while we're proving the model; intolerable as a daily-driver experience. Popout was stubbed in S3 to keep S3 finite; this sprint cashes the IOU. The deep-link is the social affordance — operator hands a teammate a URL that opens "trajectory + PDF page 12 side by side", and it just works.

3 · Non-goals

  • No server-side sync. State stays local. Multi-device sync is a multi-user concern (Sprint 22+).
  • No undo of layout actions. (Drag a panel by accident → use the kebab to put it back. Layout history is a S22+ topic if at all.)
  • No automatic layout templates ("research mode preset" etc.). Operator builds their own.

4 · Architecture

4.1 · Persistence layers

ScopeStorageKeyWhy
Global panel layout (NavRail, ProjectTree)localStorageantiek.workspace.globalPersists across routes
Per-route layout (RW, Wrestle, Notebook…)localStorageantiek.workspace.route.<route>Each surface has its own preferred layout
Per-investigation overrideslocalStorageantiek.workspace.inv.<id>Operator pins a layout to a specific investigation
URL shareable snapshotURL query param?ws=<base64-json>Send links that open a configured workspace
Popout window stateBroadcastChannel "antiek-workspace"—Cross-window sync of focused panel state

4.2 · Reconciliation order

  1. On AppShell mount: read antiek.workspace.global.
  2. When a route component (e.g. RW) mounts: read antiek.workspace.route.<route>, layer over global.
  3. If investigationId is present and an investigation-specific snapshot exists: layer that over the route default.
  4. If ?ws=… is present in the URL: layer that over everything; clear after applying.

Conflicts: "layer over" means union of panel sets, latest-wins on position/size. Snapshots include a schemaVersion; mismatched versions skip the layer with a debug log.

4.3 · Popout

main window popout window ┌──────────────────────┐ ┌──────────────────────┐ │ ⌘K palette → popout │ window.open ──▶ │ /_panel/<panelId> │ │ Notebook panel │ │ <PanelHost mainSlot= │ │ │ ◀── BroadcastChan ─│ {<PanelRenderer/>}│ │ │ "antiek-workspace" │ /> │ │ panel removed from │ │ panel id stays │ │ floatingIds │ │ "owned" by popout │ └──────────────────────┘ └──────────────────────┘

Single source of truth: the popout window mounts its own useWorkspace store but subscribes via BroadcastChannel to the main window's store. The popout is told only its own panel; closing the popout fires a message and the main window re-adds the panel to its floating layer.

5 · Work packages

WP-9.1

Persistence middleware on WorkspaceStore

File: src/workspace/persistence.ts Effort: 0.7 d

Zustand has a persist middleware; we use it but with a custom storage adapter that writes to multiple keys based on current route + investigation id + a debounce (250 ms). 

// src/workspace/persistence.ts
type PersistKey = "global" | { route: string } | { investigationId: string };

export function snapshotFor(key: PersistKey, snapshot: WorkspaceSnapshot): Partial<WorkspaceSnapshot> {
  // strip transient state (focusedPanelId, zCounter), keep panels + dock arrays
  return {
    panels: snapshot.panels,
    dockLeftIds: snapshot.dockLeftIds,
    dockRightIds: snapshot.dockRightIds,
    dockBottomIds: snapshot.dockBottomIds,
    schemaVersion: snapshot.schemaVersion,
  };
}

export function applySnapshot(s: WorkspaceSnapshot, snap: Partial<WorkspaceSnapshot>) {
  if (snap.schemaVersion !== 1) return s;  // version mismatch: ignore
  return { ...s, ...snap };
}

WP-9.3

URL shareable snapshot

File: src/workspace/urlSnapshot.ts Effort: 0.5 d

Encode the current layout as a base64 JSON in ?ws=…. Decode on load, apply, then strip the param from the URL via history.replaceState. A new palette action "Copy shareable layout link" emits this URL into the clipboard. 

// src/workspace/urlSnapshot.ts
export function encodeWs(s: WorkspaceSnapshot): string {
  const minimal = snapshotFor("global", s);
  return btoa(unescape(encodeURIComponent(JSON.stringify(minimal))));
}
export function decodeWs(raw: string): Partial<WorkspaceSnapshot> | null {
  try { return JSON.parse(decodeURIComponent(escape(atob(raw)))); }
  catch { return null; }
}

Size budget: real layouts encode to ≤ 1.2 KB. URL caps are 2 KB on most servers and 8 KB on browsers; we're well under both.

WP-9.4

Popout via window.open + BroadcastChannel

Files: src/workspace/popout.ts, new route /_panel/:id, src/PanelWindowApp.tsx Effort: 1.4 d

Setting a panel's mode to "popout":

  1. Opens window.open("/_panel/<panelId>", "popout_<id>", "popup,width=720,height=560").
  2. Removes the panel from main-window floatingIds + adds it to a popoutIds array.
  3. The popout window mounts <PanelWindowApp />: a minimal AppShell-like layout that renders just the one panel.
  4. Both windows open the BroadcastChannel "antiek-workspace". Main window posts the panel descriptor to popout on open; popout posts size/position changes back; main window posts close intent.
  5. When popout window closes (operator clicks X), beforeunload fires a "popout closed" message → main window re-adds the panel to floatingIds at the position the popout window had.

Browser support: BroadcastChannel works in every modern browser. Fallback: if BroadcastChannel is undefined, popout opens but cannot sync — main window shows a toast "popout sync unavailable in this browser; layout will not roundtrip." 

// src/workspace/popout.ts
export function openPopout(panelId: string, ws: WorkspaceSnapshot) {
  const panel = ws.panels[panelId]; if (!panel) return;
  const win = window.open(
    `/_panel/${panelId}`,
    `popout_${panelId}`,
    `popup,width=${panel.rect.width|0+40},height=${panel.rect.height|0+80}`
  );
  if (!win) {
    toast.err("Popup blocked. Allow popups for this site.");
    return;
  }
  const ch = new BroadcastChannel("antiek-workspace");
  ch.postMessage({ kind: "popout-init", panelId, descriptor: panel });
}

Security: popout windows are same-origin and pass no opaque tokens; they identify their panel by id only. Substrate auth (when it lands) flows through the same cookies as the main window.

WP-9.5

Layout reset + presets

File: src/workspace/presets.ts Effort: 0.4 d

Three palette commands:

  • Reset layout (this route) — clears the per-route snapshot.
  • Reset layout (this investigation) — clears the per-investigation snapshot.
  • Reset all layouts — clears all antiek.workspace.* keys; confirms with LemonModal.

Built-in presets are explicitly out-of-scope; operators build their own and share via URL.

6 · Acceptance criteria

  • Reload preserves docked + floating panels for the current route.
  • Navigating between investigations and back restores per-investigation layouts.
  • Cmd+K → "Copy shareable layout link" → paste in another browser tab → same workspace renders.
  • Popout a panel via kebab → "Pop out". A second OS window opens containing only that panel; main window's floating layer no longer shows it.
  • Drag the popout window to a second monitor; it stays open + responsive.
  • Close popout window → main window re-adds the panel to floating layer at the popout's last position.
  • Reset commands clear the right scope without affecting others.
  • Schema-version mismatch in localStorage logs once and falls back to defaults; no crash.
  • Bundle delta ≤ 6 KB gzipped.

7 · Risks & mitigations

  • Popup blocked by browser. Mitigation: popout action triggered only from user-initiated event (click); show toast on null window return.
  • BroadcastChannel message ordering racing with React effects. Mitigation: popout window queues incoming messages until React has hydrated; small ready handshake.
  • localStorage quota exceeded with many investigation snapshots. Mitigation: per-investigation snapshots cap at 50 entries (LRU); global state always under 4 KB.
  • Schema-evolution: changing PanelDescriptor shape later breaks saved snapshots. Mitigation: schemaVersion bump triggers ignore; a tiny migration step can be added per version when needed.
  • Popout window depends on substrate APIs (e.g. fetching investigation data) that may have CORS issues. Mitigation: same-origin window.open; substrate calls work identically.

8 · Open questions

  1. Default behaviour on first visit per investigation: blank workspace or inherit route default? Default: inherit route default (already familiar layout).
  2. Should the URL snapshot include the current investigation id, or only layout? Default: layout only — the URL stays general; the investigation id is the path segment.
  3. Should a popout window also persist its own state? Default: no — popouts are transient; main window owns persistence.

9 · Verification protocol

  1. Build a panel layout in /; reload; verify it survives.
  2. Switch to /inv/X; build a different layout; back to /; verify route default returns. Back to /inv/X; verify the investigation-specific layout returns.
  3. Copy shareable link; open in fresh tab; verify same layout.
  4. Popout the Notebook panel; drag the popout to a second monitor; type into it; verify changes save.
  5. Close popout; verify Notebook re-docks/floats in main window with its last popout position.
  6. Manually corrupt antiek.workspace.global in DevTools; reload; verify graceful fallback + console log.
  7. Run Cmd+K → "Reset all layouts"; confirm modal; everything resets.

10 · Rollback plan

Persistence is a Zustand middleware. Disabling it = removing the middleware call site (one line). Popout = one new route + a couple of files; deletable in isolation. URL snapshot = optional read at bootstrap; if removed, links with ?ws= harmlessly ignored.
