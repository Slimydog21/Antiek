## Design notes (craft bar)

1. **One keymap table.** Every new action is a row in keymap.ts with a prefix binding. A direct ctrl+alt chord is allowed only when it is not destructive and passes the MS-01 desktop-collision check. The key sheet and aria-keyshortcuts render from the table, and nothing adds a window keydown listener. The hierarchy:
   - **L1 Product:** ⌘ doors, `mode.cycle` prefix+m / ctrl+alt+m, `mode.pick` prefix+shift+m.
   - **L2 Project:** `project.list` prefix+w / ctrl+alt+w, `project.new` prefix+shift+n / ctrl+alt+n, prefix+g / ⌘K with a project kind.
   - **L3 Cockpit:** h/l, n/p, u/o/t, f, 1..9, c, shift+x, i, `pane.solo`, `voice.toggle` (prefix v / ctrl+alt+v), and island prefix+a.
   - **Scoping:** Speak sections reuse n/p, digits and h/l, scoped to the door. The key sheet groups by level.
2. **Homes lead into the cockpit.** Every product home shares one anatomy: a continue row, a projects list and a collapsed create. The home is the left pane's untabbed state, and launching turns the chosen row into tab 1 with one ≤200 ms shared-element move (an instant swap under reduced motion). No home autofocuses, so the prefix works on arrival.
3. **Designed states everywhere.** Every surface designs loading, empty only after a real answer, error with retry, partial, stale/refreshing, refused_capped, offline, busy (503) and gated. Unknown counts and costs render '—' with a reason, never 0 or $0.00. Every new state gets a story in both themes with lostpixel baselines. New surfaces (MergeFlow, draft review, output island renderer, create page, project overlay, Converse, Autonomous, Notebook, Speak detail) load lazily, because the carrier is about 0.42 KB over budget and the rescue App.tsx predates main's all-lazy routes.
4. **One island, two hosts.** A document island anchors through anchored_highlights. An output island anchors through thread_ref plus NodeTextAnchor in the parent's `branched` event. No new anchor table.
5. **Three verbs, three cost regimes.** Chase answers an open question. Harden stress-tests one claim, is launched by the operator and is ACU-gated. Flag for diligence is consented, capped and runs in the background. Each has its own cost line.
6. **Draft before accept.** The operator reviews the merged analysis, and commit adopts that exact draft, so spend happens at draft time under an estimate.
7. **No parallel stores.** An agent is a dialogue thread, and its memory is its own log plus `context_attached`. A group is a dialogue thread with attached participants. A Converse session is a dialogue thread. A monologue is a §1.11a derived asset. The book notebook is a §1.12 scope. Speak links into projects by membership. Projects extend write_folders.
8. **Rights.** Only served GatedText reaches a model, a merge preview, TTS or an output selection. cite_only and withheld items show under 'what the agent was not shown'. The server enforces the TTS span gate, not an optional client chunkId.
9. **Label-only rename.** Books renames the UI noun only. Code keys (`read`, `reading`, `/read/:id`, `/library`, `read-<doc>`) stay.
10. **Async voice.** Voice is async clips (record, transcribe, editable draft). Spoken prompts stay `user` provenance, and TTS output is `ai`. Duplex voice is an operator decision, not an assumption.

Keep that narrow default, and add a per-project 'let agents read everything here' toggle later only if you want it. Agents never write your account memory until the R15 confirmation step exists.
4. What is a cross-project agent? Recommendation: a long-lived thread that belongs to several projects by membership, with a home project. It is not a first-class entity above threads and not a standalone 'agent desk'. Revisit when Autonomous Research needs scheduling or ownership a thread cannot hold.
5. Accepting a merge: new merged thread, fold into an existing agent, or both? Recommendation: both, with 'Accept as new thread' as the default and 'Accept into agent…' beside it.
