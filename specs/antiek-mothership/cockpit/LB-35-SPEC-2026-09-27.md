Lane B W1, serving lane A F8. Base: `origin/main` at `d61e5256d`. PR #3527 (derived `drv-*` documents) is open at `c0845e327` and is not on main. Every PR #3527 detail below comes from the precedent grounding report. I did not read that branch, because this task limits reads to `origin/main`.

## 1. Problem

**1.1 The detail route rejects any document without a `book_assets` row.**
- `GET /books/{id}` calls `get_book_asset` and answers `404 book_not_found` when it gets `None`: `interfaces/research/api/books.py:2014-2026`, with the 404 at `:2024-2025`.
- `get_book_asset` reads `_BOOK_SELECT`, which is `FROM book_assets b JOIN documents d`, an INNER JOIN: `substrate/books/model.py:162-171`, `:205-211`.
- So a document that exists in `documents` but has no `book_assets` row gets a 404. That covers web articles, T1 arXiv papers promoted by `acquisition/arxiv/store.py:329-352`, inbox articles and Link Monster pages.

**1.2 The reader fails on that one 404, even though the body is servable.**
- `apps/reading/src/modes/Reading/index.tsx:111-114` fetches `Promise.all([getBook, getBookFullText])`.
- `apps/reading/src/api/books.ts:96-100` throws `"book_not_found"` on a 404.
- `index.tsx:714-719` then renders "That book isn't in the library."

**1.3 The body routes already work for any `documents` row, and they already run the book gate.**
- The body routes are `/books/{id}/full-text` (`books.py:2028-2054`) and `/owner-full-text` (`books.py:2056-2085`). Both 404 only when `result.found` is false (`:2044`, `:2083`).
- The gate reads `FROM documents d LEFT JOIN book_assets b` and `COALESCE(b.taken_down, FALSE)` (`substrate/books/serve.py:117-126`).
- It has three outcomes:
  - taken down: no body (`:139-146`)
  - servable: full text (`:167-182`)
  - gated: a snippet of at most 500 characters (`:184-189`)
- On the owner path only, `personal_reading` gets its full body with `servable=False` (`:155-165`).
- `serve_full_text_guarded` adds the arXiv license-tier and link-back checks (`substrate/books/serve_guard.py:233-314`).
- The anchor-map routes key on the same guard: `interfaces/research/api/book_anchor_routes.py:418-452` and `:454-492`.

**1.4 A non-book cannot be taken down.**
- `take_down` selects `FROM book_assets b JOIN documents d` and raises `BookNotRegistered` when that row is missing: `substrate/books/takedown.py:62-75`.
- `reinstate` behaves the same way (`:146-153`).
- The serve gate reads its takedown flag only from `book_assets` (`serve.py:120-122`).
- The arXiv takedown CLI exits with code 2 for any paper without a `book_assets` row: `tools/arxiv_takedown.py:35`, `:52`, `:114-120`.
- The arXiv store path promotes a body to a servable class without writing a `book_assets` row. `acquisition/arxiv/store.py:329`, `:347` do the promotion, and a grep of `acquisition/arxiv/` finds `book_assets` writes only at `adapter.py:537`, `:648`, through `register_book`.
- Result: served non-book bodies exist today that no removal demand can reach.

**1.5 The frontend is also blocked (lane A).**
- The `Servability` union has no `personal_readable` value: `apps/reading/src/api/books.ts:21-31`.
- `servabilityLabel` has no case for it and no default branch: `books.ts:1076-1091`.
- The backend does emit it: `substrate/books/servability.py:73`, `:128-129`.
- `index.tsx:722` destructures the result of `servabilityLabel`, which will be `undefined` for that value.
- Third-party non-books default to `personal_reading` when no class is given (`substrate/graph/ops.py:227-231`), so this likely crashes on exactly the documents ruling 12 cares about. The crash is INFERRED; I did not run the page.

## 2. Design decision

### D1. Extend `GET /books/{id}` with a documents-backed detail. No new route.

The route resolves in this order:

1. **Read the `documents` row**, taking `document_type`. If there is no row, answer `404 book_not_found`, exactly as today.
2. **Call `get_book_asset(con, id)`, which stays unchanged.** If a row exists, take today's registered path: `BookDetail` is built from the `BookAsset` as now, plus the three marker fields below. Books, uploads, CC-BY YouTube transcripts and `drv-*` documents from PR #3527 all resolve here.
3. **If there is no registered row and `document_type == "derived"`, answer `404 book_not_found`.** A derived view may open only through its own registration, which is the row PR #3527 writes and the row its takedown propagation joins on. This refusal keeps PR #3527's invariant visible instead of hiding a missing row.
4. **Otherwise build the fallback detail.** Construct a `BookAsset` in memory. Its `__post_init__` sets `servability` and `servable_full_text` from `servability_of(content_class, taken_down=False)` (`model.py:86-89`). That is the same projection the book path uses. It also matches what `serve_full_text` computes for the same row, because `COALESCE(b.taken_down, FALSE)` is FALSE when there is no row (`serve.py:120-122`).

What this deliberately leaves alone:
- `get_book_asset` and `list_book_assets` are not changed. Their other callers depend on `None` meaning "not registered": `books.py:1821`, `:2299`, `:2873`; `substrate/book_acquisition/port.py:318`; `substrate/book_import/publish.py:492`; `substrate/books/ingest.py:155`.
- `BookSummary` is not changed, so `/books` and `/library` stay byte-identical.

**Marker fields.** These are added to `BookDetail` only:

| Field | Value |
|---|---|
| `document_type: str` | `documents.document_type`, taken verbatim |
| `is_book: bool` | `document_type == "book"`. The server decides this so lane A does not have to. |
| `registered: bool` | `true` if a `book_assets` row exists |

**What the fallback detail contains, when there is no `book_assets` row:**

| Field | Value | Source, and how the reader copes |
|---|---|---|
| `document_id`, `title`, `author` | from `documents` | The same values `/full-text` already returns (`serve.py:117-126`) |
| `servability`, `servable_full_text` | `servability_of(content_class, taken_down=False)` | The same projection as books |
| `taken_down` | `false` | No row, so this matches the serve gate |
| `page_count` | `0` | The reader cuts pages on the client (`index.tsx:174-178`) |
| `pagination_scheme` | `"none"` | The reader does not read this field |
| `toc` | `[]` | `TocPanel` shows its empty state (`TocPanel.tsx:17-22`); lane A changes the copy |
| `cover_uri`, `provenance`, `license_basis` | `null` | The reader does not read these |
| `ip_holder_id` | `null` | `/full-text` does not expose it. This is a conservative choice; see Q5. |
| `document_type`, `is_book`, `registered` | the marker, with `registered=false` | Lane A renders the non-book marker and hides TalkToBook |

**No-widening argument.**
- `BookDetail` never carries a body: `books.py:299-343`, pinned by `tests/test_book_corpus_gate.py:601-616`.
- Every non-default fallback value is either something `/full-text` already returns for the same id, or its servability projection, or one of the three marker fields.
- The text the reader shows still comes only from `/full-text` or `/owner-full-text`, through `serve_full_text_guarded`. Neither route changes.

### D2. Takedown must reach non-books

This is a rights precondition and ships in the same PR.

**Taking down a document that has no `book_assets` row:**
- If the `documents` row is missing, raise `BookNotRegistered`. Keep that class name so the CLI stays compatible.
- Otherwise, inside one explicit transaction, and only when `not con.in_explicit_transaction` (`runtime/db_lock.py:612`; `update_document_gate_columns` already defers to an outer transaction at `ops.py:379`):
  1. `INSERT` a takedown-record row into `book_assets` with `taken_down=TRUE`, `taken_down_at`, `takedown_reason`, `pre_takedown_content_class=<current>`, `provenance=TAKEDOWN_RECORD_PROVENANCE`, `page_count=0` and `pagination_scheme='none'`. The flag goes in first, so the operation fails closed.
  2. Call `update_document_gate_columns(content_class=TAKEDOWN_CONTENT_CLASS, set_content_class=True, null_raw_text=True)`. This is the same purge the registered path uses (`takedown.py:86-92`).
  3. `COMMIT`, then emit the same two events (`:94-126`).
- The registered-row path does not change.

**Reinstating a takedown record** (a row whose `provenance == TAKEDOWN_RECORD_PROVENANCE`):
- Restore the class as today (`:158`), then `DELETE` the row. The document goes back to exactly its pre-takedown registration state, so listings do not change.
- `raw_text` stays purged. That asymmetry is intended today (`takedown.py:23-27`).

**Why the record lives in `book_assets` and not in a new store.**
- The serve gate reads the takedown flag there (`serve.py:120-122`).
- Per the precedent report, PR #3527's `_source_chain_status` and `_derived_books` read it there too.
- One store means no new reader has to learn about a second one.

**Side effect.** `tools/arxiv_takedown.py` starts working for promoted T1 papers that have no `book_assets` row.

### D3. `POST /books/{id}/ask` refuses taken-down documents

**The change.** In `ask_book`, after the existence check (`books.py:2299-2307`), if `asset.taken_down`, answer `403 book_taken_down`. This happens before any retrieval or dispatch.

**Why this is required.**
- D2 makes `get_book_asset` non-`None` for a taken-down non-book.
- `/ask` retrieves chunks with the owner's policy tag (`books.py:2421`, INFERRED from a grep window).
- The privileged tag lets `restricted_pending_opt_in` through (`substrate/graph/retrieval_gate.py:127-135`), and takedown rewrites the class to exactly that value (`constants.py:651`, `takedown.py:86-92`).
- Without D3, LB-35 would open a way to chunk text from a taken-down non-book. The same hole already exists for books today, so D3 also tightens books. See Q4.

**Non-books without a row keep `/ask` → 404, unchanged.** Relaxing that would widen what is served. The chunk gate is a denylist that lets NULL-class chunks through (`retrieval_gate.py:136-142`), while the full-text gate is an allowlist that limits NULL to a snippet (`constants.py:521-543`).

### D4. Explicitly unchanged

- `serve.py`, `serve_guard.py` and `servability.py`
- `list_book_assets`, `/books`, `/library`, the house-ad pool and meta-readings
- `/full-text` and `/owner-full-text`
- The anchor-map routes and anchor CRUD
- Reading-state, spin-research and voice-note
- `/sources/{id}/reader-html`
- The retrieval gate

The body path is already documents-keyed and gated (1.3). Touching it would add conflict with PR #3527 and add nothing.

**`source_tier` and `cite_only` are not part of the book gate.**
- `serve.py:117-126` does not select `source_tier`.
- `cite_only` exists only in `services/html_projection/adapters/*`, per the rights report.
- On the reader path, the equivalent of `cite_only` is "gated, bounded snippet".
- LB-35 reuses the book gate as it is (Q7).

### D5. Interaction with PR #3527

**Merge order.** PR #3527 goes first: it is open, mergeable, and larger, and it rewrites `serve.py`, `takedown.py` and `list_book_assets`. LB-35 then rebases onto it.

**No double logic.**
- LB-35 adds no path for derived documents. A `drv-*` document resolves through its registration on the unchanged registered branch and only gains the marker (`document_type="derived"`, `is_book=false`, `registered=true`).
- The fallback's `"derived"` exclusion must use the same constant or literal as PR #3527's `list_book_assets` filter. Per the report, that filter is the literal `d.document_type IS DISTINCT FROM 'derived'`. Whichever PR lands second merges them into one constant in `substrate/books/model.py`.

**`takedown.py` conflict.**
- Per the report, PR #3527 adds propagation at branch `takedown.py:140-141`, `:149-163` and `:212-218`.
- LB-35's takedown-record INSERT must run **before** that propagation. Then taking down a non-book source that has no `book_assets` row also reaches its `drv-*` documents; today it can reach neither.
- On reinstate, the record DELETE runs **after** PR #3527's propagation of the reinstate.

**Known inconsistency, not fixed here.** After PR #3527, detail servability for a `drv-*` document is its copied class, while `/full-text` applies the source-chain cap. The detail can say "servable" while the body is withheld. That is a label inconsistency, not a leak, and it is the same pattern as arXiv license drift (Q8).

**If LB-35 lands first:** skip test E1 and add it during PR #3527's rebase. E2 runs on main either way.

## 5. Mutants to kill

| # | Mutant | Killed by |
|---|---|---|
| M1 | The fallback hard-codes `servable_full_text=True`, or takes servability from a constant | B1, F1 |
| M2 | The fallback projects with owner semantics, so `personal_reading` counts as servable | B2 |
| M3 | The route uses the documents-only projection for every document, ignoring `book_assets` takedown, TOC and page count | A3, C1 |
| M4 | The fallback answers 200 for a missing `documents` row | A4 |
| M5 | The fallback admits `document_type="derived"` | E2 (and E1 later) |
| M6 | `is_book` comes from `registered` instead of `document_type` | A3 |
| M7 | The fallback leaks `ip_holder_id`, `provenance` or `license_basis` | A2 |
| M8 | The marker fields are added to `BookSummary` | D1, through its key set |
| M9 | `list_book_assets` or `/library` start using a documents LEFT JOIN | D1 |
| M10 | The takedown-record row is inserted with `taken_down=FALSE`, or outside the transaction | C1, C7 |

## 6. Risks and open questions for the operator

**Q1. Ads on non-books (the main one to rule on).**
- For anything not from arXiv, `ad_eligible == servable` (`serve_guard.py:307`), and the reader mounts ad rails from it (`index.tsx:941-943`).
- Opening servable non-books puts house-ad rails and impression accrual on them. For example: a web page with a `source_declared_open` or `public_domain` class, or an arXiv T1 paper.
- LB-35 does not change the backend's ad logic. Ruling 12 does not cover ads, so lane A F8 should not enable rails on `is_book=false` until you rule.

**Q2. How to mark a non-book.**
- `is_book` is `document_type == "book"`.
- Uploads (`upload_routes.py:664`) would get the non-book marker even when the upload is a whole book. Accept that, or widen the rule?

**Q3. `/ask` on unregistered non-books stays 404.**
- Enabling it needs model context gated on the serve verdict, not just the chunk denylist. Confirm it stays out of scope.

**Q4. D3 tightens `/ask` for books too.**
- More broadly, the privileged retrieval tag lets taken-down chunks (`restricted_pending_opt_in`) through on every owner path, including corpus search and the context picker (`retrieval_gate.py:127-135`). That is an existing hole outside LB-35. It needs its own lane.

**Q5. `ip_holder_id` is null in the fallback but present for registered documents.**
- The reader does not use it. Confirm the conservative null.

**Q6. The takedown-record semantics.**
- The record uses a sentinel `provenance` value and is deleted on reinstate. The alternative is to keep it as a registration, which would change listings after a reinstate.
- DuckDB risk: a child INSERT and a parent gate-column UPDATE share one transaction. `acquisition/youtube/adapter.py:474-481` records a silent drop in a similar pattern. C1 and C7 read through a fresh connection for this reason.
- `index-job` (`books.py:1821-1823`) would accept a takedown record. It only embeds text and does not serve it, so this is low risk, but it is worth refusing as well.

**Q7. `source_tier` and `cite_only` are not in the book gate** (`serve.py:117-126`).
- LB-35 reuses the gate as it stands. Adding either term would change how books are served too.

**Q8. Detail servability is a projection, not the guard's verdict.**
- This is the arXiv drift case in B3, and PR #3527's source cap for `drv-*` documents.
- It does not leak text, because the reader needs `/full-text`, but the label can be wrong.
- Follow-up after PR #3527: compute detail servability through `serve_full_text_guarded` for both paths.

**Q9. NULL-class non-books** (legacy `paper`, `article`, `pdf`, `external_deep_research`).
- The reader gives them a snippet, while chunk search serves them in full (`retrieval_gate.py:136-142`).
- They should be classified before they go on a shelf. That is W1's shelf-write step, not LB-35.

**Q10. The owner full-read has no per-document ownership check.**
- It relies only on the single-operator rule (`books.py:106-137`).
- An interest shelf of `personal_reading` web pages would read entirely through this path. This is existing behaviour and unchanged here.

**Q11. The `personal_readable` crash is lane A's to fix.**
- It is INFERRED and not run. It probably also affects registered `personal_reading` books, such as ported books.

**Q12. The research seed says "From the book" for every document** (`substrate/books/passage_research.py:118`).
- Non-books get the same wording. It is a cosmetic voice fix, outside LB-35 unless you want it included.
