# LB-8 executable spec: Write `informs` persistence

## 0. Verdict

- **Base:** `origin/main` at `b41f4ec9b`. Nothing needs a code stack. LB-8 uses no code from #3530 (LB-2), #3527 (`c0845e327`) or the wave-5 branch. It borrows LB-2's patterns and nothing else.
- **What it builds:**
  - one new shared module: the §1.11 revise primitive, which LB-4b and LB-5 then reuse;
  - three new tables;
  - `PUT …/informs`;
  - a read of one block's informs.
- **What blocks the merge:** five things the signed text leaves open, and they change a type, a route or a state (R-LB8-1…5, §5B). Under the contract's rule these need a dated revision that both lanes sign (`THREAD-CONTRACT.md` Signatures, "any change to a type, route or state is a new dated revision"). The code in §6.1–6.5 can be built and tested now. The outbox event (R-LB8-1) and the GET (R-LB8-2) cannot merge until that revision is signed.
- **What makes it inert in production:**
  - Nothing on any permitted ref writes revision 1 of `write:<deliverable_id>` (`THREAD-CONTRACT.md:577`).
  - LB-8 does not write it either: doing that honestly needs the W3 member rebuild (`:583-609`), which main's evidence-only member table cannot hold (`origin/main:substrate/graph/schema.py:1326-1343`).
  - So in production, PUT and GET answer 404 for every Write deliverable until the W3 Write revision writer lands. Nobody has claimed that writer on the board.
  - Lane A cannot ship S5 persistence on LB-8 alone.
- **The dependency list is short:** the LB-8 row (`cockpit/FORENSIC-SWEEP-V2-KIMI-COCKPIT-2026-09-26.md:400`) lists only LB-1(b). LB-1(b) is done (rev 8.10 carries both signatures), but it is not the whole list.

### 5B. Contract request R-LB8 (needs a dated revision that both lanes sign before merge)

Cite in the `path@commit` form plus an anchor phrase (`THREAD-CONTRACT.md:89`).

- **R-LB8-1, the event.**
  - NEW `derived_asset.revised {derived_asset_id, revision_id, parent_revision_id, operation, block_ids[]}`, written through `write_event_outbox` in the revise transaction.
  - It carries no document ids, so no saved reference leaks into event logs.
  - The log is `write-<deliverable_id>` for `write:` assets, mirroring `read-<source_document_id>` (`:834`).
  - It rides the next sequenced `EVENT_SCHEMA_VERSION` bump, with codegen in the same commit (§1.16, `:1187`).
  - Why it is needed: without a named event, `:646` cannot be met.
- **R-LB8-2, the read.**
  - NEW `GET /derived-assets/{asset_id}/blocks/{block_id}/informs`. It answers the PUT's answer shape at the current revision, and 404 exactly as the PUT does. It writes nothing.
  - Why it is needed: without it, "persistence across reload" cannot be shown to lane A, and the only signed way to learn the current revision is a 409.
- **R-LB8-3, block identity.**
  - `block_id` is the stable Write block id (`outline_blocks.outline_block_id`, `schema.py:964-965`).
  - A Write revision records its blocks under those ids, which makes `:588`'s "html_projection block" and `:628`'s "stable Write block id" one id.
- **R-LB8-4, carry-forward.**
  - Every revise copies unchanged each per-revision row it does not replace: members, block inventory and informs. Bites and member_bites follow LB-5's carried-bite rule.
  - A block removed by a revise loses its informs.
  - Without this rule, a fork or merge would silently empty every list, which is a second lost update.
- **R-LB8-5, no revision yet.**
  - A deliverable with no revision answers 404 to the PUT and the GET.
  - LB-8 writes no revision 1. The `:577` `create` belongs to the W3 Write revision writer.

Whether these go into a narrow rev 8.11 or into rev 9 is the orchestrator's call. The rev-9 draft covers none of them; it only reads informs as Converse model context (`THREAD-CONTRACT-REV9-PART1-DRAFT.md:1663`).

## 6. Design (signed core, plus §5 marked where it applies)

### 6.1 Shared module `substrate/derived_assets/repository.py` (NEW)

- **Scope:** revisions only. It has no route and no DDL (`schema.py:1238`: "routes never own DDL").
- **Callers** hold `runtime.db_lock.connect_write` (`origin/main:runtime/db_lock.py:811`) and call inside one `BEGIN…COMMIT`, using `eventful_transaction` (`origin/main:substrate/write/event_outbox.py:35-47`).

```python
class NotFound(Exception): ...                      # → 404 {"detail":"not_found"}
class RevisionMoved(Exception): current_revision_id: str
class IdempotencyConflict(Exception): ...
class RevisionIntegrityError(Exception): ...        # → 500, nothing written

@dataclass(frozen=True)
class Head: derived_asset_id: str; revision_id: str; content_sha256: str; generation: int

def load_owned_head(con, asset_id: str, *, owner_user_id: str) -> Head        # missing == foreign → NotFound
def find_operation(con, *, owner_user_id: str, idempotency_key: str) -> StoredOperation | None
def block_in_revision(con, head: Head, block_id: str) -> bool
def revise(con, *, head: Head, expected_revision_id: str, owner_user_id: str,
           idempotency_key: str, request_sha256: str, operation: str,
           patches: Mapping[str, ChildPatch], event_log_id: str, block_ids: Sequence[str],
           build_answer: Callable[[str], dict]) -> dict
def create_revision(con, *, asset_id, owner_user_id, asset_kind, title, canonical_html,
                    manifest_json, sanitizer_policy, sanitizer_version, blocks, members, ...) -> Head
    # §1.11 :577 primitive. LB-8 gives it no production caller (test fixtures only).
CHILD_TABLES: Mapping[str, ChildCopier]   # members, revision_blocks, block_informs
```

`revise()` runs these steps in order:
1. Precheck `expected_revision_id == head.revision_id`, or raise `RevisionMoved`.
2. Check that the parent manifest's member count equals its member rows (the record, `:89-91`), or raise `RevisionIntegrityError`.
3. INSERT the revision with a new `rev-<uuid4hex>`, `operation_kind='revise'`, `parent_revision_id=head`, bytes, hashes and sanitizer copied, plus A1 and A2.
4. For each `CHILD_TABLES` entry, copy the parent's rows under the new id, except the rows its patch replaces.
5. INSERT the operation row with the stored `response_json` from `build_answer(new_rev)`.
6. Run `UPDATE derived_asset_current_revisions SET current_revision_id=?, current_content_sha256=?, generation=generation+1, updated_at=now WHERE derived_asset_id=? AND current_revision_id=? AND current_content_sha256=? AND generation=? RETURNING generation`. An empty result raises `RevisionMoved`. The idiom is `origin/main:tests/test_derived_asset_schema.py:327-342`; "rowcount is not a CAS signal" (the record, `:77-78`).
7. Update `derived_assets.updated_at` (the record, `:91`).
8. Call `enqueue_event(operation_id=<dop id>, aggregate_kind='derived_asset', aggregate_id=asset_id, …)` (`event_outbox.py:85-118`). This step needs R-LB8-1.

The legacy rule (`:628`) is a hook in the members copier. It does nothing on main, where no legacy revisions exist; it is filled in when the W3 member rebuild lands.

LB-8 must not use `validate_commit_boundary`: the informs body fails it as unknown fields (`derived_asset_boundary.py:68-70`).

```sql
CREATE TABLE IF NOT EXISTS derived_asset_revision_blocks (
  derived_asset_id TEXT NOT NULL, revision_id TEXT NOT NULL,
  block_index INTEGER NOT NULL CHECK (block_index >= 0),
  block_id TEXT NOT NULL CHECK (length(block_id) BETWEEN 1 AND 256),
  PRIMARY KEY (derived_asset_id, revision_id, block_id),
  UNIQUE (derived_asset_id, revision_id, block_index),
  FOREIGN KEY (derived_asset_id, revision_id) REFERENCES derived_asset_revisions(derived_asset_id, revision_id));
CREATE TABLE IF NOT EXISTS derived_asset_block_informs (

  ordinal INTEGER NOT NULL CHECK (ordinal >= 0 AND ordinal < 50),
  document_id TEXT NOT NULL CHECK (length(document_id) >= 1),

  PRIMARY KEY (derived_asset_id, revision_id, block_id, ordinal),
  UNIQUE (derived_asset_id, revision_id, block_id, document_id),
  FOREIGN KEY (derived_asset_id, revision_id, block_id)

CREATE TABLE IF NOT EXISTS derived_asset_operations (
```

### 6.3 `substrate/derived_assets/informs.py` (NEW)

- **`InformsAnchor`** (pydantic, `extra="forbid"`) mirrors §1.4 field for field:
  - `document_id` (min 1);
  - `source_locator: TextLocator | None`, using main's type (`origin/main:substrate/contracts/html_projection.py:71-82`: end > start, 64-hex sha);
  - `region_id`, `quote`, `prefix`, `suffix` (`str | None`);
  - `page_index` (≥ 0).
  - There is no `anchor_id`. §1.4's field list omits it, and B0's shipped `BranchAnchor` also forbids it (`origin/fix/audit-wave5-c2-export:substrate/schemas/events.py:2546-2558`).
  - Quote, prefix and suffix are normalized with `normalize_node_text` (`origin/main:substrate/feedback/domain.py:18-20`).
- **`validate_entries(con, owner, entries) -> list[ValidEntry]`** raises `InformsInvalid(index, detail)`. It checks in this order and reports the lowest failing index:
  - the length cap (`too_many_entries` at index 50), before any per-entry work;
  - then, for each entry in list order:
    - entry shape (`entry_invalid`);
    - a repeat, reported at the second occurrence (`duplicate_document`);
    - anchor shape (`anchor_invalid`);
    - anchor naming another document (`anchor_other_document`);
    - readability (`document_not_readable`).
- **`replace_block_informs(...)`** is `revise()` with a patch that replaces this block's rows. All other blocks' rows are carried forward.
- **`read_block_informs(con, asset_id, block_id, owner)`** is read-only.

### 6.4 Readability predicate (private to `informs.py`; no edit to any rights or auth file)

There is one SELECT over `documents(document_id, content_class, owner_user_id)` for all the ids. A document is readable when all of these hold:
- it exists;
- `content_class IS NULL` (grandfathered, `origin/main:substrate/graph/retrieval_gate.py:18-22`) or `content_class ∈ VALID_CONTENT_CLASSES` (`origin/main:substrate/rights/register.py:71-79`). An **unknown non-NULL class fails closed**; that includes `user_authored_private` until PA04 lands;
- `content_class ∉ PERSONAL_ONLY_CONTENT_CLASSES` (`retrieval_gate.py:72-74`), or `owner_user_id ==` the verified requester.

Two rules follow:
- Legacy `user_owned` keeps its current behaviour: readable, as in the privileged arm (`retrieval_gate.py:127-135`), and OPEN until PA06.
- Gated classes are readable as references, because citing a non-servable source is allowed (`THREAD-CONTRACT.md:609`).

Missing, foreign-private and unknown-class documents all get the same `detail`. The docstring names A06's planned `substrate/rights/document_visibility.py` as the replacement.

## 7. Wire shapes

**Signed:**
```
PUT /derived-assets/{asset_id}/blocks/{block_id}/informs
  {"informs":[{"document_id":str,"anchor"?:{document_id, source_locator?:{start,end,text_sha256}, region_id?, quote?, prefix?, suffix?, page_index?}}],
   "expected_revision_id":str, "idempotency_key":str}
200 {"revision_id":str,"block_id":str,"informs":[{"ordinal":int,"document_id":str,"anchor"?:{…as stored}}]}   # replay: byte-identical 200
404 {"detail":"not_found"}                                           # missing/foreign asset, block not in current revision, no revision
409 {"reason":"revision_moved","current_revision_id":str}
409 {"reason":"idempotency_conflict"}
422 {"reason":"informs_invalid","index":int,"detail":<A11 code>}
```
- `anchor` is left out when absent.
- The answer carries the stored anchor, after the cite-only drop.
- No 403 is ever returned.

**Proposed (R-LB8-2):** `GET` on the same path answers the 200 shape at the current revision, and 404 exactly as the PUT.
