## 1. Design decisions, each on signed text

Items marked **[RULING]** are interpretations. Lane B must confirm each one before the PR that carries it merges. The listed default is what the PR builds.

**D1. Store: `evidence_index`, refs only, `entry_id = evidence_id` (TC:1010).** The id is owner-safe in both allowed ways (TC:1011):
- **Material.** The id material includes the owner: `"ev-" + sha256("\x1f".join(["companion_document.v1", owner_user_id, scope, scope_id, kind, anchor]))[:24]`.
- **Anchor.** The anchor is pointer-only: `node:<node_id>`, and later `event:<event_id>#<i>` for claims. It is never text, which closes comp's oracle: comp hashes claim text (comp:substrate/companions/evidence_index.py:143-149) and still serves the id when the text is withheld (comp:substrate/companions/projector.py:475-479).
- **Primary key.** The key is `(owner_user_id, evidence_id)`.
- **Scope in the material.** One node can appear in both the project scope and the document scope for the same owner. Without scope and scope_id in the material, those two rows would collide under the composite key.
- **Columns.**
  - Identity: owner_user_id, evidence_id, scope ∈ {project, document}, scope_id, kind ∈ {claim, open_question, insight}.
  - Refs: thread_ids_json, doc_ids_json, pins_json, process_thread_id, process_event_id.
  - Values: confidence, updated_at, text_sha256 (server-only, never serialised).
  - Receipt link: refresh_event_id.
- **No text column.**

**D2. The receipt (TC:1039).** The receipt is the typed event `companion_document.refreshed {scope, id, content_hash, covered}`. It is emitted strict into a per-owner receipt log named `companion-document-<sha256(owner\x1fscope\x1fid)[:32]>`.
- **Never a member thread's log.** A receipt there would make the document stale by staleness criterion 1 (TC:1042).
- **Never `read-<doc>`.** comp's watcher wrote `companion.rebuilt` onto that shared log (comp:substrate/companions/watcher.py:317-319).
- **The id is valid.** It matches w5x's storage-id pattern (w5x:substrate/event_log/events.py:787).
- **It is not listed as a thread.** `GET /investigations` skips logs that are not `inv-` and carry no lifecycle marker (main:interfaces/research/api/app.py:3088-3091).
- **The DB index.** A DB row `companion_document_receipts (owner_user_id, scope, scope_id, refresh_event_id, content_hash, covered_json, positions_json, membership_digest, reading_baseline_json, refreshed_at; PK (owner_user_id, scope, scope_id))` indexes the receipt and holds the staleness baselines.
- **Trust rule.** A GET trusts a row only when its `refresh_event_id` is present in the receipt log.
- **[RULING]** The contract does not name which log the receipt goes to.

**D3. GET never writes (TC:1012).**
- **No initialisation.** The GET opens `connect_read(default_db_path())` and never calls `_resolve_db_path`. That helper calls `ensure_initialized` (main:interfaces/research/api/books.py:157-162), whose cold path takes `connect_write` (main:substrate/graph/schema.py:2593-2607).
- **Read-only event reads.** Events are read only through `trajectory()` (main:substrate/event_log/events.py:752-806) or `trajectory_read`.
- **Nothing that locks.** The GET never uses `read_physical_event_page`, `iter_physical_events` or any emit. `investigation_event_lock` runs `makedirs` and creates lock files with O_CREAT (main:substrate/event_log/events.py:184-213).
- **Missing tables.** They are detected with `table_exists` (lb2:substrate/projects/schema.py:140-146) and never created on a GET.

**D4. The rights switch.**
- **Where.** `substrate/companion_document/rights.py` holds `RIGHTS_BRANCHES_LANDED: Final[bool] = False` and `bound() -> RightsBinding | None`.
- **While off:**
  - every GET answers 200 with the unavailable body;
  - every POST answers `409 {reason: "unavailable_until_rights"}` and writes nothing.
- **The flip.** Only LB-9d flips it. That is one reviewed PR, and a test in it fails unless every landmark of both branches is importable or present on its base:
  - `resolve_pin_sources` (w5x:services/html_projection/resolvers/substrate_refs.py:377);
  - `trajectory_read` (w5x:substrate/event_log/events.py:795);
  - `_excerpt_cleared` (w5x:substrate/research_artifact/build_body.py:71);
  - `tools/antiek_memory/mcp-tools.manifest.json`, which exists only on mcp.
- **No env var.** An environment flip is not a reviewed change.
- **Import failure at runtime.** The routes answer unavailable, failing closed.

**D5. GatedText.** It is NEW and shared, in `substrate/schemas/gated_text.py`, exactly as TC:209-220 and TC:1626 define it.
- **Fields.** `{text: str|None, gate: served|cite_only|withheld, reason: None|unresolved|not_servable|lineage_unreconciled, origin: source|operator|generated|unsourced, source_refs: [SourceRef]}`.
- **SourceRef.** `{kind, id, document_id?, anchor?, gate, reason}` (TC:212, TC:254). It has no title field; lane A resolves titles through owner-checked reads.
- **Validators** enforce the discriminated shape of TC:217-220.
- LB-3 and W2 must import these types, not redefine them.

**D6. The entry gate (TC:224, TC:1631).** An entry drawn from a body is a synthesis, so its gate is only `served` or `withheld`, never `cite_only`. The excerpt gate decides it for each member thread. The entry is served only when both of these hold:
- every source in the excerpt-source set of every contributing thread is resolved and servable after the owner overlay (D8);
- no contributing thread's walk is unreadable.

Otherwise it is withheld. The rules for the reason:
- **Several threads.** The most restrictive result across `thread_ids` wins (TC:231).
- **Reason precedence.** lineage_unreconciled over unresolved over not_servable.
- **No sources.** A thread with no sources is `withheld · unresolved` (TC:225; w5x:substrate/research_artifact/build_body.py:144 `return bool(sources) and all(...)`).
- **lineage_unreconciled.** No ref computes it (git grep over main, lb2 and w5x finds nothing), so LB-9 never emits it, although the composer handles it.

Choosing the reason needs the list of sources, not a bool. LB-9d therefore extracts `excerpt_sources()` from w5x:build_body.py:99-144 without changing behaviour.

**[RULING]** Under this literal reading, one non-servable source in a thread withholds every entry drawn from that thread.

**D7. `source_refs` (TC:1643: the operator sees exactly which source held the text back).** The list is the entry's own node pins, from `resolve_pin_sources(con, [("node", id)])`, plus the non-served sources of each contributing thread's excerpt set.

Each ref's gate follows the quotation rule (TC:223):
- `served`: resolved and servable;
- `cite_only · unresolved`: the source cannot be found;
- `cite_only · not_servable`: resolved but not servable;
- `withheld · not_servable`: set by the owner overlay, with `document_id` and `anchor` dropped.

**D8. Owner overlay (TC:1183, "owner-scoped from day one").** The signed allowlist includes `user_owned` (main:substrate/constants.py:537-543). The w5x resolver reads documents by id with no owner check (w5x:substrate_refs.py:390-401), so a foreign `user_owned` document would come back as served.
- **The overlay rule.** A resolved document whose owner is not admitted (D9), and whose class is not in `PUBLIC_GRAPH_CONTENT_CLASSES` (main:substrate/ad_inventory/attribution.py:79-85), becomes `withheld · not_servable` and opaque.
- **Unknown and NULL classes.** They are not in SERVABLE, so they are not servable (fail closed).
- **The owner's own `personal_reading` documents.** They are also not servable, because signed 8.10 has no owner path.
- **[RULING]** In practice the operator's own reading-based threads will read as held back.

**D9. Who the requester is.**
- **Identities.** The requester's identities are `{_reader_owner_id(request)}` (main:books.py:140-149), plus `request_owner_user_id(request)` when it resolves (main:interfaces/research/api/settings_models_admin.py:229).
- **The `__operator__` sentinel.** It counts only under the single-operator predicate that main:books.py:130-137 already uses: auth_method in `_OWNER_AUTH_METHODS` and the operator allowlist ≤ 1 (main:interfaces/research/api/operator_allowlist.py:15), or `unauthenticated_local`.
- **Document owner.** `documents.owner_user_id` is `NOT NULL DEFAULT '__operator__'` (main:substrate/graph/schema.py:104).
- **Thread owner.** The start payload's `owner_user_id` is nullable (main:substrate/schemas/events.py:2425), and NULL reads as `__operator__`.
- **[RULING]** There are two owner namespaces. A BYOT thread's owner comes from the email-derived `request_owner_user_id`, while projects use `_reader_owner_id`.

**D10. Member threads.**
- **Project scope.** The members come from `list_members` with `member_kind = 'investigation'` (lb2:substrate/projects/registry.py:308-317). They are re-filtered on every read to real threads the requester is admitted to, because `add_member` never checks the investigation (lb2:registry.py:253-282).
- **Document scope.** The §1.2 definition applies (TC:274):
  - passage links: `question.escalated_to_research` events in `read-spin` whose `question_id` starts with `passage:<doc>:p` (main:substrate/books/passage_research.py:47-55, 146-177);
  - plus threads whose envelope `document_id` is the document. INFERRED: that means the start event's envelope.
- **`read-<doc>` is excluded.** TC:1005 says "Reading threads are single-operator today. Their owner-scoped ids come with §1.15." Its answer and position events feed staleness criterion 3 only.

**D11. Entries.** For each admitted, summarised thread, LB-9 calls `build_body` (w5x:build_body.py:147-192).
- **Kinds.** Body insights become `insight`, and open questions become `open_question`.
- **Merging.** Entries are deduplicated by `node_id`, and `thread_ids` is the union of the threads.
- **No `claim` entries.** The body carries no claims (TC:203; main:substrate/research_artifact/schema.py:28-40). The only signed source of claims is the §1.10 pack over `supporting_claims` (TC:535), which is W2 work and exists on no ref.
- **twin_note_taker adds nothing.** A twin body's insights and questions are empty (main:substrate/twin_note_taker/generate.py:642-676, per the sources report), and its ids carry no owner. **[RULING]**

The entry fields:

| Field | Source |
|---|---|
| `text` | Set only when served: the live `nodes.canonical_label` at GET time. |
| `origin` | `source` when the entry has at least one own pin, otherwise `unsourced`. Never `operator` or `generated`. **[RULING]**: w5x treats a question with no source as the operator's own words (w5x:substrate_refs.py:28-33). |
| `confidence` | The insight's metadata string (main:roles/note_taker/distill_query.py:144). Omitted when absent. |
| `doc_ids` | The distinct `document_id` values of the entry's own pins, after the overlay. |
| `process_ref {thread_id, event_id}` and `updated_at` | The newest event across `thread_ids` that produced or refined the node: `graph.node_inserted`, `note.emerged`, or `note.refined`, whose `note_id` is the node id (main:roles/note_taker/living_note.py:125-138). |

The process_ref walk comes from an additive `distilled_node_events()` in `roles/note_taker/distill_query.py`, sharing the existing walk at main:distill_query.py:69-109. I found no live board claim on that file.

**D12. `state`.** The values are `ready | stale | unavailable_until_rights`. TC:1533 and TC:1537 name the last two; Part 1 never lists the set.
- A scope that has never been refreshed reads `stale`, with `content_hash: null` and `entries: []`.
- `partial` and `empty` are lane-A derivations (TC:1531, TC:1535).
- **[RULING]**

**D13. Counts.** `total_thread_count` is the exact number of admitted member threads.
- **It is null when:**
  - a candidate member's start event cannot be read, so its ownership is unknown; or
  - the membership read fails.
- **`summarised_thread_count`** is the size of `covered ∩ admitted`, and it is null exactly when the total is null.
- **While unavailable,** both counts are null.
- A count is never 0 for an unknown (TC:207, TC:154).

**D14. Staleness (TC:1041-1044), plus one extension.**
1. **Newer thread events.** Each thread's stored event count and its `through_event_id` are compared by count, because event ids are not ordered (TC §1.5, `thread_seen`).
2. **Membership changed.** A sha256 digest over the sorted `(member_kind, member_id)` pairs of investigation and document members, or over the sorted thread set for document scope. `write_folders.updated_at` is not used: PATCH bumps it (lb2:registry.py:237-243), and the alias writes skip it (lb2:substrate/write/folders.py:148-188).
3. **Reading or answer events.** The watched `read-<doc>` logs are counted for `read.book_answered` events whose `payload.owner_id` is among the requester's identities and whose envelope is the document (the pattern at main:books.py:176-185), and for `reading.position` events. `reading.position` exists on no ref; it is W1 (TC:1170). For project scope, the watched documents are the project's document members. **[RULING]**
4. **Drift.** If the hash of the live served projection differs from the receipt's `content_hash`, the document reads `stale`. This catches refinements logged outside the member threads (living_note.py:125-138 emits into whichever investigation raised the challenge) and takedowns. **[RULING]** This is a cause outside the three signed ones. The honesty rule "a stale document says stale" supports it.

**D15. `content_hash`.** It is the sha256 of canonical JSON (sorted keys, entries sorted by id) over the served projection at refresh time. Each entry contributes `{entry_id, kind, gate, reason, origin, source_refs, thread_ids, doc_ids, process_ref, confidence}`, plus a `text_sha256` only when the entry is served. Withheld text never enters the hash, so the hash cannot confirm a guess at withheld text.

**D16. Errors.**

| Status | Body | When |
|---|---|---|
| 401 | `authenticated_owner_required` | no owner resolves |
| 404 | `project_not_found` (lb2:registry.py:43-47) or `document_not_found` | the scope is missing or another owner's, answered identically and before any other read (the pattern of comp:interfaces/research/api/companion_routes.py:109-117) |
| 409 | `{reason: "unavailable_until_rights"}` | POST while the switch is off |
| 503 | `{reason: "receipt_not_written"}` | the strict emit failed |
| 503 | `{reason: "graph_unavailable"}` | the database cannot be opened |

**D17. Refresh order.**
1. Do every read, with no lock held.
2. Open `connect_write` and initialise the schema.
3. In one transaction: delete the owner's rows for (owner, scope, id), insert the new rows, and upsert the receipt row with `refresh_event_id = E`.
4. `emit_typed(receipt_log, payload, event_id=E, strict_write=True, idempotent=True)` (main:substrate/event_log/events.py:358-420).
5. If the emit fails, answer 503. The rows are then unattested, so a GET treats the scope as never refreshed until a retry succeeds.

## 2. Rev-9 §1.15 compatibility (Astra's four amendments), without building on unsigned text

1. **Exact-owner discovery, and an opaque 404 before metadata, refs or context.**
   - The document route checks ownership before any other read, and a missing or foreign document gets the same 404.
   - Refs to another owner's private document are opaque (D7, D8).
   - LB-9 is stricter than draft rule 4 ("Documents are corpus rows and are not owner-checked", draft:3116). Relaxing that for non-private corpus documents waits for a signed rev 9.
2. **Upload is the entrypoint, and PA04 allows same-owner derivatives.**
   - LB-9 mints no document, class or text. Its rows are refs only and bound to their owner.
   - It is still a cached-refs container and a derivative producer. LB-9 should ask Astra for a PA04b/PA04c ledger row through the board rather than edit Astra's files.
3. **Fail closed on unknown non-NULL classes, and keep legacy `user_owned` and NULL.**
   - The allowlist, plus a test for an unknown class and a test for NULL.
   - A `user_owned` document is served only to an admitted owner.
   - LB-9 relabels nothing.
4. **Activation covers more than chunk bodies.** The LB-9d activation receipt records the deployed API SHA, lane A's frontend SHA, and signed A/B/absent-owner probes, plus takedown and unknown-class probes. A merged PR is not activation.

Historical `user_owned` remains OPEN until PA06.
