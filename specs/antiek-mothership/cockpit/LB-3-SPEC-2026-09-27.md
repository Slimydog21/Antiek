LB-3 spec is below. Signed-text gaps are marked `[N#]`, and everything I didn't read directly is marked INFERRED.

> **Superseded in part by THREAD-CONTRACT rev 8.11 (draft v4, 2026-09-27).** Where the note and this spec differ, the note governs:
> - **N1 → 8.11 A1.** The precedence is: a recovered terminal from any readable layer; then reading → idle; then an incomplete read (a failed layer or skipped records) → `null`; then a cascade session whose leaf reads are incomplete → `null` before the aggregate; then derive.
> - **N2 → 8.11 A2.** A chase halt with no completion is terminal **only for a budget reason** (`budget_exceeded`, `aggregate_budget`, `per_research`, `aggregate`). Any other halt reason ends the chase, not the thread (signed :269).
> - **N6 → 8.11 A6.** `thread_seen` stores `seen_through_position` (an advisory cursor) **and** `seen_terminal_event_id`. `done_unseen` compares each done thread's completion event id (its own terminal, or for an aggregate-done session its latest leaf terminal) with `seen_terminal_event_id`, and a null completion id always counts as unseen.
> - **A7.** `thread_counts` is `null` when any member's `state` is `null`, or when a member read or the `thread_seen` read fails.
> - **ThreadSummary wire (8.11 A10).** It adds `failure_reason: "owner_model_unavailable" | "owner_model_outcome_unknown" | null` and `failed_before_start: bool | null`. Both are non-null only for `state: failed`, and `failed_before_start` is true when no `phase.enter` precedes the failed terminal.
> - **LB-3c (dialogues and ask)** moves to rev 9 §1.8 (the T2 package). 8.11 withdrew Part B.

## 0. Corrections the spec rests on

1. **The signed contract has no state for an unreadable log.** The brief assumes "failed/unknown per the contract", but neither §1.2 nor rev 9 defines one.
   - The only signed basis is the Part 1 header rule "An unknown value is always `null` with a reason, never `0`" (THREAD-CONTRACT.md:156) and the count-nullability rule (:207).
   - Emitting `failed` would claim the run failed. The spec uses `state: null` instead, which needs co-sign item [N1].
2. **`trajectory()` hides incompleteness.**
   - It silently skips malformed JSONL lines (substrate/event_log/events.py:777-783).
   - It silently drops the Parquet snapshot when pyarrow is missing (:767-772).
   - It raises on a corrupt Parquet file, and the list does not catch that. So one bad sealed log can fail the whole `GET /investigations` today (app.py:3083).
   - `iter_physical_events` is no substitute for a read. It takes `investigation_event_lock`, which runs `os.makedirs` and creates the file `.{id}.delivery.lock` with O_CREAT (events.py:193-217). Any read path using it would write to disk.
3. **c2-export already contains half of the "one helper".** `runtime.research_runner.terminal_event(rows)` (2be3e0d1b:runtime/research_runner/protocol.py:60-100) makes completed or failed win over a chase halt. The list, detail and `reconstruct_session` all call it there. c2-export also rewrites the legacy status lines in both routes, and it adds `trajectory_read` (2be3e0d1b:substrate/event_log/events.py:767-860). LB-3a must reuse both, not fork them.
4. **The runners' lifecycle rows are all invalid as typed events.** Examples: `completed {outcome}`, `chase_halted {reason: aggregate_budget | per_research | aggregate}`, `failed {error}`, `start_requested {sub_question}`, `spawned_from {sub_question}` (host_local.py:232-238, 246-248, 319-321, 358-383; events.py:824-830 `extra="forbid"`). So the helper reads raw rows, and runner threads cannot be pushed as Events without a type change. Runner push stays on the signed cascade SSE (THREAD-CONTRACT.md:494).
5. **A producer bug defeats "failed reads failed".** Loop One builds `InvestigationFailedPayload(phase=0)` on the owner-model paths (orchestrator.py:2111-2121, 2127-2137) and uses `phase=ctx.failed_phase or 0` in the phase loop (:1884-1885). The payload requires `phase` in 1..9 (schemas/events.py:2549). The ValidationError escapes the detached task, no terminal is ever written, and the thread reads as running forever. PR LB-3a0 fixes it.
6. **The "needs attention" label is lane A's.** The server list already says `failed`. The relabel happens in apps/reading/src/shared/researchState.ts:120,217, ReadingCompanion.tsx:692-694 and ThreadIsland.tsx:62,72, and MyResearch.test.tsx:125 pins it. LB-3 adds a new `state` field and never changes the legacy `status` values, because lane A's status unions are closed and throw on unknown values.
7. **Several LB-3 row items are already covered.**
   - "Right-pane tab state persisted per (owner, project, mode)" is LB-2's `project_tabs` tree with `side: right` nodes (LB-2 substrate/projects/schema.py:65-77). LB-3 adds nothing there.
   - "a `/ws/events` filter" already EXISTS (app.py:4970-4996, broadcast.py:73-78, signed :278). LB-3 changes no socket route.

## PR LB-3a — thread state helper, per-thread fetch, listings, `thread_seen`, §1.5 aggregates

No event-schema bump. Graph schema: one per-account table.

**Problem (origin/main).**
- Three disagreeing derivations:
  - the detail route treats only `completed`/`failed` as terminal and ignores `outcome` and chase halts (app.py:2913-3008, esp. 2982-2987);

**Design (signed §1.2 :256-271, :274-278; §1.5 :379-383; Part 2 §2.1, §2.2, §2.4; plus N1–N8).**

*The helper* lives in `substrate/threads/state.py` and has no FastAPI imports.

- **`read_thread_log(id) -> ThreadLog(rows, stored, complete, readable)`**
  - Wraps `trajectory_read`, catching any exception as `readable=False`.
  - Never uses `iter_physical_events`, a lock or the outbox.
  - Validates the id with the storage-id regex `[A-Za-z0-9_][A-Za-z0-9_.-]{0,199}`.
- **`thread_kind(id, rows)`**
  - None for the attribution buckets `read-spin`, `__sidecar__`, `__operator__` and `reformat:*` (signed :189).
  - `reading` for `read-<doc>`. `read-spin` must be excluded explicitly, because it shares the prefix.
  - `cascade_session` when a `cascade.launched` row exists.
  - `cascade_leaf` when the id matches `^session-.+-leaf-\d+$` (cascade_routes.py:1229, 1368, 1411, 1500).
  - `research` for an `inv-` id or a log carrying a lifecycle marker (:3067-3070).
  - Otherwise None.
  - `reformat` is not derivable on main (no reformat events; #3527 is open), and `dialogue` arrives with LB-3c.
- **`derive_state(kind, log, leaves=None) -> (state, stop_reason)`**
  - Unreadable log: `(None, None)` [N1].
  - Terminal (via `terminal_event`, N2):
    - `completed` with outcome `stopped` → `stopped`/`user`; outcome `cancelled` → `stopped`/`cancel`; otherwise → `done`;
    - `failed` → `failed`;
    - a chase halt with no completion → `stopped` with `budget` or `null`.
  - No terminal:
    - `research`: `running` when any `phase.enter` exists, otherwise `queued` when a start exists, otherwise `None` [N1];
    - `cascade_leaf`: `running` when `start_requested` exists (it is written after the semaphore, host_local.py:309-336), otherwise `queued` when `spawned_from` exists (:232-238), otherwise `None`;
    - `reading`: always `idle` (:271);
    - `cascade_session`: `running` if any leaf is queued or running (or no leaf exists yet); then its own failed or `synthesis_tail.failed` → `failed`; its own completed → `done`; otherwise the leaf aggregate kept from main (:3179-3198): any failed → `failed`, any done → `done`, else `stopped` with stop_reason null. Any unreadable leaf → `None`.
  - `needs_you` is never emitted [N3], and `cap_*` is never emitted (no `investigation.cap_halted` on main).

- **`enumerate_thread_ids()`**: `.jsonl` plus `.parquet`, deduplicated, as app.py:2633-2652 already does.

## PR LB-3c — dialogues, ask, persisted turns, structured `source_refs` (W2 schema bump, needs N10–N12)

**Problem.**
- `/thought-partner` persists nothing. It returns `{shape, text, library_retrieval_status, library_retrieval_degraded_reason}` (app.py:6646-6652, 6726-6732) and writes only an anonymous `dispatch.call` to `__sidecar__` (:6719).
- The retrieval hits carry `chunk_id`, `document_id`, `section_path` and `document_title` (substrate/graph/search.py:262-277). `_retrieve_thought_partner_context` keeps only the chunk id plus `document_id` under the key `source_event_ids` (app.py:1463-1522). The response then drops even those.
- The client keeps turns in sessionStorage keyed by reading focus (useThoughtPartnerThread.ts:4, 38, 49), so they vanish on a tab hop or a reload.
- The server trusts client `history` (app.py:6687-6691), and a failed turn's error string is resent as a prior answer (useThoughtPartnerThread.ts:70-80).
- No `/ask`, `thread.turn` or `answer.provenance` exists on main.

**Design (signed §1.8 :502-508, §1.2 GatedText :209-254, §1.11a :798-800, §1.7 :494-496, plus N10–N12).**

- **Create.** `POST /investigations {kind: "dialogue", title?, project_id?, document_id?, investigation_id?}`.
  - A `kind` Literal is added, defaulting to `"research"`, and `question` is required only for research.
  - The create runs no ACU precheck or charge and never emits `investigation.start_requested`.
  - It writes `thread.dialogue_started` strictly. For a document scope the envelope `document_id` is set.
  - With `project_id`, it writes membership the same way LB-3b does.
  - An `investigation_id` that already has a stored log answers `409 {reason: "investigation_id_conflict"}`.
  - The owner is `request_owner_user_id`.
  - Response: `201 {investigation_id, status: "created", start_event_id}`.
- **Kind and state.**
  - The first start-family event `thread.dialogue_started` gives `kind: dialogue`, and that event joins the list's marker set.
  - State is `running` while an ask for that id is in flight, tracked in an in-process set (sound under the single-worker invariant); otherwise `idle`. There is no terminal (Part 2 :1437).
- **Ask.** `POST /investigations/{id}/ask {question (1..2000), context_items?: ContextItem[] (at most 20)}`.
  - Unknown fields → 422. There is no `system_context` and no `history`.
  - Owner mismatch or not a thread → `404 {reason: "not_found"}`.
  - Not a dialogue → `422 {reason: "not_a_dialogue", kind}`.
  - Already in flight → `409 {reason: "turn_in_progress"}`.
  - Steps:
    1. The policy tag comes from `_owner_read_policy_tag` (books.py:106).
    2. Library hits come from a NEW sibling helper that returns the raw hits. `_retrieve_thought_partner_context` becomes a thin wrapper with an unchanged signature, so no #3278 hunk is touched.
    3. `context_items` resolve through `_compose_context` (app.py:1345), one call per item. Served → `served`; withheld → `cite_only · not_servable`; missing → `cite_only · unresolved`.
    4. History is the dialogue's last 8 `thread.turn` rows, matching today's client cap (useThoughtPartnerThread.ts:24).
    5. The model receives only served text (signed :507). Account memory context is excluded, because R15 owns it and it is not a served source.
    6. One `dispatch(…, "thought_partner", investigation_id=<dialogue id>)` call.
    7. `parse_thought_partner_response` (roles/thought_partner/parser.py:38-94) supplies `shape` and `challenges[].note_ids`.
  - **The answer** is a GatedText with `gate: served` and the raw model text. Rendering stays lane A's (F-23).
    - `origin` is `source` when at least one served source was given, `unsourced` when none were.
    - `source_refs` are the served retrieved items (signed :507).
  - **`cited_refs`** are the parsed note ids that fall inside the retrieved set. An invented id is dropped (`cited_refs ⊆ retrieved_refs`).
  - **`presentation_mode`** is `cited_quietly` when `cited_refs` is non-empty and `metadata_only` otherwise. The model makes no such choice today, so this is the server's rule [N12].
  - **Write order.**
    1. Mint `turn_event_id`.
    2. `answer.provenance` (strict).
    3. `thread.turn` with that event id (strict).
    4. Broadcast `thread.turn` on the dialogue id.
    - A provider error → `503 {reason: "thought_partner_unavailable"}`, and no turn or provenance is written.
  - `POST /events/typed` refuses `thread.dialogue_started`, `thread.turn` and `answer.provenance` with 422 `server_owned_event`.
