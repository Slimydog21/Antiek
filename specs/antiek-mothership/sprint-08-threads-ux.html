Contract: row state derives from the event log's terminal reader. merged_into is investigation-level lineage. Base: MS-07. Branch: design/mothership-08-threads.

Contract facts (THREAD-CONTRACT.md rev 7, signed by both lanes 2026-09-26): these override any older wording on this page.
  • Row states are queued, running, needs_you, done, failed, stopped, idle (reading threads) and merged_into; done carries an unseen marker from thread_seen. Opening a thread sends POST /investigations/{id}/seen {through_event_id}, only ever forward (§1.5). There is no capped row state (§1.1.4).
  • Lists come from GET /investigations with project_id, document_id, kind, state and parent_thread_id filters (§1.2). claim_count, source_count and spend_cents are nullable and render "—" with a reason. The process view is a projection of GET /trajectory/{id}.
  • Merge preview is POST /threads/merge/preview → {preview_digest, items[], conflicts[]}. Commit is POST /threads/merge {thread_ids[], preview_digest, question, idempotency_key}: 409 preview_stale (the digest covers gated text, pointers and rights) re-previews and keeps the question; 503 means nothing has run, and Retry with the same key resumes from thread.merge_started. Show merged only when the start event is confirmed; member rows read merge_pending / merge_failed until then (§1.10, Part 2 §2.4–2.5). 409 idempotency_conflict is a lane-A bug. Every item is a GatedText: render Part 2 §2.10 by gate, never by empty text.

Goal

Threads are listed where they were made (per document, per workstation), can be asked again with their held context, and can be merged with the provenance and conflicts made visible.

The document's rail and its margin marks list its threads. The workstation's Threads tab and the sidebar list all of them with live state. Any row opens an "ask this thread" composer. Selecting two or more rows offers Merge: a preview tags every claim and source with its origin thread, conflicts are shown and never averaged, and accepting produces a merged thread with lineage. An automatic merge from lane B arrives as an inbox suggestion and is never applied silently.

Rigor — operating manual for this sprint

How to execute well. Each value has been adapted to this sprint's specific work.

1 · Intellectual honesty

Calibrate confidence to evidence

If lane B's merge entity isn't ready, the merge flow can preview but not accept. Ship it with Accept disabled with a reason: W2's disabledReason prop on LemonButton if it has landed, otherwise add the prop here. The flow then stops at contract §2.5's previewing/conflicts_shown, with no merging, and the stopping point is checked by a test. Never fake a merged thread client-side.

2 · Fairness

Steelman the rejected alternative

Steelman merging by concatenating two threads' outcomes into a note: cheap, and it works today. It fails the operator's ask. A concatenation can't be asked again, carries no lineage, and hides conflicts. Cheap merge is what ArtifactOutlineShelf already does (C05), and it was found insufficient. Who pays for the real merge: lane B builds the B2 merge engine and conflict detection ({claim_a, claim_b, reason}). Until it ships, the operator gets a merge that previews but cannot accept.

3 · Rigor

Claims are mechanically checkable

Conflict display is the correctness core. Build a fixture where two threads assert contradictory claims about the same source, and assert that the preview shows both, with origin chips and the conflict reason. Assert it never picks one. Also assert: a merge of three or more threads previews correctly; a merge suggestion leaves both sources' merged_into unset until accept; and an AskThread request carries thread_id, with its turns appended to that same investigation.

4 · Diligence

Read before writing

Read MyResearch.tsx (grouping and attention), ArtifactOutlineShelf's draft merge (:128-151), DRW steer (ResearchPanel.tsx:71-92) and the #3078 attention registry before building rows or merge. Before DocThreads, also read ReadingCompanion.tsx's saved-chases section and the backend researches_for_passage (C01). Before ProcessView, read the TalkToBook and Dialogue session stores (C07/C08).

5 · Defensibility

Decisions survive turnover

The rule that row state comes from the terminal reader, never a client field, goes in a comment on the shared row component (apps/reading/src/threads/ThreadRow.tsx, used by DocThreads and WorkstationThreads), citing the contract §2.4 agreement. Otherwise a future "optimistic state" shortcut will reintroduce the second state column.
