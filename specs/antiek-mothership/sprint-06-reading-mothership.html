What this sprint is about. The operator (D5, 2026-09-24) wants a Reading mothership for two uses:

  • (i) a Kindle or real-book replacement, where companion deep researches, footnotes and references open in tabs, so he can "tunnel through a rabbit hole and open many documents in the tabs";
  • (ii) reading as the entry into a research or writing project: something specific, something he or an agent flagged, or something new.

Grounding (ground/lane-a-reading-mothership.json, refuted MOSTLY_RELIABLE) found the reader short of a Kindle in five ways:

  • no page keys (R2)
  • no Aa control (R7)
  • no focus mode (R5)
  • position only in sessionStorage, per tab, and clobbered when a citation opens the book (R4)
  • OS-only dark mode (R6)

It also found that footnotes are deleted at ingest or left as dead text (F1), that in-body links navigate the whole app away (F2, ABSENT), and that there is no Continue or To-read door (H1, H2, T2, T3).

Goal

Opening the Reading mothership asks what to read: Continue, To read, or New. Reading feels like a good e-reader, and every footnote, reference and citation opens as a child tab you can return from to the exact passage.

Kindle-grade here means:

  • a 60–72ch measure in Charter
  • page turns on ←/→ and space
  • visible progress
  • text size and line height
  • day, night and paper themes
  • no layout shift while loading
  • a distraction-free mode (prefix+f) that leaves only the path header

The rabbit hole is the branch tree from MS-04. The Continue door resumes the exact passage on any device once lane B's position record exists.

2
Kindle-grade reader: keys, progress, Aa, themes, stability

Page keys (←/→, space, PgUp/PgDn, Home/End) in a reader key scope inside MS-01's keymap. They never fire in inputs or FloatMenu, and they defer to a focused WorkspaceWindow, which owns ←/→ (MISS5). Also: a progress bar with % and chapter-remaining; an Aa control (size, line height, margins; pagination is size-independent per the usePosition docblock); day, night and paper themes on the W1 tokens; and a skeleton shaped like the final TOC and column.

Acceptance criteria
  • Key-scope tests: keys work when the reader has focus and are inert in inputs, FloatMenu and focused windows.
  • Measure: the rendered line is 60–72 characters at the default size (measured in a story test).
  • Theme contrast is AA in all three themes (the tokens contrast test is extended).

3
Distraction-free mode (prefix+f)

Hides NavRail, docks, the mascot, rails and ads, leaving the path header and the column. It is reversible with the same key or Esc, and the choice is remembered per document.

Acceptance criteria
  • Chrome occupancy at 844 px tall drops from about 35–42% to under 10% (measured in a story).
  • The ad-frame attribution hooks are untouched when ads are shown (the existing ad tests pass).
apps/reading/src/modes/Reading/FocusMode.tsx (new)
4
Footnotes and endnotes in place

For documents whose ingest keeps structured notes (lane B), a note reference opens a popover in place, anchored to the marker and closable with Esc. "Open as tab" spawns a child tab at the note. For the legacy text-only case, notes are detected in the text; detection happens in the UI and never rewrites the stored document.

Acceptance criteria
  • Stories: a footnote popover, an endnote at the end of a chapter, and a note on another page window (the paginate() split).
  • Tests: Esc returns focus to the marker, and "Open as tab" creates a child with branch_origin.kind = footnote.
apps/reading/src/components/reader/Footnote*.tsx (new)
5
Every in-body link becomes a branch, never a navigation

Intercept clicks on links in the reader body (F2). An internal document opens through openDocument(id,{where:'child_tab', at}). A DOI or arXiv reference opens a "resolve reference" state (in the graph → open; else a rights-aware "ingest?" offer from lane B). External web links get an explicit "open outside Antiek" confirmation.

Acceptance criteria
  • A test: clicking a body link never changes location.pathname outside the workstation.
  • The resolve-reference state machine has a story for each state: found, not stored (offer), rights-blocked (honest reason), failed.

Rigor — operating manual for this sprint

How to execute well. Each value has been adapted to this sprint's specific work.

1 · Intellectual honesty

Calibrate confidence to evidence

"Kindle-grade" invites adjectives, so every claim is one of these numbers:

  • 60–72 characters per line at the default size
  • under 10% chrome at 844 px tall in prefix+f mode (today 35–42%)
  • AA contrast in day, night and paper
  • CLS ≈ 0 in the load story
  • ←/→/space inert in inputs and FloatMenu (the key-scope matrix)
Anything unmeasured is written NOT MEASURED; never write "feels like a Kindle".

2 · Fairness

Steelman the rejected alternative

Steelman keeping footnotes as plain popovers with no tabs: simpler, and closer to a real book. It loses for use case (i), because the operator explicitly wants to tunnel down references as tabs. The popover stays the default, with the tab one click away, so the book-like reader isn't forced into branching. Who pays: the book-first reader pays one extra click per tunnel, and the use-case-(i) reader pays nothing. The builder carries two code paths (popover and child tab), plus the text-only detection fallback for legacy documents.

3 · Rigor

Claims are mechanically checkable

Enumerate the link kinds in reader bodies before intercepting them: same-document anchor, other document in the graph, DOI, arXiv id, plain web URL, mailto:, and javascript: (strip it, it's a sanitiser failure). Each has an asserted behaviour. A same-document #fn anchor on another paginate() window is the tricky case, and it gets its own test.

4 · Diligence

Read before writing

Read usePosition.ts (the pagination and size-independence docblock), paginate(), readingFocus.ts, ReadingCompanion, PersonalSpace (/readings) and W3's .prose-antiek before building. Ingest strips Wikisource footnotes (reading-lane F1 in ground/lane-a-reading-mothership.json, not GAPS F1): read acquisition/books/wikisource.py:93-114 and paginate.ts:23-60, so the UI's detection fallback matches what actually survives. Also read the PersonalSpace dwell query that feeds the Continue door.

5 · Defensibility

Decisions survive turnover

Record why Continue reads lane B's position record first and local position second, and why a citation open never writes position (it would clobber the operator's real place, R4). Put that in a comment at the position hook, citing R4 and MISS6. For the no-clobber rule, point to MS-05 M4 and its page-40 resume test rather than re-owning it. Record the Continue precedence in DECISIONS.md under D5.
