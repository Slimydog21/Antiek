What this spec is now

A reconciliation, not an execution backlog. The genius is recognizing what's already owned and refusing to fork it.

Lineage: the Karpathy Deep Dive into LLMs like ChatGPT talk (post-training, RL, cognition), distilled into six truths at the philosophy canon ~/specs/antiek-karpathy-deep-lens/ (which survives, outside the repo). An in-session 10-sprint execution draft was written against that lens, then swept by a parallel-stream branch operation while untracked in specs/ — the exact collision CLAUDE.md warns about. This reconciliation is re-created and committed.

Between the draft and now, the operator crystallized the product into four workflows (Research · Read · Write · Speak), the antiek-unified integration capstone froze a tech-stack ledger with one canonical owner per layer, enforced mechanically, and the sibling karpathy-engineering spec (the Intro to LLMs lens) already collapsed its nine candidate sprints to two. Re-grounding the deep-lens draft against that reality is the whole job — and the honest result is that the deep-lens's distinctive payload is the RL layer, which is owned by substrate/loop_3/ and gated behind G8: the gate the operator controls and that no engineering sprint may fire.

The anti-pattern this spec exists to refuse. Executing ten substrate sprints against an essentially-complete codebase with named owners. Building substrate/rewards/ next to substrate/loop_3/verifiers_env.py, or substrate/trajectory/ next to trajectory_harvest.py, is a second owner per layer — a CI failure under the unified invariant and a divergence bug in waiting. Where the lens and the four-product reality disagree about who owns a layer, reality wins.

The surviving sprint (ungated)

Uniform role-parser provenance validation. One sprint, executable now, serving all four workflows' provenance moat.

S
SPR-01 · Uniform role-parser ID/provenance validation

Generalize the grounder's "validate the model-emitted ID against the canonical set, treat a miss as a failure not a fact" pattern into a single shared validator that every role parser uses. Today only the grounder bridge does this, only for located_chunk_id. Every other parser that surfaces a model-emitted reference (note_taker source_event_ids, parameter_extractor node/edge endpoints, cross_doc question_id, connector edge refs) trusts the model. A hallucinated ID becomes a fake provenance edge — silently poisoning the graph that is the moat.

Acceptance criteria
  • One shared helper (substrate/provenance/validate_refs.py — under the provenance-graph owner, not a new top-level layer) exposing validate_ref(candidate, canonical_set) -> str | None and a list variant; pure, deterministic, no model in the loop.
  • The grounder bridge is refactored to call it (behaviour bit-identical; existing grounder tests pass unchanged).
  • Each remaining ID-emitting parser validates against its canonical set; a hallucinated reference is dropped/flagged, never written as a provenance edge.
  • An adversarial test per refactored parser: model returns a fabricated ID → parser rejects it; ≥3 such cases that no current check catches.
  • A tools/lint/ rule (joining the existing lint owner, not a new runner) flags any new parser that surfaces a model-emitted *_id without routing it through the validator.
substrate/provenance/validate_refs.py roles/grounder/parser.py (refactor) roles/note_taker/parser.py roles/parameter_extractor/… interfaces/research/api/cross_doc.py tools/lint/ (new rule)

Why this is the survivor, and hard to vary

It is the only deep-lens concern that is (a) ungated — pure deterministic validation, no RL, no G8; (b) unowned — grounder does it locally, nobody does it uniformly; (c) demanded by the vision — "every claim cites a node, no orphan prose" is the Write/Read/Speak provenance moat; and (d) consistent with its own lens — W4 says ID/character-level work stays in code. Every other deep-lens sprint fails at least one of those tests.

The G8-gated package (specced, not built)

The deep-lens's distinctive RL payload, re-homed onto substrate/loop_3/. One package, executed only when the operator opens G8. Specced now so it's ready; built never-before-G8.

G8
SPR-02 (gated) · loop_3 verifiable-reward + per-step + interrogation extensions

When and only when substrate/loop_3/unlock_gate.py reports G8 open, three extensions land inside substrate/loop_3/ — never as parallel modules:

The three extensions (all to existing loop_3 owners)
  • Populate verifiers_env.py's scaffold with the 7 named verifiable rewards from deep-lens W5: grounder-pass, cross-doc-match, constraint-convergence, claim-survival, schema-conformance, id-validity (reuses SPR-01's validator), attribution-coverage. Each is a pure event-log function — no LLM judge (W5: verifiable means no model in the reward).
  • Add per-step reward shaping to trajectory_harvest.py (the DeepSeek-R1 insight from W5): attach per-event marginal reward to HarvestedTrajectory so RL sees per-step gradient, not just final-answer reward.
  • Add the "I don't know" / interrogation data path: the Meta-Llama-3 boundary-probing procedure (W4) feeds refusal-target trajectories into the harvest, coordinated with antiek-eval-discipline/generate.py (the likely existing owner) to avoid a second generator.
Hard gate
  • The package is inert behind unlock_gate. No file in it runs before G8. The W5 verdict is absolute: RLHF-style neural reward models are rejected as terminal training signal; only the verifiable catalog populates the env.
